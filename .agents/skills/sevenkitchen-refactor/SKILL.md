# SevenKitchen 模块重构

本仓库有生产流量，且 `CLAUDE.md` 里已有硬规则。本技能只补充**重构时的额外纪律**，不替代 `CLAUDE.md`；两者冲突时以 `CLAUDE.md` 为准。

## 1. 开工前：锁范围、拿基线

1. **确认只动一个模块**：`backend/`、`admin-web/`、`miniapp/` 三选一。跨模块改动先拆成多次任务。
2. **先跑基线测试，记录结果**（不是"应该能过"，是真跑）：
   - `backend/` → `cd backend && npm test`
   - `admin-web/` → `cd admin-web && npm run test`
   - `miniapp/` → `cd miniapp && npm run test`
3. **基线就是红的** → 先报告哪几个失败，不要开始重构。基线红的情况下重构，等于分不清是你的改动坏了还是本来就坏。
4. **字段名先查** `docs/DATABASE_NAMING_CONVENTIONS.md`，禁止猜。

## 2. 重构手法

1. **先补 characterization test**：动手改结构前，把"当前行为"用测试锁住（同样的输入 → 同样输出）。
   现有测试已覆盖的部分，不必重复补；只补你要动的、当前没被覆盖的那块。
2. **小步走，每步可回滚**：一次只改一个关注点（先搬文件 / 再改接口 / 最后清死代码），
   不要一个提交里同时做"改名 + 拆函数 + 改数据结构"。
3. **行为不变是唯一标准**：对外接口、返回结构、错误码、数据库字段都不许"顺手优化"。
   要改行为，那是需求变更，不是重构，先找用户确认。
4. **数据库只走 Prisma migration**，禁止直连改库、禁止手写 SQL 改结构。

## 3. 禁区（本仓库特有）

- ❌ **联调期间不要跑 `npm run build`**：`deleteOutDir: true` 会删掉 `dist/`，正在跑的后端会直接死掉。
  自检只用 `cd backend && npx tsc --noEmit`。
- ❌ 不要为自查新建临时小程序工程（会多开一个开发者工具窗口），复用现有项目。
- ❌ 不自动 `git push`、不自动部署。部署按 `CLAUDE.md`「生产部署授权」一节执行，且必须先合并到 `main`。
- ❌ 不自动提交：改完先汇报，等用户说提交再提交。

## 4. 完成标准（四条全中才算完）

1. 目标模块测试全绿，且与基线对比**没有新增失败**。
2. `git diff --stat` 只包含目标模块的路径；出现别的模块 → 停下来解释。
3. 能给出**可复现的验证命令和真实输出**（贴结果，不写"应该没问题"）。
4. 汇报里写明：改了哪些文件、为什么这么改、怎么验证的、怎么回滚。

## 5. 汇报格式（用户非技术）

- 先说结论：这次重构解决什么问题、有没有风险。
- 再说证据：跑了哪几项检查、结果如何。
- 最后说下一步：要不要提交 / 要不要部署。
- 不贴大段代码，除非用户要求。
