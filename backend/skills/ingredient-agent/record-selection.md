# 选记录

候选是**记录**，不是名字。同名的多条记录可能是不同批次、不同版本、不同数据源，
要逐条看，不能按名字合并。

## 看什么

按顺序比：

1. **状态对不对**：要生档案就选生（raw / 生 / 생것）；要熟档案就选熟（水煮 / boiled / ゆで）。
   没标状态的记录可以用，但要在方案里说明“未标生熟”。
2. **已填项多少**：`getRecord` 返回的 coverage（或已填项数）越高越好。
3. **关键字段齐不齐**：能量、水分、粗蛋白、粗脂肪、灰分、碳水；再看矿物质/维生素。
4. **数值合不合理**：能量与 4/9/4 反算差太多、宏量之和超过 103g/100g，先在方案里提示。
5. **来源与口径**：同一条原料尽量固定一个来源；中式食材可以优先 CFCT，但字段少时用 USDA。

## 同名多条怎么办

- 全部列进方案的 `candidates`，按推荐程度排序；
- 把你看重的差异写进 `findings`（例如“其中一条多 12 项矿物质”）；
- 不要自己挑一条就说“库里只有这一条”。

## 生熟两份

- 用户要“生 + 熟都要”时，方案里分别给出建议记录，一份档案一条来源；
- 只做生档案也完全可以，但要说明“熟档案暂缺”。

## 交方案

`chosenRecordId` / `chosenRecordName` 写你的建议；`candidates` 写备选；
`rationale` 一句话说清为什么选它。
