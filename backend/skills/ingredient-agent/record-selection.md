# 选记录

候选是**记录**，不是名字；同名多条可能是不同版本，逐条看，不要合并。

## 硬规则（按顺序，前面的不能被后面的推翻）

1. **状态**：要生就选明确标生的，要熟就选明确标熟的。未标生熟的只能当备选，
   且 rationale 第一句必须写“该状态无明确记录，暂用未标生熟”。
2. **覆盖率**：差 >10 个百分点 → 必须选覆盖率高的；“中文口径 / 名字更像 / 来源更权威”都不构成理由。
   差 ≤5 个百分点，才允许看第 3–5 条。
3. **关键字段**：能量、水分、粗蛋白、粗脂肪、灰分、碳水。
4. **数值自洽**：能量与 4/9/4 差太多、宏量之和 >103g/100g，在方案里提示。
5. **来源**：同一条原料尽量固定一个来源；覆盖率接近时中式食材可优先 CFCT。

选了覆盖率更低的：rationale 必须写清低几个百分点、差在哪几类字段、为什么仍选它。写不出就选高的。

## 方案怎么写

- candidates 全部列出、按推荐排序；不要挑一条就说“库里只有这一条”；
- name 只写库里原名，不要拼来源 key；
- 生熟都要时，两个状态各给一条建议，一份档案一条来源；
- rationale 一句话说清为什么。
