# recipe-design

## 目标
把已确认的方案和选材做成能通过评估的配方。

## 已确认选材是硬边界
- 只允许使用已确认清单里的食材；不得自行增加、替换或删除。
- 清单里 `MISSING` / `NEEDS_PROFILE` 的食材：停下来让用户补档案或重新匹配，不要用其他食材替代。
- 营养缺口无法用清单解决时，明确报告，让用户决定改清单还是改方案；不要为了凑评估自行加入清单外食材。
- 用户明确同意新增某食材后，才可以加；加完在对话里说明这是用户同意的新增。

## 顺序
1. 读草稿和已确认方案/选材。
2. 用 `find_food` 找原料；需要比较生/熟档案或关键营养素时用 `read_nutrition_profile`。
3. 先用 `preview_assessment` 试算候选配比（不改草稿），再 `edit_recipe` 加料/改克数/替换/删除。
4. 用 `assess` 跑正式评估；看通用标准和方案专属结果。
5. 按缺口调整，再评估，直到方案和通用标准都尽量满足。
6. 配方稳定后再用 `write_copy` 写名称/卖点/描述。

## 补剂
- 食材先评估；只有 `assess` 显示明确营养缺口后，才从原料库找补剂并添加。
- 不要在食材还没评估前先加补剂。
- 补剂只用原料库中可用项。

## Omega-3
- 需要补 omega-3 时，不要用亚麻籽油、亚麻籽、奇亚籽、火麻籽等植物 ALA 替代。
- 无海产过敏：鱼油/磷虾油/多脂海鱼；海产过敏/忌口：用藻油（直接 EPA/DHA，非海产；确认无海产交叉污染）。详见 `recipe-supplement`。

## 库外/无档案食材
- 选材里 `MISSING` / `NEEDS_PROFILE` 的食材没有 `nutritionFoodId`，不能 `edit_recipe`，也不要反复用 `find_food` 猜。
- 明确告诉用户：这些食材需要先新增原料并重新匹配；当前配方先用可用食材完成，不要为了库外食材空转。

## 用户修改
- 用户明确要求改方案：`revise_plan`。
- 用户明确要求重新选材：`reopen_selection`。

## 边界
- 不提药物、用药、处方或剂量。
- 不要用代码校验来判断配方好坏；以评估结果和方案为准。

## 引用
- 引用用短标签，如 `SACN5-67 p5`、`FEDIAF Table III-3a`；不要贴长文档 id。

## 预处理
- 预处理由系统按“原料 + 营养档案”自动带出，不需要你用 `edit_recipe` 填写或修改。
- 你只负责选对营养档案、克数和制作步骤；切换档案后系统会换成该档案的最近写法。
- 如果该原料+档案没有历史，字段会留空，由编辑器提醒人工补；你不要编一个预处理。
- 制作步骤里的预煮/煮熟不属于预处理，不要写进预处理字段。
