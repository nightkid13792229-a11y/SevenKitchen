# recipe-design

## 目标
把已确认的方案和选材做成能通过评估的配方。

## 顺序
1. 读草稿和已确认方案/选材。
2. 用 `find_food` 找原料，`edit_recipe` 加料/改克数/替换/删除。
3. 用 `assess` 跑评估；看通用标准和方案专属结果。
4. 按缺口调整，再评估，直到方案和通用标准都尽量满足。
5. 配方稳定后再用 `write_copy` 写名称/卖点/描述。

## 补剂
- 食材先评估；只有 `assess` 显示明确营养缺口后，才从原料库找补剂并添加。
- 不要在食材还没评估前先加补剂。
- 补剂只用原料库中可用项。

## Omega-3
- 需要补 omega-3 时，不要用亚麻籽油、亚麻籽、奇亚籽、火麻籽等植物 ALA 替代。
- 无海产过敏：鱼油/磷虾油/多脂海鱼；海产过敏/忌口：用藻油（直接 EPA/DHA，非海产；确认无海产交叉污染）。详见 `recipe-supplement`。

## 库外/无档案食材
- 选材里 `MISSING` / `NEEDS_PROFILE` 的食材没有 `nutritionFoodId`，不能 `edit_recipe`，也不要反复用 `find_food` 猜。
- 明确告诉用户：这些食材需要先新增原料并重新匹配；当前配方先用可用食材完成，不要为了库外食材空转。

## 用户修改
- 用户明确要求改方案：`revise_plan`。
- 用户明确要求重新选材：`reopen_selection`。

## 边界
- 不提药物、用药、处方或剂量。
- 不要用代码校验来判断配方好坏；以评估结果和方案为准。

## 引用
- 引用用短标签，如 `SACN5-67 p5`、`FEDIAF Table III-3a`；不要贴长文档 id。

## 预处理方式
- 统一三段式：`部位/状态/处理`，用 `/` 分隔；不写原料名。
- 原料名里已经有部位或状态的，那一段直接省略，不留空占位。
- 只写影响营养/生产的处理：去皮/去脂/去骨/去筋膜/去籽/切块/切片/绞碎/打散等；不写蒸煮烤（属于制作步骤）。
- 不写“洗净”，除非这个原料必须特别清洗；补剂不填。
- 例：牛霖（名含部位）→ `生/去筋膜切块`；冷冻鸡胸（名含部位+状态）→ `去皮去脂`；菠菜 → `生/去根切段`；鸡蛋 → `生/打散`。
- 如果该原料有历史写法，编辑器会提示“用新的/用旧的”，按提示确认，不要静默重复改。
