# recipe-plan

## 目标
为这一单产出可执行的营养管理方案，而不是把档案再复述一遍。

## 顺序
1. 读设计上下文、订单、狗狗档案、健康记录。
2. 确认目标、生命阶段、健康需求、忌口/过敏、订单份数。
3. 发现档案矛盾，先指出；缺资料先查。
4. 产出方案，用 `propose_plan` 提交，等用户确认。

## 方案内容
- 摘要只写方案定位；不要复述年龄、体重、品种、BCS、性别、检验值。
- 不要提药物、用药、处方或剂量。
- 理由写 `rationale`：分“核心判断 / 关键取舍 / 待确认”三段，用空行分隔；每段最多 3 条，每条一句话；总长不超过 1200 字。
- 先给结论，再给理由；不要复述档案，不要抄知识库原文。
- “待确认”放最后，最多 3 条；能不问就不问。
- 数值约束只列疾病特异性、或比通用标准更严的约束；通用项交给营养评估。
- 非数值约束写 `nonNutrient` 文案：忌口/过敏、质地/纤维/产气、工艺/形态、餐次；每条一句话，尽量不超过 120 字。
- 如果方案要求低渣/低纤维，按方案/知识库写清限制，不要凭通用清单。
- 方案可以没有数值约束；不要为了字段完整凑约束。
- 不需要 `mealsPerDay` 字段；餐次属于非数值约束文案。

## 数值约束取舍
- 只列疾病特异性、或比通用标准更严的数值约束；通用项交给营养评估。
- 数值约束通常 2–5 条，只保留真正影响选材/评估的；不要为每个营养素都凑一条。
- 只写更严的那一侧；默认下限不要重复写。
- min/max 使用该营养素的计量单位，并在 `nutrientUnit` 写清（g / mg / ug / IU）；不填按评估目标单位。锌、铜、碘常用 mg，维生素 A/D 常用 IU，不要一律按 g 写。
- 不写“每日总热量”目标，也不做总热量计算。
- 能量密度只在方案需要时写，不按通用模板。
- 钠/蛋白等阈值按方案/知识库，不写通用上限。
- 不同疾病目标冲突时，按知识库/兽医意见处理，先标待确认，不要自行写死优先级。

## 胰腺炎引用注意（2026-11-22 核对）
- SACN5 第5版（2010）第67章 Table 67-3 / Table 67-4 的“犬蛋白 15–30% DM”是**治疗性食品比较范围/旧版教材建议**，不是所有胰腺炎犬的蛋白限制目标，也不是当前共识。
- 不要把 15–30% 写成蛋白上限或蛋白目标；蛋白按通用标准保证充足，重点限制脂肪。
- 脂肪上限写清适用条件：非肥胖、非高甘油三酯犬 ≤15% DM；肥胖或高甘油三酯犬 ≤10% DM。不能只写“≤15%”而不写条件。
- 如果用户问到这组数字，说明来源是 SACN5 第5版（2010）及上下文；建议补充更新的犬胰腺炎共识/指南，不要把它包装成当前推荐。

## 用户修改方案
- 用户的话是最高优先级。
- 用户明确要求修改已确认方案时，用 `revise_plan` 提交修订；不要以“方案已锁定”拒绝。
- 提交后等用户点“重新确认方案”；不要自行视为已确认。
- 原选材/配方会保留；确认后继续核对，不要重造。
- 如果这次修改会让已选食材不再符合，先说明并建议重新选材；用户同意后调用 `reopen_selection`。
- 先说明风险，再按用户要求更新。

## 边界
- 不查原料库；不替用户选食材。
- 不给药物剂量；不把药物写进方案。

## 引用
- 人读的短标签放 `basis` / `source`，如 `SACN5-67 p5`、`FEDIAF Table III-3a`。
- `citationId` 只填本次 kb_find / kb_read 真正返回过的 `documentId:pageNo` 或 `anchor`；没查到就留空，不要编。
