# 报销单详情页（管理员审核）改版 · 会话归档

日期：2026-11-08
范围：`miniapp/` 员工端报销详情页 + 支撑它的 `backend/` 采购/定价逻辑 + `admin-web/` 一处文案
入口页面：`miniapp/src/pages/staff-purchasing/reimbursement/detail.vue`

## 一、要解决的问题

这页原本是员工填单后看明细的页面，被管理员当成审核页用：10 条采购记录、每条 6 个数字，
却没有「凭证金额/差额」「哪几项价格变更」「我不同意怎么办」；底部只有「上传报销凭证」，
而这个动作在后台会直接完成报销并让价格变更生效。

## 二、老板拍板的口径（后续改动都以此为准）

1. 手机端必须能驳回：原因必填，员工可见，可改单重提。
2. 价格变更不做逐项确认，只展示；**涨跌并进采购明细的第四列**，不再单独一张表。
   单位统一用「每 500g / 每个」，与「折算单价、上次单价」同口径。
3. 审核通过后 **24 小时内可撤销**，撤销要回退价格、回到待审核、保留痕迹。
4. 「上传凭证」和「审核通过」是两个动作：上传只挂附件、不改状态、不让价格生效。
5. 自己的单（提交人＝审核人）**不需要转账凭证**，可直接通过，备注记「本人审核通过（无转账凭证）」。
6. 价格闸的基准从「历史采购价中位数」改为**原料档案当前生效价**，阈值 **8% → 10%**
   （页面上的「涨跌」就是闸门判断的那个数）。
7. **提交报销时全量判定一次**：能过的直接生效；不能过的标「需放行」并写明理由；
   审核通过**不会**再偷偷应用「需放行」的项，必须逐条点「放行」。
8. 允许自审（不做"不能审自己"的隔离）：老板很可能既是提交人又是唯一管理员。

## 三、最终行为

| 时点 | 发生什么 |
|---|---|
| 提交 | 创建调价记录 → 全量过闸门：≤10% 直接写价（已生效）；超阈值/首次定价/数量离群 → 标「需放行」；>5 倍 → 作废 |
| 审核通过 | 只改单据状态与事件，不再动价格；被挂起的项保持 PENDING |
| 放行 | 单条应用，写原料价 + 采购商品价 + 成本流水 |
| 驳回 / 要求补充 | 价格变更作废、已生效价格回退、状态与事件落库 |
| 撤销（24h 内） | 同一个事务里回退原料价、SKU 价、成本流水，变更回到待确认，状态回待审核 |
| 自己审自己 | 免转账凭证，事件写「本人审核通过」 |

## 四、数据与接口变化

- 新表 `reimbursement_review_event`（迁移 `20261107230000_reimbursement_review_event`）：
  只追加的审核事件（SUBMIT / RESUBMIT / APPROVE / REJECT / REQUIRE_RESUBMIT / REVERT），
  含操作人昵称快照、前后状态、备注。页面「处理进度」读真表，老单据无事件时兜底。
- 配置迁移 `20261108013000_price_gate_threshold_10`：阈值默认值与生产配置 0.08 → 0.10。
- 价格变更视图新增 `gatePreviewAction / gatePreviewReason`（与写入闸同函数预演）。
- 上传付款凭证接口新增 `autoComplete` 参数：手机端传 `false`（只挂附件），
  电脑端不传＝旧行为（上传即完成），保证电脑端不被这次改动带崩。
- `reimbursement.service.ts`：审核/撤销改为 `$transaction`，价格、事件、单据一起成功或回滚。

## 六、已知未做 / 风险（下次接手先看这里）

1. **没有真库端到端测试**：`$transaction` 回滚、以及「撤销 → 再通过 → 价格真的生效」两条关键路径没有覆盖，
   现有测试把事务 mock 掉了。这是本会话两次"看起来修好、其实没修好"的共同原因。
2. **后端多图并发覆盖窗口仍在**：单台手机已串行上传，两台设备同时传仍可能丢图。
3. **提交/重提的事件不在事务里**（save 之后写），写事件失败会"单已建、接口报错"；
   管理员替员工重提时，事件 `actorId` 记的是原提交人。
4. **旧单据的判定文字会过时**：`gateReason` 是判定当时存的，规则改了不会重算
   （例：山药 0% 却写着 89.9%、8%）。放行弹窗已改成以当前口径为主、旧文字标「当时判定」，
   数据本身仍是旧的；要彻底解决需要「按当前规则重判」入口。
5. **首次定价即使 ≤10% 也要放行**（产品选择）。新原料多时会多点几次，可再议是否放宽。
6. **撤销后 `deltaRate` 不复算**；别人之后改过价时，「原价/涨跌」可能已过期。
7. **SKU 价与档案价可能长期不一致**（例：树莓 SKU 196 元/kg vs 档案 79.2 元/kg；
   进口牛霖 SKU 0 元）。不影响食谱成本，只影响「参考价 / 预估成本」，下次采购会自愈。
8. **电脑端未做功能改造**：仍是「通过并上传凭证一步完成」（现在有事务与事件），
   但按钮文案与手机端不完全一致。
9. 顶部「上次审核已撤销/已驳回」与「处理进度」里会出现同一句话两次。
