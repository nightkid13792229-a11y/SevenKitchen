# 01_Project_Overview.md
# Project Overview & System Boundaries

    本文档用于定义：
        - 项目的整体目标与业务定位
        - 系统服务的对象与范围
        - 系统明确“不做什么”
        - AI 在工程实现时必须遵守的边界条件

    本文档不描述：
        - 技术栈选型
        - 数据库结构
        - 算法公式细节
        - UI 页面实现细节

    上述内容分别由其他文档负责。


============================================================
# 1. Project Background
============================================================

    本项目是一套面向中国地区狗狗家长的
    “宠物鲜食 + 犬营养服务”支持系统。

    业务形态为：
        - 小规模宠物鲜食作坊
        - 通过自媒体内容进行获客
        - 以“专业、可信、可追溯”为核心竞争力

    项目目标不是打造通用型电商平台，
    而是构建一套高度贴合实际生产与服务流程的
    业务支撑系统。


============================================================
# 2. Core Business Objectives
============================================================

    本系统的核心目标包括：

    1) 为狗狗家长提供：
        - 免费的犬营养食谱浏览
        - 狗狗档案管理
        - 基于档案的喂食建议计算
        - 食谱定制服务与成品鲜食下单

    2) 为内部员工提供：
        - 订单执行支持
        - 生产排产与厨房执行指引
        - 采购与原料管理辅助
        - 物流与发货操作支持

    3) 为管理者提供：
        - 配方管理与审核
        - 订单与生产全流程监管
        - 食品安全与溯源资料管理
        - 基础经营数据查看


============================================================
# 3. Target Users & Access Channels
============================================================

    系统服务的核心角色包括：

    - Customer（狗狗家长）
        - 使用微信小程序
        - 不直接接触后台系统
        - 不具备业务配置权限

    - Staff（内部员工）
        - 使用微信小程序
        - 按职责划分功能可见性
        - 不具备系统规则修改权限

    - Admin（管理员 / 老板）
        - 使用 Web 管理后台
        - 负责系统配置与核心数据维护


============================================================
# 4. System Scope (What This System Does)
============================================================

    本系统负责的内容包括：

    - 狗狗档案与营养相关数据管理
    - 犬营养计算与喂食建议生成
    - 食谱数据的结构化管理
    - 订单从创建到发货的全流程支持
    - 生产批次与食品安全溯源数据记录
    - 与支付、物流等外部服务的业务级对接


============================================================
# 5. Explicit Non-Goals (What This System Does NOT Do)
============================================================

    以下内容明确不在本系统的目标范围内：

    - 不构建通用型电商平台或商城系统
    - 不支持多商家 / 多品牌入驻
    - 不提供用户之间的社交功能
    - 不提供公开 API 供第三方系统自由接入
    - 不试图覆盖宠物医院或临床诊疗系统
    - 不替代专业兽医的诊断与治疗决策

    AI 在任何阶段都不得试图“扩展”到以上领域。


============================================================
# 6. Product Philosophy & Quality Principles
============================================================

    本项目遵循以下核心原则：

    - 专业性优先于娱乐性
    - 正确性优先于实现便利
    - 数据可追溯优先于流程简化
    - 明确边界，避免功能膨胀

    所有计算结果均以“辅助决策”为目的，
    而非强制指令或医疗建议。


============================================================
# 7. AI Collaboration Boundary
============================================================

    本项目使用 AI（如 Cursor）作为编程执行辅助工具。

    AI 的角色被严格限定为：
        - 工程实现执行者
        - 既有文档的忠实翻译者

    AI 明确不具备以下权限：
        - 决定产品方向
        - 修改业务目标
        - 推断或补全未定义需求
        - 擅自扩展系统边界

    若文档中未明确说明某一行为或规则，
    AI 必须中止实现并向人类提出问题。
