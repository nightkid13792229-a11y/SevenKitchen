# 订购配置页 UX 评估与优化方案

> 版本：v1（2026-09-17）
> 视角：产品经理 · 普通养狗家长视角 + 合规视角
> 页面：`miniapp/src/pages/recipe-order/index.vue`（4580 行，模板 481 行）
> 配套：`docs/plans/2026-09-16-recipe-detail-page-ux-design.md`、`docs/plans/2026-09-17-health-tag-compliance-checklist.md`

---

## 一、页面现状（实测结构）

| 顺序 | 区块 | 内容 |
|:---:|------|------|
| 1 | 食谱信息区 | 生命阶段下拉 + 封面图 + 食谱名 + **健康标签** + 3 张参数卡（营养标准 / 配方软件 / 能量密度） |
| 2 | 狗狗与喂食 | 空态（创建档案）／狗狗头像选择 + 档案信息 + 生命阶段提醒卡 + 喂食量三格（每日参考 / 每餐约 / 主食能量）+ 首单喂食量说明 |
| 3 | 配置天数与分装 | 周期选项（N 天）+ 分装摘要 + 自定义分装（每袋 g × 袋数）+ 最低订购量提示 |
| 4 | 原料明细 | 类型标签 + 名称 + 用量 + 渠道 / 品牌 / 规格 |
| 5 | 说明 | 物流（顺丰生鲜 + 冷链）/ 存储 / 烹饪 |
| 6 | 价格计算明细 | 仅管理员可见（成本拆分） |
| 7 | 底部固定栏 | 客服入口 + 价格（总价 + 每袋价）+ 确认订单 |

## 二、问题清单（按严重程度排序）

### 🔴 P0-1【合规·紧急】健康标签直接展示，且包含违规标签

**位置**：模板第 42–51 行

```
v-if="recipe.targetHealthTags && recipe.targetHealthTags.length > 0"
  v-for="tag in recipe.targetHealthTags"
    {{ getHealthTagLabel(tag) }}
```

**问题**：
1. 详情页的健康标签**已按合规要求隐藏**，但**订购页仍在直接展示**。
2. 实测这些标签包含**已判定违规**的「抗炎」「低敏」。
3. 也就是说：**同一份违规内容仍在对外展示**，只是换了个页面。

**建议**：与详情页保持一致，**立即隐藏**；或改为只展示合规标签（需先完成标签字典合规化）。

---

### 🔴 P0-2【体验缺陷】加载失败没有错误态，且会误导用户去建档

**实测代码**：
- `loadRecipeDetail()` 的 catch 只有 `console.error('Load recipe error:', error)`，无任何用户提示、无重试
- `loadDogs()` 的 catch 同样只打日志，`dogs` 保持为空
- 页面在 `dogs.length === 0` 时渲染空态：**「请先创建狗狗档案 / 创建档案」**

**后果**：网络故障或接口异常时，**已经有档案的家长会看到"请先创建狗狗档案"并被引导去重复建档**——这是误导，而不是降级。

**建议**：加页面级加载失败态 + 重试按钮（复用详情页刚落地的模式：骨架屏 / 失败重试 / 区块级更新提示）。

---

### 🟠 P0-3【信息错位】首屏黄金位置放的是技术参数，而不是决策信息

首屏三张参数卡：

| 卡片 | 问题 |
|------|------|
| 营养标准 | 与详情页重复，且此处为裸术语（详情页已改结论式表达） |
| **配方软件** | **内部工具名**，顾客视角无价值（详情页已按决策去掉） |
| 能量密度 kcal/kg | 裸术语（详情页已补 DM 口径与通俗化） |

而家长在这个页面的核心决策信息是：**多少钱、多少量、够吃几天**——价格在底部固定栏，天数与分装在第三屏。

**建议**：三张卡替换为决策信息（总价 / 总量 / 可吃天数），技术参数要么去掉、要么降级到页面底部。

> ⚠️ 注：回归测试**锁定**了 `配方软件` 与 `能量密度` 必须存在于本页（`recipe-order.regression.spec.ts` 第 188–189 行），改动需同步更新断言。

---

### 🟡 P1-1【待你确认】原料明细展示「渠道 / 品牌 / 规格」

**位置**：模板第 244–257 行

这是**采购侧信息**。对家长的决策价值有限，同时会**暴露供应链渠道**。

需要你判断：这是有意的"原料透明化"，还是应该收敛为「原料名称 + 用量」？
（注：测试中存在 `not.toContain('采购渠道</text>')`，说明此前已做过一次文案收敛，方向可能是"保留但弱化"。）

---

### 🟡 P1-2【一致性】「能量密度」与详情页口径不统一

- 详情页：已标注干物质（DM）口径 + 通俗化表达
- 订购页：仍是裸的 `能量密度 xxx kcal/kg`

同一个人在相邻两个页面看到同名的两个数字、口径说明不一致，容易产生怀疑。

---

### 🟡 P1-3【待梳理】生命阶段有两个修改入口

详情页有"切换生命阶段版本"，订购页顶部也有生命阶段下拉。两处都能改，用户可能困惑"我在哪改才对"。

建议：保留订购页入口（配置前确认是合理的），但明确两者关系（例如订购页改动后是否回写详情页选择）。

## 二、🔴 新发现（本次复查重点）：原料明细暴露采购侧数据

**数据来源**：生产库 `procurement_sku` 表（318 条 SKU）+ 价格预览返回的 `ingredientDetails`。

顾客在「原料明细」看到的**名称用的是采购 SKU 名**（`procurementSkuName` 优先于食材名），
并且同时展示**渠道 / 品牌 / 采购规格**。生产真实样例：

| 顾客看到的「名称」 | 真实食材 | 渠道 | 品牌 | 规格 |
|---|---|---|---|---|
| 土豆 **盒马日日鲜去皮新土豆** | 土豆 | 盒马鲜生 | 盒马自营 | 500g/份 |
| 鸡胸 **生鲜鸡大胸** | 鸡胸 | 山姆会员店 | 山姆自营 | 2.6kg/份 |
| 无抗保洁鸡蛋 | 鸡蛋 | 沃尔玛 | 沃集鲜（沃尔玛自营） | 1.59kg(30枚)/盒 |
| 板栗红薯 | 红薯 | 本地生鲜市场 | 盒马自营 | 500g/袋 |
| 蓝莓 云南蓝莓 | 蓝莓 | 盒马鲜生 | Driscoll's | 125g/盒 |

**三个问题**：

1. **名称不规整**：「土豆 盒马日日鲜去皮新土豆」「鸡胸 生鲜鸡大胸」是采购侧原始商品名（含渠道词、重复、长度不一），
   展示给顾客会显得不专业。
2. **采购规格对顾客无意义**：「2.6kg/份」「1.59kg(30枚)/盒」是**采购包装规格**；顾客买的是成品，不是原料。
3. **供应链暴露**：渠道（山姆会员店 / 盒马鲜生 / 沃尔玛 / 本地生鲜市场）与品牌（盒马自营 / 山姆自营）属于供应链信息。

**但需注意**：暴露渠道/品牌也可能是**有意的"透明供应链"卖点**（"我们的食材来自山姆、盒马"是品质信号）。
这是一个**产品定位决策**，不是纯技术问题。

### 建议方案（三选一）

| 方案 | 内容 | 适用 |
|------|------|------|
| **A 收敛** | 只显示「食材名 + 用量」（改用 `name`，去掉渠道/品牌/规格） | 最简洁专业，不暴露供应链 |
| **B 透明背书** | 「食材名 + 用量」+ **保留品牌**（如"盒马自营/山姆自营"），**去掉渠道与采购规格** | 想把供应链当卖点，但必须先把名称改干净 |
| **C 保持** | 现状不动 | — |

> A/B 都必须先修**名称**（用食材名而非采购 SKU 名），这是明确缺陷。

# v3 商品详情页（PDP）视角转化评估（2026-09-17）

> 本轮换视角：不再只看「有没有 bug」，而是问一句——
> **如果把这个页面当成一个独立的商品详情页，它够不够让一个陌生用户掏钱？**

## 一、核心结论

**订购成品页目前是一个「配置器」，不是一个「商品详情页」。**

- 它把「**怎么买**」做得相当完整：选狗 → 算饭量 → 配分装 → 看原料 → 下单。底栏禁用原因、价格竞态保护、快照防篡改这些工程细节都到位。
- 但它没有回答下单前最后三个必答题：
  1. **为什么买这个**（价值主张）
  2. **凭什么信你**（信任）
  3. **买完会怎样**（交付与风险）
- 实测结果：一个成熟商品详情页应具备的 9 类转化要素，本页 **9 类全部缺失**（评价 / 保障 / 售后 / 时效 / FAQ / 优惠 / 复购 / 推荐 / 溯源 检索命中数均为 0）。

换句话说：**页面把「促成」的按钮做得很扎实，但「促成」前面的整段说服过程是空的。**

## 二、现有板块盘点（7 段）

| # | 板块 | 实际承担的作用 |
|---|------|----------------|
| 1 | 生命阶段版本下拉 | 选规格（藏得深） |
| 2 | 封面图 + 食谱名 + 营养标准背书卡 | 商品识别 + 唯一的信任点 |
| 3 | 狗狗档案 + 6 项参数面板 | 个性化配置 |
| 4 | 饭量设置（天数快选 / 自定义分装） | 规格选择 + 价值锚（总净重） |
| 5 | 原料明细（食材 + 用量 + 渠道/品牌/规格） | 透明度（事实上的第二个信任点） |
| 6 | 说明（存储 / 烹饪 / 物流） | 使用与交付说明 |
| 7 | 底部固定栏（客服 + 价格 + 确认订单） | 促成 |

**判断**：7 段全部集中在「**配置**」与「**促成**」两端，中间的「**信任 + 风险消除**」整段是空白。

## 三、缺口清单

### A 类 · 决策信息缺口（让用户「想买」）

| 编号 | 缺口 | 说明 |
|------|------|------|
| A1 | **一句话卖点在订单页消失** | 详情页有「一句话卖点」，订单页只剩食谱名。到了掏钱的一步，价值主张反而没了。**接口已经返回 `sellingPoint`，页面没用** ★ |
| A2 | **没有「这一单能吃几天」** | `estimatedFeedDays` 已经算好、也已经传给结算页，**只是没在本页显示**。用户最关心的"买一次顶多久"要自己心算 ★ |
| A3 | **没有每日 / 每餐成本** | 只有总价和 `¥/袋`。而在最后一步，用户真正用来对比的是"**每天花多少钱**"（对标进口粮、处方粮、外卖鲜食），不是"每袋多少钱" |
| A4 | **营养与成分断档** | 详情页有完整营养面板（蛋白 / 脂肪 / 钙磷比等），订单页一点没有。**接口已返回 `nutritionDetailedData`，页面没用** |
| A5 | **无致敏原 / 换粮提示** | 鲜食最大的顾虑是"会不会不吃、会不会过敏、会不会拉肚子"。全页没有任何相关提示或安抚 |
| A6 | **没有回详情页的入口** | 用户想在最后一步再看一眼营养 / 评价 / 做法，只能退回上一页重进，操作成本高 |

### B 类 · 信任与风险逆转缺口（让用户「敢买」）

| 编号 | 缺口 | 说明 |
|------|------|------|
| B1 | **零售后保障** | 全页 0 处提及「不爱吃怎么办」「运输破损 / 变质怎么赔」。**食物类目这是最大的下单阻力**，尤其对首次尝试鲜食的新客 |
| B2 | **零社会认同** | 订单页 0 条评价、0 个好评率。详情页有评价组件，但下单页完全没有承接"别人买过且满意"这件事 |
| B3 | **零交付时效** | 物流卡只写了「顺丰生鲜 + 冷冻包材冰袋」，**没说什么时候发货、几天能到**。鲜食是现制，交付周期直接决定用户"能不能等" |
| B4 | **零溯源 / 质检标识** | 原料明细其实已经暴露了渠道与品牌（是很好的透明供应链信号），但缺少"检测报告 / 资质 / 中央厨房"层面的背书 |
| B5 | **零库存 / 产能信号** | 现制产能是真实约束，页面上完全没有呈现 |

### C 类 · 转化加速缺口（让用户「现在就买 / 买更多」）

| 编号 | 缺口 | 说明 |
|------|------|------|
| C1 | 无优惠 / 首单激励 | 无券、无满减、无赠品、无分享得券 |
| C2 | 无复购机制 | 无定期配送、无"再来一单"。**鲜食是高频消耗品，复购才是核心生意** |
| C3 | 无连带推荐 | 没有同系列食谱、其他生命阶段版本、加餐零食的推荐位 —— **客单价提升通道目前为 0** |
| C4 | 无收藏 / 无分享 | 页面没有 `onShareAppMessage`。家庭多人决策（另一半 / 家人拍板）场景走不通 |
| C5 | 无步骤指示 | 这是「配置 → 确认订单 → 支付」的第一步，页面没告诉用户还要走几步 |

### D 类 · 体验摩擦

| 编号 | 问题 | 说明 |
|------|------|------|
| D1 | 原料明细信息密度过高 | 渠道 + 品牌 + 采购规格三段并列，主线"这袋里到底有什么"被淹没 |
