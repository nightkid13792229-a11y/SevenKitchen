## 二、① 首页推荐与配餐统一标准

### 问题

首页推荐里写死了一套老标准：**12 个月算成犬、84 个月算老年**，不看品种也不看体型。
而真正配餐用的是「按品种/体型的成犬与老年阈值」（例如小型犬 10 个月成犬、11 岁老年）。

**后果**：同一只 **8 个月的小型犬**，首页判它是幼犬、配餐判它是成犬 —— **推荐语和实际给的饭对不上**。

### 改法

- 首页推荐改用领域层的权威实现（`resolveDogProfileStage`）
- 同时把推荐的狗狗查询补齐了**品种阈值与体型**字段（缺这些，权威实现也只能回落成"中型犬 / 12 个月 / 10 岁"）
- 选品与打分统一使用"带品种"的狗对象

> 现在首页推荐、食谱详情、订购页、DIY 页，**四处用的是同一把尺子**。

## 三、② 同一提醒只说一次

### 问题

顾客在 DIY 页看到「生命阶段不符」→ 点「我已知晓」→ 翻到制作单，**又弹一次一模一样的提醒**。

### 改法

制作单是**结果页**（制作单已经生成、顾客已经确认过），提醒在这里再要求确认毫无意义。

→ 制作单上的提醒改为**静态展示**（去掉「我已知晓」按钮），只作为页面上的记录，不再打断。

## 四、③ 每次都提醒 + 留痕（你的关键决定）

### 你的判断

> 「宁愿多提醒一次，也不能以流失订单为借口，不履行我们的责任，并且要把顾客已确认记下来。」

### 改法

| 改动 | 说明 |
|------|------|
| **每次都确认** | 移除了"确认过就不再提醒"的逻辑（原来 `showWarning = false` 之后就再也不拦了）。现在**每一次下单 / 生成制作单**都要确认一次 |
| **确认文案讲清责任** | 「继续表示您已知晓并自行决定；如狗狗有明确诊断或正在遵医嘱饮食，请先咨询执业兽医。」 |
| **留痕** | 顾客确认后**立即写入后端**，作为"已明确告知"的凭据 |

### 留痕记录了什麼

新表 `life_stage_acknowledgement`（每次确认记一条，不去重 —— 每次都是一次独立的告知行为）：

| 字段 | 含义 |
|------|------|
| `customer_id` | 哪位顾客 |
| `dog_id` / `recipe_id` | 哪只狗、哪张食谱 |
| `match_type` | 确认时系统给出的结论（如 `MANUAL_MISMATCH`） |
| `dog_life_stage` / `recipe_life_stage` | 确认时双方各自的生命阶段 |
| `source` | 从哪个页面确认（order / diy / diy_sheet） |
| `acknowledged_at` | 确认时间 |

> **这张表就是那份凭据**：将来若狗狗因吃错生命阶段的粮出问题，
> 我们能证明"在某年某月某日，我们明确告知过，顾客确认了"。
> 此前这个确认只在前端（点完就没了），**拿不出任何凭据**。

## 五、④ 保留"无法确认"提示

系统没能算出结论时（网络/服务异常），显示：

> 暂时无法确认这份食谱是否适合当前狗狗，建议稍后重试或联系客服。

用**中性灰**而不是警示红 —— 不装懂（避免"该提醒没提醒"），也不因为一次网络抖动就吓到顾客。
