# 手机号绑定：收窄到唯一必需点

> 日期：2026-09-19
> 起因：验收时发现「用未绑手机号的账号进入确认订单页会立刻被弹去绑定」，且**切换到后台再回来也会弹**

---

## 一、先核实：手机号到底在哪些环节是必需的

### 结论：**下单与支付都不需要**

| 环节 | 是否用到账号手机号 | 证据 |
|------|:---:|------|
| **创建订单** | ❌ 不需要 | 后端下单流程不校验顾客手机号 |
| **微信支付** | ❌ 不需要 | `resolvePayerOpenid()` **优先用 `userId + appId` 直接取 openid**；只有取不到时才用手机号做**老账号兜底查询** |
| **物流面单 / 发货** | ❌ 不需要 | 面单用的是 `address.phone`（**收货地址里的收货人电话**），不是账号手机号 |

### 手机号真正的用途（都是次要的）

1. 老账号历史资料合并（过渡期一次性）
2. 后台发货工具里展示客户联系方式
3. 跨设备账号识别

> 也就是说：**原来的强制绑定是过度拦截，不是业务必需。**

| 位置 | 行为 |
|------|------|
| **确认订单页 · 点「提交订单」时** | ✅ 唯一的强制点：下单后需要用它做订单履约与售后联系 |

### 具体动作

| # | 文件 | 改动 |
|---|------|------|
| 1 | `App.vue` | **删除** App 级强制弹窗调用（切后台回来不再弹） |
| 2 | `utils/account.ts` | **删除** `promptPhoneBindingIfNeeded()` 整个函数及其路由集合（含那个 `showCancel:false` 的强制弹窗），避免被误用；文件从 187 行精简到 86 行 |
| 3 | `pages/me/index.vue` | 删除 7 处拦截 + 无用 import |
| 4 | `pages/orders-list/index.vue` | 删除 2 处拦截 + 无用 import |
| 5 | `pages/order-detail/index.vue` | 删除 1 处拦截 + 无用 import |

| 7 | `pages/order-config/index.vue` | 删除 1 处拦截 + 无用 import |
| 8 | `pages/checkout/index.vue` | **保留但后移时机**：从 `onShow`（一进页面）移到 `submitOrder()`（点提交订单） |

### 为什么结算页要后移时机

原来一进确认订单页就被弹走，顾客**连地址、日期、金额、售后保障都没看到**。
后移到提交那一刻，顾客可以先核对订单，再在真正需要授权的一秒被询问。

## 六、留在桌面上的一个决策

我查到**下单在技术上也不需要账号手机号**（物流用地址电话）。
所以「确认订单页保留强制」目前是**业务选择**，不是技术必需。

如果将来想进一步降低首单门槛，可以考虑：
- **A**：保留（现状）——业务上确实需要能联系到下单人本人
- **B**：也去掉——完全依赖收货地址里的收货人电话
- **C**：改成可跳过——提交时提示"建议填写，便于客服联系"，允许暂不提供

本次按你的表述（"没有手机号就没法下单"）保留了 A。
