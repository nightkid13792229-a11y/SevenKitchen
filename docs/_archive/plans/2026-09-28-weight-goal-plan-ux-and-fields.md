## 一、计划的状态机（只有 4 个状态）

| 状态 | 含义 | 顾客看到 |
|---|---|---|
| **进行中** | 正在减重或增重 | 进度条 + 当前每日能量 + 下次称重日 |
| **维持期** | 已达标，正在防反弹 | 「已达标，正在维持」+ 维持目标 |
| **已结束** | 顾客手动结束，或维持期满 | 历史记录 |
| **已取消** | 顾客中途放弃 | 历史记录（可重新新建） |

**自动流转**：

```
新建 → 进行中 ──达标──→ 维持期 ──满 3 个月──→ 已结束
         │                  ↑
         └──连续 8 周未称重──→ 暂停（提醒后可恢复）
```

## 二、力度档位

### 减重：**只有一档，不分轻度/标准**

| 项 | 取值 | 依据 |
|---|---|---|
| 起步力度 | RER(目标体重) × **1.0** | 老板定（最温和起点） |
| 目标速率 | **0.5% - 2%/周** | SACN5 |
| 校正触发 | 慢于 0.5%/周 → 下调 10-20%；快于 2%/周 → 上调约 10% | SACN5 |
| 能量下限 | 不低于 RER(目标体重) × **0.6** | 知识库原文：「多数犬可耐受低至理想体重 RER 的 60%」 |

**为什么不需要两档（2026-09-28 老板提出后重新评估）**：

1. 两档**起步力度本来就相同**（都是 ×1.0），差异只可能放在「目标速率」和「下限」上；
2. 但如果目标速率不同，就会和知识库那条固定的校正规则（<0.5%/周 → 下调）打架——
   要么为轻度档发明一个新阈值，要么规则形同虚设。**两条路都不干净。**
3. **BCS 6 与 BCS 7+ 的差别本来就是自动形成的**——因为目标体重（理想体重）不同，要减的量天差地别：

| BCS | 目标体重 | 需要减掉 |
|---|---|---|
| 6 | 当前 × 0.889 | **约 11%** |
| 7 | 当前 × 0.800 | 约 20% |
| 9 | 当前 × 0.690 | 约 31% |

   系统不需要额外分档，**「要减多少」这件事本身已经把差别表达清楚了**。

### 增重

| 档位 | 适用 | 起步力度 | 目标速率 | 上限保护 |
|---|---|---|---|---|
| **增重** | BCS **≤3** | 维持需求 **+10%** | 0.5%-2%/周 | 不超过维持需求 × **1.4** |

> ⚠️ 这里的 **+10% 是我们的取值、无权威依据**（知识库明确「增重方案超出 AAHA 指南范围」）。
> 它偏保守，宁可 2 周后上调一次。

## 三、4 个触点的交互流程

### 触点 1：新建计划

**入口**：档案页 / 体重管理区 → 「设定体重目标」

**流程**：

```
第 1 步  系统读当前体重 + 体况分，给出建议
        ┌────────────────────────────────────┐
        │ 建议：减重                          │
        │ 目标体重：17.5 kg（现在 20 kg）      │
        │ 力度：温和（约 1%/周）               │
        │ 预计：约 14 周达标                   │
        │ 每天能量：812 kcal                   │
        └────────────────────────────────────┘
              〔就用这个方案〕  〔我要调整〕

第 2 步  选「我要调整」→ 只能往温和方向调
        · 目标体重：只能调高（少减一点）
        · 力度：只能选更温和
        （方向不提供「不要减」以外的激进度）

第 3 步  确认 → 计划生效 → 该狗的每日能量目标切换为计划值
```

**增重走同一流程，但前面多一道站内排查**：

```
第 1 步  先回答 5 个问题（体重是否持续下降 / 食欲是否变差 / 有无呕吐腹泻 /
        驱虫是否按时 / 最近是否换粮）
第 2 步  前 3 项有「是」→ ⚠️ 提示就医（兽医提醒白名单第 1 类：疑似疾病信号）
        前 3 项都正常 → 进入方案建议
```

### 触点 2：计划进行中（档案页）

显示：

| 元素 | 内容 |
|---|---|
| 进度 | 「已减 2.5 kg / 目标 2.5 kg（100%）」+ 进度条 |
| 当前每日能量 | 「每天 812 kcal」 |
| 最近速率 | 「最近 2 周：−1.1%/周（正常）」 |
| 下次称重 | 「建议 10 月 12 日前称重」 |
| 操作 | 〔记录体重〕〔调整计划〕〔结束计划〕 |

### 触点 3：需要称重时（提醒）

- **频率**：每 2 周一次
- **文案要点**：必须解释**为什么要称**（不是催，是告诉顾客系统要靠它调整）
  > 「称一下体重，我们才能知道现在这个量合不合适，需要的话帮你调。」
- **连续 8 周未称重** → 计划转「暂停」，并说明恢复方式

### 触点 4：达标时

- 转「维持期」，热量按减重期上浮 **10%**（AAHA）
- 文案：说明「现在不是结束，是换成维持量；前 2 周每 2 周复查，之后每月一次」
- 若**已达理想体重仍继续掉重** → 再加 10%

## 四、自动校正的判定逻辑（业务语言）

**每次顾客称重后，系统自动做三件事**：

1. **算速率**：`（上次体重 − 这次体重）÷ 上次体重 ÷ 间隔周数`
2. **对照目标区间**：

| 实测速率 | 系统动作 |
|---|---|
| 慢于目标（减重 <0.5%/周） | 力度**下调 10-20%**（少吃一点），2 周后复查 |
| 在区间内 | 保持，改为每 4-6 周复查 |
| 快于 2%/周 | 力度**上调约 10%**（减太快会掉肌肉） |

3. **撞到下限就停**：算出来低于下限保护值 → 不再下调，并提示「已到安全下限」。

**全程无人工**：不靠客服催、不靠营养师盯。

### 顾客可改的项

| 项 | 可调范围 |
|---|---|
| **目标体重** | **完全自由可调**（2026-09-28 老板决定），**且计划期间随时可改** |
| 力度 | 只能往**更温和**方向调（避免顾客把自己调到危险区间） |

**为什么目标体重不做「只能更温和」的限制（老板原话）**：
> 「因为我们使用的或者计算出来的目标体重也不一定准确。这一块还是需要给用户更大的权限的。」

**保留三道护栏（都不拦截，只保护）**：

| # | 护栏 | 说明 |
|---|---|---|
| 1 | **提示** | 目标体重与系统建议相差 **>30%** 时提示一次「偏离较大，建议确认」（不拦） |
| 2 | **能量下限** | 不低于 RER(目标体重) × 0.6（知识库规则） |
| 3 | **自动校正（最重要）** | 实测减重**快于 2%/周 → 自动上调 10%**。这是真正的动态保护：**即使目标定得不合理，掉秤过快也会被系统拉回来** |

> 力度仍然只能往温和方向调；但目标体重放开，等于把「到底减到多少」的决定权交还顾客——
> 因为这个数字本身就有不确定性，而安全由能量下限与自动校正负责。

## 六、边界情况怎么处理

| 情况 | 处理 |
|---|---|
| 计划期间顾客改了狗的体重档案 | 以体重记录为准，计划不受影响 |
| 计划期间体况分变了 | 提示「体况已变，建议重新评估目标」，但不自动改目标 |
| 顾客同时想改目标类型（减重→增重） | 需结束当前计划再新建 |
| 计划期间狗怀孕了 | **计划自动暂停**，转孕哺能量口径（与批次内另一项任务联动） |
| 计划期间狗去世 / 档案删除 | 计划随档案一起结束 |
| 顾客手动结束计划 | 立即恢复默认维持量 |
| 目标体重离当前体重 <5% | 建议不做计划（变化太小，无法有效监测） |

| **1** | 减重是否分两档 | ✅ **不分档，只有一档**（老板提出后重新评估：两档起步力度相同、差异无处安放，且与知识库校正规则打架） |
