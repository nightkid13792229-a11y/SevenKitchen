## 三、现有知识库技术评审

被评审对象：后端 `recipe-designer` 下的结构化知识库（20 领域 / 202 条，每条强制带出处）。

### 3.1 长处（要保留）

- 结构清晰：条目有 id、领域、标签、关键词、结论、要点、注意事项、出处、引用优先级
- **出处强制校验**：没有出处的条目直接报错，进不了库
- 检索结果直接序列化进提示词，并**要求 AI 标注条目编号**——每句话可倒查
- id 无重复（已实测）

### 3.2 问题（8 条，按严重度排）

| # | 问题 | 实测结果 | 后果 |
|---|---|---|---|
| **T1** | **SAFE 领域 7 条完全检索不到** | 它们的标签是 `safe` / `food-safety` / `foodborne` / `all`，而系统**永远不会产出**这些标签；关键词路径也全部落空 | 🔴 **食品安全知识从未进入过任何一次 AI 提示词**——写了等于没写 |
| **T2** | **标签没有受控词表，写错没人管** | 全库出现 **155 个**标签，系统只会产出 **54 个**；已发现错字 `oain`（应为 `pain`）、断词 `hepato`、`he` | 🔴 拼错的标签静默失效，没有任何报错 |
| **T3** | **提示词没有上限** | 多系统疾病犬实测命中 **102 / 202 条 ≈ 12.2 万字符 ≈ 6.1 万 tokens**；常见组合（老年＋超重）也有 2.2 万 tokens | 🔴 成本高、且条数过多会稀释 AI 注意力，"中间的内容"容易被忽略 |
| **T4** | **出处是自由文本，不能反查** | 出处写成 `'AAHA 2014 体重管理指南'` 这样的字符串 | 🟡 无法回答"哪些条目引用了已被取代的 2014 版""哪些超过半年没复核" |
| **T5** | **没有治理层** | 没有来源登记表、没有证据分级、没有复核周期、没有生效日期 | 🟡 无法判断任何一条知识是否过期 |
| **T6** | **校验太弱** | `validateEntries()` 只查"id / 标题 / 出处非空" | 🟡 不查 id 唯一、不查标签合法、不查出处是否来自登记过的来源 |
| **T7** | **关键词只能全等匹配** | 条目关键词必须和系统产出的关键词**一字不差**才命中；`慢性肾病` 匹配不上 `肾病` | 🟡 漏召回 |
| **T8** | **没有紧急程度，也没有纠错入口** | 条目只有 `priority`（引用优先级），没有"多久之内必须就医"；营养师看不到某次建议引用了哪些条目，也不能修正 | 🟡 与"不做诊断、只做分诊"的要求不匹配；营养师无法纠错（对应需求 R6.4） |

### 3.3 最该先修的三条

1. **T2 + T1**：给标签建受控词表 + 加一条校验（标签必须来自词表，否则报错）。
   这一条修完，`oain` 这类错字和 SAFE 那种"整块失效"会立刻暴露出来。
2. **T3**：给提示词加**条数上限 + 相关度排序**（现在只按引用优先级排，不按相关度）。
3. **T4 + T5**：把 `auto recipe design` 的来源登记表与证据分级搬过来，出处从"自由文本"改成"引用登记表里的来源 ID"。

## 四、建议的知识库结构（两套合并）

```
运行时层（现在这版，保留并小改）
  └ 每条知识 = id · 领域 · 标签 · 关键词 · 结论 · 要点 · 注意事项 · 出处 · 引用优先级
                ＋ 新增：紧急程度 · 来源ID · 生效日期 · 下次复核日期

治理层（从 auto recipe design 搬过来）
  ├ source-register.md    来源登记表（ID / 分级 / 获取方式 / 本地路径 / SHA256 / 检索日期）
  ├ evidence-policy.md    证据分级 A–E 与使用规则
  ├ intake-sop.md         新资料入库流程
  └ evidence-update-sop.md 复核周期与更新流程
```

**新增的"紧急程度"字段说明**（这是回答老板"要不要加家长版字段"的关键）：

| 字段 | 取值 | 谁来决定 | 用途 |
|---|---|---|---|
| `urgency` | 立刻就医 / 尽快就医 / 可观察 | **写死在条目里**，人工审 | AI 只能照用，不许自己判断有多急 |
| 具体话术 | —— | **AI 现场翻译成人话** | 老板的理解，正确 |

> 也就是说：**"怎么说"交给 AI，"有多急"不交给 AI**。
> 免责声明、"这不构成诊断"这类固定话术，**完全不进 AI**，写死在输出层。

## 六、扩充计划

### 6.0 先把"资料齐不齐"说清楚

**不齐。** 准确的说法是"**开工不需要再等资料**"，不是"资料齐了"。

| | 手上的 | 还缺的 | 缺了会怎样 |
|---|---|---|---|
| 免疫 | WSAVA 2024 正本 | AAHA 犬免疫指南、国内法规原文 | 🟡 不挡开工，可后补 |
| 营养 | 全部正本 | — | — |
| 检查指标解读 | SACN5 + 公开手册 | 无（参考区间按设计决定处理，不需要额外来源） | — |
| 常见病与就医时机 | SACN5 | WSAVA 各专科指南、ACVIM 共识 | 🟡 **按疾病逐条取，不预先囤积** |
| 治理层 | 模板 | — | — |

**关于"要不要下载到本地"**——分两种，不能一概而论：

| 类型 | 做法 | 例子 |
|---|---|---|
| **公开网页 / 开放获取** | **登记链接即可，不必下载**；用到哪节读哪节 | **Merck 兽医手册**、IRIS 分期、WSAVA 各指南页、ACVIM 共识 |
| **必须拿到手才能逐条核对** | 需要本地正本 | WSAVA 2024 疫苗指南（免疫程序要逐条抄准）、FEDIAF（数值） |
| **有版权限制的大部头** | 只登记路径 + SHA256，**不进代码仓库** | SACN5（309 MB）、NRC |

> 所以默克兽医手册**确实不在本地，也不需要下载**——它是 C 级来源，只用于机制与警示，
> 登记官方链接、按需读取即可。**真正必须有正本的只有疫苗指南那一类。**
