# 事故与修复：带强阳性的过敏报告保存被 400 挡下（缩略图看不到）

> 日期：2026-10-05｜发现人：老板（实测反馈"我并未看到过敏检测报告的缩略图"）
> 影响：**报告与原件没入库**（过敏信息本身照常带到订单）
> 状态：**已定位、已修、已部署、已验证**

---

## 一、现象与真因

老板上传报告、确认之后，过敏信息板块里看不到报告缩略图。

一开始怀疑是显示问题（缩略图没渲染），查生产日志发现**根本不是显示问题**：

```
ERROR [AllExceptionsFilter] Unhandled exception:
  results[0].0.level: level must be one of the following values:
  POSITIVE, WEAK_POSITIVE, SUSPECTED, NEGATIVE, UNKNOWN
Request: POST /api/v1/dogs/86e175bb-.../allergy-reports
```

上一批为了区分"强阳性"新增了 `STRONG_POSITIVE` 等级，识别侧、归一化、落库映射都改了，
**但控制器 DTO 的 `@IsIn` 白名单漏改** —— 那份白名单是另一处手抄的五个值。
于是带头几项（强阳性排在排序最前）的报告在保存时被 400 挡下：

- 报告实体没入库 → 页面上永远没有缩略图
- 原件照片已经在 COS 上，但没有任何记录指向它们
- 小程序那边 `catch {}` 把失败**静默吞掉**了，家长只看到"缩略图没出现"，
  没有任何线索能判断是没传成功还是页面坏了

---

## 二、修法（四层，缺一不可）

1. **白名单只留一份**：`allergy-report.service` 导出 `ALLERGY_RESULT_LEVELS`，
   控制器 DTO 的 `@IsIn(ALLERGY_RESULT_LEVELS)` 直接引用 —— 不许再手抄一张表
2. **失败必须说话**：报告存不下时提示「报告原件没存下来，过敏信息已记上」，
   不再静默（过敏信息照旧记上，不影响下单）
3. **有历史报告时默认答"有过敏"**：否则档案里没有过敏记录（报告全是阴性、
   或订单还没提交）时，整块界面连预览一起被收起，家长再也看不到传过的原件
4. **回归断言**：
   - 识别侧能产出的每个等级（含中文/符号别名）都在白名单里
   - 控制器必须用同一份常量（老的手抄写法出现即报红）

---

## 三、验证

- `node scripts/tmp-dto-check.js`（生产服务器上跑真实部署产物）：
  `STRONG_POSITIVE / POSITIVE / WEAK_POSITIVE / SUSPECTED / NEGATIVE / UNKNOWN`
  **六种等级全部通过校验**
- 后端：291 套 / 2996 条全过（新增 3 条白名单断言）
- 小程序：118 个文件 / 1506 条全过（新增 2 条：失败要提示、历史报告兜底）
- 生产后端已部署该修复；体验版 1.9.1 已上传

---

## 四、教训（写给下一次）

**同一张取值表出现在两个地方，迟早会漏一处。** 这次的代价是"报告没存下来"
——数据真的丢了（原件还在 COS，但没有记录指向它）。所以：
新增/修改任何枚举，先搜一遍它在几处被写死，能合并成一份常量就合并，
不能合并的（如前端）至少加一条"两边一致"的断言。
