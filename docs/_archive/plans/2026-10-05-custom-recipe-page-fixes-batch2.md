## 二、第 1 条：那片白块是怎么来的

页面在 Banner 之后有一张**常驻**的「状态区」卡片，里面装着五类内容：

1. 体重管理计划横幅（有计划时）
2. 定制门槛卡（体况/活动量/餐数没确认时）
3. 未登录
4. 档案读取中
5. 还没有狗狗档案

在**"已登录 + 有档案 + 门槛已确认 + 没有计划"**这个最常见的正常状态下，
五个分支**一条都不成立**，于是这张卡渲染成只剩内边距与白底的空白卡 ——
就是老板看到的那片白。

**改法**：整张卡改成按内容出现（`showStatusSection`）。五类内容一条都没有时，
它不再占版面；一旦任一条件成立（换狗、掉登录态、门槛未确认……）立刻回来。
五个条件一个都没删，所以不会出现"该提示的时候不提示"。

## 三、第 2 条：先问一句「需要给它做体重管理吗？」

**为什么改**：原来一进页面就直接摆一个「去制定体重管理计划」的大按钮。
多数家长只是想定制一单鲜食，看到这个按钮会以为**必须先做计划**才能往下走。

**改后**：
- 没有进行中的计划 → 先问「需要给它做体重管理吗？」（需要 / 不需要）
- 答**需要** → 展开体况建议 + 「去制定 / 查看体重管理计划」
- 答**不需要** → 只留一句「好的，这一单按它平时的用量给」
- **已经有进行中的计划 → 不再问**（顾客本来就在管理体重，问一遍等于否定他自己定过的东西），
  计划入口与建议直接展开
- 没作答时提交按钮为灰，点它会提示「请先回答：是否需要体重管理」

**老板当场选定的口径**：

| 情形 | 这一单交给营养师的方向 |
|---|---|
| 有计划（进行中/维持期） | 按计划（减重计划→减重、增重计划→增重、维持期→维持） |
| 没计划 + 答"需要" | 按体况（偏胖减重 / 偏瘦增重 / 理想维持） |
| 没计划 + 答"不需要" | **按维持**（老板选定）—— 家长说了不需要管理，就不再把减重/增重交给营养师 |

体况偏胖/偏瘦时，答"不需要"那句话里会补一句"以后想减重/增重，随时可以回来制定计划"
—— 这一单按维持给是家长的选择，但体况结论不该被藏起来。

## 四、第 4 条：报告写着"阳性"，系统却当成"没写"—— 断在两处

老板拿的是一份**中农董军实验室过敏原检测报告**：表格里有分组、数值、颜色条，
表格之外另有一段「**过敏原结果判定**」，逐条写着阴性 / 阳性 / 强阳性。

### 断点一：提示词不敢认"强阳性"，也不去找判定区

- 允许的五个值里只写了「阳性」，**没写"强阳性"**；判定区里写的正是"强阳性"，
  模型不敢映射，整份退回 `UNKNOWN`
- 判定区在**数值表格之外**，提示词没有要求专门去找它；
  而"不要根据数值大小自己推断等级"这句又很硬，模型干脆全填 `UNKNOWN`

### 断点二：小程序把等级**读出来又丢掉**（后果比断点一更重）

报告识别返回的 drafts 里本来带着 `level`，但小程序确认时**写死** `level: 'UNKNOWN'`：

```
results: picked.value.map(allergen => ({ allergen, level: 'UNKNOWN' }))
```

后端按 level 定可信度：**阳性 → 确诊（食谱彻底避开）**、弱阳性/疑似/没写 → 可疑。
写死 UNKNOWN 等于把报告上写着"阳性"的**确诊过敏一律降级成"可疑"** ——
食谱就不会严格避开它。这不是"少一个标签"，是安全口径被改掉了。

### 修法

- 提示词：**先找「结果判定 / 结论 / 判读」那一段**，每项 level 以那一段为准；
  "强阳性/++/+++"按阳性认，"弱阳性/±"按弱阳性认；数值与颜色条仍**不作为依据**；
  阴性项不进 drafts（它们恰恰说明不过敏）
- 小程序：等级照抄进报告实体（`level: item.level`），并在候选标签上显示出来
  （「鸡肉 · 阳性」「小麦 · 弱阳性」），家长一眼看到报告上写了什么

### 用老板那份真实报告在生产上实测，又抓出两个问题（同日修完）

拿真实报告（中农董军，2 页）跑了一次真实识别，结果是：

| | 第 1 页（只有数值 + 颜色条） | 第 2 页（有「过敏原结果判定」） |
|---|---|---|
| 识别条数 | 52 项（食物 26 / 环境 26） | 53 项（食物 24 / 环境 29） |
| 等级 | **全部读成"阳性"**（照颜色条猜的） | 正确分出阳性 / 弱阳性（小麦·弱阳性、花生·阳性） |
| 模型自报"这页有没有判定区" | `false`（它知道没有） | `true` |

两个问题：

1. **颜色条不是报告写的字。** 第 1 页没有判定区，模型照颜色条把一批"弱阳性"
   读成了"阳性" —— 一旦被当成权威等级，后端会落成"确诊"，食谱把小麦彻底避开。
2. **两页打架时听谁的。** 同一项在两页都出现时，必须听**有判定区那一页**的。

修法（两层，缺一不可）：

- 提示词新增 `hasVerdict`：这一张图上有没有判定区；没有就一律填 UNKNOWN
- 小程序新增 `src/utils/allergy-candidates.ts`（纯函数，10 条单测）：
  **没有判定区那一页的等级一律不当真**（记 UNKNOWN），名字与分组照收；
  同一项再出现时，**判定页的等级说了算**，与上传顺序无关

> 实测确认：模型能正确回答 `hasVerdict`（第 1 页 false、第 2 页 true），
> 但"没有判定区就填 UNKNOWN"这条它不照做 —— 所以这一层必须由系统自己兜住，
> 不能只靠提示词。

## 五、第 5 条：环境类过滤 + 对照项 + 「加入这一单」点不了

### （1）环境类过敏原不该进"这单不能用的食材"

过敏报告一页里常同时有**食物组**与**环境组**（尘螨、花粉、霉菌、皮屑、昆虫…）。
食谱只关心吃进去的东西。修法分两层：

- 提示词：新增 `group` 字段（FOOD / ENVIRONMENT / OTHER / UNKNOWN），
  **只能照抄报告上写的分组列或分组小节**，报告没写就填 UNKNOWN，不许自己分类
- 后端归一化：报告没写分组时用**名字兜底**判一次（关键词表，只收"不可能是食材"的词：
  螨、花粉、霉菌、皮屑、昆虫…）。兜底这一层是**系统行为**，不交给模型
  - 边界：**报告自己写的 FOOD 优先**，名字像环境项也不替顾客丢掉
  - 宁可漏判（环境项留在列表里，家长点掉即可），也不能误判（真食物过敏原被藏起来）
- 小程序：候选只列食物类；环境类不记进过敏信息，但会告诉家长
  「报告里还有 N 项环境类（粉尘螨、柳树花粉），与吃的东西无关，没有记进过敏信息」
  —— 读到的东西不默默吞掉

### （2）顺手修掉一个更隐蔽的坑：**组胺（阳性对照）**

报告开头常用"组胺（阳性对照）"证明试剂有效，它的值必然是阳性 ——
但那不是这只狗对组胺过敏。老版本会把它当成一条真过敏记进档案，从此被食谱严格避开。
现在后端归一化时**一律丢掉**含"对照/组胺"的项（新旧两条数据通路都丢）。

### （3）「加入这一单」为什么点不了

老版本读完报告**一个都不勾**，按钮在 0 项时是灰的 —— 家长看到的是"读到了却加不进去"。
**老板选定：读到的食物过敏原默认全部记上**，按钮立刻可用，不对的逐项点掉即可。
