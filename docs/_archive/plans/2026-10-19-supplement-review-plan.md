# 预分装补剂 · 需求与原型审查矩阵（2026-10-19）

> 逻辑审查回答的是“前后有没有矛盾”；它不回答“这门生意做不做得成、顾客会不会用、我们交付得了吗、钱对不对、合不合规”。
>
> **老板 2026-10-19 决定**：运营可行性、合规/标签、商业定价**暂缓**——运营做不过来可随时改 Web 单量；合规主要担心小程序审核；定价等真实订单数据再复盘。
>
> **本轮做**：顾客体验/可用性、权限/安全、状态/异常、页面/交互一致性、数据/指标。

## 二、每一类具体查什么

### 1. 商业/定价审查

- 2.5 倍加价 + 服务费 ¥10 + 运费 ¥6 + 门槛 99/129，在真实成本下单均贡献是多少？
- 小单（商品 <¥29）占比多少？贡献率会不会被拉低？
- 顾客拿“整瓶单价”对比时，我们怎么解释“整单更省”？
- 免服务费/包邮门槛是否真的能覆盖人工+包材+运费？
- 7 天 vs 30 天、1 份 vs 3 份，哪种组合更赚钱？
- 售后预留 3% 够不够？无理由退/补的实际发生率是多少？

**方法**：用真实进货价、包材价、人工分钟、快递价做 5 档敏感性测算；跑 30–50 单后复盘。

### 2. 顾客体验/可用性审查

- 第一次看到“预分装补剂”，能不能在 10 秒内说出“是什么、为什么买、是否强制”？
- 制作单不显示价格，顾客会不会因为“不知道多少钱”而不敢点？
- 结算页的服务费/运费解释，能不能让顾客觉得“合理”而不是“被坑”？
- 下单步骤是否超过 3 步？地址、日期、勾选是否顺畅？
- 支付失败/取消/排期待确认的文案，是否分得清？
- 订单详情能不能一眼看到“什么时候发、到哪了、出问题找谁”？
- 标签上的字，40×60mm 实贴能不能看清？长品名会不会挤爆？
- 字号、颜色对比、按钮热区是否适合中老年用户？

**方法**：认知走查（第一次用的顾客）、5 人可用性测试、打印实物标签让非项目人员读。

### 3. 运营可行性审查

- 30 单/天 × 10 分钟 = 300 分钟；加上打包/发货/客服，现有人员扛得住吗？
- 截单 17:00、当天发，快递几点来收？赶不上怎么办？
- 6×8 / 8×11 / 10×15 / 13×18 袋子、干燥剂、40×60 标签纸，库存够不够？
- 打印机断连/标签打歪/贴坏，现场怎么补？
- 缺料时谁来决定补货/改期/强制分装？决策链是否清楚？
- 周末/节假日/请假，营业日历谁来维护？
- 爆单（比如 40 单）时，是顺延还是加人？顾客怎么通知？

**方法**：跟一天真实分装；用秒表记录每单耗时；做一次“40 单压力演练”。

### 4. 合规/标签审查

- 经营许可是否覆盖“保健食品/预包装食品销售”、分装口径？
- 标签是否印全：品名、分装量、分装日期、有效期、储存、原品、分装者、用法、 “非直接食用”、干燥剂提示？
- 有没有功效宣称/医疗声称？有没有“预防/治疗”字样？
- 原瓶保质期、分装效期、油性/粉剂/片剂系数是否按规则取 min？
- 过敏原/交叉污染（同一台秤、同一台面）怎么控制？
- 顾客健康信息、地址、售后照片的访问与留存是否合规？

**方法**：拿最终标签给合规/法务或专业人士过一遍；做一次标签内容核对表。

### 5. 财务/对账审查

- 商品、服务费、运费、退款、补发在财务上怎么记？
- 部分退款、多次退款、补发单 0 元，怎么对账？
- 支付手续费、快递费、包材费、人工怎么归集？
- 退款失败/线下退款怎么留痕？
- 补发单的成本记到哪？会不会重复算收入？
- 是否需要发票？开票主体/税点怎么处理？

**方法**：拿 10 笔模拟订单（含退款/补发/部分退）走一遍财务台账。

### 6. 权限/安全审查

- 顾客能不能看/改别人的订单？改地址、售后、再次购买是否校验归属？
- 员工能不能调退款/补发/改期/强制分装接口？后端是否 403？
- 管理员账号共享吗？退款操作是否留操作人？
- 售后照片、地址、手机号是否会被未授权访问？
- 改地址后，旧地址/新地址是否留痕？面单是否需要重打？
- 补发单能否被重复生成？退款能否重复打款？

**方法**：权限矩阵 + 越权用例（顾客 A 改顾客 B 地址、员工调管理员接口）。

### 7. 状态/异常审查

- 支付成功但排期失败，订单停在哪？谁重试？顾客看到什么？
- 两人同时排期/分装/退款，会不会超卖/重复扣库存/重复退款？
- 退款接口失败/回调丢失，售后记录停在哪？怎么重试？
- 补发单取消，售后记录回到哪？
- 营业日历临时停发，已排订单怎么办？
- 库存负值/强制分装，怎么留痕？
- 制作单快照缺失（旧单），再次购买按什么？
- 时区/截单边界（16:59 vs 17:01）怎么算？

**方法**：状态迁移表 + 异常用例清单 + 并发/幂等测试（开发后）。

### 8. 页面/交互一致性审查

- 需求 v2 页面全景里的每一页，原型是否都有？没有的是复用还是漏了？
- 同一文案在不同页面是否一致（“预计发货日期” vs “分装日” vs “发货日”）？
- 空态/加载/错误/权限不足/部分失败，是否每页都有？
- 长品名、多袋、长地址、0 元补发单，布局会不会崩？
- 移动端是否有桌面端才有的批量操作？
- 返回路径是否清楚？会不会点进死胡同？
- 标签 40×60 实物是否和屏幕预览一致？

**方法**：页面清单逐项打勾；用最长/最极端数据跑一遍；手机真机走查。

### 9. 测试/上线审查

- 验收场景是否覆盖：截单前后、停发、满产能、缺料、强制分装、改地址、退款失败、多次售后、补发取消、快照缺失？
- 鲜食/定制回归是否全绿？
- 上线配置是否齐：包材档案/规则、日历、截单/产能/费用、订阅模板、支付退款开关？
- 数据迁移是否 dry-run？回滚是否验证？
- 监控/告警是否能看到待排期、逾期、缺料、退款失败、售后超时？
- 客服/员工是否培训过新流程？

**方法**：测试计划 + 上线检查表 + 回滚演练。

### 10. 数据/指标审查

- 补剂渗透率、单均贡献、售后率、准时发货率、小单占比、复购率的定义是否唯一？
- 看板数字和订单明细能否对上？
- 退款/补发是否从收入里正确扣除？
- 指标按天/周/月哪个口径？时区是否一致？
- 谁能看？是否需要导出？

**方法**：指标字典 + 用 10 笔订单手工复算看板。

## 三、原型专项审查方法

| 方法 | 怎么做 | 能发现什么 |
|---|---|---|
| **认知走查** | 找一个没看过需求的人，让他完成“从制作单买补剂→看订单→申请售后” | 文案看不懂、入口找不到、步骤太多 |
| **启发式评估** | 按 Nielsen 10 条（系统状态可见、用户控制、一致性、防错、识别优于回忆等）逐页看 | 缺少反馈、无法撤销、术语不一致 |
| **状态覆盖** | 每页列出默认/空/加载/错误/权限/部分失败 | 只画了“成功态” |
| **极端数据** | 最长品名、最多袋数、最长地址、0 元补发、退款失败 | 布局崩、文案截断 |
| **真机走查** | 微信开发者工具 + 手机 | 字号、热区、滚动、键盘遮挡 |
| **实物标签** | 打 40×60 真标签，贴在 6×8 袋上 | 字太小、放不下、贴不住 |
| **角色走查** | 顾客/员工/管理员各走一遍 | 权限错、按钮不该出现 |
| **财务复算** | 拿原型金额手工算一遍 | 服务费/运费/退款累计对不上 |

## 四、建议的执行顺序

### 本轮（已执行 5 类）

1. **顾客体验/可用性审查**：认知走查 + 文案/字号/订单上下文 + 状态覆盖清单。
2. **权限/安全审查**：权限矩阵 + 员工端管理员动作 + 消息/地址归属。
3. **状态/异常审查**：异常目录补齐 + 状态覆盖矩阵。
4. **页面/交互一致性审查**：页面清单 + 术语统一 + 筛选/数据一致。
5. **数据/指标审查**：指标字典 + 看板复算 + 退款/订单口径。

### 暂缓（等真实数据/审核）

- 运营可行性：30 单/天、截单/快递、包材/标签现场。
- 合规/标签：经营许可、标签终稿、功效宣称。
- 商业/定价：真实成本、单均贡献、小单占比。
- 财务/对账：等退款/补发真实发生后再细对。

### 开发后

6. **测试/上线审查**：验收、回归、UAT、上线检查表。
7. **并发/幂等专项**：两人同时分装/退款/改期、退款回调丢失。
