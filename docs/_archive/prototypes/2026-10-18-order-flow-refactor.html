  • ① 前后端都还留着「确认收到」 —— 后端动作表里 CONFIRM_RECEIPT 还在， 前端还有 handleConfirmReceipt。你早就取消了。

  • ③ 售后类型是成品线共用的 5 种（REFUND / REMAKE / COMPLAINT / RESOLVED / RESHIP）， 含投诉和补发。你定过定制售后只留「调整食谱」一种。
  • ④ 售后状态里没有「已撤回」 —— 现在是 PENDING / ACCEPTED / PROCESSING / RESOLVED / REJECTED， 但你定过顾客可以撤回。
  • ⑤ 售后页根本没有任何上传功能 —— 500 行里没有 chooseImage / uploadFile。 后端有 photos String[] 字段，但前端从来没接。 （我之前在原型里画的"＋ 上传照片"是我编的，线上没有。）
  • ⑦ 后端定义了「用这份食谱订购成品」「联系客服」两个动作，前端从来没渲染 —— ORDER_FINISHED_FOOD / CONTACT_SERVICE 在动作表里有， 但页面 0 处。所以这两个按钮现在等于不存在。
  • ⑥ 支付确认页是有的，是我在清单里叫错了名字 —— 它叫 success.vue，我标成"提交成功页（优先级低）"， 但它上面有「立即微信支付 ¥300」按钮，它就是支付确认页。

六、几个口径写死在这（避免以后又各说各的）

项约定
三个筛选对应哪些状态 · 全部 = 6 个状态全要（含已取消）
· 进行中 = 待付款 / 已付款 / 已交付 / 售后中
· 已完成 = 已完成（+ 可考虑把「已取消」并进来，看你）
状态标签的颜色 待付款 黄 已付款 橙 已交付 绿 售后中 红 已完成 灰 已取消 浅灰
列表卡片 标题 = 食谱名（交付前显示「设计中的专属食谱」）／ 副标题 = 给谁 + 品种年龄 ／ 删掉「目标」（已在食谱名里体现）／ 整张卡可点 → 该订单详情页
「返回定制订单」去哪 redirectTo('/pages/custom-recipe/orders') —— 用 replace 而不是压栈， 避免顾客在"订单详情 ↔ 订单列表"之间来回堆栈
「查看售后进度」去哪 同一个售后页 aftersale?orderId=xxx —— 这页兼做两件事：没提过售后就是提交表单；提过了就显示进度 + 撤回
一个共用的东西
  • 状态标签在三个地方都要出现（详情的状态头、列表的徽章、售后页的状态）—— 所以它应该抽成一个组件：OrderStatusBadge，吃后端给的 { code, label, tone }。
  • 「售后窗口剩余几天 / 免费次数剩余几次」也是三处都要 （详情、售后页、列表）—— 同样该由后端算好下发，前端只显示。
