## 重要前提

生产库当前仍然是**旧版原料结构**，尚未承接本分支已经完成的解耦模型。

表现为：

- `ingredient` 仍保留大量旧采购字段：`brand / product_model / purchase_channel / purchase_unit / current_price_per_purchase_unit / reorder_point / target_stock`
- 营养与补剂信息仍主要保存在 `ingredient.properties`
- `procurement_sku` 仍是旧字段集，未看到本地分支中的扩展字段
- `recommended_product` 与 `procurement_sku` 覆盖率极低

这意味着：

- 可以直接基于生产数据做“只读审计”和“治理名单梳理”
- 但如果要真正按新模型在生产上录入、合并和迁移，**应先部署当前分支的后端 migration 与管理后台**

生产库存在 `11` 组“同类型 + 同名称”的重复标准原料。

### 高置信度可合并

这些更像是“同一个标准原料，被渠道/规格拆成了多条标准原料”，建议后续合并为 1 条标准原料，并在其下补多个采购 SKU：

- `鸡蛋` × `3`
  - 盒马 / 山姆 / 沃尔玛
  - 当前主要在用的是盒马这条，食谱引用 `21`
- `猪里脊` × `3`
  - 本地生鲜 / 山姆 / 山姆黑猪
  - 当前主要在用的是本地生鲜这条，食谱引用 `11`
- `牛霖` × `2`
  - 本地生鲜 / 山姆
  - 当前主要在用的是本地生鲜这条，食谱引用 `8`
- `土豆` × `2`
  - 本质都是去皮土豆，只是 `份 / 袋` 差异
  - 低风险合并

### 中置信度，合并前需确认

这些名称相同，但“营养对象是否可以视为同一标准原料”需要业务确认：

- `糙米` × `2`
  - 一条是普通有机糙米
  - 一条是三色糙米
  - 如果你希望标准原料层按“糙米”做抽象，可合并
  - 如果后续营养建模要区分三色糙米，则应拆开并重命名
- `沙丁鱼` × `2`
  - 两条都是罐装水浸沙丁鱼，但品牌不同
  - 当前都未进入食谱，优先级不高

### 不建议自动合并，应拆分或重命名

这些虽然同名，但本质上不是同一个营养对象，不能简单并到一个标准原料下面。

- `鱼油` × `2`
  - 一条 `EPA+DHA = 300mg/粒`
  - 一条 `EPA+DHA = 750mg/粒`
  - 这两条应视为不同补剂原料，建议后续重命名区分
- `骨粉` × `2`
  - 两条的 `钙 / 磷 / 镁` 含量不同
  - 不能共用同一套标准营养档案，建议后续重命名区分

### 包材类不建议“同名合并”

这些更像“规格不同但名字没区分清楚”，建议后续按规格重命名，而不是合并。

- `泡沫箱` × `2`
  - `3号箱` / `4号箱`
  - 容量分别约 `5000g` / `2500g`
- `铝箔保温袋` × `2`
  - 分别适配 `3号箱` / `4号箱`
- `食品真空袋` × `4`
  - `10*15 / 12*17 / 15*20 / 20*25`

建议后续调整为：

- `泡沫箱（3号）`
- `泡沫箱（4号）`
- `铝箔保温袋（3号箱适配）`
- `铝箔保温袋（4号箱适配）`
- `食品真空袋（10*15）`
- `食品真空袋（12*17）`
- `食品真空袋（15*20）`
- `食品真空袋（20*25）`

## 生产治理建议

### 结论 1：生产库已经可以做“治理名单梳理”，但还不适合直接按新模型落库

原因不是数据不能整理，而是生产库当前 schema 还停留在旧结构，直接开改会继续把采购和推荐信息写回标准原料旧字段，反而不利于后面真正解耦。

### 结论 2：最稳的执行顺序

1. 先把当前分支部署到生产
   - 包括后端 migration
   - 包括管理后台原料编辑页
2. 在生产上执行一次“旧字段 -> 默认采购 SKU”回填
3. 再开始人工治理生产数据

### 结论 3：人工治理推荐按 4 批走

#### 第一批：先补在用原料的采购 SKU

目标：

- 先让生产/采购调用链有真实落点
- 优先处理高频食材与高频补剂

#### 第二批：处理高置信度重复项

建议优先：

- 鸡蛋
- 猪里脊
- 牛霖
- 土豆

处理方式：

- 保留 1 条标准原料
- 其余渠道/规格转为采购 SKU
- 修正历史名称和备注

#### 第三批：处理“同名但不该合并”的对象

重点：

- 鱼油
- 骨粉
- 包材规格件

处理方式：

- 不合并
- 明确重命名
- 必要时重录营养档案

#### 第四批：清理闲置原料

针对 `61` 条未进食谱且未进采购的原料：

- 明确后续会用的：按新结构补齐
- 没明确用途的：先停用或归档
