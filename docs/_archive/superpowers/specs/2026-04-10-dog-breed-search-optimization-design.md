# 狗狗品种搜索优化设计

## 背景

当前小程序端“创建狗狗档案”和“爱犬概览”页面共用同一套品种搜索逻辑。现状主要问题有三类：

1. 只能做非常浅层的包含匹配，缺少排序与容错。
2. 搜索结果强依赖后端返回的 `aliases`，而现有品种数据并未完整覆盖常用别称、简称和关联词。
3. 用户会输入俗称、简称、去后缀写法和轻微错别字，例如“泰迪”“边境牧羊犬”“雪纳锐”，当前体验会出现搜不到或结果不完整。

## 目标

本次优化要让小程序端品种搜索具备以下能力：

1. 支持更自然的模糊搜索，而不是仅依赖精确命中。
2. 支持高频关联搜索，例如“泰迪”可联想到贵宾犬系，“边境牧羊犬”可命中“边牧”。
3. 支持轻量错别字容错，例如“雪纳锐”可命中“雪纳瑞”。
4. 在两个小程序页面统一生效，避免同一关键词在不同页面表现不一致。
5. 不要求先改造数据库内容即可立即生效。

## 非目标

1. 本次不引入后端独立搜索接口。
2. 本次不改造后台品种管理页面交互。
3. 本次不建设完整拼音检索体系；如后续需要，可在 alias 体系稳定后追加。

## 现状判断

当前前端搜索仅做：

1. 去空格和转小写。
2. 对 `name + aliases` 做单向 `includes` 过滤。

这意味着：

1. `边境牧羊犬 -> 边牧` 这类简称/标准名转换无法命中，除非数据中显式写了别名。
2. `雪纳锐 -> 雪纳瑞` 这类单字错别无法命中。
3. 搜索结果没有相关性排序，后续即使补充别名，体验也不够稳定。

## 方案

### 1. 搜索词归一化

对用户输入和品种词条统一做更强的归一化处理：

1. 去首尾空格、内部空格。
2. 转小写。
3. 统一全角/半角字符。
4. 去除括号与常见分隔符。
5. 生成“去括号版本”和“去 `犬/狗` 后缀版本”的辅助 token。

示例：

1. `贵宾犬(小型)` 会同时生成 `贵宾犬(小型)`、`贵宾犬`、`贵宾` 等可检索 token。
2. `边境牧羊犬` 会额外生成 `边境牧羊`。

### 2. 内置高频关联词目录

在小程序侧增加一个轻量的内置品种关联词目录，用于补齐当前后端 `aliases` 不足的高频词。目录只覆盖高频、确定性强的映射，不做开放式推断。

首批覆盖方向：

1. 俗称与标准名：`边牧 -> 边境牧羊犬`、`法斗 -> 法国斗牛犬`、`拉拉 -> 拉布拉多`。
2. 品种家族：`泰迪 -> 贵宾犬(小型)`、`贵宾犬 -> 贵宾犬(小型)/贵宾犬(标准)`。
3. 常见展示写法：`雪纳瑞 -> 雪纳瑞(小型)`、`小型雪纳瑞`、`标准雪纳瑞`。

该目录与后端返回的 `aliases` 合并使用，优先保证线上现有数据不回填也能生效。

### 3. 匹配与排序

搜索不再只返回“是否匹配”，而是按分数排序：

1. 精确命中最高。
2. 别名精确命中次之。
3. 前缀命中高于普通包含。
4. 轻量错别字命中低于直接匹配，但高于完全无关项。
5. 同分时优先常见品种，再按名称长度和名称字典序稳定排序。

这样可以保证：

1. 搜索“泰迪”时，`泰迪` 本身排最前。
2. `贵宾犬(小型)` 作为强关联结果也会出现，但排在直接命中后面。

### 4. 轻量错别字容错

对归一化后的 token 增加小规模编辑距离判断：

1. 仅对足够长的中文关键词启用，避免短词误召回。
2. 只允许很小的编辑距离阈值，优先覆盖单字误写、误输和少量漏字。

目标覆盖：

1. `雪纳锐 -> 雪纳瑞`
2. `贵兵犬 -> 贵宾犬`

### 5. 页面接入

`dog-create` 与 `dog-profile-overview` 已共用 `dog-breed-search.ts`，因此本次只需升级公共搜索工具并保留页面接入方式不变，两个页面会同时受益。

## 测试策略

重点回归以下场景：

1. 空关键词返回空结果。
2. 已有 alias 仍可命中。
3. `边境牧羊犬` 能命中 `边牧`。
4. `泰迪` 能同时看到 `泰迪` 和贵宾犬相关结果，且 `泰迪` 排前。
5. `雪纳锐` 能命中 `雪纳瑞(小型)`。
6. `贵宾犬` 能命中带括号的贵宾犬品种。

## 风险与约束

1. 纯前端内置关联词需要维护，但胜在本次能立刻生效。
2. 错别字容错阈值过宽会引入误召回，因此只做轻量容错，不做激进模糊匹配。
3. 后续如果后台持续维护 `aliases`，可以与本次目录共存，再逐步收敛为统一数据源。
