# Web 管理后台食材类编辑页重构设计

## 背景

当前管理后台的食材编辑页已经完成了“标准原料 / DIY 推荐商品 / 生产采购 SKU”的第一轮拆分，但在实际维护食材时仍有三个问题：

1. 标准原料信息里仍残留了一些更适合放到采购 SKU 上的业务策略字段。
2. 标签分类只有快速新建入口，缺少在当前页面内更名、删除、合并、调整层级的管理能力。
3. 可食部比率目前更像标准原料级字段，但不同采购来源、不同修切规格的可食部会有差异，继续只放在标准原料上会影响成本和采购量判断。

本设计只针对 `FOOD` 食材类编辑页。补剂和包材已经在前序设计中改为单层模型，不纳入本轮页面重构。

## 目标

1. 让标准原料信息只表达“这个食材是什么”，不承接具体采购商品和库存执行。
2. 让生产采购 SKU 成为采购、库存、生产执行和成本计算的主要维护入口。
3. 在食材编辑页内补齐标签管理能力，减少维护标签时的跳转和上下文丢失。
4. 支持采购 SKU 级可食部比率，并保留标准原料默认可食部比率作为兜底。
5. 明确当前采购价、参考单价在页面和计算中的业务含义，避免维护人员误以为两个字段都会进入成本计算。

## 非目标

- 不重构补剂和包材编辑页。
- 不改变小程序订购成品页的原料展示布局。
- 不新增采购 SKU 自动打标签或自动回填来源等级的初始化迁移。
- 不在本轮引入批号、效期、先进先出等库存批次能力。
- 不在本轮重新设计完整采购报销流程。

## 核心结论

### 1. 标准原料负责“定义原料”

标准原料是食谱、营养建模和原料分类的对象。

标准原料页保留：

- 原料名称
- 原料类型
- CFCT / 营养分类
- 基准单位
- 营养信息摘要或营养数据入口
- 标签分类
- 默认可食部比率
- 备注

标准原料页不再作为主要维护入口的内容：

- 具体品牌
- 具体产品规格
- 采购渠道
- 来源等级
- 采购策略
- 库存策略
- 采购单位和换算关系
- 成本计算价
- SKU 级可食部比率

默认可食部比率仍保留在标准原料上，因为它有兜底价值：当某个采购 SKU 未维护自己的可食部比率时，系统使用标准原料默认值。

### 2. 生产采购 SKU 负责“采购与执行”

生产采购 SKU 是采购、库存、生产执行和订单成本计算使用的对象。

SKU 编辑弹窗应承接以下信息：

- SKU 名称
- 品牌
- 规格
- 采购渠道
- 来源等级：有机、商超、性价比
- 采购策略
- 是否允许入库
- 安全库存
- 目标库存
- 采购单位
- 换算倍数
- 成本计算价
- 市场参考价
- SKU 可食部比率
- 默认 SKU
- 启用状态
- 备注

其中“采购策略、是否允许入库、安全库存、目标库存”从业务语义上应归属到 SKU，而不是标准原料。原因是同一种食材可能同时存在日采 SKU、可库存 SKU 和特殊来源 SKU。

### 3. SKU 可食部优先，标准可食部兜底

成本、采购缺口和生产用量计算使用以下规则：

```text
如果选中的采购 SKU 填写了可食部比率：
  使用采购 SKU 可食部比率
否则：
  使用标准原料默认可食部比率
```

示例：

- 标准原料“牛霖”默认可食部比率：0.92
- 盒马精修牛霖 SKU 可食部比率：0.95
- 本地市场牛霖 SKU 可食部比率：0.88

当订单采购来源方案选中盒马 SKU 时，成本和采购量按 0.95 推导；选中本地市场 SKU 时，按 0.88 推导；如果某个 SKU 未填，则按 0.92 兜底。

### 4. 价格字段重新命名和分工

页面上建议使用更贴近业务的字段名：

- `currentPurchasePrice` 展示为“成本计算价”
- `referencePurchasePrice` 展示为“市场参考价”

业务规则：

- 成本计算价进入订单售价、采购缺口、生产成本等计算。
- 市场参考价只用于人工参考和比价，不进入任何成本或售价计算。
- 如果启用的采购 SKU 缺少成本计算价，则该 SKU 不应被订单采购来源自动匹配算法选中。

这样能避免“参考单价”被误认为也参与实际报价。

### 5. 标签管理采用“当前页抽屉 + 独立管理页并存”

食材编辑页内新增“管理标签”入口，打开右侧抽屉。

抽屉内支持：

- 查看当前标签树
- 新增标签
- 更名标签
- 删除未使用标签
- 合并已使用标签
- 调整父级分类
- 调整排序
- 显示每个标签被多少原料使用

独立“原料标签管理”页面继续保留，适合批量管理；当前食材编辑页抽屉适合在编辑原料时顺手处理少量标签问题。

删除规则：

- 未被使用、没有子标签的标签可以直接删除。
- 已被使用的标签不能直接删除，先引导合并到其他标签或批量移除。
- 有子标签的标签不能直接删除，先处理子标签。

## 页面结构设计

### 一、标准原料信息板块

页面顶部保留“标准原料信息”板块。

建议字段排布：

```text
标准原料信息
  原料名称        CFCT 分类        基准单位
  默认可食部比率  主要营养价值      原料类型
  标签分类        [快速新建] [管理标签]
  备注
```

该板块下方增加一条轻提示：

```text
标准原料只描述“这个食材是什么”。采购来源、采购策略、库存策略、成本价和 SKU 可食部比率在生产采购 SKU 中维护。
```

这条提示用于帮助后台人员理解为什么部分字段被移动。

### 二、生产采购 SKU 表格

生产采购 SKU 表格作为页面第二个主要板块。

建议列：

```text
SKU
来源等级
采购策略
入库
SKU 可食部
单位 / 换算
成本计算价
库存策略
状态
操作
```

SKU 单元格中展示：

- SKU 名称
- 品牌
- 规格
- 采购渠道

来源等级展示为标签：

- 有机
- 商超
- 性价比
- 未设置

成本计算价展示当前实际参与计算的价格。市场参考价不放在表格主列中，避免表格过宽；进入编辑弹窗后再展示。

### 三、编辑生产采购 SKU 弹窗

SKU 编辑弹窗分为三组。

#### 基础信息

```text
SKU 名称
来源等级
品牌
规格
采购渠道
供应商
默认 SKU
启用状态
```

#### 采购与库存策略

```text
采购策略
是否允许入库
安全库存
目标库存
```

采购策略建议继续沿用现有业务含义：

- 日采
- 库存补货
- 混合

是否允许入库用于解决用户之前提出的业务场景：

- 蔬菜、水果等日采且不可保存的多采部分，不进入库存。
- 鲜肉等日采但可保存的多采部分，可以在生产结算后入库。

#### 成本与损耗

```text
采购单位
换算倍数
成本计算价
市场参考价
SKU 可食部比率
显示单位
备注
```

SKU 可食部比率为空时，弹窗中显示当前会使用的标准原料默认值，避免维护人员不知道系统如何兜底。

## 数据模型设计

### 标准原料

`Ingredient` 对 `FOOD` 保留：

- `name`
- `type`
- `baseUnit`
- `nutritionProfile`
- `tags`
- `properties.defaultEdibleYieldRatio`
- `notes`

现有标准原料级采购策略字段进入兼容期：

- 页面不再把它作为主要编辑字段。
- 后端在 SKU 未维护对应策略时，可以短期读取标准原料旧字段兜底。
- 所有 SKU 补齐上述字段并通过回归验证后，再移除旧字段入口。

### 生产采购 SKU

`ProcurementSku` 对 `FOOD` 增加或明确以下业务字段：

- `sourceTier`
- `procurementStrategy`
- `allowInventoryEntry`
- `safetyStockG`
- `targetStockG`
- `edibleYieldRatio`
- `currentPurchasePrice`
- `referencePurchasePrice`
- `purchaseUnit`
- `purchaseToBaseRatio`
- `displayUnit`
- `brand`
- `productModel`
- `purchaseChannel`
- `supplierName`
- `isDefault`
- `isActive`
- `notes`

字段解释：

- `sourceTier` 用于小程序订购成品页的“有机优先 / 超市优先 / 性价比优先”来源匹配。
- `procurementStrategy` 用于采购缺口和采购单生成。
- `allowInventoryEntry` 用于生产完成后剩余原料是否可以入库。
- `edibleYieldRatio` 用于该 SKU 的采购毛重、可用净重和成本换算。
- `currentPurchasePrice` 是计算价格。
- `referencePurchasePrice` 是人工参考价格。

## 计算链路影响

### 订单价格预览

订单价格预览需要使用订单来源方案匹配出的采购 SKU。

计算成本时：

1. 先按来源方案匹配 SKU。
2. 使用 SKU 的成本计算价。
3. 使用 SKU 可食部比率；为空时使用标准原料默认可食部比率。
4. 将选中的 SKU、来源等级、渠道、品牌、规格写入订单价格快照。

### 采购缺口

采购缺口按采购 SKU 聚合，而不是只按标准原料聚合。

同一标准原料下，如果不同订单选择了不同来源等级的 SKU，不应合并成同一条采购需求。

### 生产结算

生产结算时，剩余原料是否入库取决于 SKU 的 `allowInventoryEntry`：

- `true`：剩余可入库，形成 SKU 库存。
- `false`：剩余不入库，只记录损耗或废弃。

成品短缺、退款或补差价仍沿用本阶段已经确认的生产结算调整逻辑。

## 迁移与兼容策略

本轮不做来源等级自动初始化迁移，因为来源等级需要人工判断。

兼容策略：

1. 已有采购 SKU 的 `sourceTier` 为空时，不参与三档来源方案自动匹配。
2. 已有采购 SKU 的 `edibleYieldRatio` 为空时，使用标准原料默认可食部比率。
3. 已有采购 SKU 的 `procurementStrategy` 为空时，短期使用标准原料旧策略兜底。
4. 已有采购 SKU 的 `allowInventoryEntry` 为空时，短期使用标准原料旧库存规则兜底。
5. 后台列表应突出显示“缺少来源等级 / 缺少成本计算价 / 缺少策略”的 SKU，便于人工补齐。

人工补齐顺序建议：

1. 先补来源等级。
2. 再补成本计算价。
3. 再补采购策略和是否允许入库。
4. 最后补 SKU 可食部比率。

## 权限与校验

### 标签管理

- 更名标签时名称不能为空。
- 同一父级下不能出现重名标签。
- 删除标签前必须校验使用数量和子标签数量。
- 合并标签时，目标标签不能是自己，也不能是自己的子级。

### 采购 SKU

- 来源等级可为空，但为空时不参与小程序来源方案匹配。
- 启用状态为启用时，SKU 名称、采购单位、换算倍数必须有效。
- 成本计算价必须大于 0 才能参与订单价格计算。
- SKU 可食部比率为空时允许保存；填写时必须大于 0 且小于等于 1。
- 允许入库为 `false` 时，安全库存和目标库存应置灰或清空。

## 测试策略

### 前端

- 食材编辑页能打开并正确展示标准原料信息、标签、生产采购 SKU。
- 点击“管理标签”打开抽屉。
- 标签更名、删除、合并后，当前食材标签显示刷新。
- 点击“新增采购 SKU”或“编辑”打开 SKU 弹窗。
- SKU 弹窗能保存来源等级、采购策略、是否允许入库、SKU 可食部比率。
- 只有食材类型显示生产采购 SKU 的多层编辑能力。

### 后端

- 采购 SKU 保存后能正确持久化来源等级、采购策略、是否允许入库、SKU 可食部比率。
- SKU 可食部比率为空时，成本计算使用标准原料默认可食部比率。
- SKU 成本计算价为空或小于等于 0 时，不参与订单来源方案匹配。
- 采购缺口按采购 SKU 聚合。
- 生产结算剩余原料按 SKU 的允许入库规则处理。

### 回归

- 小程序订购成品页三档采购来源价格仍能正常预览。
- 已有订单详情、采购单、生产单、财务结算不因字段移动而丢失历史快照。
- 补剂和包材编辑页不受本轮食材页面重构影响。

## 实施顺序建议

1. 后端补齐采购 SKU 字段和保存接口。
2. 后端调整订单价格、采购缺口、生产结算使用 SKU 级策略和可食部比率。
3. 管理后台重构食材编辑页布局。
4. 管理后台补齐标签管理抽屉。
5. 管理后台补齐 SKU 编辑弹窗字段和校验。
6. 用一条测试食谱和三档来源 SKU 完整验证小程序下单到后台采购、生产、结算链路。

## 验收标准

本轮完成后，应满足：

1. 管理员能在食材编辑页内清楚区分标准原料信息和采购 SKU 信息。
2. 管理员能在采购 SKU 上维护来源等级、采购策略、库存策略、成本计算价和 SKU 可食部比率。
3. 管理员能在当前页管理标签分类，不必只依赖快速新建。
4. 小程序来源方案匹配使用人工维护的 SKU 来源等级。
5. 订单价格、采购缺口和生产结算使用选中 SKU 的成本与可食部信息。
6. 补剂和包材页面保持现有单层模型，不被本轮改动破坏。
