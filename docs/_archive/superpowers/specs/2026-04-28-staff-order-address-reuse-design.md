# 工作台订单地址录入与复用设计

## 背景

成品配置页面当前会在顾客点击“保存采购及分装配置”后创建订单。随后顾客通过微信沟通并完成线下支付，地址信息也会通过微信给到店内人员。

现有系统已有客户地址库、订单地址绑定、顾客端地址管理和工作台订单详情页，但工作台还没有一个面向员工的“为当前订单录入客户地址并复用”的闭环。

## 目标

1. 员工能在微信小程序工作台订单详情页为订单录入收货地址。
2. 新录入地址保存到该订单所属客户的地址库，而不是只写入当前订单。
3. 当前订单立即绑定该地址。
4. 客户后续能在自己的地址库里看到并使用该地址。
5. 员工后续处理同一客户订单时，可以从该客户已有地址中快速选择。
6. 默认不把员工录入的地址设为默认地址，只有员工主动勾选时才设为默认。
7. 订单发货后不允许再修改收货地址。

## 非目标

- 不改变顾客成品配置页的保存与支付沟通方式。
- 不要求顾客必须自己补录地址后才能付款。
- 不在本次实现物流发货、运单号、冷链接口等发货能力。
- 不把地址写成管理员备注或订单自由文本。
- 不做跨客户地址复用；员工只能选择当前订单所属客户的地址。

## 业务规则

员工在工作台订单详情页看到“收货地址”区域：

- 订单没有地址时，显示“录入地址”和“选择已有地址”。
- 订单已有地址时，显示地址，并提供“更换地址”和“编辑地址”。
- 订单状态为 `SHIPPED`、`COMPLETED`、`CANCELLED` 时，地址区域只读。
- 新增地址时，地址归属为订单的 `customerId`。
- 选择已有地址时，只展示该订单客户自己的地址。
- 保存地址后，当前订单绑定该地址。
- 如果员工勾选“设为默认地址”，该客户其他默认地址会被取消默认。

订单每次绑定或更新地址时，都会把当时的完整地址复制一份到订单地址快照。历史订单展示优先读取订单地址快照，地址库中的地址后续被客户或员工编辑时，不会悄悄改变已经锁定的历史订单展示。

## 推荐交互

### 工作台订单详情

收货地址卡片放在客户信息之后、商品详情之前。

无地址：

```text
收货地址
暂未录入收货地址
[选择已有地址] [录入新地址]
```

有地址：

```text
收货地址
张三 138****8000
广东省 深圳市 南山区 科技园南区123号
[更换地址] [编辑地址]
```

只读状态：

```text
收货地址
张三 138****8000
广东省 深圳市 南山区 科技园南区123号
已发货后不可修改
```

### 地址选择

员工点击“选择已有地址”后进入当前客户地址列表：

- 只列出该客户地址。
- 点击地址后返回订单详情并绑定。
- 页面底部保留“新增地址”入口。

### 地址录入

员工点击“录入新地址”后进入地址表单：

- 收货人姓名
- 手机号
- 所在地区
- 详细地址
- 设为默认地址，默认关闭

保存成功后：

1. 地址进入客户地址库。
2. 当前订单绑定该地址。
3. 返回订单详情并刷新。

## 后端设计

新增面向管理员/员工的订单地址能力，避免复用顾客端接口时被当前登录员工身份误判为地址归属人。

新增接口：

```text
GET /api/v1/admin/orders/:orderId/addresses
POST /api/v1/admin/orders/:orderId/addresses
PUT /api/v1/admin/orders/:orderId/address
PUT /api/v1/admin/orders/:orderId/addresses/:addressId
```

接口职责：

- 查询订单所属客户的地址列表。
- 为订单所属客户创建地址。
- 将订单绑定到该客户的某个地址。
- 编辑该客户已有地址。

权限与校验：

- 只有管理员或员工可调用。
- 地址必须属于订单客户。
- 订单必须存在。
- 订单状态为 `SHIPPED`、`COMPLETED`、`CANCELLED` 时拒绝修改。
- 地址字段必须完整。

数据层不新增临时订单地址表。继续使用现有地址库和订单 `addressId` 关系，同时在订单上新增 `shippingAddressSnapshot` JSON 字段，保存绑定时的完整收货地址。

订单地址展示规则：

- 优先展示 `shippingAddressSnapshot`。
- 没有快照的历史订单，回退展示当前 `addressId` 关联地址。
- 员工通过订单详情编辑当前绑定地址时，同时更新客户地址库记录和当前订单地址快照。
- 客户以后从自己的地址库编辑同一个地址时，只更新地址库，不主动改写已经绑定过的历史订单快照。

## 小程序设计

修改工作台订单详情页：

- 展示无地址、有地址、只读三种状态。
- 增加选择已有地址入口。
- 增加录入新地址入口。
- 绑定地址后刷新订单详情。

复用现有地址表单体验，但需要支持员工场景：

- 员工场景由订单详情传入 `orderId`。
- 地址保存接口使用管理员/员工接口。
- 地址归属由后端根据订单 `customerId` 决定，前端不传客户 ID。

## 数据流

```text
员工打开订单详情
-> 后端返回订单和当前绑定地址
-> 员工选择已有地址或录入新地址
-> 后端确认订单客户
-> 后端创建或更新该客户地址
-> 后端绑定地址到订单
-> 小程序刷新订单详情
```

客户下一次复购：

```text
客户或员工打开该客户订单
-> 地址选择页读取该客户地址库
-> 选择地址
-> 订单绑定地址
```

## 错误处理

- 订单不存在：提示“订单不存在或已被删除”。
- 地址不属于该客户：提示“不能使用其他客户的地址”。
- 地址信息不完整：提示“请填写完整收货地址”。
- 订单已发货或结束：提示“该订单已不可修改收货地址”。
- 网络失败：保留当前页面，提示“保存失败，请重试”。

## 测试计划

后端：

- 员工为无地址订单创建地址并绑定成功。
- 创建地址后，该地址能从客户地址列表查到。
- 员工选择同客户已有地址并绑定成功。
- 员工不能把其他客户地址绑定到当前订单。
- 已发货、已完成、已取消订单不能修改地址。
- 勾选默认地址时，客户其他默认地址被取消。

小程序：

- 工作台订单详情无地址时显示录入入口。
- 有地址时展示地址和修改入口。
- 只读状态隐藏修改入口。
- 新增地址保存后返回详情并展示新地址。
- 选择已有地址后返回详情并展示选中地址。

## 验收标准

1. 顾客保存成品配置并完成线下付款后，员工能在工作台订单详情里录入收货地址。
2. 录入的地址能在客户自己的地址库中看到。
3. 同一客户下一次下单后，员工能在订单详情里选择这个已有地址。
4. 地址不会被保存到错误客户名下。
5. 已发货或已结束订单不能修改地址。
6. 小程序预览构建通过。
