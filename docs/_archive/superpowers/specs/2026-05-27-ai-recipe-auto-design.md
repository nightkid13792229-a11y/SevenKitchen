# AI 食谱自动设计与个性化营养管理设计

## 背景

SevenKitchen 已经具备食谱、DIY 制作单、狗狗档案、健康记录、原料营养档案、补剂目标、FEDIAF 2025 犬标准嵌入设计，以及移动端食谱设计器设计。

现有移动端食谱设计器第一版定位为专业手动工具：营养师在移动端编辑原料克数、查看 FEDIAF 2025 评估、保存草稿并审核发布。本设计在这个基础上增加 AI-first 自动设计能力，让管理员可以通过对话、狗狗档案和报告资料，先形成个性化营养管理方案，再由 Agent 在受控约束内自动生成食谱草稿。

本功能不是简单的“AI 生成配方”。它应被设计为：

```text
营养评估 + 知识治理 + 约束合成 + 食谱自动设计 + 审计发布
```

核心原则是：Agent 不能凭模型记忆做专业判断。所有关键结论必须来自已登记、已审核、可追溯的知识、规则、计算结果或人工依据。

## 已确认决策

1. 第一版采用 AI-first 双模式设计器：`AI Agent 设计 / 手动编辑`。
2. AI Agent 是未来主路径；手动编辑用于审核、修正和兜底。
3. 第一版运行时只对 `ADMIN` 开放。
4. 设计上预留 `RECIPE_DESIGNER`、`RECIPE_REVIEWER`、`KNOWLEDGE_EDITOR`、`KNOWLEDGE_REVIEWER` 等细粒度权限。
5. 完整工作流拆成两个阶段：营养评估与约束生成、食谱自动设计。
6. 第一版从“选择一只狗狗”开始，不要求管理员预先选择“标准食谱/个性化食谱”或“严格/探索模式”。
7. 设计完成后可保存为该狗狗个性化食谱，也可通过泛化检查发布为标准食谱候选。
8. 结果状态在输出阶段给出：可审核发布、需人工审核、受限草稿、无法完成。
9. 第一版输入支持：文字描述、已有狗狗档案、检查报告/诊断报告上传与自动抽取。
10. 报告自动抽取结果必须经管理员确认后，才能参与证据分级和规则包启用。
11. 大便照片第一版只作为低证据附件保存，不直接触发疾病规则包。
12. 知识库第一阶段基于五类国际来源：FEDIAF 2025、WSAVA、AAHA 2021、SACN5、ACVIM。
13. 暂不采用中国本土资料作为核心科学依据；中国资料未来可作为合规、标签或商业声明参考。
14. 五类来源是第一阶段专业骨架，不是完整知识库边界。
15. 首批功能性规则包只做两个：胰腺呵护/低脂、减重/肥胖管理。
16. 生产、采购、成本作为软约束，不阻断第一版食谱生成。
17. 功能性食谱默认强制人工审核。
18. 受限草稿不能直接发布。
19. 发布时保存快照，后续知识库、规则包或原料数据更新不能静默改变历史结论。
20. 第一版预留未来 C 端问答式引导的数据结构，但不做 C 端页面。

## 目标

1. 让管理员可以从一只狗狗档案出发，通过 Agent 生成个性化营养管理方案。
2. 让 Agent 在已确认的营养约束内自动生成食谱设计草稿。
3. 支持首批两个功能方向：胰腺呵护/低脂、减重/肥胖管理。
4. 将 FEDIAF 2025 作为完整均衡营养底线，和功能性规则包共同约束食谱设计。
5. 降低 Agent 幻觉：每个关键结论都可追溯来源、规则、计算或人工依据。
6. 建立知识源资格评估、证据分级、规则包版本、审核发布和审计快照机制。
7. 支撑未来普通狗狗家长使用时的问答式信息采集和报告输出。

## 非目标

1. 第一版不开放给普通 C 端用户。
2. 第一版不让 Agent 替代兽医诊断。
3. 第一版不让照片直接触发疾病规则包。
4. 第一版不覆盖所有疾病营养管理。
5. 第一版不做全自动从 PDF 导入、抽取并发布知识规则。
6. 第一版不做无需人工确认的诊断报告解释。
7. 第一版不支持 Agent 自动发布正式食谱。
8. 第一版不把采购、成本、生产复杂度作为硬阻断条件。
9. 第一版不以中国本土营养标准作为核心科学依据。

## 产品定位

本功能定位为 AI-first 的食谱自动设计与个性化营养管理系统。

它面向内部管理员，帮助管理员完成：

1. 选择狗狗。
2. 读取档案与健康记录。
3. 补充当前饮食、目标、报告等信息。
4. 生成个性化营养管理方案。
5. 自动生成食谱草稿。
6. 查看营养、功能性约束和证据链。
7. 审核、微调、保存或发布。

未来开放给普通狗狗家长时，用户不应直接面对专业食谱编辑器，而应通过问答式引导完成信息上传、症状描述、报告补充和结果理解。

## 知识源资格评估与证据分层

### 第一阶段知识源

第一阶段基于五类国际来源搭建知识库骨架：

| 来源 | 系统角色 | 说明 |
| --- | --- | --- |
| FEDIAF 2025 | 完整均衡营养底线 | 覆盖犬生命阶段、MER 档位、上下限、单位、组合项和比值项。 |
| WSAVA Nutrition Guidelines / Toolkit | 营养评估流程 | 用于饮食史、BCS/MCS、喂养管理和营养评估框架。 |
| AAHA 2021 Nutrition and Weight Management Guidelines | 体重管理流程 | 用于减重、体况管理、复评和客户沟通。 |
| SACN5 | 临床营养规则包底座 | 覆盖面广，但版本较旧，不能单独作为高风险疾病唯一依据。 |
| ACVIM Endorsed Statements | 疾病专项高权重证据 | 不覆盖所有疾病，但有对应主题时权重高。 |

这五类来源不能被写成“全部金标准”。更准确的定位是：

```text
五类来源足以构成第一版专业营养评估骨架，但不足以覆盖所有疾病、所有诊断场景和所有功能性食谱规则。
```

每个新增规则包上线前都必须单独做来源资格评估：

- 权威性
- 发布时间与版本
- 适用物种
- 适用生命周期
- 适用场景
- 是否可量化成规则
- 是否适用于家制或鲜食
- 是否有版权限制
- 是否与已有规则冲突
- 审核人和审核时间

若 SACN5 与更新、更专项的 ACVIM 或其他高质量资料冲突，优先采用更新、专项、证据等级更高的来源，并记录冲突。

参考来源入口：

- FEDIAF Nutritional Guidelines: https://europeanpetfood.org/self-regulation/nutritional-guidelines/
- WSAVA Global Nutrition Guidelines: https://wsava.org/global-guidelines/global-nutrition-guidelines/
- AAHA 2021 Nutrition and Weight Management Guidelines: https://www.aaha.org/aaha-guidelines/2021-aaha-nutrition-and-weight-management-guidelines/home/
- Small Animal Clinical Nutrition 5: https://www.markmorrisinstitute.org/sacn5
- ACVIM Endorsed Statements: https://www.acvim.org/journals-research/research/acvim-endorsed-statements

### 版权和引用边界

SACN5 等书籍资料不能直接全文入库或大段复制。第一版应保存：

- 来源元数据
- 章节或页码线索
- 人工整理的规则摘要
- 结构化约束
- 审核记录

Agent 输出时应引用规则和来源信息，不应输出大段版权文本。

### 证据等级

狗狗个体资料进入系统后，按证据等级参与判断：

| 等级 | 类型 | 用途 |
| --- | --- | --- |
| A 级 | 医生诊断报告 + 关键检查指标 + 日期/机构信息完整，并经管理员确认 | 可触发疾病或功能性规则包。 |
| B 级 | 检查报告提示风险，但诊断不完整或未明确，并经管理员确认 | 可触发谨慎规则或受限规则包。 |
| C 级 | 用户自述症状、历史病史、当前饮食描述 | 只能触发追问、风险提示、建议就医或低风险支持。 |
| D 级 | 照片、便便状态、体态观察等低证据材料 | 第一版只作为附件或观察项，不直接触发疾病规则包。 |

规则：

1. 症状不等于诊断。
2. 照片不触发疾病规则包。
3. 报告自动抽取结果必须人工确认。
4. 未经确认的报告解析结果只能作为候选信息。
5. Agent 不能将 C/D 级材料写成明确诊断。
6. 证据不足时，严格结果不能被标记为可审核发布。

## 知识库建设与运行机制

知识库不是一个大文档仓库，而是可治理、可检索、可版本化、可被规则引擎调用的系统。

### 知识形态

第一版知识分为四类：

1. **知识源登记**
   记录来源名称、版本、URL、适用范围、权威等级、版权限制和审核状态。

2. **知识条目**
   用于解释依据，例如某个营养评估流程、体况判断、复评原则或疾病营养原则。

3. **结构化规则**
   用于真正约束 Agent，包括启用条件、目标区间、上下限、禁忌、冲突规则。

4. **审计记录**
   保存每次任务使用过的知识条目、规则版本、人工依据和计算结果。

### 运行时检索

Agent 每次任务不能读取完整知识库，只能读取本次任务相关的“证据包”：

```text
狗狗档案 + 用户描述 + 已确认报告结论
  -> 检索相关知识条目
  -> 命中规则包
  -> 生成营养约束
  -> 调用确定性计算服务
  -> 输出营养管理方案和食谱草稿
```

检索策略建议：

- 元数据过滤：物种、生命阶段、规则包、疾病方向、证据等级。
- 关键词搜索：营养素、疾病名称、检查指标、规则名称。
- 向量检索：用于从知识条目中找到语义相关材料。
- 结构化规则查询：真正进入计算和约束合成的部分必须来自结构化规则。

上下文限制通过“任务相关证据包”解决，而不是把全库塞给模型。

### 知识维护

第一版实现后台可维护的最小版本：

- 知识源登记
- 知识条目维护
- 规则包维护
- 版本号
- 审核状态
- 发布/停用

长期目标是半自动治理：

```text
文档导入 -> 候选知识抽取 -> 候选规则生成 -> 专家审核 -> 测试集验证 -> 发布为正式规则
```

人工经验可以沉淀，但只能先成为候选知识或人工依据，不能自动成为正式规则。

## 两阶段工作流

系统拆成两个阶段，避免 Agent 从症状直接跳到配方。

### 阶段一：营养评估与约束生成

输入包括：

- 管理员文字描述
- 已有狗狗档案
- 健康记录与过敏/禁忌
- 体重记录
- 检查报告或医生诊断报告
- 附件照片，如大便照片

流程：

1. 管理员选择狗狗。
2. Agent 读取狗狗档案、健康记录、过敏记录、体重记录、饮食提醒和附件。
3. Agent 判断档案是否满足营养评估最低信息要求。
4. 信息不足时，Agent 追问或要求上传报告。
5. 报告上传后自动抽取诊断、指标、日期、医院/医生等信息。
6. 管理员确认抽取结果。
7. 系统进行证据分级。
8. 系统匹配可启用的规则包。
9. 约束合成器合成营养约束，并检测冲突。
10. 输出完整个性化营养管理方案。

个性化营养管理方案包含：

- 输入摘要
- 档案完整度
- 证据等级
- 启用规则包及原因
- 未启用规则包及原因
- 营养目标、上下限、最佳区间
- 原料偏好、谨慎和排除
- 规则冲突和处理建议
- 信息不足项
- 风险提示
- 喂食原则
- 监测和复评建议
- 引用知识与版本

### 阶段二：食谱自动设计

Agent 只能在阶段一生成的营养管理方案约束内设计食谱。

流程：

1. 读取营养管理方案中的约束。
2. 选择原料和补剂候选。
3. 生成食谱草稿。
4. 调用确定性计算服务做 FEDIAF 2025 校验。
5. 调用功能性规则校验。
6. 调用缺数据检查。
7. 未达标时迭代调整。
8. 小改直接更新当前草稿。
9. 大改生成候选版本。
10. 输出最终草稿、差距报告、依据报告、喂食建议、烹饪建议和制作建议。
11. 进入人工审核与发布流程。

Agent 不能绕过营养管理方案直接生成配方。

## 结果状态

第一版不要求管理员一开始选择“严格达标模式”或“探索草稿模式”。系统在结果阶段给出状态：

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| 可审核发布 | FEDIAF 达标、功能性约束满足、关键证据充分、无关键缺数据 | 可进入发布审核。 |
| 需人工审核 | 功能性食谱、软约束未完全满足，或存在提示风险 | 必须人工审核后才可发布。 |
| 受限草稿 | 存在证据不足、缺数据或规则冲突，但仍有参考价值 | 可保存、复制、继续编辑，不能直接发布。 |
| 无法完成 | 硬约束不可解或关键信息不足 | 不生成可用草稿，只输出冲突/补资料报告。 |

若管理员希望发布未完全达标但仍可审核的草稿，必须填写审核说明，并保存审核记录。

受限草稿不能从受限状态直接发布。它必须先补齐证据或营养数据，或由管理员明确填写人工覆盖说明后转入“需人工审核”状态，再进入发布审核。

## 功能性规则包

第一版只上线两个规则包：

1. 胰腺呵护 / 低脂
2. 减重 / 肥胖管理

每个规则包必须结构化，而不是一段提示词。

### 规则包字段

- 规则包名称
- 规则包版本
- 适用条件
- 禁用条件
- 所需证据等级
- 必填信息
- 营养目标
- 上限、下限、最佳区间和单位
- 原料推荐、谨慎、排除
- 口味和适口性建议
- 与 FEDIAF 2025 的关系
- 与其他规则包的冲突规则
- 强制审核条件
- 可对用户展示的话术边界
- 引用来源
- 审核记录

### 首批规则包边界

胰腺呵护/低脂：

- 偏医疗安全约束。
- 需要更高证据等级。
- 不应被表述为治疗胰腺炎。
- 规则包输出应强调需管理员或兽医确认。

减重/肥胖管理：

- 偏长期营养管理。
- 需要当前体重、BCS、目标体重或理想体重、活动量、当前饮食和零食信息。
- 输出必须包含监测节奏和复评条件。

IBD、肾病、心脏病、糖尿病、肝胆疾病等作为后续规则包，不进入第一版自动设计范围。

## 约束合成与冲突处理

多规则包可以叠加，但不能简单平均，也不能让 Agent 自行折中。

约束合成器负责：

1. 合并硬约束。
2. 排序软约束。
3. 检查不可同时满足的条件。
4. 输出可执行约束或冲突报告。

冲突优先级：

1. 医疗安全风险
2. FEDIAF 完整均衡底线
3. 已确认疾病或功能性规则包硬约束
4. 当前主要目标，例如减重
5. 口味偏好
6. 成本、采购、生产便利

处理规则：

- 硬约束不可解时，结果状态为无法完成。
- 探索价值仍存在时，可生成受限草稿，但必须标记冲突和强制审核。
- Agent 不允许发明新标准。
- Agent 不允许隐藏冲突。
- 功能性食谱默认强制审核。

## 食谱设计器内的 AI 模式与交互

入口内嵌在小程序食谱设计器中，采用顶部双模式：

- AI Agent 设计
- 手动编辑

产品原则：

```text
AI 优先生成，手动编辑用于审核、修正和兜底。
```

### AI Agent 设计模式主流程

第一版不让管理员先选择任务类型或成功标准。流程从狗狗选择开始。

1. **选择狗狗**
   管理员从现有狗狗档案中选择一只狗狗。系统自动读取基础档案、健康记录、过敏记录、体重记录、饮食提醒和报告附件。

2. **资料完整度检查**
   Agent 判断当前档案是否足够生成营养管理方案。如果不足，按问题列表追问，例如当前饮食、目标体重、近期检查报告、疾病状态等。

3. **报告上传与确认**
   管理员可上传检查或诊断报告。系统自动抽取诊断、指标、日期、医院/医生等信息，但必须管理员确认后才能进入证据分级。

4. **营养管理方案生成**
   系统基于已确认资料、知识库和规则包，生成完整营养管理方案。

5. **食谱自动设计**
   Agent 在营养管理方案约束内生成草稿，并调用确定性计算服务进行 FEDIAF 2025、功能性规则和缺数据校验。

6. **结果状态输出**
   系统输出可审核发布、需人工审核、受限草稿或无法完成。

7. **结果动作**
   管理员可以保存为该狗狗的个性化食谱、生成候选版本、复制为新草稿、发布为标准食谱候选，或进入手动编辑复核。

### 发布为标准食谱候选

个性化食谱可以发布为标准食谱候选，但需要额外泛化检查：

- 去除个体病史依赖。
- 明确适用生命阶段、体型、健康标签。
- 明确不适用情况和禁忌。
- 重新运行 FEDIAF 2025 校验。
- 重新确认功能性规则是否适合作为标准食谱标签。
- 保存从个性化方案泛化而来的审计记录。

### 手动编辑模式

手动编辑模式继续承载专业工具能力：

- 查看和编辑原料克数
- 查看 FEDIAF 2025 评估抽屉
- 查看功能性约束满足情况
- 查看缺数据项
- 查看 Agent 变更记录
- 对候选版本进行采用、废弃或回退
- 发布前人工审核

### 版本规则

- 小改直接作用于当前草稿，例如“钙补到达标”“脂肪再降低一点”。
- 大改生成候选版本，例如“从牛肉体系改成鸭肉体系”。
- 每次 Agent 修改都保存输入指令、变更内容、原因、引用依据、计算前后差异。
- 已发布食谱必须保存快照。

## 数据与服务边界

### 建议新增或扩展的数据概念

第一版实施时建议新增或扩展以下概念：

- `KnowledgeSource`：知识源登记
- `KnowledgeEntry`：知识条目
- `NutritionRulePackage`：功能性规则包
- `NutritionRuleVersion`：规则包版本
- `DogNutritionAssessment`：某只狗狗的一次营养评估

- `AgentRecipeAuditSnapshot`：审计快照

现有 `DesignRecipe` 和 `DesignRecipeAIGenerationLog` 可复用，但需要校正旧字段和旧默认值，尤其避免继续默认旧 FEDIAF 口径。

### 服务边界

建议拆分服务：

- 知识源与规则包服务
- 报告解析与人工确认服务
- 证据分级服务
- 营养评估服务
- 约束合成服务
- 食谱自动设计 Agent 服务
- 食谱确定性计算服务
- 审计快照服务
- 发布与泛化检查服务

LLM 负责理解、对话、解释、候选生成和摘要；确定性服务负责计算、单位换算、规则判断、冲突检测和状态判定。

## 权限与发布规则

### 权限

第一版运行时：

- 只有 `ADMIN` 可发起 AI 自动设计。
- 只有 `ADMIN` 可确认报告解析结果。
- 只有 `ADMIN` 可发布或审核功能性食谱。

设计上预留：

- `RECIPE_DESIGNER`
- `RECIPE_REVIEWER`
- `KNOWLEDGE_EDITOR`
- `KNOWLEDGE_REVIEWER`

### 发布规则

- 功能性食谱默认强制人工审核。
- 受限草稿不能直接发布。
- 未完全达标但仍可审核的草稿必须填写审核说明。
- 受限草稿必须先补齐资料或通过人工覆盖转入“需人工审核”状态，不能直接发布。
- 发布为标准食谱候选时必须做泛化检查。
- 发布时保存快照。
- 快照不随知识库、规则包或原料数据更新静默改变。

## 错误与降级

### 报告解析失败

允许管理员手动录入关键结论。未确认的解析结果不参与证据分级。

### 档案信息不足

Agent 输出补充信息清单，不直接生成可发布草稿。

### 规则冲突

输出冲突报告。硬约束不可解时状态为无法完成；有参考价值时可保存为受限草稿。

### FEDIAF 标准不可用

不能标记为可审核发布。允许保存受限草稿。

### 原料营养数据缺失

缺数据不能当作 0。允许进入草稿，但必须标记缺数据并阻止直接发布。

### 知识库依据不足

Agent 不能编造依据。可输出受限草稿或补知识需求。

## 测试与验收

第一版验收不以“Agent 看起来聪明”为标准，而以可控、可审计、少幻觉为标准。

### 产品验收

- 可以从狗狗选择器进入自动设计流程。
- 可以读取狗狗档案、健康记录、过敏记录、体重记录和附件。
- 可以识别档案缺失项并追问。
- 可以上传报告、自动抽取并要求人工确认。
- 可以生成完整营养管理方案。
- 可以启用胰腺呵护/低脂、减重/肥胖管理两个规则包。
- 可以检测规则冲突和证据不足。
- 可以生成食谱草稿并调用 FEDIAF 2025 评估。
- 可以输出喂食、烹饪、制作建议。
- 可以保存审计报告和发布快照。

### 防幻觉验收

- Agent 的关键结论必须能追溯来源。
- Agent 不能把症状写成诊断。
- Agent 不能把照片观察写成疾病结论。
- Agent 不能使用未确认的报告解析结果启用规则包。
- Agent 不能隐藏规则冲突。
- Agent 不能绕过确定性计算服务自行判断达标。
- Agent 不能把缺失营养数据当成 0。

### 黄金测试案例

第一版至少准备以下测试案例：

1. 健康成年犬，档案完整，无功能性规则包。
2. 肥胖成年犬，信息完整，触发减重/肥胖管理。
3. 胰腺炎史犬，报告完整，触发胰腺呵护/低脂。
4. 用户自述胰腺炎但无报告，不能启用强疾病规则包。
5. 上传报告解析出指标，但管理员未确认，不能参与证据分级。
6. 大便照片异常，但无诊断或检查报告，只能触发提示和追问。
7. 减重与低脂规则共同启用，生成约束合成结果。
8. 硬约束不可解，输出无法完成和冲突报告。
9. 原料关键营养数据缺失，生成受限草稿。
10. 个性化食谱发布为标准食谱候选，必须完成泛化检查。

## 分阶段推进计划

### 阶段 0：设计文档与实施计划

完成本设计文档，确认范围、边界、知识源、规则包、交互和验收标准。

### 阶段 1：专业底座

建设知识源登记、知识条目、规则包、证据等级和审核发布模型。首批完成胰腺呵护/低脂、减重/肥胖管理两个规则包。

### 阶段 2：营养评估引擎

实现从狗狗档案、文字描述和报告确认结果到个性化营养管理方案的流程。此阶段先不追求自动生成食谱，先验证约束方案可靠。

### 阶段 3：食谱约束与计算

将营养管理方案转成设计器可执行约束，并对接 FEDIAF 2025、原料营养、补剂目标、缺数据和功能性规则校验。

### 阶段 4：AI Agent 设计模式

在食谱设计器内实现 `AI Agent 设计 / 手动编辑` 双模式。Agent 支持对话、追问、草稿生成、小改当前版本、大改候选版本、依据解释和结果状态输出。

### 阶段 5：审计、发布与验收

实现审计报告、发布快照、泛化检查和黄金测试案例验证。通过后再考虑 C 端问答式引导。

## 风险与控制

### 专业责任风险

控制方式：明确非诊断定位，症状不等于诊断，功能性食谱强制审核。

### 知识源不足

控制方式：五类来源只作为第一阶段骨架，每个新规则包独立做来源资格评估。

### Agent 幻觉

控制方式：关键结论必须绑定知识、规则、计算或人工依据；计算交给确定性服务。

### 上下文超限

控制方式：运行时只构造任务相关证据包，使用元数据过滤、关键词搜索、向量检索和结构化规则查询。

### 健康档案不足

控制方式：先做资料完整度检查和追问；必要字段可在 AI 流程中补采，再反哺档案。

### 个性化食谱误发布为标准食谱

控制方式：发布为标准食谱候选时必须做泛化检查和人工审核。

## 结论

第一版应建设 AI-first 的食谱自动设计与个性化营养管理系统，而不是简单的聊天生成配方。系统从选择一只狗狗开始，先完成营养评估和约束生成，再在可追溯的约束内自动设计食谱。知识库以 FEDIAF 2025、WSAVA、AAHA 2021、SACN5 和 ACVIM 为第一阶段骨架，首批规则包只做胰腺呵护/低脂和减重/肥胖管理。Agent 的角色是理解、对话、解释和生成候选，不负责自由判断营养达标、医学诊断或规则冲突。通过证据分级、规则包、约束合成、确定性计算、人工审核和审计快照，系统可以在降低幻觉和专业风险的前提下，为未来 C 端自动食谱设计打下基础。
