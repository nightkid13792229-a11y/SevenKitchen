# 食谱编辑器营养评估位置恢复设计

## 背景

小程序食谱编辑页中，用户会先展开营养评估，在某个分类的某个位置看到需要调整的营养项，然后收起营养评估回到原料列表修改重量。当前重量保存并重新评估后，再次展开营养评估会回到默认分类或列表顶部，打断反复调配流程。

本设计聚焦编辑页营养评估抽屉的浏览位置恢复，不改变营养计算公式、后端接口、原料重量保存逻辑或营养项排序规则。

## 目标

1. 用户从营养评估回到原料列表调整重量后，再次打开营养评估时回到刚刚浏览的位置。
2. 恢复依据以“分类 + 滚动位置”为主，不要求用户额外点击或标记某个营养项。
3. 营养重新计算后，不因为异常数量变化而强行跳回默认分类。
4. 在数据变化导致原分类不可恢复时，才回退到现有默认分类逻辑。

## 非目标

1. 不自动猜测用户关注的具体营养项。
2. 不新增关注、收藏、锚定营养项等复杂交互。
3. 不改变“含量/原料”详情弹窗的现有能力。
4. 不调整营养项排序、分类映射或异常统计口径。

## 交互设计

### 位置记录

当营养评估抽屉处于展开状态时，系统记录：

1. 当前选中的营养分类。
2. 当前分类列表的纵向滚动位置。

记录发生在用户滚动营养评估列表、切换分类、收起抽屉、编辑原料重量前后。用户不需要点击某个营养项。

### 重新打开

用户修改原料重量并触发营养重新计算后，再次展开营养评估：

1. 优先恢复上一次选中的分类。
2. 在该分类仍存在条目时，将列表滚回上一次滚动位置。
3. 不自动跳转到第一个异常分类。
4. 如果该分类不存在或为空，使用现有默认逻辑：第一个有异常数量的分类，否则宏量。

### 切换分类

用户主动点击分类标签时：

1. 更新当前分类。
2. 该分类使用自己独立的滚动位置；如果之前没有记录，则从顶部开始。
3. 后续收起和展开时恢复到这个分类及其位置。

## 实现设计

### 状态

在 `miniapp/src/pages/recipe-designer/editor.vue` 中新增轻量状态：

1. `assessmentScrollTopByCategory`：按分类保存滚动位置。
2. `assessmentScrollTop`：绑定当前分类的滚动位置。
3. `shouldRestoreAssessmentPosition`：标记重算后下一次渲染需要恢复位置。

### 模板

将营养评估列表容器改为 `scroll-view scroll-y`，绑定：

1. `:scroll-top="assessmentScrollTop"`
2. `@scroll="onAssessmentListScroll"`

当前的 `assessment-list-surface` 和营养项内容保持不变。

### 计算刷新

`refreshAssessment()` 更新评估数据后：

1. 不清空已记录的分类和滚动位置。
2. 若当前分类仍有条目，保留当前分类。
3. 若当前分类为空，再回退到默认分类。
4. 在下一次 DOM 更新后恢复当前分类的滚动位置。

现有 `watch(assessmentCategories)` 需要避免在当前分类仍有效时重置分类。

### 边界情况

1. 滚动位置超过新列表高度时，由小程序滚动容器自然夹到可滚动范围内。
2. 分类切换时，若该分类没有历史位置，滚动到顶部。
3. 页面首次加载仍沿用现有默认分类逻辑。
4. 已发布只读草稿也保留浏览位置，因为这不涉及数据修改。

## 验收标准

1. 在营养评估中滚到微量元素中部，收起抽屉，修改原料重量，再展开后仍停留在微量元素中部。
2. 重算后当前分类仍有条目时，不跳到第一个异常分类。
3. 用户主动切换分类后，每个分类恢复自己的上次滚动位置。
4. 首次进入页面时，仍默认选中第一个有异常数量的分类；全部达标时选中宏量。
5. `miniapp` 预览构建通过，并明确使用 `miniapp/dist/dev/mp-weixin` 验证目录。
