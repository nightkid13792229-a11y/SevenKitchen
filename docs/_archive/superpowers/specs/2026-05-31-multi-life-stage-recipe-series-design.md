# 多生命阶段食谱系列设计

## 背景

SevenKitchen 已接入食谱编辑器，食谱编辑器支持不同营养标准和生命阶段。如果每个生命阶段都作为一条独立食谱展示，会导致 Web 管理后台、小程序食谱橱窗和用户详情页都变得混乱。

本设计将用户可见的食谱收敛为“食谱系列”，把不同生命阶段作为同一食谱系列下的阶段版本。运营在编辑器中分别设计和发布各生命阶段版本，用户在小程序中看到的是同一个食谱，并在详情页自动或手动选择适合当前狗狗的生命阶段版本。

## 已确认决策

1. 小程序食谱橱窗卡片不展示生命阶段字段。
2. 小程序食谱详情页按当前狗狗档案自动匹配生命阶段版本。
3. 如果没有匹配阶段，优先展示普通成年犬版本，并给出不匹配提醒。
4. 如果普通成年犬版本也不存在，允许展示第一个已配置且可展示阶段，并给出不匹配提醒。
5. 小程序详情页提供手动切换生命阶段能力。
6. 未配置、未发布或不可对用户开放的生命阶段不出现在小程序切换列表中。
7. Web 管理后台和食谱编辑器都采用“食谱系列 + 生命阶段版本”的心智。
8. 食谱设计器列表展示食谱系列卡片，不展示封面、系列编号、进入编辑按钮、系列设置按钮或最近状态说明。
9. 食谱系列卡片展示五个生命阶段的当前状态，而不是只展示配置数量或上架数量。
10. 现有食谱编辑页继续作为编辑入口，不新增独立“阶段编辑页”；从某个生命阶段进入后，页面带上当前阶段上下文。
11. 已发布阶段默认只读，点击“编辑”后进入可编辑状态；系统内部仍使用修订草稿保护已上架版本。
12. 系列卡片右上角更多菜单保留“重命名”和“删除”。
13. 删除采用安全删除：用户看到的是删除，系统保留必要历史发布记录和订单引用。
14. 历史版本按生命阶段管理，从历史版本回溯时先创建草稿，不直接覆盖线上版本。

## 目标

1. 用户端只看到清晰的食谱系列，避免同一食谱因生命阶段拆成多条卡片。
2. 运营端可以一眼看出每个食谱系列下五个生命阶段的设计和发布状态。
3. 营养师可以在现有食谱编辑页中切换生命阶段、编辑当前阶段、发布当前阶段。
4. 已发布版本受到保护，任何修改先进入草稿，再发布替换对应阶段版本。
5. 小程序根据狗狗档案自动展示最合适版本，同时保留用户手动切换能力。
6. 删除、历史回溯、改名等低频管理能力保留，但不干扰主流程。

## 非目标

1. 不把每个生命阶段拆成独立食谱展示给用户。
2. 不新增一套独立的阶段编辑页面。
3. 不在小程序橱窗卡片上展示生命阶段状态。
4. 不让历史版本回溯直接覆盖线上版本。
5. 不对已发布食谱做不可追溯的硬删除。
6. 不在本设计中重做营养计算标准或 FEDIAF 计算逻辑。

## 核心概念

### 食谱系列

食谱系列是用户端看到的一条食谱。例如“牛肉南瓜鲜食”是一个食谱系列。

系列承载：

- 系列名称
- 最近编辑时间
- 五个生命阶段的状态摘要
- 系列级展示信息
- 系列级重命名和删除入口

### 生命阶段版本

生命阶段版本是食谱系列下的具体可发布版本。例如“牛肉南瓜鲜食 · 普通成年犬”是一个阶段版本。

阶段版本承载：

- 当前生命阶段
- 关联营养标准
- 配方原料和克数
- 营养评估结果
- 草稿、审核、发布状态
- 历史发布版本

### 修订草稿

修订草稿是系统内部的安全机制，不作为运营主文案。

运营点击“编辑”时：

1. 如果已有当前阶段的修订草稿，直接进入该草稿。
2. 如果没有修订草稿，系统自动创建一个草稿。
3. 草稿发布后，只替换当前生命阶段的线上版本，不影响同系列其他阶段。

## 生命阶段范围

列表和后台管理固定覆盖五个业务生命阶段：

1. 小于 14 周幼犬
2. 14 周以上幼犬
3. 普通成年犬
4. 低能量成年犬 / 老年犬
5. 繁殖期

这些阶段在管理端固定展示，方便运营判断缺口。小程序用户端只展示已配置、已发布、可开放的阶段。

## 阶段状态

管理端统一使用五类状态：

1. 未设计：该阶段尚未创建配方。
2. 草稿：该阶段已有未发布草稿。
3. 审核中：该阶段已提交发布审核。
4. 已发布：该阶段已有用户端可见版本。
5. 需修改：该阶段审核退回或需要重新调整。

食谱系列卡片中，每个生命阶段一行展示当前状态。右上角可以保留“3 已发布”这类辅助摘要，但主信息必须是五个阶段的状态列表。

## Web 管理后台

### 食谱设计器列表

食谱设计器列表只展示食谱系列卡片。

卡片展示：

- 食谱系列名称
- 最近编辑日期和具体时间
- 五个生命阶段状态
- 可选辅助摘要，例如“3 已发布”
- 更多菜单

卡片不展示：

- 食谱封面
- 系列编号
- 生命阶段单字段
- 进入编辑按钮
- 系列设置按钮
- 最近状态说明文案

### 系列卡片操作

卡片右上角更多菜单只保留：

- 重命名
- 删除

菜单项不展示解释小字。说明放在后续弹窗或规则提示中。

### 进入编辑

点击食谱系列卡片中的任一生命阶段行，进入现有食谱编辑页，并自动切换到该生命阶段。

不同状态的进入规则：

- 已发布：进入只读模式。
- 草稿：进入可继续编辑的草稿。
- 审核中：进入只读或审核中状态页，避免重复修改。
- 需修改：进入可编辑草稿。
- 未设计：初始化该阶段的新草稿。

### 删除安全

用户看到的操作叫“删除”，但系统执行安全删除。

删除弹窗必须展示影响范围：

- 将从食谱设计器列表移除的系列名称
- 将从小程序隐藏的已发布阶段数量
- 将删除的未发布草稿数量
- 将保留的历史发布记录和订单引用

删除必须二次确认：

- 输入食谱系列名称
- 勾选确认影响范围
- 点击确认删除

删除执行规则：

- 未发布草稿可以删除。
- 已发布阶段从用户端隐藏，并从默认管理列表移除。
- 历史发布记录、订单引用、审计记录保留。
- 如果存在审核中阶段，建议先撤回审核，再允许删除。

## 食谱编辑器

### 页面定位

不新增“阶段编辑页”。现有食谱编辑页继续承载编辑能力。

当用户从某个生命阶段进入时，页面顶部展示：

- 食谱系列名称
- 当前生命阶段
- 当前营养标准
- 当前发布状态

例如：“牛肉南瓜鲜食 · 普通成年犬”。

### 默认只读与编辑

已发布阶段默认只读。

只读状态展示：

- 当前阶段信息
- 切换生命阶段入口
- 历史版本入口
- 原料配方只读
- 营养校验只读
- 编辑按钮

点击“编辑”后：

- 系统进入已有修订草稿，或自动创建修订草稿。
- 页面切换为可编辑状态。
- 已上架版本不会被直接改动。

### 生命阶段切换

食谱编辑页中保留现有的营养标准 / 生命阶段切换能力。

切换弹窗中展示每个生命阶段的状态：

- 已发布
- 审核中
- 草稿
- 需修改
- 未设计

选择某个阶段后，编辑器加载该阶段对应数据。未设计阶段会初始化为新草稿。

### 发布流程

发布流程在当前生命阶段上下文中完成。

发布后：

- 只替换当前生命阶段的线上版本。
- 不影响同一食谱系列下其他生命阶段。
- 更新食谱系列卡片中的阶段状态。
- 小程序端开始使用该阶段版本参与自动匹配和手动切换。

### 历史版本

历史版本按生命阶段管理。

例如“牛肉南瓜鲜食 · 普通成年犬”有自己的历史版本列表。

历史版本支持：

- 查看当前上架版本
- 查看历史发布版本
- 从历史版本创建草稿

从历史版本回溯时，不直接覆盖线上版本。系统先创建草稿，运营检查或调整后再发布。

## 小程序用户端

### 食谱橱窗

食谱橱窗卡片代表食谱系列。

卡片展示：

- 食谱名称
- 食谱封面
- 简短描述
- 用户友好的标签
- 份量或能量摘要

卡片不展示：

- 生命阶段字段
- 阶段状态
- 后台版本信息

### 食谱详情

用户进入食谱详情后，系统按当前狗狗档案自动选择展示版本。

详情页顶部展示：

- 当前狗狗
- 当前展示的生命阶段版本
- 匹配原因
- 手动切换入口

例如：

“已匹配：普通成年犬。根据小七的档案自动展示该生命阶段版本。”

### 自动匹配规则

进入详情页时按以下顺序匹配：

1. 根据当前狗狗档案匹配对应生命阶段。
2. 如果对应阶段存在已发布且可展示版本，直接展示该版本。
3. 如果对应阶段不存在，展示普通成年犬版本。
4. 如果普通成年犬版本也不存在，展示第一个已配置、已发布、可展示版本。
5. 第 3 和第 4 种情况必须展示不匹配提醒。

### 不匹配提醒

当系统展示的版本和狗狗档案不匹配时，详情页顶部展示提醒。

提醒内容需要说明：

- 当前狗狗档案对应阶段
- 当前食谱暂无对应阶段版本
- 系统当前展示的替代版本
- 用户需要确认是否适合

示例：

“该食谱暂无繁殖期版本，已先展示普通成年犬版本。请确认是否适合奶茶。”

### 手动切换生命阶段

详情页提供手动切换入口。

切换弹窗只展示：

- 已配置
- 已发布
- 可对用户开放

的生命阶段版本。

未设计、草稿、审核中、需修改、已删除或不可开放的阶段不在用户端展示。

用户手动切换后，本次详情页和下单流程沿用用户选择的版本。更换狗狗或重新进入详情时，再重新计算默认匹配。

## 数据与接口要求

### 系列级数据

需要能支持按食谱系列查询：

- 系列名称
- 最近编辑时间
- 各生命阶段状态
- 已发布阶段数量
- 是否已删除或隐藏

### 阶段级数据

需要能支持按食谱系列和生命阶段查询：

- 当前草稿
- 当前审核状态
- 当前已发布版本
- 历史发布版本
- 是否可对用户开放
- 最近编辑时间

### 用户端详情数据

小程序详情接口需要返回：

- 食谱系列展示信息
- 系统默认选中的阶段版本
- 默认选择原因
- 是否存在不匹配提醒
- 用户可手动切换的阶段列表
- 当前阶段的营养摘要、原料摘要和购买所需信息

## 权限与留痕

需要记录以下操作：

- 重命名食谱系列
- 删除食谱系列
- 创建阶段草稿
- 编辑阶段草稿
- 提交审核
- 发布阶段版本
- 从历史版本创建草稿
- 删除未发布草稿

留痕至少包含：

- 操作人
- 操作时间
- 操作对象
- 操作前后关键状态

## 迁移与兼容

现有单生命阶段食谱需要迁移到食谱系列结构。

迁移建议：

1. 每条现有正式食谱先生成一个食谱系列。
2. 将现有食谱的生命阶段映射为该系列下的一个阶段版本。
3. 如果现有食谱没有明确生命阶段，优先归入普通成年犬，并在后台标记为待确认。
4. 历史版本继续保留，不直接丢弃。
5. 小程序橱窗切换到系列级展示后，同一系列不再因生命阶段重复出现多张卡片。

## 验收标准

### Web 管理后台

1. 食谱设计器列表只显示食谱系列卡片。
2. 系列卡片不展示封面、系列编号、进入编辑按钮、系列设置按钮。
3. 系列卡片展示五个生命阶段状态。
4. 点击生命阶段行进入现有食谱编辑页，并加载对应阶段。
5. 更多菜单只展示“重命名”和“删除”。
6. 删除必须展示影响范围，并要求二次确认。

### 食谱编辑器

1. 已发布阶段打开后默认只读。
2. 点击“编辑”进入已有草稿或自动创建草稿。
3. 切换生命阶段弹窗展示各阶段状态。
4. 发布只影响当前生命阶段。
5. 历史版本按当前生命阶段展示。
6. 从历史版本回溯只能创建草稿，不能直接覆盖线上。

### 小程序

1. 食谱橱窗卡片不展示生命阶段。
2. 详情页能根据当前狗狗档案自动匹配阶段版本。
3. 匹配不到时按普通成年犬、第一个已配置阶段的顺序兜底。
4. 匹配不到时必须展示提醒。
5. 手动切换列表只展示已配置、已发布、可开放阶段。
6. 用户手动选择的版本在本次详情和下单流程中保持一致。

## 实施顺序建议

1. 梳理并补齐食谱系列与阶段版本的数据结构。
2. 调整 Web 管理后台食谱设计器列表和系列卡片。
3. 调整现有食谱编辑页的阶段上下文、只读编辑、阶段切换和发布流程。
4. 调整小程序食谱橱窗为系列级展示。
5. 调整小程序食谱详情的自动匹配、手动切换和不匹配提醒。
6. 补齐删除安全、历史版本回溯和操作留痕。
7. 做历史数据迁移和回归验证。
