# 员工报销流程体验优化设计

## 背景

当前员工报销功能已经支持小程序提交报销申请、选择已完成采购清单、登记平台运费和打包费、添加经营费用、上传支付凭证，并在列表和详情页查看状态。

从员工视角看，当前流程可以完成报销，但页面更像一个长表单：采购清单、行政杂费、工资、凭证上传都堆在同一页。员工需要先理解哪些字段和本次报销有关，容易出现“不知道该填哪里”“从采购完成进入后还要重新找清单”“提交后才发现金额不合法”等体验问题。

本设计先优化员工报销的逻辑和交互体验，不引入 Agent 审核实现。之前归档的报销智能审核设计可作为后续增强，但不进入本次体验优化的第一阶段。

## 目标

- 让员工先选择清晰的大类，再看到相关字段。
- 支持采购报销一张或多张采购清单，不再拆成两个入口。
- 支持经营费用一次添加多项明细。
- 把会进入订单或生产成本的包材采购归入采购/补货清单。
- 员工不填写归属月份或均摊周期，是否均摊由管理员在审核或财务处理时决定。
- 提交前给员工明确的汇总页，减少漏填和误填。

## 非目标

- 不在本阶段实现 Agent 智能审核、OCR 或风险总结。
- 不改变管理员最终审核责任。
- 不把经营费用均摊规则做在员工端。
- 不把可消耗包材作为经营费用快捷分类。
- 不重做采购、库存、订单成本计算的核心模型。

## 当前问题

### 入口和类型

当前“申请报销”直接进入长表单。员工在一个页面里同时看到采购清单、平台费用、行政费用和凭证上传，缺少“这次报销什么”的第一步。

### 采购报销

采购报销和多张采购清单合并报销不应该成为两个员工入口。员工只需要选择要报销的采购清单数量：选一张就是单张采购报销，选多张就是合并报销。

如果员工从采购完成后进入报销，应自动带入并选中对应采购清单，避免再次查找。

### 经营费用

经营费用当前可以添加自定义费用，但多项费用能力不够显性。页面应明确展示“费用 1”“费用 2”“添加一项费用”“删除这一项”和合计金额。

### 包材归属

包材会影响订单成本。系统里包材已经是采购和库存中的正式类型，并参与订单包材成本计算。因此可消耗包材不应默认放到经营费用中。

### 归属月份和均摊

员工提交时只应描述事实：花了什么钱、多少钱、上传什么凭证。费用是否需要均摊、均摊几个月、归属哪个周期，应由管理员在审核或后续财务处理时判断。

## 新流程

### 第 0 步：我的报销

“我的报销”作为员工报销工作台，包含：

- 当前待处理数量。
- 需补充资料数量。
- 最近报销申请列表。
- 固定底部按钮“申请报销”。

状态文案建议使用员工能理解的表达，例如“等待处理”“已报销”“需补充”“已驳回”。如果后台仍使用 `PENDING_REVIEW`，员工端展示可以继续沿用“待报销”或调整为“等待处理”，实现前需统一文案。

### 第 1 步：选择报销类型

入口只保留两类：

- 采购报销。
- 经营费用报销。

员工判断规则：

- 这笔钱来自采购清单，或应该进入采购、库存、订单成本，选“采购报销”。
- 这笔钱不是采购清单相关支出，通常不直接进入单笔订单成本，选“经营费用报销”。

页面提示：

- 买了食材、补剂、包材，走采购报销。
- 房租、水电、工资、工具、杂物、其它日常支出，走经营费用报销。

### 第 2A 步：采购报销填写页

员工选择“采购报销”后进入采购清单选择页。

页面内容：

- 只展示已完成、未关联报销单的采购清单。
- 支持筛选：全部、日采、补货、包材。
- 支持选择一张或多张采购清单。
- 展示每张清单的日期、类型、原料或包材摘要、采购记录数量和金额。
- 自动汇总已选采购清单金额。
- 支持填写采购相关运费和采购相关打包费。
- 从采购完成页跳转时，自动选中该采购清单。
- 如果员工买的是包材但没有包材补货清单，提示先创建包材补货清单，再回来关联报销。

业务口径：

- 一张采购清单和多张采购清单不拆入口。
- 包材补货清单可以和其它采购清单一起报销。
- 采购相关运费和打包费仍随采购报销登记。

### 第 2B 步：经营费用填写页

员工选择“经营费用报销”后进入经营费用明细页。

快捷分类：

- 房租。
- 水电。
- 工资/人工。
- 工具。
- 杂物。
- 其它。

不默认提供“包材”分类。可消耗包材应走采购/补货清单。极少数不能入库、也不参与订单成本的小额包装杂项，可以选“其它”并写清楚，管理员审核时再决定是否重分类。

多项费用能力：

- 页面默认展示“费用 1”。
- 每项费用包含分类、说明、金额。
- 员工可以点击“添加一项费用”继续新增“费用 2”“费用 3”。
- 除第一项外，每项都可以删除。
- 页面底部实时展示合计金额。

不让员工填写：

- 归属月份。
- 均摊周期。
- 是否进入成本。

这些信息交给管理员在审核或财务处理环节决定。

### 第 3 步：上传支付凭证

上传凭证页单独展示，避免员工在长表单里边填金额边找图片。

页面内容：

- 提示凭证需要看清金额和支付时间。
- 支持相册和拍照上传。
- 支持多张凭证。
- 只展示缩略图和删除入口，不展示调试 URL 或 COS key。
- 展示已上传张数。

提交前至少需要一张支付凭证。

### 第 4 步：确认提交

确认页集中展示：

- 报销类型。
- 费用明细。
- 支付凭证数量。
- 报销合计金额。
- 普通提醒，例如采购价格波动、费用说明较简略。

员工确认后提交。提交后进入管理员处理。

### 第 5 步：提交成功

提交成功后不只显示 toast，而是展示结果页：

- 报销单号。
- 报销类型。
- 报销金额。
- 当前状态。
- 下一步说明，例如“管理员处理后会更新状态”。
- 操作入口：查看详情、返回列表。

## 包材成本规则

### 默认走采购/补货清单

以下包材默认作为采购或补货处理：

- 真空袋。
- 标签。
- 保温袋。
- 泡沫箱。
- 冰袋。
- 包装盒。
- 其它会被订单或生产消耗的包材。

原因：

- 包材会进入库存或采购记录。
- 包材单价会影响订单包材成本。
- 把包材走经营费用会绕过成本计算，影响毛利判断。

### 经营费用只做例外兜底

如果员工确实购买了无法入库、也不参与订单成本的小额包装杂项，可以走经营费用的“其它”，并在说明里写清楚。管理员审核时可要求重提或重分类。

## 管理员职责边界

员工端负责提交事实材料：

- 报销类型。
- 采购清单或经营费用明细。
- 金额。
- 支付凭证。

管理员端负责判断财务处理：

- 是否通过、驳回、要求补充。
- 经营费用是否需要均摊。
- 均摊周期和归属月份。
- 经营费用是否需要重分类。
- 经营费用是否进入某类成本口径。

## 数据和接口影响

第一阶段尽量复用现有报销模型：

- 采购报销继续使用 `purchaseListIds`。
- 采购相关运费继续使用 `platformShippingFee`。
- 采购相关打包费继续使用 `platformPackagingFee`。
- 经营费用继续使用 `customFees`。
- 支付凭证继续使用 `receiptUrls`。

可能需要补强：

- 提交页支持 `purchaseListId` 参数，进入后自动选中对应采购清单。
- 重新提交时必须真正更新费用明细和总金额，避免员工“看起来改了但实际没改”。
- 经营费用分类常量移除包材快捷项，保留其它。
- 采购清单列表支持包材筛选或至少清楚展示包材补货清单。
- 员工端提交按钮应在金额为 0、无凭证、无费用明细时提前禁用或提示。

如果后续管理员端要处理经营费用均摊，需要另行设计管理员审核和财务处理字段，不放在员工提交第一阶段。

## 测试范围

- 员工可以从“我的报销”进入申请流程。
- 第一步只显示“采购报销”和“经营费用报销”。
- 选择采购报销后，可以勾选一张或多张已完成未报销采购清单。
- 从采购完成页进入时，目标采购清单自动选中。
- 包材补货清单在采购报销页可见或可筛选。
- 选择经营费用后，快捷分类不包含包材。
- 经营费用可以添加多项、删除多项，并实时计算合计。
- 经营费用不要求员工填写归属月份或均摊周期。
- 上传凭证页不展示调试 URL。
- 确认提交页展示类型、明细、凭证数量和总金额。
- 金额为 0 或无凭证时，员工端提前提示，避免等后端报错。
- 重新提交时修改的费用、凭证和总金额实际生效。

## 上线建议

第一阶段先做员工端流程优化：两类入口、分步骤提交、采购清单自动带入、经营费用多项明细、包材归入采购报销。

第二阶段再考虑管理员端经营费用均摊能力，包括是否均摊、均摊周期、费用归属月份和财务报表口径。

第三阶段再接入已归档的报销智能审核 Agent，让系统在确认提交前做金额、凭证、时间和价格风险提示。
