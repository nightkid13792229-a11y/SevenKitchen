# 原文层产出规格 v1（内部使用 · 视觉模型）

**日期**：2026-11-01
**前提（老板当日定）**
- 用途：**仅内部**（营养师 / 配方设计 / 自己核对），不做顾客侧
- 模型：**只接支持视觉的模型**，不接纯文本模型
- 基线：配方营养标准以 **FEDIAF 2025** 为准
- 字段：**去掉 风险等级 / 审核状态 / 紧急程度**；顾客侧不再挡营养条目

---

## 一、为什么要这份规格

数字化的产出**不是"一堆能搜的文本"**，而是能被模型精确取用的四类东西：

```
文档 → 章节 → 段落（可引用）
             → 表格（可按行查）
             → 图片（可交给视觉模型看）
```

规格不先定，做出来只能用于一种用途，换一种就得重做。

---

## 二、数据结构

### 2.1 文档（document）

| 字段 | 说明 |
|---|---|
| `id` | 如 `SACN5-40` |
| `sourceId` | 对应来源登记表，如 `SACN5` |
| `path` | 归档相对路径 |
| `title` / `year` / `species` | 标题、年份、物种（犬/猫/混合/通用） |
| `docType` | 共识 / 指南 / 教科书 / 工具包 / 综述 / 法规 / 网页快照 |
| `pageCount` / `charCount` | 页数、字符数 |
| `hasTextLayer` | 有无文字层（扫描件为 false） |
| `parseStatus` | pending / parsed / partial / failed |

### 2.2 章节（section）

`id / documentId / parentId / title / level / pageStart / pageEnd / sortOrder`

按标题层级切，通常 2–3 层（章 → 节 → 小节）。

### 2.3 段落（paragraph）——**存储与引用的最小单位**

| 字段 | 说明 |
|---|---|
| `id` | 稳定 ID，如 `SACN5-40-p0123` |
| `documentId` / `sectionId` | 归属 |
| `text` | 正文 |
| `pageNo` | 页码（PDF 才有，XML/网页为空） |
| `charStart` / `charEnd` | 在文档全文中的位置（用于高亮） |
| `species` | 犬 / 猫 / 犬猫通用 —— **段落级判定**，因为混合文件里犬猫常并列写 |
| `contentType` | 正文 / 图注 / 表格说明 / 参考文献 / 页眉页脚 |

**粒度约定**：一个自然段（约 50–800 字）。过长的拆、过短的合并。**不跨章节。**

### 2.4 表格（table）

| 字段 | 说明 |
|---|---|
| `id` | 如 `SACN5-12-t12-5` |
| `documentId` / `sectionId` / `pageNo` | 归属 |
| `caption` | 表题（如「Table 12-5. 10 kg 成犬 RDA 与牛肉对比」） |
| `headers` | 表头数组 |
| `rows` | 二维数组，**每行可单独检索** |
| `unitRowIndex` | 单位行（很多表第二行是单位） |

> **表格必须保留结构，不能压成文本。** 配方设计要回答的是"鸡胸肉的钙是多少"——这是按行查，不是全文搜。

### 2.5 图片（figure）

| 字段 | 说明 |
|---|---|
| `id` | 如 `WSAVA-BCS-dog-2025-f1` |
| `documentId` / `pageNo` | 归属 |
| `caption` | 图注（有则存，**图注要和图绑死**） |
| `filePath` | 抽出的图片文件 |
| `kind` | 照片 / 图表 / 示意图 / **扫描整页** |
| `width` / `height` | 尺寸 |

> 扫描件（如 WSAVA 疼痛指南中文版 42 页）**整页渲染成图**，`kind = 扫描整页`。
> 因为只接视觉模型，**扫描件不再是障碍**——模型能直接看。

## 三、知识条目的对象（精简后）

去掉 riskLevel / reviewStatus / urgency 之后，模型拿到的就这 5 项：

```json
{
  "id": "urolith-005",
  "title": "草酸钙结石：不可溶解、以预防复发为主",
  "conclusion": "限钙、限草酸盐、限钠、限蛋白，并避免过度酸化尿液。",
  "points": ["...", "..."],
  "caveats": ["...", "..."],
  "sources": [
    { "source": "小动物临床营养学（第5版）", "locator": "第40章",
      "paragraphIds": ["SACN5-40-p0123", "SACN5-40-p0124"] }
  ]
}
```

**物种、领域、阶段这些不进返回对象**——它们只是检索用的索引字段，系统筛完就没用了，模型不需要看。

**出处必须能落到 `paragraphIds` / `tableId` / `figureId`。** 指不到的，标 `locatorOnly: true`，并在体检里计入"未定位"。

## 四、AI 消费契约

### 4.1 两套单元：段落是存储单位，检索块是喂给模型用的单位

| | 段落 | 检索块 |
|---|---|---|
| 用途 | 存储、定位、引用、高亮 | 实际放进上下文 |
| 大小 | 50–800 字 | **300–600 字**，由 1–N 个相邻段落合并 |
| 边界 | 不跨章节 | 不跨章节 |

只定义段落，模型会拿到一堆半句话；只定义块，又没法精确引用。**两个都要。**

### 4.2 上下文预算

现在的实际占用：条目均 1,444 字符 × 上限 24 条 ≈ **3.5 万字符**。

新模型的账（一次典型调用）：

| 内容 | 预算 |
|---|---:|
| 条目摘要卡 8 张 × 300 字 | 2,400 |
| 按需展开条目全文 2 条 × 1,500 字 | 3,000 |
| 原文检索块 3 块 × 500 字 | 1,500 |
| 表格 1 张（10 行以内） | ~1,500 |
| 图片 | **不在此预算内**——由调用方另行决定取不取、取几张 |
| **合计** | **约 8,400 字符**（图片另计） |

比现在小 4 倍，而且更准——先给卡片，需要再展开。

> **图片由谁决定**：取不取、取几张，是 Agent 层的事，知识库不管，也管不住。
> 知识库只保证两件事：① 文本检索的返回里只有 `figureId`，不含图片字节；② 取图是独立动作，单次上限可配置（默认 5，纯属防呆，防止一次要 50 张把上下文冲爆）。

### 4.3 两条访问路径 + 一条图片路径

| 路径 | 查什么 | 典型问法 |
|---|---|---|
| **文本** | 条目、原文段落 | "草酸钙结石的犬要怎么吃" |
| **表格** | 原料成分、营养标准、需求表 | "鸡胸肉的钙磷是多少" |
| **图片** | BCS/MCS 图、流程图、扫描页 | "给我看犬体况评分图" |

**配方设计走表格路径，不是文本路径。** 这是本次数字化最容易被忽略、却最关键的一条。

### 4.4 引用必须可校验

模型引用时返回的是**结构化的引用 ID**（段落 / 表 / 图），不是自由文本。

系统在返回给上层之前做一次校验：

1. 这个 ID 存在吗？
2. 它属于这份文档吗？
3. 被引用的段落是否真的包含结论里的关键内容？（数字层面的自动比对）

**任一条不过，就把这条回答标为"引用不可核"。** 这是防幻觉的最后一道闸。

## 五、知识库对外提供什么（能力，不是工具）

**这些是知识库侧的能力接口；工具名、description、调用时机属于 Agent 应用层，到时候再配。**

| 能力 | 输入 | 输出 |
|---|---|---|
| 列出可查范围 | — | 领域 / 文档 / 条数 |
| 查条目 | 关键词、筛选、条数 | 摘要卡数组 |
| 取条目全文 | 条目 ID 数组 | 完整条目（含出处段落 ID） |
| 搜原文 | 关键词、限定文档 | 检索块数组（含段落 ID、页码） |
| 取原文上下文 | 段落 ID、前后段数 | 连续文本块 |
| 查表 | 关键词 / 表 ID | 表题 + 表头 + 命中行 |
| 取图 | 图 ID / 页码 | 图片文件 + 图注 |

> 为什么现在只定"能力"：工具描述是提示工程，会随模型变；**但接口形状必须现在定死**，否则 Agent 层做工具时会反过来逼我们改数据库。

### 关于顾客侧：实际状态

`HEALTH_ANALYSIS=customer`（生产 .env 里是开着的）控制的是「顾客侧 AI 健康分析」这个功能。
但该功能的**入口自 2026-10-03 起已隐藏**（`dog-profile-health/index.vue` 有注释），
页面、接口、开关都在，顾客点不到。

**所以今天删 `reviewStatus` 不改变任何在用行为**——没人能走到那条路径。

⚠️ **待办（必须记）**：将来若要恢复顾客入口，**必须先重新定义"顾客侧能看到哪些条目"**，
因为 `filterByAudience` 就是干这个的，删掉后顾客会看到全部 387 条（含营养、分诊）。
不写这条，将来有人把入口加回来就会踩坑。

## 七、验收

| # | 验收项 | 判据 |
|---|---|---|
| A1 | 段落覆盖 | 每份文档 100% 切成段落，无 > 3000 字巨段、无大量 < 20 字碎段 |
| A2 | 表格完整 | 每张表保留表头 + 单位行 + 全部行；核心表（NRC 13-x、FEDIAF III/VII、SACN5 12-5/36-7 等）逐格抽检 |
| A3 | 图片可看 | 扫描件整页图能被视觉模型读出内容（抽样 5 页） |
| A4 | 字符保真 | 随机 30 段与原 PDF 逐字比对，零错字 |
| A5 | 引用可解析 | 每条出处能落到段落/表/图 ID；指不到的比例 < 5% 并在报告里列出 |
| A6 | 预算 | 一次典型检索拼出的上下文 ≤ 9,000 字符 + ≤2 图 |
| A7 | 表格查询 | "鸡胸肉的钙含量"能返回具体数值 + 表号 + 行号 |
