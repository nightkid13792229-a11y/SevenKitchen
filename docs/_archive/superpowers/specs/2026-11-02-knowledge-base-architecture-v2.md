# 知识库架构升级方案 v2

**日期**：2026-11-02
**唯一目标**：这套东西只服务一件事——**AI 模型能可靠地查到依据、并引用它**。
其它目标（人看、报表、管理后台）一律让路。

---

## 一、先说诊断：现在这套为什么不够用

不是"有缺陷"，是**三根柱子有一根是假的**。

### 问题 1：中间层（387 条条目）冒充了权威

| 事实 | 后果 |
|---|---|
| 条目是模型提炼的，**没有经过专业审核** | 模型读到"已审结论"，直接照抄 |
| 条目覆盖 27,911 段里的 **2,501 段（9%）** | 91% 的原文对模型不可见 |
| 63 份文档**一条都没被引用** | 有原文，但等于没有 |

**本质**：它同时扮演了两个角色——"答案"（不合法）和"中文→英文的检索桥"（很有价值）。
问题出在第一个角色，不在第二个。

### 问题 2：跨语言检索是断的（实测）

原文 27,911 段里，**26,640 段是英文**，只有 1,271 段中文。

拿 5 个真实的中文问题直接去英文原文里搜：

```
「草酸钙结石能不能吃菠菜」→ 命中 0 段
「胰腺炎要低脂吗」        → 命中 0 段
「老年犬认知障碍」        → 命中 0 段
「肾脏病蛋白摄入」        → 命中 0 段
「减肥怎么控热量」        → 命中 0 段
```

**这不是调优问题，是硬伤。** 删掉条目这一层，检索立刻归零。

### 问题 3：没有"证据"这个概念，只有"文本"

现在库里能查的东西是：段落、表格、图片。
但没有统一的"**证据单元**"——没有统一 ID、没有统一的中文名、没有统一的"这句能证明什么"。

模型拿到一段英文，还得自己判断它是否回答了问题。

---

## 二、AI 调用知识库，到底需要什么

把需求压到最简，只有四条：

| # | 要求 | 现在的状态 |
|---|---|---|
| 1 | **中文问题能找到英文依据** | ❌ 完全做不到 |
| 2 | **每条回答能追到具体一段原文** | ⚠️ 72% 条目能，但模型不读原文 |
| 3 | **覆盖全部原文，不是抽样** | ❌ 只有 9% |
| 4 | **没依据时说不出来，而不是编** | ❌ 没有机制 |

这四条里，**第 1 条是地基**。地基不解决，上面三条都无从谈起。

## 三、新架构

### 分层图

```
┌─────────────────────────────────────────────────────────┐
│ L5  回答层                                                │
│    模型只能基于 L4 给的证据作答；每条结论必须引 evidenceId │
│    校验器：引用必须存在、必须同文档、必须含关键词          │
│    过不了校验 → 回答必须降级为"知识库中无依据"             │
└──────────────────────────▲──────────────────────────────┘
                           │ 证据包（≤8 条，每条 ≤600 字）
┌──────────────────────────┴──────────────────────────────┐
│ L4  组装层                                                │
│    排序去重 → 补邻居段（让一句话不断章取义）→ 预算裁剪     │
└──────────────────────────▲──────────────────────────────┘
                           │ evidenceId 列表
┌──────────────────────────┴──────────────────────────────┐
│ L3  检索层（双通道）                                       │
│    通道 A：中文语义索引（L2 的中文 gloss）← 主通道         │
│    通道 B：英文原文索引（术语扩展后）   ← 兜底             │
│    路由：领域 → 限定文档/章节范围（不作为答案）             │
└──────────────────────────▲──────────────────────────────┘
                           │
┌──────────────────────────┴──────────────────────────────┐
│ L2  语义层（★ 本次升级的核心，现在完全没有）               │
│    每个证据单元配一条**中文摘要**（≤80 字）+ 中文关键词     │
│    中文摘要只用于"被搜到"，不用于"被当作答案引用"          │
└──────────────────────────▲──────────────────────────────┘
                           │
┌──────────────────────────┴──────────────────────────────┐
│ L1  证据层（现在已有，需要统一成一种东西）                 │
│    证据单元 = 段落(27,911) / 表格行(7,015) / 图(592)      │
│    每个单元：evidenceId + 原文 + 出处面包屑 + 物种标签     │
└──────────────────────────▲──────────────────────────────┘
                           │
┌──────────────────────────┴──────────────────────────────┐
│ L0  归档层（不可变，已有 160 份 / 650MB）                  │
└─────────────────────────────────────────────────────────┘
```

### 关键变化：中间层被拆掉了

| 旧结构 | 新结构 |
|---|---|
| 条目 = 结论（人/模型写的判断） | **不存在这一层** |
| 段落 = 原文 | 证据单元（唯一可引用的东西） |
| — | **中文语义层**（新增，让中文能搜到英文） |

**"结论"这件事整个从知识库里移出去了**——结论应该由模型在读原文之后自己形成，而不是从库里拿一条现成的。

## 四、三个核心设计

### 设计 1：统一证据单元（evidenceId）

现在段落、表格行、图片是三种东西，检索时各走各的路。统一成一种：

```
evidenceId      形如 P:sacn5-40-p00055 / T:T0012:r07 / F:fig-0123
kind            paragraph | table_row | figure
原文            段落正文 / 表格行（含表头映射）/ 图注
中文摘要        ≤80 字（L2 生成）
出处            文档 + 章节 + 页码
物种            犬 / 猫 / 混合
```

**表格行单独成证据**很重要：配方问题问"鸡胸肉的钙是多少"，答案在一行里，不在段落里。

### 设计 2：中文语义层（决定性的一步）

**给每一个证据单元生成一条中文摘要，入库，建索引。**

这样中文问题搜的是中文摘要，命中后拿到的却是英文原文 + 出处。

| 项 | 数值 |
|---|---:|
| 需要生成摘要的证据单元 | 约 **28,500**（27,911 段 + 7,015 行，按需） |
| 每条摘要 | ≤80 字 |
| 生成方式 | 批量调模型，分批跑，可断点续传 |
| 存储 | 与证据单元同表，一列 |

**这是整套架构能不能成立的关键。** 没有它，中文检索命中率是 0（已实测）。

### 设计 3：强制引用 + 校验器

模型回答时必须带 `evidenceId`，返回后过一道机器校验：

| 检查 | 不通过时 |
|---|---|
| ID 存在吗 | 标"引用不可核" |
| 属于这次检索返回的集合吗 | 标"引用越界"（防止模型自己编 ID） |
| 原文含回答里的关键数字/术语吗 | 标"依据不足" |

三道全过，回答才放行；否则降级为"知识库中无依据，建议咨询兽医"。

**没有这道闸，"能查原文"反而更危险**——模型会拿一段不相干的英文，编一个像样的结论。

## 五、旧资产怎么处置

不是全扔，三类分开：

| 资产 | 处置 | 理由 |
|---|---|---|
| **788 条出处锚点** | **保留，升级为"检索种子"** | 它把中文问题连到了具体英文段落，是评估和调优的金标准 |
| **387 条条目的正文** | **移出知识库**，归入"内部经验" | 不作为证据、不可被引用；如要保留，标明"非文献依据" |
| **139 条术语表** | 保留并扩充到 800+ | 作为检索通道 B 的查询扩展 |
| 499 张表 / 592 张图 | 保留，接入证据层 | 表格行是配方问题的主要答案来源 |

**特别说明**：条目里有些内容原文根本没有（比如"零食不超过总热量 10%"）。
这类是团队经验，不是文献结论。新架构给它单独一个位置：**内部规则**，标注"无文献依据"，模型可以说，但**不能当作引用**。

## 六、迁移路线（四阶段，每阶段可独立验收）

| 阶段 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **1** | 统一证据单元 + 建表 | evidence 表，约 28,500 条 | 每段/每行都有 evidenceId |
| **2** | 生成中文摘要 | 28,500 条中文 gloss | 抽 50 条人工看，80% 准确表达原意 |
| **3** | 检索服务 + 组装 | 中文查询能返回 ≤8 条证据 | **中文查询命中率从 0% 提到 ≥80%** |
| **4** | 强制引用 + 校验 + 接 Agent | 回答必须带 evidenceId | 引用通过率、无依据拒答率 |

**阶段 2 是最大工作量**（几万次生成），但它是唯一能解决"中文搜不到英文"的办法。
也可以用向量检索替代部分工作，但**现在库里没有 pgvector**，要额外装。

## 七、怎么证明它变好了

不能靠感觉。要建一个**评估集**：

1. 收集 **100 个真实问题**（营养师/配方设计实际会问的，从历史对话里捞）
2. 每个问题人工标一个"正确答案在哪段"（用现有 788 条锚点起步）
3. 每次改动跑一遍，量三个数：

| 指标 | 含义 | 现状 | 目标 |
|---|---|---:|---:|
| **Recall@8** | 前 8 条证据里有正确那段的比例 | ≈0%（中文搜不到） | ≥80% |
| **引用通过率** | 回答引的段落真的支持结论的比例 | 无此机制 | ≥95% |
| **无依据拒答率** | 库里没有时敢说"没有"的比例 | 无此机制 | ≥90% |

**没有这三个数，"架构升级"就是换个说法。**

## 八、需要你定的一件事

**中文语义层，用哪种方式实现？**

| 方案 | 做法 | 成本 | 效果 |
|---|---|---|---|
| **A. 中文摘要**（推荐） | 给每个证据单元生成中文摘要，存库 | 一次性大（约 28,500 条生成） | 关键词检索就能用，可解释、可人工校对 |
| B. 向量检索 | 装 pgvector，做 embedding | 中等，但要装扩展、维护向量 | 语义匹配更强，但不可解释，错了难排查 |
| A + B | 中文摘要 + 向量 | 最大 | 最好 |

**我的建议是 A 先行**：它是确定性的、可人工抽检的、不依赖新组件；将来要加 B，A 的摘要就是现成的 embedding 输入，不返工。

---

## 九、一句话总结

> 现在的架构是"**人（模型）读原文写摘要，AI 读摘要**"。
> 要改成"**AI 直接读原文，摘要只用来帮它找到原文**"。
>
> 这两者差一个东西：**中文语义层**。它现在是空的，所以架构立不住。
