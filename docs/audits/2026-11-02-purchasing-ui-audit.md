# 小程序「采购管理」UI 全面审核与优化方案

- 审核日期：2026-11-02
- 审核范围：`miniapp/src/pages/staff-purchasing/` 全部 8 个页面（采购首页、采购清单详情、需求预览、创建补货单、添加采购记录、报销列表、报销提交、报销详情）
- 审核方式：
  1. 在微信开发者工具模拟器里逐页走真实数据，截图留证（见文末索引，图存 `mockups/assets/purchasing-ui-2026-11-02/`）
  2. 逐条计算文字与底色的 WCAG 对比度
  3. 通读 8 个页面的模板、样式与格式化函数，核对设计一致性
- 配套视觉稿：`mockups/purchasing-ui-redesign-2026-11-02.html`（现状截图 + 建议界面 1:1 对照）

## 0. 结论摘要

**一句话：能用，但"看不清、找不着、点不准"。** 8 个页面在 9 月那次"员工端统一品牌视觉"的批量改色中被机械替换了文字颜色，造成 **3 处文字与底色完全相同（对比度 1.0，等于看不见）**、**6 处对比度严重不足**。这不是审美问题，是采购员在货架前、仓库里拿着手机实操时会直接卡住的问题。

| # | 问题 | 严重度 | 影响 |
|---|------|--------|------|
| 1 | 文字与底色同色 / 近同色，共 9 处 | 阻断 | 用户看不到选中状态、类型标签、入口文字 |
| 2 | 7 个页面标题显示两遍（系统栏 + 页内大标题） | 严重 | 每页白白占掉约 96pt，接近一屏的 1/8 |
| 3 | 采购清单详情一屏只能看 2 个原料，30 个原料要滑 15 屏 | 严重 | 采购效率低，容易漏买、重复买 |
| 4 | 同一件事重复说三遍（当日状态徽标 + 正文 + 按钮） | 严重 | 信息噪音，关键数字被淹 |
| 5 | 单位/小数写法不统一（561g、148 g、0g、1.924 份…） | 严重 | 看错数量，直接造成多买/少买 |
| 6 | 添加采购记录页输入框与页面同色，看不出哪里能输入 | 阻断 | 新员工不知道点哪里 |
| 7 | 报销详情"需要采购 kg"缺数字 | 严重 | 账目对不上，报销被退回 |
| 8 | 8 个页面 22 个硬编码颜色、16 种圆角、15 种字号，无规范 | 一般 | 改一处坏一处，无法防回归 |

**建议投入：约 6–8 个工作日**，分 4 个阶段。P0（止血，半天）做完，页面就能正常使用；P1（重构首页与详情，2–3 天）解决效率问题；P2（表单与报销，2 天）；P3（建规范防空回归，1–2 天）。

## 2. 阻断级问题（P0：先修这些，半天内可完成）

### UI-01 首页"补货"入口卡：深绿底 + 近黑字，等于没字

- 位置：采购首页，日采卡片下方整块深绿入口
- 样式：背景 `linear-gradient(#1E3A2F → #173026)`，标题与说明却是 `#26261F`
- 对比度：**1.23 : 1 / 1.08 : 1**（可读标准 ≥ 4.5 : 1，大字 ≥ 3 : 1）
- 实测截图：`01-index-marked.jpg`，整块卡只能看到一片深绿，字几乎融进去
- 建议：文字改 `#F3EDDD`（对比度 **10.56 : 1**），副标题 `rgba(243,237,221,.72)`

> 同一页面里"开始采购 / 确认完成"按钮用的正是 `#F3EDDD`——说明原本的设计意图是深绿底配米白字，是批量改色时被误替换。

### UI-02 补货页分类筛选：选中项是一个"黑块"

- 位置：创建补货单 →「选择原料」下的 食材 / 补剂 / 包材
- 样式：`.filter-chip.active { background:#1E3A2F; color:#1E3A2F; }` —— **文字与底色是同一个色值**
- 对比度：**1.0 : 1**
- 实测截图：`05-stock-marked.jpg`，第一个 chip 是纯黑绿色药丸，完全看不出写的是"食材"
- 建议：选中态改为深绿底 + 米白字，或白底 + 深绿描边 + 深绿字

### UI-03 报销提交步骤条：当前步骤看不见

- 位置：提交报销第 1 / 2 / 3 / 4 步顶部
- 样式：`.step-dot.active { color:#1E3A2F; background:#1E3A2F; }`
- 实测截图：`06-submit-marked.jpg`，进入第 2 步后，当前步（第 2 步）是深绿方块、没有文字；只有已完成与未开始的步骤能读到"1 类型 / 3 凭证 / 4 确认"
- 建议：当前步深绿底米白字；已完成步浅绿底深绿字 + ✓；未开始步浅底灰字

### UI-04 报销选单里的"日采 / 补货"类型标签：也是黑块

- 位置：提交报销 → 采购明细，每一张可勾选的采购清单卡片左上角
- 样式：`.purchase-kind { color:#1E3A2F; background:#1E3A2F; }`
- 实测截图：`06-submit-marked.jpg`，每张卡左上角一个黑绿色小方块
- 建议：日采 = 浅金底 `#F6EFE0` + 深金字 `#8A6B33`；补货 = 浅绿底 `#EEF2E4` + 深绿字 `#1E3A2F`

### UI-05 添加采购记录整页：看不出哪里能输入

- 位置：`record-form`（虽然当前没有入口，但一旦恢复入口就会踩坑）
- 问题：页面底色 `#FBFCF7`，输入框、日期选择器、卡片的分区底色**也全是 `#FBFCF7`**，没有边框、没有留白差
  - 结果："原料名称 / 采购商品 / 购买数量 / 付款金额"看起来像四行说明文字
  - 底部"取消"按钮与底栏同色，按钮边界消失；更糟的是原生 `<input>` 会盖在固定底栏之上（小程序原生组件层级更高），"请输入金额"的占位文字直接压到"取消"按钮上
- 实测截图：`04-record-marked.jpg`（`04-record.jpg` 为不带红框原图）
- 建议：输入区给 `#F2F4EA` 浅底 + 1rpx `#E5E8D4` 描边 + 24rpx 圆角；标签在上、输入在下，块与块之间留 24rpx

## 3. 严重问题（P1）

### UI-06 每页标题显示两遍，白占 1/8 屏

系统导航栏写"采购管理"，页面里又是一条金色大标题写"采购管理"；详情页系统栏写"采购清单详情"、页内写"日采清单详情"，**同一个页面两种说法**（系统栏固定写"采购清单详情"，页内按类型写"日采清单详情 / 补货清单详情"）。

- 占用：金色条实测高 143px（≈96pt），加下边距 ≈ 108pt，约占一屏的 12.8%
- 影响：采购首页首屏因此只能露出"日期 + 汇总 + 补货入口"，清单列表完全在屏外
- 建议：二选一，不要并存
  - 方案 A（最快，P0）：删掉页内金色标题条，只留系统导航栏
  - 方案 B（推荐，与「后台订单」等页面统一）：改自定义导航栏——深绿底 `#1E3A2F`、米白标题、高 88rpx，左侧返回；页面内容顶部留同高占位。参考 `staff-orders/index.vue` 已有实现

### UI-07 同一句话重复三遍

"今天"没有订单时，卡片里同时出现：

1. 徽标：`暂无待采购订单`
2. 正文：`暂无待采购订单`
3. 按钮：`暂无待采购订单`（而且是禁用态）

- 实测截图：`02-today-marked.jpg`
- 建议：只保留"标题行（日期 + 状态徽标）+ 一行数据 + 一个动作"。没有数据时，用一句带下一步建议的空态替代三个重复文案，例如：「今天没有待采购订单 · 去补货 →」

### UI-08 清单详情一屏只看 2 个原料

每个原料行现在有 5 层信息 + 右侧竖排 2 个按钮：

```
原料名（常被挤成 2 行）                 参考单价 ¥49.88/500g
[山姆自营] [山姆会员店] [1.2kg/盒]
订单需求 561g | 库存抵扣 561g          仍需采购 0 g
                                      [添加采购记录]
                                      [无需采购]
```

- 实测：30 个原料 → 约 15 屏
- 名称被右侧按钮挤压换行（"MM澳洲 / 谷饲牛霖"），信息密度不均
- 建议（详见视觉稿第 2 屏）：
  - 行结构改为 **两行 + 一个动作**：第一行"名称 … 仍需采购 **148 g**"（数字 40rpx 加粗），第二行"渠道 · 规格 · 参考单价"（单行省略），右侧只放一个"记录"按钮
  - 订单需求 / 库存抵扣收进可展开的"明细"，默认收起
  - 仍需采购 = 0 的行自动归入底部折叠区「库存已覆盖 7 项」

### UI-09 "仍需采购 0" 和 "仍需采购 148" 一样显眼

现在两者字号、字重、颜色完全一致，采购员需要逐行读数字才能判断该买什么。

- 建议：`> 0` 用金色大号数字（`#8A6B33`，40rpx，加粗）；`= 0` 用灰色小字"库存已覆盖"，并降低整行对比度

### UI-10 单位与小数写法不统一（会看错数量）

同一屏内实测出现的写法：

| 写法 | 出现位置 |
|------|----------|
| `561g` | 详情「订单需求 / 库存抵扣」 |
| `148 g` | 详情「仍需采购」 |
| `0g` | 记录弹窗「仍需采购」 |
| `7.5ml` | 详情（小麦胚芽油） |
| `0.158kg` | 报销详情 |
| `100.00 g` / `1.00 瓶` | 补货建议 |
| `1.924 份` | 补货建议（3 位小数） |
| `¥15.00/500 g` | 报销详情（被断行） |

- 根因：`formatQuantity` 返回纯数字、单位由模板另一个 `<text>` 渲染（中间靠 flex gap 产生空格），而 `formatResolvedQuantity` 是字符串拼接（无空格）；补货、报销又各有一套
- 建议：全模块只留一个格式化函数：拉丁单位加空格（`148 g`、`7.5 ml`），中文单位不加（`2 瓶`、`1 份`），小数统一最多 2 位（g 取整、ml 1 位、金额 2 位），数字与单位整体 `white-space: nowrap`

### UI-11 报销详情"需要采购 kg"缺数字

- 截图：`07-reimb-detail-marked.jpg`（高山本地胡萝卜这张卡）
- 原因：`formatNeededQuantity()` 在数量 ≤ 0 时 `return unit || '-'`，于是只剩一个"kg"
- 建议：数量为 0 时显示 `—` 或 `0 g`，**绝不能只显示单位**；同时补一条展示层单元测试

### UI-12 报销明细窄列断行，数字被拆开

`上次折算单价 ¥15.00/500` + 换行 + `g`；`需要采购 0.158kg` 与 `实际采购 1g x 230g` 两种写法混排。

- 建议：值列 `min-width` 加宽到 40%，数字 `font-variant-numeric: tabular-nums`，单位不换行；6 项指标由 3×2 改 2×3（标签在上、值在下），或改成 4 项主指标 + 2 项次要灰字

### UI-13 固定底栏与安全区

- 8 个页面只有创建补货单用了 `env(safe-area-inset-bottom)`；其余底栏固定 24rpx 内边距，在带 Home 指示条的机型上按钮贴着横条
- 记录页首屏"付款金额"输入框被底栏压住一半（`04-record-marked.jpg`）；因为原生 `<input>` 层级高于普通视图，输入框的占位文字会直接盖在底栏按钮上
- 补货页原料卡底部被"预估总额"栏压住（`05-stock-marked.jpg`）
- 建议：抽出统一 `<BottomActionBar>`：`padding: 20rpx 32rpx calc(20rpx + env(safe-area-inset-bottom))`；页面内容 `padding-bottom: calc(160rpx + env(safe-area-inset-bottom))`；输入框获得焦点时用 `pageScrollTo` 把它滚到底栏之上

### UI-14 金额一律用红色

报销列表、报销详情、清单列表、清单详情的金额都是 `#B4553F`。但在同一套系统里，红色还表示"删除清单 / 清空凭证 / 已驳回"。

- 影响：红色失去警示含义；财务金额看起来像"异常"
- 建议：金额常态用深绿 `#1E3A2F` 或墨色 `#26261F` + 等宽数字；红色只留给"驳回 / 超支 / 删除"

### UI-15 补货列表整屏粉色

只要库存状态是"需要补货"，卡片就是 `#F8E8E2` 粉底 + 红描边。实际业务里大部分行都需要补货，于是整屏都是警示色。

- 建议：卡片常态用白底；需要补货用 **左侧 8rpx 红色竖条 + 一个状态点**，低库存用金色竖条；只在真正异常（如负库存）时才整卡染色

## 5. 信息架构与流程问题

### 5.1 首页把两件事塞进了一屏

首页同时承担「日采」和「补货入口」两件事，而"补货"其实是一个完整的二级流程（选日期 → 载入建议 → 勾原料 → 创建清单）。现在的做法是：一大块日采区 + 一条深绿补货卡 + 一大块清单列表。

**建议结构（从上到下）**

1. 导航栏（深绿，标题"采购管理"，右侧可放"报销"入口）
2. **日期条**（横向滑动）：今天 / 明天 / 后天 / 其他日期；每项两行：日期 + 状态点（待生成 / 已有清单 / 无订单）
3. **当日行动卡**：一行数据（2 单 · 30 种原料 · 预估 ¥30.90）+ 主按钮（生成 / 查看 / 合并）。状态只出现一次
4. **两个快捷入口并排**：补货（深绿）、报销（描边）
5. **清单列表**：分段控件（全部 / 待采购 / 已完成）+ 可折叠筛选；卡片三行制（标题 / 数字 / 动作），一屏约 3 张

这样首屏可见内容从"日期 + 汇总 + 一条看不见字的入口"提升到"日期 + 行动 + 两个入口 + 约 2.5 张清单卡"。

### 5.2 详情页缺少"进度感"

采购员最关心三件事：**还要买什么、已经录了多少、多少钱**。现在这三件事散落在：底部按钮、状态卡、每行的"仍需采购"里。

建议在详情页顶部做一条**吸顶汇总条**：`11月3日 · 待采购 · 已录 6/30 · ¥106.44`，滚动时始终可见；底部操作栏左侧同步显示进度。

### 5.3 记录流程的两套实现

弹窗版与整页版字段相同、控件不同。整页版已无任何入口（`grep` 全仓只有 `pages.json` 与备份文件引用）。建议删除整页版，弹窗版补齐：
- 选择控件统一为单选圆点（未选中为空圈）
- 数量输入框右侧固定单位，下方实时显示"折合 ¥xx / 500g、比上次 +x%"
- 提交按钮给明确的禁用条件（数量或金额为空时不可点）

## 8. 验收标准

**可读性**
- [ ] 所有正文文字对比度 ≥ 4.5 : 1；≥ 32rpx 加粗文字 ≥ 3 : 1
- [ ] 不存在 `color` 与 `background` 相同的规则
- [ ] 最小字号 ≥ 24rpx，且 24rpx 只用于辅助说明
- [ ] 状态不能只靠颜色区分（至少有文字或图标）

**布局**
- [ ] 所有固定底栏含 `env(safe-area-inset-bottom)`，内容区留出等高空白
- [ ] 375 / 430 两种宽度下无横向溢出、无文字被按钮挤压换行
- [ ] 商品长名称单行省略（`text-overflow: ellipsis`），不把价格挤走
- [ ] 数字与单位不断行（`white-space: nowrap`）

**效率**
- [ ] 采购员完成"选日期 → 生成清单 → 录 10 条记录 → 完成"全程 ≤ 4 分钟（建议在 P1 前后各实测一次，作为基线）
- [ ] 详情页 30 项首屏可见 ≥ 6 项
- [ ] 首页到"继续采购"1 次点击

**一致性**
- [ ] 8 个页面使用同一套导航、状态徽标、空态、底栏
- [ ] 数量/单位/金额格式全模块一致
- [ ] 页面标题不再与系统导航栏重复
