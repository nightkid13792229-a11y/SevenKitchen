# Agent 知识库观测与分阶段执行方案

**日期**：2026-11-04
**状态**：阶段 1、2 已验收；阶段 3 核心通过（2026-11-08），保留低排名残余噪声
**目标**：先观察 Agent 真实怎么用知识库，再逐步加“目标提案、引用、元数据过滤”；不用规则表、不加健康条件字段、测试期不加无进展保护。

---

## 一、已确认的原则

1. **判断交给模型/Agent**：不建“健康条件”字段，不维护“疾病-营养素目标规则表”。
2. **测试期不加硬约束**：不做无进展保护、不做阶段预算；保留 60 次硬上限 + 完整日志。
3. **引用先观察、后强制**：阶段 1 只记录引用覆盖率，不拦截；稳定后再切强制。
4. **知识库只给原文**：不返回结论；引用必须能回到来源/章节/页码。
5. **阶段推进**：每个阶段一个工位、一个分支、一次部署、一份报告；上一阶段没看清，不进入下一阶段。

## 三、阶段 1：引用观察 + 缺口软提醒

### 目标

不改变模型判断，只回答两个问题：

1. 给了引用编号后，模型会不会在最终答案里引用？
2. 出现缺口后，它会不会先查知识库？

### 要做的事

1. **检索结果带短引用编号**
   - 每段原文返回 `citationId`（如 `K1`），同一次运行内唯一；
   - 同时带 `sourceId / sourceName / sectionTitle / pageStart`；
   - 同一次运行里重复出现的同一段，复用同一个编号；
   - 工具结果保留编号到来源/页码的映射，供校验使用。

2. **提示词要求最终答案引用**
   - 最终答案里的数值/结论后写 `[K1]`；
   - 中间过程（“我先查一下”）不要求；
   - 不强制、不拦截，只记录。

3. **观察式校验**
   - 解析最终答案中的 `[K#]`；
   - 检查编号是否在本次运行的检索结果里、页码是否一致；
   - **只记录，不阻断**；
   - 输出：引用覆盖率、无效引用数、无引用数值数。

4. **`assess` 缺口软提醒**
   - 缺口摘要追加一句：
     > 若该营养素受当前疾病影响，先查原文确认目标，再改配方。
   - 只是提醒，不阻止直接编辑。

### 测试场景（3 个）

1. CKD 2 期，血磷 5.2；
2. CKD 4 期，食欲差、体重下降；
3. CKD 2 期 + UPC 1.2 + 血压偏高。

每个场景记录：

- 最终答案引用覆盖率；
- 出现缺口后是否先查知识库；
- 工具调用次数、token、耗时；
- 是否为了满足成犬下限去加磷；
- 是否出现“膳食磷/血清磷”混用。

### 验收

- 产出一份 3 场景基线报告；
- 不改变评估标准、不加硬拦截；
- 能明确回答“引用有没有、缺口后查不查”。

### 不做

- 不做引用强制；
- 不做目标覆盖；
- 不做元数据过滤；
- 不做无进展保护。

## 四、阶段 2：Agent 目标提案 + 评估覆盖

**前置**：阶段 1 报告完成，确认模型在有无引用/软提醒下的真实行为。

### 目标

解决“CKD 要低磷，但成犬评估下限要求补磷”的冲突，不建规则表、不加健康条件字段。

### 要做的事

1. Agent 在读完知识库后，生成一份**本次目标提案**：
   - 营养素、下限/上限、单位、依据引用编号；
   - 例如：磷 0.2–0.5% DM，来源 `K1`；
   - 只对本次配方有效，不落库、不长期维护。
2. 评估引擎接受一组**通用覆盖值**：
   - 有提案 → 用提案值；
   - 无提案 → 用 FEDIAF 基线；
   - 每个覆盖值必须有有效引用，否则不生效。
3. 界面显示“本次评估使用的目标 + 来源”，让用户能看懂为什么不是成犬下限。
4. 不做疾病判断逻辑；疾病和受影响营养素由 Agent 自己判断。

### 验收

- CKD 2 期不再为了满足成犬磷下限去加磷；
- 3 个 CKD 场景评估能按提案通过；
- 每个覆盖值能回到来源/页码；
- 非 CKD 配方行为不变。

## 五、阶段 3：CKD 章节级元数据过滤

**前置**：阶段 1/2 稳定，检索噪声仍是主要问题时再做。

### 目标

解决“查 Stage 2 犬血磷，返回猫病例/血压段落”的噪声。

### 要做的事

1. 先只做 CKD 的 5 份文档；
2. 建章节级索引：
   - 文档：来源、类型、年份、物种、范围；
   - 章节：标题、页码、主题标签、物种、分期；
   - 段落：继承章节标签 + 表格/图片标记。
3. 检索工具支持过滤：
   - `species`、`stage`、`topic`、`documentIds`、`sectionIds`；
   - 先过滤，再打分。
4. 主题/物种/分期用规则 + 模型抽取 + 人工抽查；不维护全库大表。

### 验收

- 查“IRIS Stage 2 犬 血磷”，前 5 段没有猫病例、没有血压段落；
- 噪声 <10%；
- CKD 5 份文档先通过，再考虑扩全库。

## 九、阶段 2 验收结果（2026-11-08）

**场景**：CKD 2 期，血磷 5.2；按 CKD 目标评估，不按健康成犬下限补磷。

**最终评估**：

| 项 | 结果 |
|---|---|
| isCompliant | true |
| 达标 / 缺 / 超 / 缺数据 | 39 / 0 / 0 / 0 |
| 目标覆盖 | 磷 DM 0.2–0.5，引用 K11 |
| 配方磷 | 约 0.635 g，约 0.29% DM |
| 是否按成犬 0.3% 下限补磷 | 否 |
| 引用门禁 | passed=true |
| 语义裁判 | 7/7 supported，0 partial，0 unsupported |
| 未引用临床结论 | 0 |

**修复的两个实现问题**：

1. FEDIAF 同一营养素有多口径（每 1000 kcal / 每 MJ / 每 100g DM）；覆盖只改第一条会残留旧口径。现在覆盖按营养素收敛到单一 basis。
2. Agent 评估结果只有 `overallStatus`，但 `RecipeDraftPort` 读 `assessment.isCompliant`，导致 gaps 清零仍返回 false。现在按 `overallStatus === 'COMPLIANT'` 映射。

**阶段 2 验收：通过。**

## 十、阶段 3 验收结果（2026-11-08）

**场景**：新草稿，CKD 2 期犬，血磷 5.2，查磷推荐范围。

**检索入参**：

- `species: dog`
- `stage: 2`
- `topics: ["phosphorus", "staging"]`

**返回结果**：

- 前 3 段均为 **IRIS Stage 2 Canine patients p10** 的磷目标/限磷措施；
- 没有血压段落；
- 第 7 段仍有一条猫病例（`Same cat after antihypertensive treatment`），原因是章节标题是犬、正文提到猫，被识别成“犬猫都有”；
- 第二次追问的 query 没带 `stage`，返回了 Stage 4 段落；这是模型 query 选择，不是过滤器失效。

**结论**：

- 过滤和精确分期优先已生效，前 3 段正确；
- 残余噪声在低排名，模型可忽略；
- 不再为单条猫病例增加硬编码规则，避免又回到维护关联；
- 阶段 3 **核心通过**，残余噪声作为已知限制记录。

**附带发现**：这次引用门禁 `passed:false`，2 条未引用（“5.2 高于 4.6”和标题），属于引用覆盖问题，不是检索噪声；不影响阶段 3 的检索结论。
