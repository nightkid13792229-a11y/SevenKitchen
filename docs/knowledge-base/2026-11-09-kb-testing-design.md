# 知识库测试完整设计方案（v2，收缩版）

**日期**：2026-11-10
**状态**：v2 设计稿（按独立审查 P0 修正）
**适用范围**：SevenKitchen 知识库 v1（CKD）测试与后续病种批次门禁
**一句话**：v1 只证明三件事——**26 题守底线、5 个 CKD 真实 Agent 场景能用、生产只读冒烟能对上**；其他病种放到批次扩展，不混进 v1。

---

## 0. 这版设计证明什么、不证明什么

### 证明

1. 库是对的：原文/节/段/表/引用锚点没有错位，Stage 3、表格、中文、负样本没有退化；
2. Agent 用得对：真实模型会先查库、会开表、会引用、查不到会说没有、不越界给诊断/剂量；
3. 生产对得上：生产数据存在、核心表能开、代表性 CKD 证据能回源。

### 不证明

- 不证明胰腺炎/骨关节炎/髌骨脱位的 Agent 行为（这些是 v2 批次，需先开范围）；
- 不证明全库 26 题生产全量（生产只做只读冒烟）；
- 不证明长期延迟 SLA（现有生产 336ms/1002ms，先记录基线，不设硬门）；
- 不证明临床结论正确（临床正确性由内容 owner 审阅）；
- 不证明 UI/小程序/后台。

## 1. 目标与原则

### 1.1 目标

| # | 目标 | 对应层 |
|---|---|---|
| T1 | 库是对的 | L0 + L1 |
| T2 | Agent 用得对 | L2 |
| T3 | 生产对得上 | L3 |
| T4 | 扩病种有门槛 | B（批次门禁，非 v1） |

### 1.2 原则

1. **分层，不混测**：数据 / 检索+工具 / 真实 Agent / 生产，四层分开；失败能定位。
2. **测试资产不在运行时**：26 题、Agent 场景、期望章节都不进提示词、不进工具返回、不加载到知识库服务。
3. **金标准是「证据位置」**：期望命中哪一节/哪张表，不让模型背结论。
4. **负样本与正样本同等重要**：查不到说没有，比多对一道题值钱。
5. **比例适度**：26 题 + 5 个 CKD Agent 场景 + 2 个辅助场景；不做 500 题、不每次 PR 跑模型。
6. **生产只读**：生产测试不写草稿/订单/数据；Agent 测试在本地/测试账号跑。
7. **不许假绿**：负样本、禁止节、open 失败、无 DB skip、空回答，都要显式失败或标注。
8. **谁改谁跑**：改检索/工具/prompt 的人跑对应层；批次扩展由内容 owner 签字。

## 2. 被测对象与范围

### 2.1 被测对象

```
L0 数据层：source_document / section / paragraph / table / figure / citation anchor
L1 检索+工具层：KnowledgeLibraryService + SourceLayerService + Agent 工具（search/open/scope/search_knowledge）
L2 真实 Agent：配方 Agent（真实模型 + 多轮 + 引用门禁）、补剂 Agent（独立）
L3 生产：生产库数据、只读冒烟、usage 观测
B  病种批次：v2 的扩展开关（胰腺炎/骨关节炎/髌骨脱位…）
```

### 2.2 v1 范围

- 配方 Agent：**CKD 5 份**；
- 补剂 Agent：**全库关键词检索**（单独 3 查询 + 不可用分支）；
- 健康分析 387 条结论：**不在 v1 测试范围**，只做一次“与原文层数值一致性”抽查（不计门禁）。

## 3. 测试分层与门禁

| 层 | 测什么 | 怎么测 | 什么时候跑 | 成本 | Owner |
|---|---|---|---|---|---|
| **L0 数据完整性** | 文档/节/段/表/图数量、ID、页码、表结构、导入幂等 | 只读脚本 + 单测 | 每次导入/迁移后 | 低 | 工程 |
| **L1 检索+工具** | 26 题 recall、负样本、中文、表格、空范围、CKD 范围 | `kb:eval` + `kb:smoke`（无 LLM） | 每次改检索/工具；合并前 | 低 | 工程 |
| **L2 真实 Agent** | 真实模型是否先查库、开表、引用、no-match、不越界 | 受控 Agent 会话 + 引用审计 + 人工复核 | 每次改 prompt/工具/换模型；每周 | 中（模型费） | 工程 + 内容 |
| **L3 生产** | 数据存在性、核心表、代表性 CKD 证据 | `kb:prod-smoke`（只读）+ `kb:usage` | 部署后 / 每周 | 低 | 工程 |
| **B 批次门禁** | 新病种证据/物种/分期/边界 | 每批 8–10 题 + 3–5 Agent 场景（边界批 2 场景） | 开新批次前 | 中 | 内容 + 工程 |

**硬规则**：L0/L1 不过，不跑 L2；L2 不过，不扩病种；L3 冒烟不过，先回滚/降级。

## 5. L2 怎么跑（真实 Agent）

### 5.1 入口

- 本地后端 + 本地库；
- 测试账号：staff actor，`userId` 用 `kb-eval-<runId>` 前缀；
- **每个场景新建一个草稿**，不要复用草稿：`RecipeAgentService.start` 会复用该草稿最近 session，复用会串会话/K 号；
- 调 `POST /api/v1/recipe-designer/drafts/:draftId/agent/runs`，body `{ message }`；
- 轮询 `GET /api/v1/recipe-designer/drafts/:draftId/agent/session`，直到 `status` 为 `DONE` / `FAILED` / `WAITING_USER` / `STOPPED`；
- 轨迹：`session.messages`（含 TOOL 行 `toolName/toolArgs/toolResult`）；
- 引用审计：`session.citationAudit`（`gate`、`semantic`、`rewrite`）；
- 预算：单场景 ≤80 次工具调用、≤6 分钟；超限判失败并停止，不继续烧 token。

### 5.2 防假绿（硬规则）

1. 答案非空、有实质内容；空回答/拒答不算通过；
2. 每个场景有 `expectedSections` / `expectedTables` / `requiredElements`；
3. 有效引用 ≥2（S5 负样本除外）；
4. 数值行 100% 带 K；
5. `citationAudit.gate.passed === true`；
6. `semantic.unsupported === 0`；
7. 不给药物剂量/诊断（S3 单独检查）；
8. 出现「未覆盖」时，必须是真实 `no_match`，不是模型偷懒。

### 5.3 隔离与清理

- 测试草稿/会话/消息按 `createdBy='kb-eval-*'` 和测试草稿 ID 标记；
- 跑完删除测试草稿/会话/消息（或使用独立测试库）；
- `kb:usage` 统计时排除 `createdBy LIKE 'kb-eval-%'`；
- 生产不跑 L2；生产只跑 L3 只读冒烟。

## 8. 执行节奏、CI、回滚

| 触发 | 跑什么 |
|---|---|
| 改检索/工具 | L1 26 题 + 单测 + `kb:smoke` |
| 改 prompt/换模型 | L2 5+2 场景 + 引用审计 |
| 合并前 | L1 26/26、目标测试、tsc 基线、`kb:eval --no-write` |
| 每周 | L2 抽 1–2 场景 + L3 usage 周报 |
| 部署后 | L3 只读冒烟 |
| 批次扩展前 | B 门禁（见 §10） |

**CI**：

- 单测/判分：每次 PR；
- `kb:eval`：有 DB 的 CI 跑；无 DB 只跑判分单测，报告标注「未跑真实库」；
- L2：不进 PR CI，按周/按需手动；
- L3：部署后手动/脚本。

**回滚触发**：

- L1 关键项退化（Stage 3/表格/负样本）；
- L2 引用无效/unsupported >0/串物种或分期；
- L3 数据计数或核心表失败；
- 回滚操作：回退到上一个部署 commit，重新部署后端；记录事故。

## 9. 角色与失败归因

| 角色 | 负责 |
|---|---|
| 内容 owner（兽医/营养师） | 定义问题、确认期望证据、审阅覆盖说明、抽检 L2 |
| 测试 owner（工程） | 维护 26 题/场景、跑 L1/L2、出报告、修脚本 |
| 模型 owner（工程） | 模型配置、prompt/工具变更、失败归因 |
| 发布 owner | 合并/部署门禁、生产冒烟、回滚 |

**失败归因顺序**：数据 → 检索 → 工具 → Agent（prompt/模型）→ 内容缺口。

**人工复核抽样**：L2 每次至少 1 个场景由内容 owner 看答案；批次验收全部看。

**不允许**：改期望/降门槛让测试变绿；只有内容 owner 确认“原期望不合理”才改题并记录。

## 10. 批次扩展设计（B，v2；不进 v1 实施）

### 10.1 批次启用前置（产品/代码改动，需排期）

- 批次配置：文档 ID、来源 ID、核心表 ID、期望题集；
- 工具 scope：`CKD_DOCUMENT_IDS` / `CKD_SOURCE_IDS` 改为按批次配置；非本批 documentIds 仍 OUT_OF_SCOPE；
- 目录：`loadCkdCatalog` 只认 CKD，需按批次建目录（或至少 section 级检索可用）；
- 输出：`evaluate-library.ts` 加 `--out-dir`，批次报告不覆盖 CKD 的 `library-evaluation.md`；
- 核心表：`CORE_TABLE_IDS` 按批次配置；
- prompt/工具描述：加批次示例，不改全局原则。

### 10.2 批次类型

| 类型 | 适用 | 资产 | 通过线 |
|---|---|---|---|
| **正向批次** | 胰腺炎、骨关节炎 | 8–10 题 + 3–5 Agent 场景 | L1 ≥90% + 场景 3–5/5 + 引用有效 100% |
| **边界批次** | 髌骨脱位（仅 3 段） | 2 个 Agent 场景，不套 8–10 题 | 明确「没有针对性证据」+ 不编造 + 转兽医/体重管理 |

### 10.3 具体批次（建议顺序）

1. **胰腺炎**（正向）：SACN5 第 67 章犬 89 段；ACVIM 2021 猫共识 145 段作为物种对抗；
   - 4 个正向场景 + 1 个猫/犬对抗 + 1 个“不给酶制剂剂量”负样本；
   - 期望：犬证据优先，不拿猫共识当犬证据。
2. **骨关节炎/DJD**（正向）：SACN5-34 97 段、AAHA 疼痛 29 段、WSAVA DJD；
   - 3 个场景：体重、omega-3、疼痛/活动。
3. **髌骨脱位**（边界）：2 个场景；
   - 期望：明确“针对性营养证据不足”，按体重/关节管理并转兽医，不编手术/分级/剂量。

### 10.4 批次放行

- 内容 owner 签字（覆盖说明）；
- L0 数据完整性；
- L1 批次题通过；
- L2 批次场景通过；
- L3 生产只读冒烟（批次数据存在、代表表可开）；
- 报告归档；不过就停在当前批次。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 26 题过拟合 | 每批新增题；期望来自原文；定期抽换 10% |
| 模型不确定 | 固定模型/温度；关键场景重复 2 次；记录配置 |
| 空回答假绿 | 必答要素 + 有效引用 ≥2 + gate.passed + 数值行覆盖 |
| 测试成本高 | L2 按周/按需，不进 PR；单场景 ≤80 调用/6 分钟 |
| 生产与本地差异 | L3 只读冒烟 + 记录延迟；不把本地 26/26 当生产 |
| 金标准过期 | 原文更新同步改题；题集带日期/版本 |
| 假绿 | 负样本/禁止节/open 失败/无 DB skip 显式失败或标注 |
| 387 条结论与原文不一致 | 一次性数值抽样；不混入配方 Agent 测试 |
| 扩库失控 | 批次门禁；不按文档数扩 |
| 测试会话污染 | 每场景新草稿；`kb-eval-*` 标记；跑完清理；usage 排除 |

## 12. 非目标（再强调）

- 不做 500 题大题库；
- 不每次 PR 跑真实模型；
- 不做临床正确性自动裁判；
- 不测试 UI；
- 不把测试资产放进知识库运行时；
- 不一次性扩全库；
- 不用“测试全绿”代替内容 owner 审阅；
- v1 不证明胰腺炎/骨关节炎/髌骨脱位，也不证明生产长期延迟 SLA。
