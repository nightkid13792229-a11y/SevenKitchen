## 0. 一页纸结论

**一句话：内容底子是 8 分，但「给 Agent 用的服务」目前只有 4.5 分。CKD 试点证明了「原文 + 页码 + 引用」这条路走得通，但没有证明「章节元数据过滤」可靠——而后者恰恰是这次结构设计里最容易被误认为已经完成的部分。**

给老板看的五句话：

1. **最严重的问题不是「查不到」，而是「查到了却被系统自己藏起来」。** CKD 3 期的治疗内容明明在库里，但因为章节标签写成了「2 期」，Agent 一旦按 3 期筛选，这段证据会被**硬过滤掉**。14 个验收问题里没有 3 期，所以 14/14 没发现。
2. **最重要的数字在表格里，而 Agent 打不开表格。** CKD 5 份文档有 23 张表，包括 IRIS 分期表、SACN5 表 37-9「犬猫 CKD 关键营养因子」；检索只搜正文段落，表格对 Agent 不存在。
3. **「全库检索」这个选项实际是坏的。** 我实测一个常见的 CKD 查询在全库里有 11,973 段命中，但候选池按文档编号只取前 1,000 段，来自 16 份文档，SACN5 和 IRIS 一段都没进候选池。
4. **元数据是自动生成的，没人复核，而且有明显误判。** 78 个章节里 67 个标成「犬猫都有」、只有 6 个标了分期；「铁」在目录里覆盖 25 节，而正文真正出现 iron 的 17 节里，有 13 节其实只是出现了英文单词 environment。
5. **现在扩全库，会把上面这些错误放大 78 倍。** 所以「暂不扩全库」的判断是对的，但放行的门槛不能是「CKD 14/14」，而应该是「元数据人工确认 + 金标准题集 + 回归机制」。

评分（10 分制，仅代表「Agent 能不能用」）：

| 维度 | 分数 | 说明 |
|---|---:|---|
| 内容与出处纪律 | 8.0 | 387 条 100% 有结构化来源；原文有稳定 ID、页码；这是真资产 |
| 可检索性 | 5.0 | 关键词检索能命中，但候选池、排序、去重、分页都不适合 Agent |

| 评测与观测 | 3.0 | 14 题、12 个章节、8/14 题前三名存在同节重复；无 CI、无检索日志汇总 |

## 1. 评审口径：什么叫「为 Agent 调用服务」

Agent 和人的用法不一样。人打开知识库，可以翻目录、看上下文、自己判断「这段是不是我要的」；Agent 只有三样东西：**一次工具调用的返回、有限的上下文、有限的调用次数**。所以「为 Agent 服务」不是「把资料整理好」，而是满足六个测试：

| # | 测试 | 具体含义 | 不满足会怎样 |
|---|---|---|---|
| 1 | **看得见** | Agent 在提问前能知道「库里有没有这类问题、覆盖到哪」 | 问一个库里没有的问题，然后编答案或反复换词 |
| 2 | **找得到** | 一次调用能拿到真正回答问题的证据，而不是关键词碰巧出现的段落 | 多轮试错、token 浪费、答非所问 |
| 3 | **打得开** | 能顺着引用打开整节、表格、上下文，而不是只看到 900 字截断 | 看到「见表 37-9」却打不开表；证据链断 |
| 4 | **说得清** | 每条结论能回到「哪份文件、哪一页、哪一段/哪一格」，且版本可查 | 引用看起来有，实际对不上；无法追责 |
| 5 | **错得明** | 查不到时明确说「没覆盖」，而不是「换个关键词再试」 | 模型把「没查到」当成「再想想」，开始自由发挥 |
| 6 | **管得住** | 元数据谁确认、评测怎么跑、版本怎么换、回归怎么防 | 改一处坏一片，且没人知道 |

这六条就是后文所有判断的尺子。**不是「资料够不够多」，而是「Agent 能不能可靠地拿到并引用」。**

### 1.1 名词速查（给非技术读者）

| 名词 | 在这份报告里的意思 |
|---|---|
| 证据单元 | 一节只讲一个问题的原文，比如「Stage 3 的治疗建议」；检索和引用都以它为单位 |
| 硬过滤 | 不满足条件的章节直接不返回；和「排序时降权」不同，硬过滤会让证据彻底消失 |
| 候选池 | 检索第一步先捞出来、再打分的那些段落；池子选错，后面排序再好也没用 |
| 元数据 | 贴在章节上的标签：讲什么、犬还是猫、几期、什么类型；不是临床结论 |
| 覆盖矩阵 | 「哪类问题 × 哪个来源」有没有答案的表格，替代按关键词数章节 |
| 金标准集 | 一批人工确认过正确答案的测试题，用来判断改动是变好还是变坏 |
| recall@3 | 正确答案出现在前 3 条里的比例；衡量「找得到」 |
| BM25 / tsvector / trigram | 三种检索技术：按词频和相关度排序 / 英文全文索引 / 中文按片段匹配 |
| 双轨 | 新旧两套检索并行跑一段时间，用同一套题对比，达标再切换 |

## 2. 现状：三层资产、三条调用链

### 2.1 三层结构

```
来源登记（38 个来源 ID；原文层实际挂到 29 个）
   │
   ▼
原文层（Postgres 6 张表，含出处锚点）
  159 份文档 / 6,090 个章节 / 27,902 段 / 499 张表 / 592 张图
   │                    │
   │                    └── CKD 章节目录（78 节，自动生成元数据）
   ▼
结论层（387 条，写在 TypeScript 里）
   │
   ├── 配方 Agent：只读原文（search_knowledge_library），不读结论
   ├── 补剂 Agent：读另一份语料（chunks.jsonl，20,658 块）
   └── 健康分析：按标签注入结论（7 个方面各 6 条，最多 42 条）
```

### 2.2 三条调用链对比

| 链路 | 谁在用 | 知识来源 | 检索方式 | 模型看到什么 | 引用粒度 |
|---|---|---|---|---|---|
| 配方 Agent | 食谱设计 | Postgres 原文层（默认只 CKD 5 份） | 关键词 `contains` + 应用层打分 | 段落原文 + 来源/章节/页码 + K 号 | 段落 + 页码 |
| 补剂 Agent | 补剂档案 | `chunks.jsonl`（20,658 块，17MB） | 内存关键词打分 | 块原文 + 文档名 + 块号 | 块，**无页码** |
| 健康分析 | 顾客/营养师健康报告 | 387 条结论 | 标签精确匹配 + 关键词补充 | 条目摘要/要点/注意/出处名 | 条目 + 出处文字 |

### 2.3 值得保留的五件事（评审不是推倒重来）

1. **「只给原文、不喂结论」的原则是对的。** 配方 Agent 不读 387 条结论，避免了「结论过期但没人发现」；也让模型必须自己看证据。
2. **出处纪律是真的。** 387 条 100% 有结构化来源和复核日期；原文有稳定 ID 和页码；引用能回到段落。
3. **拒绝建「疾病—营养素规则表」是对的。** 疾病和受影响营养素由模型判断，系统不写死规则；这条边界要守住。
4. **「暂不扩全库」的判断是对的**（理由后文会改写）：不是省钱，而是现在的元数据和评测撑不住 78 倍放大。
5. **引用门禁 + 语义裁判 + 重写**这条链路已经跑通（2026-11-08 验收），是后面所有评测的基础设施。

## 3. CKD 试点证明了什么、没证明什么

| 试点证明了 | 试点**没有**证明 |
|---|---|
| 原文段落能按关键词找到，前 3 段能命中预期章节（14/14） | 元数据在**没测过的章节**上是对的（78 节里只有 12 节被期望命中，66 节从未验证） |
| 物种/分期/主题过滤能生效（Stage 2 场景前 3 段正确） | 过滤在**跨分期章节**上是对的（Stage 3 内容被标成 Stage 2，且被硬过滤掉） |
| 引用编号、引用门禁、语义裁判能跑通 | 数字类问题能**从表格**拿到证据（表格对 Agent 不可见） |
| 「不扩全库」在成本上合理 | 「全库检索」这个工具选项能工作（实测候选池截断，SACN5/IRIS 全部缺席） |
| 目录/覆盖地图能自动生成 | 覆盖地图统计的是「提到过」，不是「讲清楚了」（且主题有假阳性） |

**一句话：试点证明的是「能查到」，不是「查得准、查得全、查得可靠」。** 这两件事在 Agent 场景里差得很远。

## 4. 十项发现（按对 Agent 的影响排序）

### F1（P0）分期硬过滤会把正确证据藏起来：Stage 3 是现成的反例

**事实：**

- IRIS 犬治疗建议文档里，「Stage 3」的治疗内容在 `s005` 这一节里，标题却是「Additional recommendations for **Stage 2** patients aimed at improving quality of life」；这一节有 59 段、跨 p10–p17，其中 p11 开始就是「Stage 3 Canine patients:」。
- 章节目录给 `s005` 的分期标签是 `[2]`（因为只从标题里识别分期）。
- 检索的 `stage` 过滤是**硬过滤**：章节有分期标签且不包含目标分期，就整节排除。
- 结果：Agent 问「CKD 犬 Stage 3 血磷目标」，`s005` 被排除；而 `s005` 是这 5 份文档里**唯一成段的** Stage 3 治疗内容来源。Stage 3 相关段落共 19 段，其中 6 段（31%）被这条规则藏掉。
- 14 个验收问题里**没有 Stage 3**，所以 14/14 全过，问题没暴露。

**对 Agent 的影响：**

- 它按 3 期查，拿到的是 SACN5/AAHA 的通用营养目标，可能错过 IRIS 的「Stage 3 治疗后血磷目标 <1.6 mmol/l（5.0 mg/dl）」这类分期特异结论。
- 更糟的是它不知道自己被过滤了——工具只返回「没找到」或别的内容，不会说「我因为分期标签排除了 3 节」。
- 这条错误在扩全库后会复制成「每个跨分期章节都可能藏错」的系统性风险。

**改法（详见 6.6）：**

- 分期标签从「单值」改成「范围/列表」（`s005` 应为 2–3 期），或改成「本节的适用分期」由人确认。
- **未确认的元数据只能影响排序，不能做硬排除**；只有人工确认过的字段才允许硬过滤。
- 补 Stage 3 的验收问题，并把「跨分期章节」列成必测样本。

### F2（P0）表格被排除在「原文」之外：最重要的数字 Agent 看不到

**事实：**

- CKD 5 份文档共 **23 张表**：AAHA 11 张、SACN5 12 张，IRIS 0 张。
- 其中包含：SACN5 表 37-1（IRIS 分期系统）、表 37-9（犬猫 CKD 关键营养因子：蛋白 14–20%、磷 0.2–0.5%、钠 ≤0.3%、氯 1.5×钠、钾 0.4–0.8%、omega-3 0.4–2.5%）、表 37-11/37-12（商业肾脏处方粮对比）、AAHA 表 8（疾病相关营养素）。
- `search_knowledge_library` 只查 `source_paragraph`，不查 `source_table`；Agent 没有表格工具。
- 表格的页码也基本丢了：全库 499 张表里 483 张没有页码；CKD 23 张里 22 张没有页码；23 张里 22 张没有经过数字校验（唯一校验通过的是表 37-9）。
- 「碘未覆盖」的结论是用**段落**统计出来的：SACN5 第 37 章 0 段提到 iodine。这个结论碰巧是对的（AAHA 表 8 里的 iodine 属于甲亢，不是 CKD），但**方法本身不成立**——表格里的内容没被检查过。

**对 Agent 的影响：**

- 问「膳食磷多少」时，模型只能从正文段落里拼；问「血清磷目标」时，又可能把「0.2–0.5% DM」和「<1.6 mmol/l」混在一起——这正是 2026-11-08 验收里点名的「膳食磷/血清磷混用」风险，而表格的列名/表题本来能区分它们。
- 表 37-9 是**已校验**的（30 个数字全对），却没接给 Agent；这是「有资产、没接线」的典型。
- 覆盖地图把「正文没提到」当成「来源没有」，会误导补来源的决策。

**改法：**

- 把表格作为「原文」的一等公民：至少提供「按章节/文档打开表格」的能力；表格返回列名、行、单位、口径、页码、校验状态。
- 先做 CKD 核心 5 组表（37-1、37-9、37-11/12、AAHA 表 8）的列级元数据（单位、DM/每 1000 kcal、膳食 vs 血清），人工确认后再开放。
- 「碘」的结论要重做：用「问题清单」而不是关键词判断是否需要覆盖。

### F3（P0/P1）章节边界和标题不可靠：17/30 的标题是页眉

**事实：**

- SACN5 第 37 章被切成 30 节，其中 **17 节标题是「781 Chronic Kidney Disease」「783 Chronic Kidney Disease」这类页眉**；再加 4 个 CASE 和 1 个 ACKNOWLEDGMENT，**22/30 的标题不携带主题信息**。
- 78 节里 `sectionType` 有 40 节是 `other`；IRIS 治疗文档因为「文档类型=治疗指南」，9 节里有 6 节被统一标成 `treatment`（其余 3 节是 appendix），也就是说同一份文档内部的类型区分基本没有发生。
- 章节粒度也不均：中位数 6.5 段，最大 59 段（`s005` 跨 8 页）。

**对 Agent 的影响：**

- 模型看到 `sectionTitle: "781 Chronic Kidney Disease"`，既不知道这节讲什么，也无法判断该不该打开；「按章节路由」在最重要的教科书来源上实际退化成「按页路由」。
- 引用写「SACN5 第37章 p781」对人还能接受，但 Agent 需要的是「这节讲蛋白/磷/贫血」；标题不提供这个信号。
- 长节没有子结构，`kb_open` 打开后是一大段，模型只能再搜一次。

**改法：**

- 重新切分：用 PDF 的标题层级/目录（不是页眉）切节；至少把「页眉型标题」识别出来，显示为「第37章 · p781」而不是假标题。
- 一节只讲一个问题，控制在 3–15 段；超长节按小标题拆，过短节并回父节。
- `sectionType` 改为按本节内容判定，不允许「文档类型」覆盖整篇。

### F4（P1）元数据自动生成且未复核：过滤要么没用，要么用错

**事实（78 节实测）：**

| 维度 | 现状 | 问题 |
|---|---|---|
| 物种 | 67 节 `both`、9 节 `dog`、2 节 `cat` | 「犬猫都有」是默认值；`species=dog` 几乎过滤不掉任何东西 |
| 分期 | 只有 6 节有分期 | 其余 72 节「无分期」，分期过滤大部分时候是空转；有分期标签的跨期节（如 `s005`、`s004`）反而会被误伤 |
| 主题 | 21 个主题靠子串统计 | 「铁」17 节里 13 节只是出现了 `environment`；「蛋白」43 节里 7 节只命中了 `proteinuria`（另一个临床概念） |
| 主题回填 | 本节没命中时，回填整份文档的主题 | 「磷」在目录里覆盖 40 节，其中 18 节正文根本没提磷；AAHA 的封面、致谢、客户沟通节都被打上「磷/铁/分期」 |
| 类型 | 40/78 是 `other` | 对 Agent 没有区分价值 |

**对 Agent 的影响：**

- 过滤条件看起来很强，实际要么是空转（物种/分期大部分为空），要么是误伤（`s005`）。
- 覆盖地图被放大：比如「磷覆盖 5 份文档 / 40 节」听起来很全，扣掉回填和假阳性后要打折。
- 模型看到 `topics`/`species` 字段，会以为这些是可信的；它没有「置信度」可参考。

**改法：**

- 主题检测改成词边界 + 短语规则（`\biron\b` 不匹配 `environment`）；「提到」与「讲清楚」分开，后者用标题/小标题/TF-IDF 判断。
- 删掉「整份文档主题回填到本节」的逻辑；宁可为空，也不要污染。
- 元数据加「状态」（机器建议 / 人工确认 / 人工否决）和「来源」（规则/模型/人）；**只有人工确认的字段能硬过滤**。
- 覆盖地图重做成「问题类型 × 来源」矩阵（见 6.8），不再按关键词计数。

### F5（P0）`scope=all` 结构性失效：候选池按文档编号截断

**事实：**

- 工具 schema 向模型暴露了 `scope: ckd | all`，说明是「all=全库」。
- 检索实现是：先按关键词 `OR` 查最多 **1,000 段**（`take: 1000`），按**段落 ID 升序**，再在应用层打分。
- 我用一个常见 CKD 查询（ckd/dog/stage/phosphorus/protein）实测：全库命中 **11,973 段**，进候选池的只有 **1,000 段**，来自 **16/159 份文档**，全部是 `aaha-*`/`acvim-*` 开头的早编号文档；**SACN5 和 IRIS 一段都没进候选池**。
- 而且全库路径没有 CKD 目录（`loadCkdCatalog` 只认 CKD 文档），物种/分期/主题过滤退回逐段文本判断，等于没有章节元数据。

**对 Agent 的影响：**

- 模型一旦按说明切到 `all`（比如问一个 CKD 以外的问题），会拿到「看起来有结果、实际完全不相关」的段落；它无法知道候选池被截断。
- 这是典型的「工具说谎」：参数承诺了能力，实现没有。
- 扩全库之前，这条路径必须先修；否则全库检索的结论全部不可信。

**改法：**

- **P0 立刻**从工具 schema 去掉 `scope: all`（默认只 CKD），或至少标注「仅试点范围」；不要让模型选一个坏路径。
- 中期用全文索引（英文 `tsvector` + 中文 trigram）做候选生成，按相关性取候选，不按 ID 截断；分页游标，不设「前 1000」硬顶。
- 候选生成和过滤顺序要改：先过滤（已确认元数据）再取候选，而不是先取 1000 再过滤。

### F6（P0/P1）工具面太窄：只能搜，不能打开、不能看目录、不能看表

**事实：**

- 配方 Agent 只有 8 个工具，知识相关只有 `search_knowledge_library` 一个。
- 它不能：按文档/章节打开、读表格、读某段上下文、列目录、查覆盖、按「问题类型」筛。
- 返回最多 10 段（默认 8），单段超过 900 字截断，且**没有续读手段**；同一节的多段会重复占位（实测 8/14 题的前 3 名存在同节重复，其中 2 题的前 3 名全是同一节）。
- 没有游标/翻页；模型想「再多看几条」只能换关键词重搜，成本翻倍。
- 模型看到「见表 37-9」也打不开表——引用链断在工具边界。

**对 Agent 的影响：**

- 它无法完成「先定位章节 → 再读全节 → 再看表 → 再引用」这条人类很自然的路径；只能反复关键词碰撞。
- 同一节重复返回浪费上下文，挤掉真正需要的另一节。
- 长节被 900 字截断后，关键句可能正好在截断点之后；模型不知道还有下半段。

**改法：**

- 四个工具（见 6.4）：`kb_scope`（有什么）、`kb_search`（找单元）、`kb_open`（打开单元/表/上下文）、`kb_lookup`（查表值）。
- 「单元优先」：一次返回 ≤5 个证据单元，每个带 2–3 段最相关原文 + 表命中；同一节最多 2 段，同一文档最多 2 个单元。
- 支持游标；`kb_open` 负责续读，不在搜索里塞全文。

### F7（P0）空结果不是信号：模型分不清「没有」和「没搜对」

**事实：**

- 搜不到时，工具给模型的摘要只有一句：「知识库原文里没有找到「…」；换个关键词或来源再查」。
- 没有区分：关键词没命中 / 被过滤条件排掉 / 这个主题根本不在覆盖范围。
- 未知主题值是**静默 0**：比如 `topics: ["iodine"]` 在目录里不存在，过滤后为空，但工具不会说「iodine 不是合法主题」。
- 中文主题值也是静默 0：`topics: ["磷"]` 在 `matchesTopic` 里会被归一成空字符串，所有章节都被筛掉；模型只会看到「没找到」。
- 中文查询在英文语料上同样会 0 命中（除非模型自己补英文关键词）；目前靠工具说明「优先英文关键词」在约束模型，不是结构保证。

**对 Agent 的影响：**

- 这是「知识库为 Agent 服务」最关键的失败模式：**模型无法把「知识库没有」与「我查错了」分开**，于是要么反复换词（浪费步数），要么干脆按常识编（违背「没有出处不说」）。
- 对「碘」这类真缺口，模型即使查对了也只会得到「换个关键词」，不会得到「本库不覆盖碘对 CKD 的目标值」。

**改法：**

- 所有工具返回 `status`：`ok / no_match / out_of_scope / filtered_out`；每种带一句可执行提示（合法主题列表、最近覆盖、下一步建议）。
- 参数校验：未知 topic/document/source 直接报错并列出合法值，不静默返回空。
- `kb_scope` 先告诉模型「有什么、没什么」，把「不知道」变成可查的状态。
- 中文查询走双语词典/查询改写（已有 139 条术语的 `glossary-zh-en.json` 可复用），或在索引层做中英混合。

### F8（P1）三条知识通路各自为政：同一问题可能得到三种答案

**事实：**

- 配方 Agent 用 Postgres 原文层；补剂 Agent 用 `chunks.jsonl`（20,658 块，17MB，来自 `docs/knowledge-base/tools/build-chunks.py`）；健康分析用 387 条结论。
- 三套语料、三套打分、三种引用粒度（段落+页码 / 块+无页码 / 条目+出处文字）。
- `chunks.jsonl` 被 `.gitignore` 忽略，部署脚本不生成它；补剂 Agent 在语料缺失时会如实返回「知识库当前不可用」，但这等于**生产上可能没有知识库**（需上线核实）。
- 387 条结论与原文层的数字没有一致性校验：比如 `renal.ts` 的 CKD 目标与表 37-9 是同一组数值的两个副本，任何一边改了都不会报警。

**对 Agent 的影响：**

- 同一个「CKD 磷目标」，配方 Agent 从原文段落拼、补剂 Agent 从 chunk 拼、健康分析从条目抄；三者可能不一致，且没有仲裁。
- 维护成本 ×3；任何检索改进只覆盖一条链路。
- 补剂 Agent 的 `search_knowledge` 在无 chunks 时直接不可用，模型只能「改用人工判断」，知识库对它等于不存在。

**改法：**

- **一个语料、一个检索服务、多个视图**：原文层是唯一真源；`chunks.jsonl` 要么由部署生成并纳入健康检查，要么退休，补剂 Agent 改调同一服务。
- 387 条结论保留给健康分析，但每条锚到证据单元，并加「与原文层数值一致性」的抽查；不作为配方 Agent 的输入。
- 引用句柄统一：模型看到的 K 号是展示层，底层统一映射到「文档/章节/段落/表格单元格」的稳定 ID。

### F9（P0/P1）评测与观测不足：14/14 不能证明「Agent 可用」

**事实：**

- 14 道题、12 个不同的期望章节；78 节里 **66 节从未被期望命中**；AAHA（27 节）和 IRIS 口袋指南（5 节）整份文档没进过期望集。
- 8/14 题的前 3 名里出现**同一节重复**（例如 Stage 4 贫血题的 3 段全在 `s006`），「前 3 命中」被一节填满，指标虚高。
- 没有 Stage 3 题；没有「错误物种/错误分期」的负样本（除了碘）；没有「表格数值」题；没有「模型会不会用工具」的 Agent 级评测。
- 评测脚本每次覆盖结果文件，但**没有 CI、没有阈值、没有基线对比**；排序里的 `×3`、`×1.05`、`×1.03` 是针对 CKD 题集手调的，换病种没有依据。
- 工具调用虽然落库（`recipe_design_agent_message` 有 toolArgs/toolResult），但没有汇总成「查询→命中→引用→采纳」的检索日志；无法回答「哪些查询经常 0 结果」「哪些段落从没被引用」。

**对 Agent 的影响：**

- 改一个排序权重，可能让某类问题变好、另一类变坏，但没人知道；回归不可见。
- 扩全库时没有「批次验收」的客观依据，只能凭感觉。

**改法：**

- 建 50 题 CKD 金标准集（数值/分期/治疗/监测/负样本/对抗样本六类），按「单元」判分，不按段落重复计数；加 Stage 3、猫内容、Stage 2 vs 4、膳食磷 vs 血清磷。
- 指标：recall@3（单元）、证据精度、no-source 准确率、过滤泄漏率、表格单元格命中率、引用有效率、无引用结论数、调用次数/token/延迟。
- 进 CI：固定测试库或快照，回归超阈值阻断合并；每次改动记录基线。
- 检索日志汇总成周报：0 结果查询、重复查询、被引用最多的单元、从未被引用的单元。

### F10（P1/P2）生命周期与治理漂移：版本、复核、文档、鉴权

**事实：**

- 检索结果带 `sourceVersion`，但版本是**来源级**的（IRIS 三份文档共用一个 `IRIS-CKD-2026`），没有文档级出版日期，也没有「已被取代」标记；旧版和新版可以同分返回。
- 387 条结论的 `reviewBy` **全部是同一天 2027-04-01**（批量填的），所以「复核到期」这条控制实际上不会区分任何条目；`conflicts` 字段 387 条里 0 条使用，尽管证据政策要求冲突要记录。
- 出处锚点 788 条里 387 条只到小节（49%），与收尾报告写的「72% 精确到段落」口径不一致，需要核对。
- 文档与代码漂移：`evidence-policy.md` 仍要求「每条知识条目必须带紧急程度字段」，但该字段已在 2026-11-01 删除；`docs/knowledge-base/README.md` 仍把「紧急程度/来源 ID/生效日期/复核日期」写成「计划新增」；文档数 160 与本地 159 不一致。
- `knowledge-source` 的 11 个只读接口没有鉴权（controller 无 `@UseGuards`，全局也没有 guard），原文和图片对外可读。

**对 Agent 的影响：**

- 它无法判断一条证据是不是旧版；旧指南和新指南会以相同权重出现。
- 治理文档不可信时，人无法用文档验收代码；「说了」和「做了」继续分叉。
- 原文接口公开，既是版权风险，也是「谁都能拿原文拼结论」的合规风险。

**改法：**

- 文档/单元级字段：`published_at`、`version`、`supersedes`、`status`（current/superseded）；检索默认降权/隐藏 superseded，并在结果里显示版本。
- 每条证据单元有自己的 `reviewBy` 和 owner；复核日期按内容风险分档，不再批量同一天。
- 冲突必须有记录（至少对 CKD 蛋白/磷这类有争议的主题），由人裁决并在单元里写明。
- 文档与代码对齐：删掉 A–E 和紧急程度的残留表述；把原文层表数量（5/6 张）、文档数（159/160）等口径统一；接口加管理员鉴权。

## 5. 对现有方案的四条判断

### 5.1 「只给原文，不给结论」——对，但「原文」不能只是正文段落

这条原则避免了「结论过期」和「模型抄结论」，应保留。但这次实现把「原文」缩成了「段落文本」，把 23 张表排除在外。表格不是结论，它是最硬的原文证据。**原则没错，实现窄了。**

### 5.2 「暂不扩全库」——对，但理由要改写

原判断的四条理由（目录没验收、元数据要人审、碘缺口、维护成本）都成立，但最硬的理由是：**现在的元数据会把 Stage 3 的证据藏起来，而评测发现不了。** 扩全库不是「多 78 倍工作量」，是「多 78 倍同类错误」。放行门槛应从「CKD 14/14」改为：

1. 78 节的物种/分期/主题/类型**人工确认**；
2. 50 题金标准集（含 Stage 3、负样本、表格题）通过；
3. 元数据错误率抽检 <5%；
4. 检索日志和回归 CI 跑起来。

### 5.3 「不建疾病—营养素规则表」——对，但别把「结构元数据」当成「临床规则」

这是两件事：

- **临床规则**（CKD 就该低磷、几期用磷结合剂）：不建，交给模型判断。✅
- **结构元数据**（这一节讲什么、适用哪个物种/分期、是不是表格、单位是什么）：必须建，而且要人确认。✅

现在的混淆在于：因为怕回到「规则表」，连「章节讲什么」这种纯结构信息也只敢自动生成、不敢人工确认，结果得到一个「看起来有、实际不可信」的中间态。**结构元数据不是临床判断，它是检索的路标；路标必须准。**

### 5.4 「章节级元数据过滤」——方向对，但目前是负资产

过滤的价值取决于元数据质量。现在：

- 物种 67/78 是「both」，过滤基本不生效；
- 分期 6/78 有值，过滤大部分空转；
- 有分期标签的跨期章节（如 `s005`、`s004`）被误伤；
- 主题有 13/17 的「铁」假阳性、18/40 的「磷」回填。

在这种质量下，**硬过滤的期望收益是负的**：它挡掉的真证据可能比挡掉的噪声多。正确顺序是：先把元数据做到「可硬过滤」，再打开硬过滤；在此之前只做排序加权。

## 6. 目标设计：把「档案室」改成「参考台」

### 6.1 五条设计原则

1. **单元优先**：检索和引用的单位是「一节讲一个问题的证据单元」，不是段落，也不是整篇文档。
2. **数字是一等公民**：表格、单元格、单位、口径必须可检索、可引用；「原文」包含表格。
3. **元数据是契约**：只有人工确认的字段能做硬过滤；未确认的只影响排序。错的路标比没有路标更糟。
4. **先告诉模型「有什么」，再让它「找」**：覆盖查询是一等工具；「没有」必须是明确答案。
5. **一个语料、一个服务、多个视图**：所有 Agent 共用同一套证据和引用语义；不为每条链路维护一套检索。

### 6.2 四层数据 + 一个服务

```
L0 来源登记
   source_id / 机构 / 版本 / 出版日期 / 状态（current|superseded）/ 取代关系 / owner
        │
L1 原文层
   document → section（按标题层级重切）→ paragraph
                                   └→ table（列/行/单位/口径/页码/校验状态）
        │
L2 证据单元层（新增，核心）
   kb_unit：一节一个问题；挂段落、表格、页码、元数据（带确认状态）、版本、owner
        │
L3 结论层（保留，仅健康分析）
   387 条；每条锚到 kb_unit；与 L2 数值做一致性抽查
        │
        ▼
一个 KnowledgeService
   kb_scope / kb_search / kb_open / kb_lookup
   ↑ 配方 Agent   ↑ 补剂 Agent   ↑ 健康分析（只读结论）
```

### 6.3 证据单元（`kb_unit`）长什么样

| 字段 | 说明 | 谁填 |
|---|---|---|
| `unit_id` | 稳定 ID，如 `IRIS-CKD-2026/stage-3-treatment` | 导入生成 |
| `title` / `display_title` | 真标题；页眉型标题降级为「第37章 · p781」 | 重切 + 人工抽查 |
| `heading_path` | 章 > 节 > 小标题 | 解析 |
| `page_start` / `page_end` | 页码范围 | 解析 |
| `text` | 本节全文（不截断） | 解析 |
| `paragraph_ids` / `table_ids` / `figure_ids` | 证据锚点 | 解析 |
| `species` | dog / cat / both / unknown；**带确认状态** | 机器建议 + 人确认 |
| `stage_scope` | all / 1–4 / 2–3；跨期节用范围 | 机器建议 + 人确认 |
| `question_types` | 定义/诊断/营养/治疗/监测/并发症/沟通 | 机器建议 + 人确认 |
| `topics` | 受控词表；带「提到/主讲」区分 | 机器建议 + 人确认 |
| `section_type` | staging/treatment/nutrition/diagnosis/appendix/… | 规则 + 人确认 |
| `authority` / `document_type` / `published_at` | 权威性、类型、日期 | 来源登记 |
| `metadata_state` | 每个字段：proposed / confirmed / rejected + 审核人 + 日期 | 审核流程 |
| `coverage_role` | answers / mentions / context | 人确认 |
| `superseded_by` | 被哪一版取代 | 来源登记 |
| `content_hash` | 变更检测 | 导入 |

**切分规则：**

- 一节只回答一个问题；3–15 段；超过 15 段按小标题拆；少于 3 段并回父节。
- 表格归属到它出现的节；跨页表保留 `page_start/page_end`。
- 页眉/页脚/参考文献/致谢单独标 `appendix` 或 `front_matter`，不参与临床检索。

### 6.4 Agent 的四个工具（不多不少）

| 工具 | 回答的问题 | 返回什么 | 关键约束 |
|---|---|---|---|
| `kb_scope` | 「你们有什么？CKD 3 期覆盖到哪？」 | 问题类型 × 来源的覆盖矩阵；章节清单；已知缺口；最近复核 | 不需要 query；先看再搜 |
| `kb_search` | 「哪个证据单元最相关？」 | ≤5 个单元；每个 2–3 段原文 + 引用号；表命中（表题/行数/关键列）；覆盖状态；命中原因 | 只对已确认元数据硬过滤；同节 ≤2 段、同文档 ≤2 单元；游标 |
| `kb_open` | 「打开这个引用/这一节/这张表」 | 全节原文、表格（列/行/单位/页码）、相邻单元、版本、全部引用号 | 支持引用号/单元/段落/表；可续读截断段 |
| `kb_lookup` | 「这个指标的目标值是多少？」 | 表格行/单元格 + 单位 + 口径（DM/每1000kcal/血清）+ 物种 + 分期 + 出处 | 只返回表值，不返回建议；膳食 vs 血清分开 |

**返回状态（所有工具统一）：**

- `ok`：命中；
- `no_match`：关键词没命中（建议换词/换来源）；
- `out_of_scope`：本库不覆盖（给覆盖矩阵和最近主题）；
- `filtered_out`：被过滤条件排掉（列出哪个条件、放宽建议）。

**参数校验：** 未知 `topic/sourceId/documentId/stage` 直接报错并列出合法值；不接受「静默 0」。

**提示词分工不变：** 系统提示词只写「你是谁、任务是什么、什么算做完、引用要求」；「什么时候用哪个工具」写在工具说明里。不要用提示词硬编码检索步骤——工具的形状本身就是操作规程。

**结果形状（描述，不是代码）：**

- 单元头：标题、页码范围、来源/版本、权威性、物种/分期（带确认标记）、覆盖角色；
- 证据：2–3 段原文（带段落 ID/页码/引用号），每段一句「为什么是它」（命中词/标题/表题）；
- 表：表题、页、列名、行数、与问题最相关的 2–3 行预览、校验状态；
- 导航：相邻单元、相关主题、下一步建议（打开表/换分期/看负样本）。

### 6.5 检索管线

| 环节 | 现在 | 目标 |
|---|---|---|
| 候选生成 | `contains` OR，最多 1000 段，按 ID 截断 | 英文 `tsvector` + 中文 trigram/phrase；按相关性取候选；不按 ID 截断 |
| 过滤 | 逐段文本推断 + 部分目录元数据 | 先用**已确认**元数据过滤；未确认只加权 |
| 排序 | 手调 `×3 / ×1.05 / ×1.03` + 词频 | BM25 + 字段权重（标题/表题 > 正文）+ 权威性/时效 + 多样性；参数可配置、可评测 |
| 去重 | 无 | 同节 ≤2 段、同文档 ≤2 单元；跨查询缓存去重 |
| 输出预算 | 10 段 × 900 字 | 5 单元 × 2–3 段，约 1.5–2k token；游标续读 |
| 延迟 | 顺序扫描 | 27k 段 p95 <300ms；为 60 万段设计索引 |
| 语言 | 靠模型写英文 | 双语词典/查询改写；中文查询至少能命中英文原文 |

**一条硬规则：** 排序里不允许出现「针对某个来源/某类问题的魔法系数」；要加权就做成可解释、可评测的字段权重（权威性、时效、标题命中），换病种不需要改代码。

**向量检索不是当前瓶颈：** 现在暴露的失败（Stage 3 被藏、表格打不开、空结果没有语义、全库候选截断）没有一个是「语义相似度不够」造成的。先用结构和索引解决；等这些修完、召回仍有明显天花板，再评估向量/重排，避免用新模型掩盖旧结构问题。

### 6.6 元数据生产：机器建议 → 人工确认 → 才可硬过滤

**流程：**

1. **重切**：先按标题层级/目录把章节切对（尤其是 SACN5 的页眉型标题、IRIS 的 Stage 3 缺失章节）。
2. **机器建议**：物种、分期、主题、类型、覆盖角色；每条带「证据」（标题/正文/表格）。
3. **人工确认**：导出审核包（CSV 或 Web 勾选），逐节确认；CKD 78 节 × 4 个字段，约 2–3 小时；记录审核人/日期。
4. **发布**：只有 `confirmed` 字段进入硬过滤；`proposed` 只做排序；`rejected` 不参与。
5. **抽检**：每批扩库抽 10% 复核；错误率 >5% 回退。

**检测器要修的具体点：**

- 词边界：`iron` 不能匹配 `environment`；`protein` 与 `proteinuria` 分开；
- 去掉「整份文档主题回填到本节」；
- 分期：从标题、正文首段、表格三处取；跨期节用范围，不用单值；
- 物种：文档级 + 节级显式标记；`both` 不是默认值，`unknown` 要显式；
- 类型：按本节标题/内容判定，不允许文档类型覆盖；
- 页眉型标题：识别 `^\d{3} ` / 重复字符串，降级为 display_title。

### 6.7 数字与表格：把「最硬的证据」接进来

**表格元数据（列级）：**

| 字段 | 例 |
|---|---|
| `measure` | 膳食磷 / 血清磷 / 钠 / 钾 / 氯 / omega-3 / 蛋白 |
| `species` | dog / cat |
| `stage_scope` | all / 1–4 |
| `unit` | % DM / mg/dl / mmol/l / % |
| `basis` | DM / as-fed / per 1000 kcal / per MJ |
| `value_type` | min / max / range / target / threshold |
| `verified` | 数字校验通过 / 未校验 / 图片型 |
| `page` | 表格所在页 |

**为什么必须做：** 表 37-9 的「磷 0.2–0.5%」是**膳食**口径；IRIS 的「<1.6 mmol/l」是**血清**口径。正文里两句话都可能出现「磷」，模型很容易混；表格的列名和 `measure` 是唯一能稳定区分它们的结构。表 37-9 已经通过 30 个数字校验，具备开放条件。

**先做哪几组：** 37-1（分期）、37-9（关键营养因子）、37-11/12（处方粮对比）、AAHA 表 8（疾病相关营养素）。这 5 组覆盖了 CKD 绝大多数数值问题；其余表格按需开放。

**引用到单元格：** 「SACN5 表37-9 · 磷行 · 犬列 · p17」比「SACN5 第37章」更可核；单元格引用也让语义裁判能精确判断「这个数字是否被原文支持」。

### 6.8 覆盖矩阵：从「关键词出现」改成「问题类型 × 来源」

**CKD 问题清单（建议 7 类）：**

1. 定义与分期（IRIS 1–4、UPC/血压亚分期）
2. 诊断与鉴别（肌酐/SDMA、UPC、血压、影像、活检）
3. 营养目标（蛋白、磷、钠、钾、氯、omega-3、能量、水、维D、纤维）
4. 治疗原则（磷结合剂、蛋白尿、血压、贫血、酸中毒）
5. 监测与复查（频率、指标、目标值）
6. 并发症（贫血、高血压、蛋白尿、低钾、酸中毒）
7. 沟通与预后（生活质量、临终、主人沟通）

**每个格子四态：** `完整 / 提到 / 缺失 / 不适用`；附来源章节、页码、复核日期、owner。

**这张矩阵同时服务三件事：**

- `kb_scope` 直接返回它，模型先知道「有什么」；
- 覆盖地图文档由它渲染，不再按关键词计数；
- 扩库按「缺的格子」排优先级，不按「文档数量」排。

「碘」在这张矩阵里会落到「营养目标」下的一个子项：来源没有给出 CKD 目标 → 标 `缺失` 或 `不适用`（取决于临床是否需要），而不是含混的「未覆盖主题」。

### 6.9 评测与观测：让「改好/改坏」可见

**金标准集（CKD 先做 50 题）：**

| 类别 | 数量 | 例子 | 判分点 |
|---|---:|---|---|
| 数值目标 | 12 | 犬 CKD 膳食磷范围；Stage 3 血清磷目标；钠上限 | 命中正确单元/表格；数值+单位+口径正确 |
| 分期/亚分期 | 10 | Stage 3 怎么分；UPC 亚分期；血压亚分期 | 命中分期章节；不串期 |
| 治疗原则 | 8 | 何时加磷结合剂；蛋白尿处理 | 命中治疗节；不越界给剂量 |
| 监测/复查 | 6 | 多久复查；查什么 | 命中监测节 |
| 负样本 | 8 | CKD 犬碘目标；猫专属内容；不存在的主题 | 明确「不覆盖」；不编 |
| 对抗样本 | 6 | Stage 2 vs 4；膳食磷 vs 血清磷；犬 vs 猫 | 不串期/不串物种/不混口径 |

**指标与门槛（建议，跑完基线再校准）：**

| 指标 | 目标 |
|---|---|
| recall@3（单元） | ≥0.90 |
| 证据精度（返回单元确实相关） | ≥0.80 |
| no-source 准确率 | 100%（8/8） |
| 过滤泄漏（错误物种/分期进入前 3） | 0 |
| 表格题命中（数值来自表格单元格） | ≥0.90 |
| 引用有效率 | 100% |
| 无引用临床结论 | 0 |
| 每场景检索调用次数 | ≤3 |
| 检索 p95 延迟 | <300ms（27k 段） |
| 回归 | CI 阻断，不允许静默下降 |

**观测：**

- 每次 `kb_*` 调用记录：query、过滤条件、返回单元、被打开、被引用、token、延迟；
- 每次 Agent 会话记录：检索次数、0 结果次数、引用覆盖率、裁判结果（已有）；
- 周报：0 结果查询 Top 20、重复查询、从未被引用的单元、被引用最多的单元、覆盖矩阵缺口变化。

### 6.10 迁移策略：双轨、可回滚、不搞大爆炸

1. **影子生成**：`kb_unit` 先离线生成，与现有检索并行，不影响线上；用同一套 50 题对比新旧结果。
2. **双读**：新服务上线后，配方 Agent 可配置走新/旧路径；用开关按会话切换，便于回滚。
3. **达标切换**：新路径在原 14 题 + 新增 36 题上不低于旧路径，且 Stage 3/表格/空结果三类问题有明确改善，再切默认。
4. **补剂 Agent 最后切**：先保证配方 Agent 稳定，再把补剂 Agent 从 `chunks.jsonl` 迁到同一服务；期间保留旧路径只读。
5. **旧路径保留一个版本**：确认无回归后再删除旧代码/旧语料，避免「切了才发现回不去」。

### 6.11 生命周期与治理

- **版本**：文档级 `published_at/version/supersedes/status`；检索默认隐藏/降权 superseded；结果里显示版本和日期。
- **复核**：每条单元/每条结论有自己的 `reviewBy` 和 owner；按内容风险分档，不批量同一天。
- **冲突**：CKD 的蛋白/磷等争议主题必须有 `conflicts` 记录和裁决理由；0 冲突不是好事，是没记录。
- **一致性**：387 条结论与表 37-9/IRIS 的数值做抽查；不一致时以原文层为准，并回改结论。
- **文档**：新增一份《知识库 Agent 契约》（工具、状态、元数据字段、覆盖矩阵、引用格式）；同步修订 `README.md`、`evidence-policy.md`，删掉 A–E 和「紧急程度」残留；统一文档/段落/表数量口径。
- **安全**：`knowledge-source` 的只读接口加管理员鉴权；图片同样；审计访问日志。
