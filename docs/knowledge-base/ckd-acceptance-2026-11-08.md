# CKD 配方稳定性验收与归因更正（2026-11-08）

## 结论

**CKD 3 第 2 次已通过。**  
此前把失败归因于“补剂档案缺 servingWeightG / 补剂贡献按 0”是错误的，现更正为：

- 碘钾片档案完整，评估也算对了：1 片 = 0.225mg 碘，折合 0.064mg/1000kcal；
- 目标 0.26mg/1000kcal，缺口是 **0.196mg**，约需 4 片；
- Agent 只加了 1 片，之后从未改过剂量；
- 氯是 **11/11 原料都没有 chloride 数据**，属于数据缺失，不是配方缺氯；
- 镁/铁/锌/维D 库里有原料，Agent 找不到，因为 `find_food` 当时不支持按营养素搜。

## 修复（按顺序）

1. **find_food 按营养素找**：工具 schema 增加 `nutrientKey`，候选返回含量/单位/基准；`port.findFoods` 已透传 `nutrientKey`。
2. **编辑/评估反馈**：
   - `edit_recipe` 支持 `trackNutrients`，返回改动前后缺口和剂量提示；
   - `assess` 返回 `deficit`（还差多少）和补剂 `doseGuidance`（1 片/粒约多少、目标多少、约需几片）。
3. **摘要措辞与缺数据披露**：
   - “碘 0.064（目标 0.26）”改为“还差 0.196（当前 0.064 / 目标 0.26）”；
   - 全部原料缺字段时，摘要显示“缺数据：氯（11/11 原料无数据）”，不再当 0 不足；
   - 缺数据不计入 deficient。

## 复核结果（修复后同一场景）

- Agent 用 `find_food` 按 `zinc / iron / magnesium / iodine / chloride / copper` 找到了原料；
- `edit_recipe` 返回了碘、氯、铜、维D 等的剂量和缺口变化；
- 最终 `assess`：39 项达标，0 缺，0 超；缺数据 2 项（可溶性纤维、不可溶性纤维，原料库无数据）；
- 碘、氯、镁、铁、锌、维D 均已补齐；
- 会话 55 步，评估通过。
