# 补剂原料缺口诊断（D6 暴露）

- 日期：2026-11-10
- 来源：多轮设计场景 D6（`docs/knowledge-base/eval/design-scenarios.json`）
- 结论：**这不是知识库问题，是配方编辑器"补剂目标营养素"的入口缺失。**

## 1. 现象

D6 第二轮，Agent 按方案把 4 种原料加进草稿：

| 原料 | 结果 |
|---|---|
| 鸡胸 90 g | ✅ 加入 |
| 大米 40 g | ✅ 加入 |
| 鸡蛋壳粉 1.8 g | ❌ 系统拒绝 |
| 鱼油胶囊 3.5 g | ❌ 系统拒绝 |

拒绝原因（原文）：

> 补剂原料「鸡蛋壳粉」缺少营养目标：请在添加时选择目标营养素，或为该补剂的营养档案配置默认目标

结果：只加进 2 种原料，配方缺钙、缺 omega-3，评估必然不过。Agent 如实报告并停止，没有无限重试。

## 2. 机制

- `edit_recipe` 的 `add` 操作只有 `nutritionFoodId` / `weightG` / `preparationMethod` 三个字段，**没有"目标营养素"参数**；
- 服务端在添加补剂时要求存在 `SupplementTarget`（`recipe-designer.service.ts` 的 `buildMissingSupplementTargetMessage`）；
- 补剂营养档案如果没有默认目标，就必然抛错——而工具层没有任何办法在添加时补上目标。

也就是说：**当前工具链下，"没有默认目标的补剂"结构性不可添加**，不是模型不会用。

## 3. 影响

- CKD 配方最需要的补钙（鸡蛋壳粉/碳酸钙）与 omega-3（鱼油）恰好属于这一类；
- 评估会稳定报"缺钙、钙磷比过低、缺 omega-3"，配方无法收口；
- 这会让"从零设计完整 CKD 食谱"永远无法通过验收，和知识库质量无关。

## 4. 两个修法

### 方案 A：工具层支持目标营养素（推荐，彻底）

在 `edit_recipe` 的 `add` 操作增加可选字段：

- `nutrientTargetKey`（如 `calcium`、`omega3`）；
- `targetValue` 与 `unit`/`basis`。

服务端用它构造 `SupplementTarget`，不再要求档案必须有默认值。需要同步补工具描述与测试。

### 方案 B：给补剂档案配默认目标（快，但只覆盖已知补剂）

在营养档案里为常用补剂配置默认目标：鸡蛋壳粉→钙，鱼油→EPA+DHA/omega-3。数据量小、当天可做；但每来一个新补剂都要配一次。

**建议先做 B 解眼前（鸡蛋壳粉、鱼油两种），再做 A 兜底。**

## 5. 复验方式

修好后重跑 D6：

```bash
KB_EVAL_ADMIN_PASSWORD=... npm run kb:agent -- --scenario D6 --json
```

期望：4 种原料全部加入；`assess` 带 `phosphorus` 覆盖（`citationId` 非空）；最终回答含钙/omega-3 的处理说明。

## 6. 与知识库上线的关系

知识库六域、生产检索、生产冒烟都已通过；本缺口只影响"配方编辑器能不能把补剂加进草稿"，不影响"知识库能不能被检索和引用"。建议作为独立产品任务排期，不阻塞知识库上线。
