# 配方设计 · 现有原文档覆盖度评估

**日期**：2026-11-01
**问题**（老板原话）：针对配方设计来说，现有的知识来源的原文档是否足够覆盖现在最要紧的这个需求？
**结论**：**主干够用，比预想的好；真正的缺口只有一块——原料营养数据。**

---

## 一、先更正我上一轮的一个错误判断

上一份《知识结构 v1》里，我把「B1 原料营养档案」标成 ⬜ 空白、把整个 B 板块标成 🔴。

**这个判断错了两处**：

1. 我是**按知识条目**（387 条里只有约 7 条沾边）判断的，没有回去翻原文档。
2. 翻完之后发现：**NRC《犬猫营养需要》2006 本身就带一整套原料成分表，而且是机器可读的 HTML 表格，不是图片。**

EPUB 里有 **62 张结构化数据表、共 1,739 行**，其中直接服务配方设计的有 11 张、约 1,280 行。

## 二、配方设计到底需要什么（判断标准）

要设计一份定制鲜食配方，至少需要 10 块信息。逐块对照：

| # | 需要什么 | 现有原文档 | 判断 |
|---|---|---|---|
| 1 | **能量需求**（RER/MER、体况、活动、绝育、温湿） | NRC 第 4、12 章 + 表 4-1~4-4；FEDIAF 表 VII-1~VII-7；SACN5 第 12–17 章 | ✅ 够 |
| 2 | **营养需求标准**（最低量 / 推荐量 / 安全上限） | NRC **表 16-1~16-6**（MR / AI / RA / SUL，犬猫分生命阶段，共 339 行）；FEDIAF 表 III-3a、III-4a | ✅ 够，且两套可交叉验证 |
| 3 | **原料常规成分**（水分、蛋白、脂肪、纤维、能量） | NRC **表 14-1**（176 行，31 类 / 71 条原料） | 🟡 有骨架，**但窄且旧** |
| 4 | **原料矿物质**（钙、磷、可利用磷、镁…) | NRC **表 14-9**（172 行） | 🟡 同上 |
| 5 | **原料氨基酸 / 脂肪酸 / 维生素** | NRC 表 14-8（168 行）/ 14-4、14-6 / 14-10（172 行） | 🟡 同上 |
| 6 | **补钙与微量元素源的成分**（配方配平必用） | NRC **表 14-12**（钙磷钠钾源）、**表 14-13**（铜铁锌锰碘硒源） | ✅ 够 |
| 7 | **加工与储存损失、生物利用度** | NRC **表 9-2**（不同产品形态加工后回收率、每月储存损失）；正文 188 处生物利用度讨论 | ✅ 够 |
| 8 | **配方范式与补充剂剂量** | **SACN5 第 10 章**：3 个犬用配方 + 3 个猫用配方，含每味食材克数、碳酸钙 1.5 g、碘盐 0.5 g，以及成品营养分析结果 | ✅ 够（最直接的模板） |
| 9 | **体况与肌肉评估** | WSAVA 犬 BCS 2025、犬 MCS；AAHA 2021 营养与体重管理 | ✅ 够 |
| 10 | **个体与疾病约束** | SACN5 疾病章；ACVIM 23 份共识；IRIS 肾病 | ✅ 够 |

**10 块里 7 块够、3 块勉强——而且 3 块勉强的是同一件事。**

## 三、真正的缺口：原料库太窄、太旧

### 问题在哪

NRC 那张原料表覆盖面是这样的（实测抽出来的分类）：

> 动物源：Beef / Chicken / Egg / Fish / Lamb / Turkey / Milk / Whey / Shrimp / Poultry / Meat
> 植物源：Barley / Carrots / Corn / Oats / Peas / Potato / Rice / Sorghum / Soybean / Wheat / Beet / Molasses / Yeast

**共 31 类、约 71 条具体原料**，每条带常规成分 + 氨基酸 + 矿物 + 维生素。

但它有三个硬伤：

| 硬伤 | 说明 |
|---|---|
| **口径是美国饲料数据库** | 主词表是 IFN 编号体系，描述是 "Meat, mechanically separated"、"By-product meal, rendered" 这类工业饲料词，不是"鸡胸肉 300 g" |
| **年代久** | 2006 年数据，之后 USDA/USDA-FDC 的食材数据更新了很多轮 |
| **现代鲜食食材几乎不在里面** | 没有南瓜、山药、西兰花、羽衣甘蓝、三文鱼、蓝莓、奇亚籽这类我们真正在用的原料 |

### 但它仍然极有用

它给了三样我们真正缺的东西：

1. **每一个营养素的"标准值 + 变异系数 + 观测样本数"**——这是做配方容差计算的依据；
2. **可利用磷、生物利用度**这类只有专业书才有的修正项；
3. **补充剂源的化学构成**（碳酸钙含钙 40%、磷酸氢钙含钙磷多少）——配平钙磷没有这个就是在猜。

## 四、两个"不是缺资料、是要我们定规矩"的问题

| 问题 | 选项 | 影响 |
|---|---|---|
| **用哪套标准做基线** | NRC 的 RA / FEDIAF 的推荐水平 / AAFCO | 三套数值不一样，不先定会来回打架 |
| **上限（SUL）冲突听谁的** | 取严 / 取宽 / 按场景 | 直接决定配方能不能出 |

另外有一份**确实是缺的**：**AAFCO 官方标准全文**（NRC 大量引用但没归档）；中国宠物食品国标目前只在登记表里标"待核"。

> 如果只做内部参考配方，这两份可以先不补；如果要出产品标签或做合规声明，必须补。

## 五、回答你的问题

> **现有的知识来源，对"配方设计"这个最要紧的需求，够不够覆盖？**

**够，够到可以开始做的程度。** 而且比上一轮我判断的好得多——因为 NRC 一个来源就覆盖了需求标准、原料成分、补充剂成分、加工损失四块最硬的东西，SACN5 第 10 章还给了现成的配方模板和补剂量。

**不够的地方只有一处：原料库。** 而这不是"缺知识"，是"缺我们自己的食材数据"——NRC 的 71 条原料对不上我们实际用的菜。这块的解法不是找新文献，而是：

1. 把 NRC 的表完整抽出来当**交叉校验基准**；
2. 用 USDA FoodData Central / 中国食物成分表补现代食材；
3. 关键食材（我们自己配比用的那几十种）**做实测**。

## 六、建议下一步（只做一件事）

**把 NRC 的 11 张关键表抽成结构化数据，1,280 行。**

理由：
- 它是机器可读的，抽出来就能用，不用 OCR、不用猜；
- 抽完立刻能做一件事：**用 NRC 的标准值，把我们 `ingredient` 表里的营养数据核一遍**——现在原料表的数据是哪来的、准不准，没人验证过；
- 这一步不依赖"知识结构定稿"，也不依赖"原文档全部数字化"，可以独立做。

抽完你就能看到一个实证：**我们的原料表 vs NRC 的基准，差多少、差在哪几种原料上。**
