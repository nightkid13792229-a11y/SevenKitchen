# CKD 图书馆试点 v0.1

**日期**：2026-11-03
**目的**：用 CKD 一个主题，验证“段落检索 + 来源标签 + 逐字引用”的图书馆路径，先看模型能不能找到对的原文。
**不是**：不是生产服务；不生成答案；不改数据库；不重写 387 条结论。

---

## 一、数据

| 项 | 内容 |
|---|---|
| 文档 | 5 份：SACN5 第 37 章（CKD）、IRIS 分期、IRIS 犬治疗、IRIS 口袋指南、AAHA 2021 营养 |
| 段落 | **853 段**（过滤掉少于 40 字的碎片） |
| 问题 | **20 道** CKD 问题，见 `questions.json` |
| 金标 | 每题的“可接受段落”，允许多来源；不是唯一段落 |

> 选 CKD 的原因：原文、表格、数字、复查节奏最全，最容易判断“找得对不对”。

---

## 二、方法

- **BM25** + 简单词干（dogs→dog、binders→binder）。
- **中英术语表**：把“磷/蛋白/钠/钾/蛋白尿/UPC/血压/复查/能量/磷结合剂/自制鲜食”等扩成英文检索词。
- **表格/数字加权**：段落里数字比例高、且问题在问“多少/范围/上限/推荐”时，加权 1.9 倍。
- 两种模式：
  - `zh_expanded`：中文问题 → 术语表扩英文（模拟“查询理解”）。
  - `oracle_en`：人工写英文 query（上限，不是自动能力）。
- 评估：段落级 / 章节级 **R@1、R@5、R@10、MRR**。

## 四、四个发现

### 1. 中文扩词能把 R@10 拉到 100%，但 R@1 只有 15%

也就是：**找得到，但排不准**。

- 20 题全部能在前 10 段里找到可接受答案；
- 只有 3 题第一段就命中；
- 人工英文 query 的 R@1 是 70%。

说明下一步的关键不是继续堆关键词，而是 **reranker / embedding**：把“对的段落”从第 5–10 名提到第 1–3 名。

### 2. 表格/数字段落必须单独加权

CKD 的关键营养因素表（犬磷 0.2–0.5%、蛋白 14–20%、钠 ≤0.3%、钾 0.4–0.8%）在纯 BM25 下排到 **第 20 名**；加了“表格/数字”加权后才进前 5。

原因：这张表很短、词频低，长段的“磷代谢机制”反而词多分高。**表格不是普通段落，检索时要单独识别。**

### 3. 金标必须接受多来源

同一个 CKD 问题，答案可能在 SACN5、IRIS、AAHA 三处；只认一个精确段落 ID，会把“检索到了另一份正确指南”误判为失败。

试点里已经按“多来源可接受段落”建金标；生产评估还需要人工/模型判断“这段是否支持答案”，不能只看 ID。

### 4. 20 题 / 853 段是试点，不是基准

R@10 100% 不能外推到全库 27,902 段。下一步要扩题、扩库、加盲测。

---

## 五、局限

- 只在 CKD 相关 853 段里检索，不是全库。
- 术语表是人工写的，可能对 20 题过拟合。
- 没有 reranker、没有 embedding。
- 没有答案生成、没有逐字引用校验。
- 是 Python 研究脚本，不是后端服务/数据库查询。

---

## 六、下一步

1. **扩库**：把检索范围从 853 段扩到 27,902 段，加章节/主题元数据。
2. **扩题**：50–100 题，双人标注，留 20% 盲测。
3. **提 R@1**：加 reranker；对比 embedding；目标中文 R@1 ≥ 70%。
4. **接后端**：只读工具 `search_passages → get_passage → get_table → validate_citation`，先内部用。
5. **通过后再接** Agent / 健康分析；不直接开放顾客侧。

---

## 七、怎么跑

```bash
cd <repo>
python3 docs/knowledge-base/pilot/ckd/search.py --compare
python3 docs/knowledge-base/pilot/ckd/search.py --mode zh_expanded --show ckd-02
```

`--show ckd-02` 会打印“CKD 犬磷的推荐范围”前 5 段；你会看到第 5 段才是关键营养表，前 4 段是磷代谢机制——这就是“找得到但排不准”的典型例子。
