## 一段可以直接粘贴微信/邮件的话

> X 医生您好，麻烦您帮我们审一批狗狗健康知识条目。
>
> **我们是谁、要做什么**：我们是做狗狗鲜食定制的（SevenKitchen）。要上线一个「健康管理」功能 —— 顾客把自家狗的病历、体检报告、化验单记进来，系统基于我们自己的知识库给一份**初步的**健康解读和饮食建议。我们**不下诊断、不给药名和剂量、不解读 X 光/B 超片子**，所有涉及判断的地方都会写"建议咨询执业兽医"。
>
> **为什么必须请您审**：我们给自己定了条死规矩 —— **没经过专业审核的知识，一个字都不给顾客看**。所以这 189 条现在全部处于"待审核"状态，顾客侧完全看不到。您审过、标了"通过"的，才会进到面向顾客的回答里。
>
> **需要您做什么**：附件文档里每条知识后面有四个框 —— **通过 / 需修改 / 删除 / 拿不准**，您勾一个就行；有意见写在下面「意见」那一行，写多写少都可以，**只要指得出问题就够了**。拿不准的就勾"拿不准"，不用勉强 —— 我们不希望为了凑数让您背书。
>
> **时间紧的话**：文档开头列了优先级（风险等级"高"的 79 条、回答"要不要去医院"的 51 条、只有一个来源的 18 条）。您**先审这 79 条高风险**就已经帮了大忙，剩下的我们下批再来。需要的话我们也可以单独导一份"只有高风险 79 条"给您。
>
> **两条想请您特别留意**：
> 1. 其中一条（`clinical-009`，心肌病相关）引的出处是 **ACVIM 2020 关于猫心肌病的共识** —— 我们只做狗，这条要么换成犬的等价依据，要么删掉，请您定。
> 2. 有 138 条没填"紧急程度"（要不要立刻去医院）。涉及就医时机的条目缺这个字段，顾客就少一道保护，麻烦您顺手指一下。
>
> **我们的自律边界**（供您判断我们有没有越界）：不写化验参考区间（区间以顾客手上报告为准）、不下诊断结论、不给药名与剂量、不做影像解读、过敏与"不爱吃"严格分开说。
>
> **怎么回传**：md 上直接批注/打印后拍照；或者 csv 里填最右边那两列「审核结论」「审核意见」。您口述、我们代填也可以，我们会在文档里注明"由 X 医生口述、我方代填"。
>
> 辛苦了，有任何拿不准的条目随时问我们。

## 我们这边的执行口径（不用发给兽医）

| 兽医的结论 | 我们做什么 | 谁能做 |
|---|---|---|
| 通过 | 一条命令回填进审核登记表（带审核人 + 日期），条目立刻对顾客可见 | 我方，机械操作 |
| 需修改 | **不自动改**：打印清单，按意见改内容，改完仍是待审核，下轮再审 | 我方改字，兽医复核 |
| 删除 | **不自动删**：列入清单人工确认后从数据文件移除（编号不回收） | 我方执行 |
| 拿不准 | 原样保持待审核 | — |

回填命令（拿到填好的 csv 后）：

```bash
cd backend
# 先预览，确认无误加 --apply
npx ts-node -r tsconfig-paths/register scripts/apply-knowledge-review.ts <填好的.csv> \
  --reviewer "XX动物医院 X医生"
```
