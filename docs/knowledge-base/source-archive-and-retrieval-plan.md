# 资料库 B 方案 · 原文归档 + AI 读原文

**日期**：2026-09-30
**老板决定**：
1. 资料库做到 **B**——存档备查 **＋ 让 AI 直接读原文**（不只是人工消化成条目）
2. **全部来源下载到本地，并上传生产服务器**，不依赖网络的实时访问
3. 版权风险："要上生产服务器，先不用管版权问题"（决定人：老板，2026-09-30）

---

## 一、三层结构（关键：AI 能读原文，但下结论只能引用已审核条目）

```
第三层 · 原文层（新增）
  原文文档 → 解析成「章节 + 段落 + 页码」→ 存数据库
  AI 按「领域标签 → 章节」精确定位，读到原文段落并给出页码
  用途：佐证、溯源、营养师查阅、精确引用

第二层 · 结论层（现有，保持不动）
  202 条结构化知识条目，每条带出处、紧急程度、人工审核状态
  ★ 面向顾客的"结论"只能来自这一层

第一层 · 输出层
  分诊口径（立即就医 / 尽快就医 / 可观察）+ 固定免责声明
```

**为什么这么分**（这直接对应老板"边界把严一点"的要求）：

| 做法 | 后果 |
|---|---|
| 让 AI 自由读原文、自由下结论 | ❌ 原文里有诊断标准，AI 会顺着往下诊断；三份文档的片段还能被拼出一个谁也不认识的新结论 |
| **原文只用于佐证与溯源，结论仍走已审核条目** | ✅ 每句面向顾客的话都有出处、有紧急程度、有人审过 |

原文层允许 AI 做的事：
1. 给出**精确出处**（来自哪份指南、第几章、第几页）
2. **原样摘录**原文段落，并明确标注"以下为指南原文摘录，未经我方解读"
3. 营养师侧**点开看原文全文**

原文层**不允许** AI 做的事：拿原文片段拼出一个新结论、或据此下诊断。

## 二、技术选型（每一条都有实测依据）

| 需要的能力 | 选型 | 实测依据 |
|---|---|---|
| **文档解析** | 直接解析 PDF，**不需要 OCR** | 实测 `SACN5_37.pdf`、`SACN5_50a.pdf`、WSAVA 疫苗指南**都能抽出文字**，不是扫描件 |
| **章节定位** | **文件名数字＝章号**，每篇第 1 页有章标题 → 可自动建索引 | 实测 `SACN5_37.pdf` = 第 37 章「Chronic Kidney Disease」，与知识库引用的"第37章 慢性肾病"完全对上 |
| **检索方式** | **「领域标签 → 章节」映射表**（人工建一次）+ 关键词兜底 | 我们本来就知道这只狗是什么领域（`ckd`/`pancreatitis`…），可以直接定位章节，**比语义相似更准、页码更精确** |
| 中文关键词检索 | Postgres **`pg_trgm`**（本地已可用） | 实测可用 |
| **向量检索** | **暂不做** | 实测生产/本地 PG 是 **16 Alpine，没装 `pgvector`**（`pg_available_extensions` 里只有 `pg_trgm`、`unaccent`）。要上得换镜像或装扩展 |

### 为什么先不上向量检索

1. **我们已经有标签了**——狗的领域标签直接决定去哪一章，不需要让机器"猜语义"
2. 向量检索要引入**三样新东西**：embedding 模型（又一路外部 API）、切片质量、向量库
3. 中文医学文本的语义切片检索，效果未必比"标签＋关键词"好
4. **等前三条跑通、发现确实不够用，再加也不迟**——不影响 B 方案成立

## 三、存储方案

| 存什么 | 放哪 | 说明 |
|---|---|---|
| **原文文件**（约 550 MB） | 生产服务器**受保护目录**，不对公网开放 | 按规范命名（`来源ID/文件名`），附 SHA256 清单 |
| 解析后的文本（章节＋段落＋页码） | Postgres 新建表 | 供 AI 检索与营养师查阅 |
| 登记信息 | `docs/knowledge-base/source-register.md` | **新增"生产服务器路径"一列** |
| ~~原文文件进 git 仓库~~ | ❌ 不进 | 体积太大 + 版权 |

### 版权风险（已记录在案）

老板 2026-09-30 决定"先不用管版权问题"。已知风险与缓解措施：

| 风险 | 缓解措施 |
|---|---|
| 服务器泄露 → 被认为在分发受版权保护的教材 | ① 受保护目录，不对公网开放；② 仅营养师/管理员账号可访问；③ 登记表保留获取方式与合法持有说明 |

> 记录此决定不等于风险消失。将来若要对外开放任何原文内容，需重新评估。

## 四、执行步骤

| 步 | 内容 | 依赖 |
|---|---|---|
| **1** | **先修检索上限**（提示词只挑 15–25 条最相关） | 无——**必须最先做**，否则加了原文层提示词会更大 |
| 2 | 补齐下载缺失来源：WSAVA 其余专科指南、AAHA 免疫/老年/生命阶段、ACVIM 共识、国内法规 | 无 |
| 3 | 建统一归档目录：规范命名 + SHA256 + 更新登记表（含服务器路径列） | 步 2 |
| 4 | 批量解析全部原文 → 建**章节索引**（章号、标题、页码范围） | 步 3 |
| 5 | 建**「领域标签 → 章节」映射表**（人工，一次建好长期复用） | 步 4 |
| 6 | 上传生产服务器受保护目录 + 数据库建原文表 | 步 4 |
| 7 | 后端加原文检索接口；营养师侧加查阅页面 | 步 5、6 |
| 8 | AI 接入原文层：按标签取段落，随结论给出精确出处 | 步 7 |

> **步 1 不能跳过**：现在的检索是"命中就全抄"，没有上限。
> 再叠一个原文层，提示词会从 7.4 万 tokens 继续往上走，直接跑不动。
