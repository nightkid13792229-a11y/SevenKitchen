## 二、怎么做的

### 第 1 步：先定位，不先抽

用表题（`Table 12-5` / `TABLE III-3a`）在全文里定位，产出「文档 / 页码 / 表题 / 坐标」清单。
扫描 128 份 PDF，命中 1,391 处，其中**行首就是表题的**（真表题）486 处，去重后 484 张。

### 第 2 步：两条路并存

| 方法 | 适用 | 结果 |
|---|---|---|
| 坐标法（按表题位置切区、按 y 聚行） | 规则排版的表 | 159 张可自动 |
| **视觉读图**（渲染成图 → 读 → 转录成 JSON） | 双栏、横扫、跨页、图片型表格 | 其余全部 |

第一批用坐标法跑，只有 34% 能出可靠结构；剩下的转视觉。**视觉是主力。**

### 第 3 步：自动校验（关键）

视觉会看错行，所以每张表的**每个数字都要回到原文去查**：
数字必须出现在该页（及其前后各一页，防止跨页表误判）的文本层里。

- 全部命中 → 通过
- 有命中不了的 → 标记出来返工

## 三、返工过程

| 轮次 | 做法 | 通过数变化 |
|---|---|---|
| 1 | 首轮视觉转录 | 325 |
| 2 | 横排表识别（页面旋转 90° 自动转正） | 335 |
| 3 | 表跨页：同时看第 N、N+1 页 | 352 |
| 4 | 全文搜索"表题后紧跟大量数字"的页，重新渲染 | 369 |
| 5 | 校验范围扩到相邻三页（跨页表数字在下一页） | 381 |
| 6 | 200dpi 高清整页 + 要求识别"正文引用 vs 真表格" | **384** |

**这轮最重要的发现是第 5 轮**：一开始校验只比对表题所在那一页，把跨页表的数字全判成"错"，
导致一批本来正确的转录被打回。

### 剩下 4 张未通过

| 表号 | 情况 |
|---|---|
| T0019 | AAHA 2021 的 TABLE 2（BCS 评分对照），表中数值以图形呈现，文本层无数字可校 |
| T0024 | AAHA 2021 的 TABLE 7（资源清单），同上 |
| T0025 | AAHA 2021 的 TABLE 8（营养素与疾病），部分数值为图片，文本层取不到 |
| T0026 | TABLE 8 的续表 |

这四张**内容已经转录出来**（行数 3–31 行），只是"数字回原文核对"这一步过不了——
因为原文那部分本身是图。属于校验方法的限制，不是转录错误。

## 四、产物格式

每张表一个文件，例如 `tables/T0012.json`：

```json
{
  "tableId": "T0012",
  "caption": "TABLE 12-5. Comparison between the recommended daily allowances...",
  "columns": ["Nutrient", "10-kg dog", "per 100 g"],
  "rows": [["Protein (g)", "24", "17"], ["Calcium (mg)", "1,000", "10"]],
  "verify": { "numbers": 30, "found": 30 }
}
```

`_index.csv` 是总表：每张表的 文档 / 页码 / 表题 / 状态 / 列数 / 行数 / 校验结果 / 备注。

## 五、已知局限

1. **合并单元格**：跨行合并（如"General (PE and consultation)"横跨多行）在转换时会被压到首行，
   后续行该列留空。阅读时按"向下延续"理解即可。
2. **图片型表格**：4 张无法用文本层校验，但内容已转录。
3. **表题误判 15 处**：这些"表题"其实是正文引用。它们说明**更新版文档里表号会变**，
   将来如果条目引用这些表号，需要人工确认对应的是哪一张。
4. **跨页表**：已尽量合并，但个别超长表可能只录到首屏。
