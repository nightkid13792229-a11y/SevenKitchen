## 零、先纠正一个认知（本次最重要的发现）

线上公开接口实测（2026-09-18）：

| 指标 | 实测值 |
|------|--------|
| 公开可订购食谱 | **24 道**（24 个系列，每系列 1–4 个生命阶段版本） |
| 累计浏览 | 16,094 |
| 累计收藏 | 426 |
| **免费食谱单（DIY）生成量** | **2,717 份** |
| 已支付成品订单 | 229 个（文档记录，未复核） |

| 漏斗 | 转化率 |
|------|--------|
| 浏览 → 生成免费食谱单 | **16.9%** |
| 浏览 → 支付成品订单 | **约 1.4%** |

**结论：我们真正的生意，是一条「免费营养方案」的宽漏斗，成品只是它最窄的一条出口。**

2,717 份免费食谱单 = 2,717 个**已经信任我们的营养能力**、并且**已经暴露了「我家狗该吃什么」需求**的真实用户。
他们今天没有被任何方式承接：没有预拌粉、补剂点击没有追踪、也没有被引导到成品。

> **不要在 1.4% 的窄漏斗上抠按钮，要在 16.9% 的宽漏斗上建变现。**

## 一、产品结构（v3 修正版）

### 1.1 一个免费工具 + 三条收费产品线

| 类型 | 是什么 | 面向谁 | 我们的收入 | 现状（2026-09-18 核实） |
|------|--------|--------|-----------|------------------------|
| **免费工具** | 现成食谱浏览 + 按狗算量 + **DIY 制作单** | 想做/预算有限的家长 | 不直接收费（**获客引擎**） | ✅ 已上线，2,717 份生成量 |
| **产品线 ①** | **成品鲜食**（含试吃装） | 想省事的家长 | 成品差价 | ✅ 已上线；试吃装待建 |
| **产品线 ②** | **补剂预分装** + 推荐商品链接 | 用免费工具的 DIY 家长 | ① 分装差价 ② 推广佣金 | 🔀 **已移交另一任务会话**（代码已完整开发，未提交） |
| **产品线 ③** | **食谱定制** ¥300 | 现有食谱**不适用**的家长（对症） | 定制费 | ⚠️ 顾客端页面已写好但路由被摘，目前靠人工 |

> ⚠️ **重大修正**：本文 v1/v2 建议「新建预拌粉产品线」——**该判断已被推翻**。
> 工作目录中已存在一套完整的补剂商城实现（后端 + 后台 + 小程序全链路），
> 且**成本倍率 / 分装服务费 / 运费三项已完全解耦，后台可随时调整**，与业务要求完全一致。
> 详见 `docs/plans/2026-09-18-supplement-shop-design.md`。本设计文档只做**链路归位**，不重复定义该产品。

### 1.2 ⚠️ v2 的一处错误（已修正）

v2 把「食谱定制」当成了 DIY 客户的降级选项——**这是错的**。

正确的关系是：

| | DIY 客户 | 定制客户 |
|---|---|---|
| 用什么食谱 | **现成的 24 道**（可以自己微调） | **我们为他新设计的**一道 |
| 为什么 | 想自己做饭 / 控制预算 | 现有食谱**不适用**（对症、特殊需求） |
| 收费 | **免费** | **¥300** |
| 我们怎么赚钱 | 预拌粉 + 补剂佣金 | 定制费（买成品则抵扣） |

**两者是不同客群，不是同一条漏斗的两档。**

### 1.3 定制 ¥300 的抵扣结构（已确认）

| 场景 | 收多少 |
|------|--------|
| 只要定制食谱 | **¥300** |
| 定制食谱 + 我们做成品 | **¥300 全额抵扣货款** |

- 对成品客户：实际免费（与今天一致，不产生新阻力）
- 对只要食谱的客户：为专业性付费
- ¥300 同时对成品客户形成"必须用掉才划算"的拉力

## 二、顶层结构总览

```
                        【我家狗该吃什么】
                                │
                 ┌──────────────┴──────────────┐
            日常主食线                      特殊需求线
        （现成食谱 · 健康犬）          （现成食谱不适用）
                 │                              │
     ┌───────────┴───────────┐         ┌────────┴────────┐
  ① 买成品                ② 自己做    ③ 定制 ¥300      选对症现成食谱
  （含试吃装 = 新客入口）   DIY制作单    │                → 买成品
     │                       │          ├─ 要做成品 → ¥300 抵扣
     │                       ├─ 预拌粉（我们分装）        └─ 只要食谱 → 付 ¥300
     │                       └─ 补剂推荐链接（佣金）
```

**核心原则：把「嫌贵」从流失变成降级。**
觉得成品贵的人，不必离开——他可以去 DIY（我们卖预拌粉、赚补剂佣金），而且他还是我们的用户。

## 三、两条内容产线：分区分口径

### 3.1 现状问题：货架气质是「病号饭」

24 道公开食谱封面角标：

| 分类 | 数量 | 角标 |
|------|------|------|
| 疾病/症状标签 | **5 道** | IBD、草酸钙结石、胆泥淤积、皮肤与毛发、体重管理 |
| 正向标签 | 4 道 | 均衡营养、高适口性（成年犬）×2、适合春季食用 |
| 无角标 | 15 道 | — |

说明文案直接写疾病名与处理建议（例：*"草酸钙结石无法通过饮食或者药物溶解…请立刻送医！！！"*）。

**两个后果**：
1. **合规风险**：健康标签清理过一轮（"抗炎""低敏"下线），但**疾病名从封面角标与说明文案漏过去了**——而封面角标是首页最显眼的元素。
2. **商业风险**：健康犬家长看到"IBD""结石""胆泥"，会判断"这不是给我家狗吃的"然后退出。**把日常主食卖成了病号饭，主动放弃大盘。**

### 3.2 对策：分区分口径（不是删掉疾病词）

| | 日常主食线 | 特殊需求线 |
|---|---|---|
| 面向 | 健康犬家长（主推，做大基数） | 有明确状况的家长（做深信任） |
| 位置 | 首页默认 | 独立专区 |
| 封面角标 | 食材 / 口味 / 生命阶段（正向） | 状况标签 |
| 文案口径 | 好吃、营养全、省事 | 配比依据 + **适用边界** + **不替代兽医诊疗** |
| 背书 | FEDIAF / 商超采购 / 现做冷链 / 售后承诺 | + **Setar 完整营养评估报告**（已有，几乎没用） |
| 出口 | 买成品 / 自己做 | **定制 ¥300** / 对症现成食谱 |

### 3.3 ⚠️ 用词红线（已确认）

- **禁止使用「处方粮」这个词。**
- 建议对外统一用：**「专属定制」「专项营养定制」**；内部按状况分类（肠胃敏感 / 体重管理 / 结石管理等），页面上写"根据狗狗的具体情况定制"，**不做疗效承诺**。
- 疾病名称与功能表述出现在**日常货架**上是风险；出现在**独立专区 + 明确适用边界 + 免责声明**里，才讲得清楚。
- 最终对外口径需过一次合规确认。

## 四、三档交付的落位（不要三个按钮并排）

**三类客户不应该在同一个决策点被并列询问。**

| 位置 | 承担什么 | 不承担什么 |
|------|----------|------------|
| **首页 / 入口** | 按**需求**分流：日常主食 / 特殊需求 | 不问交付方式 |
| **食谱详情页** | 主 CTA = **买成品**；次入口 = 一行小字「想自己做？免费生成食谱单」 | 不并列三个价格档 |
| **DIY 制作单生成后** | ← **卖预拌粉的位置**（顾客刚看到"需要 N 种补剂"，痛点最强） | — |
| **特殊需求入口** | ← **卖定制 ¥300 的位置** | — |

**为什么预拌粉不放详情页**：同类替代摆在旁边会削弱成品转化。放在 DIY 单生成后，是**解决顾客刚刚产生的真实麻烦**。

## 五、试吃装（v3 重做）

### 5.1 定位：口味测试装（三个目标合一）

1. **新客入口**——降低第一次 ¥345–976 的决策风险
2. **口味画像采集器**——挑食是鲜食第一大顾虑
3. **评价生产线**——229 单产出 0 条购买评价

### 5.2 规格与形态（已定稿）

| 项 | 规格 |
|----|------|
| 道数 | **5 道菜**（系统推荐，覆盖 5 种蛋白：鸡/牛/猪/鱼/兔，自动避开过敏原） |
| 顾客可换 | ✅ **可自行替换其中任意 1–N 道**（**不限制**换成什么菜） |
| 每道 | **2 袋 × 80g = 160g**（**固定 2 袋**，不做"1 袋可加购"） |
| 总净重 | **800g** |
| 价格 | **实时计算**（不统一定价，因每道原料成本不同） |
| 起订量 | **豁免** 1000g |
| 售后 | 同样适用「破损变质无理由全额退款」 |
| 抵扣 | ❌ **不做**全额抵扣 |

> **为什么固定 2 袋、不做"1 袋可加购"**（已确认的结论）：
> 克重低的时候，每单的**大头是运费与人工，食材占比很小**，减量省不了多少成本，
> 却会让"每种蛋白只尝一次"的试吃结论不可靠。**固定 2 袋的单位经济学更好，顾客价值也更实在。**

### 5.3 「优惠前 / 优惠后」怎么算（技术形状）

- 用**试吃装专属算法**：同一份成本，套**比成品更低的倍率**
- 同一套菜同时算两遍：
  - **优惠前（划线价）** = 按**成品倍率**算出的价格
  - **优惠后（实付）** = 按**试吃倍率**算出的价格
- 页面展示：`正装口径 ¥XXX → 尝鲜价 ¥YYY ｜ 立省 ¥ZZ`

### 5.4 ⚠️ 定价的三个硬约束（必须先知道）

**约束一：固定成本刚性。** 冷链箱 + 保温袋 + 冰袋 + 顺丰生鲜运费 ≈ **¥30–50**，这是**每一单都要付的固定成本**。
摊在正装 3kg 上 vs 摊在试吃装 800g 上，**单克成本相差 3–4 倍**。

**约束二：5 道菜 = 5 次小批量生产 + 10 个分装袋。** 分装人工与包材都比单道正装更多。

**约束三：首页参考价的口径是「1000g 起订、单道菜、含运费」算出来的**（后端在最小起订量 1000g 上算价再除以 10），所以线上 ¥12.77–21.21/100g 本身已经是最小订单口径。

**推论：试吃装的「单克价格」很难低于正装。** 这是物理决定的，不是定价策略问题。
所以：

> ❌ **不要用"每天多少钱"来宣传试吃装**（会显得比正装贵）
> ✅ **要用"一单尝 5 种、不用下 5 单、不用凑 1000g 起订、只付 1 次运费"来宣传**

### 5.5 建议的定价公式（供你用真实成本核对）

```
试吃装实收 = (5 道菜原料成本 + 分装包材 + 冷链箱/冰袋 + 运费 + 分装人工) × 试吃倍率
优惠前划线价 = 同样的成本 × 成品倍率
```

| 项 | 说明 |
|----|------|
| 成品倍率 | 当前 ≈ **1.67×**（成本 ÷ 0.6，即 40% 毛利） |
| **试吃倍率建议** | **1.25× 左右**（相当于正装口径的 **75 折**） |
| 预估成本 | 约 **¥105–150**（视 5 道菜与真实运费） |
| **预估实收** | **约 ¥130–190，视选菜而定**（实时计算，不统一） |

> 💡 **一个能让"优惠"叙事更真实的小技巧**：把「优惠前」的锚点定义成
> **"这 5 道菜如果分开买正装，最低要 ¥857 + 5 次运费"**（5 道 × 1000g 起订 × 均价），
> 而不是 800g × 单价。这个对比是**真实成立**的——顾客确实无法用别的方式只花一次运费尝到 5 道菜。

### 5.6 ⚠️ 技术前置（必须先立）

后端目前**一单只能装一个食谱**（所有下单路径只处理第一个商品 `items[0]`，购物车能力已被删除）。
试吃装需要：
1. **一单多道菜**的下单与快照能力
2. **多道菜合并定价**（预览 + 下单两条路径）
3. **试吃装专属倍率**参数（现有 `discountRate` 是个空壳，三处调用写死 1.0，可复用）
4. 跨菜品的**合并包材与运费**计算

**这是整个设计里工程量最大的一块，必须先评估再排期。**

```
包材费 = 每袋单价 × 袋数                      ← 后台可调
运费   = 一口价 / 独立运费模板，支持包邮门槛   ← 后台可调（默认 8 元）
```

## 七、链路重新分工（每页只回答一个问题）

| 页面 | 回答的问题 | 应该放 | 应该拿走 |
|------|-----------|--------|----------|
| **首页** | 我家狗适合吃鲜食吗？买哪个？ | 两条产线入口；**简化版个性化推荐**；试吃装入口；售后承诺一句话 | 24 道菜平铺成"创建时间倒序"的信息流 |
| **食谱详情页** | 这道菜好在哪？适合我家狗吗？ | 一句话卖点；适合/不适合；原料与营养要点；**购买评价** | 操作信息（完整配比、做法）→ 交给 DIY 单 |
| **订购成品页** | 买多少？多少钱？凭什么信你？ | 每天成本 / 可吃几天 / 交付节奏 / **售后承诺** / **配餐实拍** / 商超采购 | 上游已讲过的故事（只复述，不重新论证） |
