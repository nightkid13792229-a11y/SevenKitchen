## 0. 前置准备（不做的项目会"看不到"，不是 bug）

| # | 准备项 | 怎么做 |
|---|--------|--------|
| 0.1 | **打开正确的目录** | 微信开发者工具 → 导入项目 → 选择<br>`/Users/zhaochen/Documents/SevenKitchen/miniapp/dist/build/mp-weixin` |
| 0.2 | **关闭域名校验（如有报错）** | 右上角 **详情 → 本地设置 → 勾选「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」** |
| 0.3 | **准备一个"已登录 + 已建狗狗档案"的状态** | 因为订购页的价格必须按狗狗体重算。<br>若没有档案，订购页会显示「请先创建狗狗档案」，属于正常表现 |
| 0.4 | **准备随时登出** | 「我的」页最下方有「**退出登录**」按钮 —— 验证首单路径（未登录状态）时要用 |
| 0.5 | **打开 Network 面板** | 用于验证埋点（第 5 节） |

> ⚠️ **为什么必须用 `dist/build` 而不是 `dist/dev`**：
> 发布构建会**强制走生产接口**，而本次的内容改动（卖点、合规封面角标）都在生产数据库里。
> 打开 `dist/dev/mp-weixin` 会连到本地旧数据库，**看不到卖点和合规后的角标**。

## 3. ⭐ 首单路径修剪（本次最核心的改动）

### 3.1 登录按钮文案

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 点「买成品」→ 弹窗里点「去登录」→ 进入登录页 | 按钮文案是「**微信一键登录**」<br>（**不应**是"手机号快捷登录"） |

### 3.2 ⭐ 登录后直达订购页（关键）

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 在**未登录**状态，从详情页点「买成品」→ 去登录 → 完成登录 | **直接落在「订购成品」页**<br>❌ 不应退回食谱详情页让用户重新点一次「买成品」 |

> 这是本次最重要的一项。原来登录后会退回详情页，用户的购买意图被打断。

### 3.3 不再强制绑手机 / 不再强制填资料

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 用一个**没有绑定手机号**的新账号登录 | **不会被强制跳到手机绑定页**，直接进入目标页 |
| ☐ | 同上 | **不会被强制跳到头像昵称完善页** |
| ☐ | 走到结算页点「提交订单」 | 这时**才会**要求绑定手机号（这是设计如此：手机号在真正需要履约时才要） |

> 说明：绑定手机号这一步没有取消，只是**从"登录时"后移到了"结算时"**，避免在顾客刚表达购买意愿时就拦一道。

### 3.4 游客放弃登录后不丢意图

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 未登录 → 点「买成品」→ 弹窗选「**暂不**」 | 留在当前页，不跳转 |
| ☐ | 未登录 → 去登录页 → 点「**暂不登录，先逛逛**」 | 回到首页 |
| ☐ | 之后再次进入登录页并完成登录 | 会**自动续上**之前想去的订购页（而不是只回首页） |

## 5. 首页 · 个性化推荐（简化版）

> **前提**：必须**已登录**且账号下**有狗狗档案**，否则该区块**故意隐藏**。

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 进首页 | 出现一块「**给 {狗狗名字} 的推荐**」 |
| ☐ | 副标题 | 一行理由，形如「成犬 · 12kg · 已避开档案里的过敏与挑食食材」 |
| ☐ | 卡片数量 | **最多 3 张**，横向排列 |
| ☐ | 点任意一张卡 | 进入该食谱详情页，并带着狗狗 |
| ☐ | 底部按钮 | 「**按推荐配一周**」，点击直接进订购页 |
| ☐ | 登出后再看首页 | 推荐区块**消失**（不会残留上一个账号的数据） |
| ☐ | 反向检查（重点） | ❌ **不应**出现「专属优先 / 通用也适合」双分组、星级、匹配分、狗狗切换器 —— 这些正是上一版被下线的原因 |

## 6. 埋点（打开 Network 面板操作）

| ☐ | 操作 | Network 里应出现 |
|---|------|------------------|
| ☐ | 打开首页 | `analytics/funnel/events`，`eventName = home_view` |
| ☐ | 点进任意食谱 | `detail_view` |
| ☐ | 点「买成品」 | `tap_buy` →（未登录时）`login_prompt_shown` |
| ☐ | 完成登录 | `login_done` |
| ☐ | 到达订购页 | `order_page_view` |
| ☐ | 价格算出来后 | `price_ready` |
| ☐ | 进入结算页 | `checkout_view` |
| ☐ | 点「按推荐配一周」 | `tap_recommend_buy` |

> 请求失败**不影响任何功能**（埋点是旁路，失败只打日志）。

## 7. ⚠️ 这里验不了、需要真机的两项

| 项 | 原因 |
|----|------|
| **微信支付真正拉起** | `requestPayment` 在模拟器不可用，必须真机 + 体验版/正式版 |
| **手机号授权** | 开发者工具不支持 `getPhoneNumber` 真实授权 |

也就是说：**「点买成品 → 登录 → 建档 → 出价 → 结算」都能在这里走完，只有最后「提交订单 → 拉起支付」那一下需要真机。**
