| # | 准备项 | 怎么做 |

## 3. ⭐ 首单路径修剪（本次最核心的改动）

### 3.1 登录按钮文案

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 点「买成品」→ 弹窗里点「去登录」→ 进入登录页 | 按钮文案是「**微信一键登录**」<br>（**不应**是"手机号快捷登录"） |

### 3.2 ⭐ 登录后直达订购页（关键）

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 在**未登录**状态，从详情页点「买成品」→ 去登录 → 完成登录 | **直接落在「订购成品」页**<br>❌ 不应退回食谱详情页让用户重新点一次「买成品」 |

> 这是本次最重要的一项。原来登录后会退回详情页，用户的购买意图被打断。

### 3.3 不再强制绑手机 / 不再强制填资料

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 用一个**没有绑定手机号**的新账号登录 | **不会被强制跳到手机绑定页**，直接进入目标页 |
| ☐ | 同上 | **不会被强制跳到头像昵称完善页** |
| ☐ | 进入**确认订单页** | **不再**被立刻弹去手机绑定页，可以先正常看订单内容 |
| ☐ | 点「提交订单」 | 这时**才会**要求绑定手机号（唯一强制点） |
| ☐ | 把小程序切到后台再切回来 | **不再**弹出任何手机号弹窗 |
| ☐ | 「我的」页点：狗狗列表 / 收藏的食谱 / 我的制作单 / 我的补剂订单 / 意见反馈 | **不再**被拦去绑手机 |

> **2026-09-19 修订**：原先「任何页面 + 每次切后台回来」都会强制弹手机绑定（且不可取消），
> 现已在 12 处移除，只保留「提交订单」这一个真正需要的强制点。
> 依据：手机号在下单与支付中都不是必需的（微信支付靠账号身份取 openid，
> 物流面单用收货地址里的收货人电话）。详见 `2026-09-19-phone-binding-scope.md`。

### 3.4 游客放弃登录后不丢意图

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 未登录 → 点「买成品」→ 弹窗选「**暂不**」 | 留在当前页，不跳转 |
| ☐ | 未登录 → 去登录页 → 点「**暂不登录，先逛逛**」 | 回到首页 |
| ☐ | 之后再次进入登录页并完成登录 | 会**自动续上**之前想去的订购页（而不是只回首页） |

## 5. 首页 · 个性化推荐（简化版）

> **前提**：必须**已登录**且账号下**有狗狗档案**，否则该区块**故意隐藏**。

| ☐ | 验证点 | 期望看到 |
|---|--------|----------|
| ☐ | 进首页 | 出现一块「**给 {狗狗名字} 的推荐**」 |
| ☐ | 副标题 | 一行理由，形如「成犬 · 12kg · 已避开档案里的过敏与挑食食材」 |
| ☐ | 卡片数量 | **最多 3 张**，横向排列 |
| ☐ | 点任意一张卡 | 进入该食谱详情页，并带着狗狗 |
| ☐ | 底部按钮 | 「**按推荐配一周**」，点击直接进订购页 |

| ☐ | 反向检查（重点） | ❌ **不应**出现「专属优先 / 通用也适合」双分组、星级、匹配分、狗狗切换器 —— 这些正是上一版被下线的原因 |

## 7. ⚠️ 这里验不了、需要真机的两项

| 项 | 原因 |
|----|------|
| **微信支付真正拉起** | `requestPayment` 在模拟器不可用，必须真机 + 体验版/正式版 |
| **手机号授权** | 开发者工具不支持 `getPhoneNumber` 真实授权 |

也就是说：**「点买成品 → 登录 → 建档 → 出价 → 结算」都能在这里走完，只有最后「提交订单 → 拉起支付」那一下需要真机。**
