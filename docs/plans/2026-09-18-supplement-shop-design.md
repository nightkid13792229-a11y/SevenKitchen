# 补剂商城 · 设计与实施计划

> 状态：设计已确认，第 0 期进行中
> 创建日期：2026-09-18
> 目标一句话：用户在 DIY 制作单页配完餐后，一键买齐这一单需要的补剂；我们分装后独立发货。

---

## 1. 业务闭环

```
DIY 制作单页 →「一键购买补剂」→ 补剂下单页（可勾选 / 看用量与价格）→ 支付
    → 后台生成【补剂分装工单】→ 拣原料 → 分装 → 贴标 → 打包 → 独立发货
    → 小程序「我的订单」里作为独立一类展示
```

## 2. 已确认的关键决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 商品形态 | **按制作单用量分装成小份**卖（不卖整瓶） |
| 2 | 分装粒度 | **按补剂品种分开装**（混装留到后续） |
| 3 | 计价方式 | **成本 × 倍率 + 固定分装服务费**，倍率/服务费在后台可调 |
| 4 | 发货方式 | **独立发货**（补剂客户与鲜食客户基本是两类人） |
| 5 | 订单落地 | **新建独立的「补剂订单」体系**，不动现有鲜食订单 |
| 6 | 第一期范围 | 最小闭环：下单支付 + 分装工单 + 人工发货（库存先手工登记） |
| 7 | 售后口径 | 缺货 / 发错 / 破损 / 量不对 → **无理由退款或免费补发** |
| 8 | 销售名义 | **分装小样** |
| 9 | 部分购买 | 允许只买其中几样（默认全选、可逐项取消） |
| 10 | 液体补剂 | **暂不支持分装**（现有库存中也没有） |

## 3. 补剂库存盘点结论（本地库，33 条档案）

**物理形态只有 3 类，没有液体补剂。**

| 形态 | 条数 | 分装方式 | 精度 | 需要设备 |
|---|---|---|---|---|
| 粉剂 | 11（含自制鸡蛋壳粉 2 条） | 电子秤称重 | ±2% | 0.01g 电子秤 |
| 粉剂·按勺 | 其中海藻粉按"平勺"计量 | 用原瓶自带的勺数勺 | ±1 勺 | 不需要 |
| 片剂 | 8 | 数片 | 精确 | 不需要 |
| 胶囊 | 14 | 数粒 | 精确 | 不需要 |
| 液体 | 0 | — | — | — |

### 盘点发现的数据问题

1. **7 条进货价为 0**：海带片、骨粉片（KAL）、Swanson 铜片、Jarrow B-Right、NOW L-OptiZinc 锌、鸡蛋壳粉 ×2。→ 不能上架，需先定价。
2. **5 处单位口径不一致**（`unit_display_label` 与 `properties.display_unit` 不同）：
   柠檬酸钙粉、柠檬酸钾胶囊、柠檬酸镁胶囊、洋车前子壳粉、鸡蛋壳粉（无品牌）。
3. **同名重复档案**：柠檬酸镁胶囊 ×2、鱼油胶囊 ×2、骨粉 ×2（NOW / KAL 属合理替代）、鸡蛋壳粉 ×2。

> **最终上架清单必须以线上库里跑出来的结果为准。**

## 5. 分装有效期与储存（合规口径）

### 5.1 法律上限

> 采用分装形式生产的食品，标注的生产日期应当为所分装食品的生产日期或者分装日期，标注的保质期不得超过所分装食品的保质期。
> —— 我国食品标识法规（FAOLEX 收录）

因此：

```
分装后有效期 = min(原瓶剩余保质期, 分装日 + 形态保守期限)
```

### 5.2 我们的保守期限（原厂没承诺，必须自己压）

| 形态 | 分装后最长标示 | 说明 |
|---|---|---|
| 粉剂 | 6 个月 | 比表面积大，氧化/吸潮快 |
| 片剂 / 胶囊 | 9 个月 | 主要风险是吸潮 |

**硬性规则**：原瓶剩余保质期不足 **90 天** 的，不允许上架。

### 5.3 储存条件

**统一 SOP：遮光铝箔自封袋 + 干燥剂 + 阴凉干燥（25℃ 以下），不冷藏。**

- 胆碱的有效成分是重酒石酸胆碱，本身即为**吸湿性结晶粉末**，必须防潮。
- 海藻粉中的碘在储存过程中会损失，需避光防潮。
- 牛磺酸稳定，但胶囊壳（明胶）吸潮会变软粘连。
- **不建议冷藏**：用户每天反复取用，冷热交替会在粉体/胶囊表面结露，反而更易受潮。

### 5.4 标签必印内容

品名 · 分装量 · **分装日期** · **有效期至** · 储存条件 · **分装者名称** ·
原产品名称/品牌/原保质期 · 「**分装小样，非直接食用，请按食谱用量添加**」

## 6. 定价与运费

### 6.1 定价公式

```
补剂费 = Σ(用量 × 单位成本) × 加价倍率
服务费 = 每单固定（含铝箔袋、干燥剂、标签）
运费   = 走补剂专属运费模板
```

- 对用户**按"添加量"卖**（制作单上显示的量），不按加过 5% 损耗的采购量卖——否则用户对不上账；分装损耗由倍率覆盖。
- **单位成本 = 进货价 ÷ purchase_to_base_ratio**（例：海藻粉 89.41 ÷ 2522 = 0.0355 元/平勺）。

### 6.2 运费

现有两条模板（顺丰特快生鲜 23 元首重 / Default CN 12 元首重）**都不适用**：

- 补剂一单可能只有 50~200g，按"首重+续重"永远只收最低档，续重规则形同虚设；
- 保价费对补剂无意义；
- 不需要顺丰。

**采用方案（已实现）**：**不改共用的鲜食运费模板表**，把补剂的运费策略整个放进 `supplement_shop_config`：

- `shipping_mode = FLAT_RATE`（默认）：直接用 `flat_shipping_fee` 一口价，不碰运费模板；
- `shipping_mode = TEMPLATE`：可选一条现有模板按重量计费（注意模板里的保价费也会计入，建议给补剂单独建一条保价费为 0 的模板）；
- `free_shipping_threshold`：商品金额达标即免运费。

这样补剂和鲜食的运费完全解耦，互不影响。

**入口位置**

- 「DIY 制作单」页的营养补充剂表格下方：**一键购买补剂**（仅当商城开放且有补剂时展示）
- 「我的」页功能列表：**我的补剂订单**

**数据传递**：补剂行带用量，塞不进 URL，走本地存储 `supplementPurchaseDraft` 在页面间传递；
价格与可购买性一律以服务端报价为准，本地只存 `ingredientId` 与用量。

**上架规则（已定）**：**凡是「可用于生产」的补剂都可以分装售卖**，不需要逐个人工审批。

- 「可用于生产」= 能出现在 DIY 制作单上（`diy_enabled`），或已被食谱引用；
- 后台「补剂上架清单」提供**一键上架全部可用于生产的补剂**：先按系统建议补齐空白档案，
  再把通过体检的全部置为可售，补不齐的（如无进货价）单独列出原因交人工处理；
- 单个补剂的上架开关仍保留，用于临时下架某一样。

**上架守卫**：档案存在 ERROR 级问题时，`supplementRetailEnabled` 会被拒绝并回滚
（无进货价、缺物理形态、缺原厂保质期都属于 ERROR）。

**报价计算口径**（`supplement-pricing.service.ts`）：

```
分装量 = 用量向上取整（片/粒/平勺→整数；按克→0.1）
补剂费 = Σ(分装量 × 单位成本) × 加价倍率，再按圆整规则处理
服务费 = 按单固定 或 金额 × 袋数
包材费 = 每袋单价 × 袋数
商品小计 = 补剂费 + 服务费 + 包材费
运费   = 商品小计 ≥ 包邮门槛 ? 0 : 一口价/模板运费
```

**安全口径**：客户端只提交 `ingredientId` + 用量，**价格永远由服务端按补剂档案现算**；
未上架 / 未定价 / 形态未配置的补剂会被单独列出原因，且只要清单里有这类补剂就拒绝下单。

**订单状态机**：

```
PENDING_PAYMENT → PAID → PACKING（分装中）→ PACKED（已分装待发）→ SHIPPED → COMPLETED
                     ↘ CANCELLED / AFTERSALE
```

一个补剂 = 一袋（按品种分装）。分装结果（批号 `batch_no`、原瓶到期日 `source_expiry_date`、
标签效期 `packed_expiry_date`、分装时间 `packed_at`）直接记在订单行上，
不再单独建分装工单表 —— 后台的"分装工单"就是这个订单的拣货视图。

### 微信支付接入

**复用鲜食订单的同一套商户配置与签名逻辑**，只把「商户单号」换成 `SP` 前缀的补剂订单号：

```
补剂订单商户单号 = order.orderNo   （如 SP20260918-001）
鲜食订单商户单号 = 订单 ID 去横线   （32 位十六进制）
```

因为十六进制里不可能出现 `S`，回调时按 `SP` 前缀分流，两条链路互不干扰：

```
POST /api/v1/payments/wechat/notify
   → 解密 resource（AES-256-GCM）
   → out_trade_no 以 SP 开头？ → 补剂订单分支
   → 校验金额（分）→ trade_state=SUCCESS → 置为已付款
```

**可靠性设计**

- **幂等**：`confirmPaymentFromWechat` 对已付款订单直接返回，微信重复回调不会重复写、不会报错；
- **金额校验**：回调金额与订单金额不一致时**拒绝入账**并记 error 日志；
- **主动兜底**：回调可能延迟或丢失，小程序在 `requestPayment` 成功后调用
  `sync-payment`，服务端主动查微信订单状态并补记收款；
- **超时自动关单**：沿用 `payment_config` 的支付时限，超时后再次发起支付会自动取消订单；
- **优雅降级**：支付未配置（或用户缺少微信身份）时，前端自动退回「待人工确认收款」，
  订单依然成立，不阻塞业务。

**支付不是前置条件**：后台「人工确认收款」一直保留，用于线下转账等场景。

### 售后闭环

三种处理方式，都在后台「补剂订单 → 售后」里：

| 方式 | 行为 |
|---|---|
| **线上退款** | 调用微信退款接口原路退回；退款单号带 `RFSP` 前缀，退款结果回调自动更新状态 |
| **免费补发** | 按原单原样生成一张 **0 元补发单**，直接进入待分装；原单标记售后中并回指补发单 |
| **仅登记** | 只标记售后中并留痕，资金动作线下处理（适合非微信支付或已在商户后台手工退款） |

**防重复与防误操作**

- 退款幂等：已成功或处理中的退款直接返回既有记录，**不会重复打款**；
- 补发防重：同一订单只能补发一次，重复操作提示已有的补发单号；
- 退款前置校验：必须已支付、且是**微信线上支付**的订单才能走线上退款，
  否则明确提示改用「仅登记」，避免"以为退了其实没退"；
- 退款金额可为部分金额，但不能超过订单金额。

### 分装标签

**标签数据由服务端算好**（`getOrderLabels`）：一个补剂一袋，一袋一张标签。

```
品牌名（可配置，同时作为分装者）
海藻粉            ← 品名
23平勺            ← 分装量（已向上取整）
分装日期 2026-09-18    有效期至 2027-03-18
批号 B2609-01          原瓶效期 2028-06-30
储存 避光、密封、阴凉干燥处保存
原品 NOW FOODS · 227g/瓶
订单 SP20260918-004 / 赵晨
分装小样，非直接食用，请按食谱用量添加
```

**关键约定**

- **未分装不允许打印**：标签上的效期是分装那一刻算出来的，分装前没有效期，接口直接拒绝；
- **储存条件随订单快照**：下单时把原料档案里的储存条件写进订单行，
  之后改档案不会让已发货的标签"变脸"；档案没填时用「避光、密封、阴凉干燥处保存」兜底；
- **打印排版**：后台 `LabelPrint.vue`，单张 60×40mm，A4 每页 21 张（3 列 × 7 行），
  打印时自动隐藏侧边栏与按钮，可直接用 A4 标签纸或热敏标签机。

**打印入口**：后台「补剂订单」中完成分装后自动引导打印；`待发货/已发货/已完成` 的订单行上也有「打印标签」。

**干燥剂提示**：分装方案要求每袋配 1 包食品级硅胶干燥剂，因此标签默认追加
「内含干燥剂，请勿食用」（可在「补剂商城设置 → 干燥剂提示」关闭）。

**包材与工具采购清单**：见 `docs/plans/2026-09-18-supplement-packaging-plan.md`。

### 标签效期与分装守卫

```
标签效期 = min(原瓶到期日, 分装日 + 效期系数)
         （粉剂 +6 个月；片剂/胶囊 +9 个月；油性软胶囊 +6 个月）
```

**油性内容物优先取油性档**：鱼油、鱼肝油这类软胶囊内容物易氧化酸败，
「补剂上架清单」里打开「油性」开关后，效期自动走更保守的一档，不影响普通片剂/胶囊。

分装时强制校验（`packOrder`）：

- 必须覆盖订单里**全部袋子**，漏填直接拒绝 —— 避免发出没有标签效期的货；
- 原瓶剩余保质期低于 `min_remaining_shelf_life_days`（默认 90 天）时**拒绝分装**，
  提示改走退款或换货 —— 不让临界货流到用户手里；
- 分装行不属于本订单时拒绝。

### 已知边界

- **切换替代品后的用量口径**：DIY 制作单允许用户把某个补剂换成别的品牌/规格，
  此时界面上的用量是按**被选商品**的浓度算的，而我们从自己的库存分装，
  需要的量应按**我们的浓度**重算。当前 MVP 按界面显示量下单，待业务确认后再收紧。
- **液体补剂**：暂不支持分装，下单时会被服务端拦截并提示原因。

## 10. 合规提醒

"分装小样"不能消除资质要求。国内线上销售膳食补充剂类产品通常需要**食品经营许可证（含保健食品经营项目）**，
且"拆零分装"是监管重点。落地时必须：

1. 确认经营许可范围覆盖；
2. 标签保留原产品信息与分装者信息；
3. 页面文案统一用"分装小样、按食谱添加"，**不出现任何保健功能宣称**。
