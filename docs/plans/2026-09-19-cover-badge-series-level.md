# 封面角标：系列级词表选择制（方案 C）· 实施记录

> 版本：v1（2026-09-19）
> 上游：`2026-09-18-special-needs-wording-compliance.md`（合规用词确认）
> 状态：**已实施并部署到生产**

## 一、解决的两个问题

| # | 原问题 | 现在 |
|---|--------|------|
| 1 | 封面角标是 Recipe（每个生命阶段版本各一份）上的**自由文本**，同一道菜要改 N 次 | 上移到**食谱系列**层级，**改一次全系列生效** |
| 2 | 自由文本**无任何校验**，`IBD`/`抗炎`/`低敏` 这类违规词可以直接填进去，而角标展示在首页橱窗 | 只能从**合规词表**里选（最多 2 个），且词表本身也加了禁用词校验 |

---

## 二、数据模型

**新增表 `recipe_series_cover_badge`**（系列 ↔ 词表标签）

| 字段 | 说明 |
|------|------|
| `series_id` | 归属的食谱系列 |
| `health_tag_id` | 只允许引用 `recipe_health_tag`（合规词表） |
| `sort_order` | 多个角标时的显示顺序 |

- **不复用** `recipe_health_tag_assignment`（那是"这个版本有哪些健康标签"，用于筛选，语义不同）
- 存**引用而非文字**：词表改一次名，所有角标自动跟着变
- `Recipe.coverTitle` **原值保留不动**，作为迁移期兜底与回滚依据

## 三、词表变化

| 动作 | 内容 |
|------|------|
| **新增 2 个词** | 「适口性优先」（适用对象）、「含马肉」（原料事实） |
| **新增禁用词校验** | `POST/PUT /admin/health-tags` 现在会拦下 `抗炎`/`低敏`/`IBD` 等违规表述 |

**校验结果**：词表 45 个词**全部通过**；抽样验证 `抗炎`/`低敏`/`IBD` 均被正确拒绝。

> ⚠️ 后果需知：以后在后台新增词表词时，如果踩到禁用词会被拦下并提示命中了哪个词。

## 四、接口变化

| 接口 | 变化 |
|------|------|
| `GET /admin/recipe-series/:seriesId/cover-badges` | 新增：读取系列角标 |
| `PUT /admin/recipe-series/:seriesId/cover-badges` | 新增：保存（≤2 个、必须在词表内、双保险过禁用词校验） |
| `GET /recipes`（公开列表） | 新增返回 `coverBadges: string[]` |
| `GET /recipes/:id`（公开详情） | 新增返回 `coverBadges: string[]` |

**取值顺序**：`coverBadges` → `coverTitle`（兜底） → 不显示。
保证迁移期间**不会出现"角标突然全没了"**。

## 五、后台编辑页（本次重点优化）

「封面标题」自由输入框 **→ 替换为「封面角标」选择器**：

| 优化点 | 说明 |
|--------|------|
| **分组下拉多选** | 按 原料事实 / 工艺特性 / 营养特性 / 适用对象 / 标准背书 分组，最多 2 个 |
| **实时预览** | 右侧渲染封面缩略图 + 底部渐变条 + 角标文字，**与小程序实际效果一致** |
| **改正错误说明** | 原文案写"显示在封面**左上角**"，实际在**底部**；已改正 |
| **标明生效范围** | 明确写"本设置对**整个系列**生效（全部生命阶段版本共用）" |
| **可就地新增词** | 词表里没有想要的词时，直接点「新增」；新增时过禁用词校验 |
| **不可自由输入** | 彻底消除了违规词溜进来的入口 |

## 九、修复记录（2026-09-19 追加）

首版交付后发现词表管理弹窗存在三个问题，已修复并重新部署。

### 9.1 问题：弹窗叫「管理健康标签」，与角标的关系说不清

**根因**：复用了原有的「管理健康标签」弹窗，未改名。

**修复**：
- 按入口区分标题：从角标入口打开时显示「**管理封面角标词表**」
- 弹窗顶部固定加一条说明：

  > 这是**全站共用的合规词表**：健康标签与封面角标用的是同一套词。
  > 在这里新增、改名或删除，会同时影响两处。

### 9.2 问题（较严重）：从角标入口新增的词，永远选不到

**根因**：原「新增」逻辑不传 `parentId`，于是新词被创建成一个**顶层分组**；
而角标下拉只列出"分组下的词"，因此新增的词不会出现在下拉里。

**修复**：
- 新增表单**必须先选分组**（默认选中第一个组），提交时带上 `parentId`
- 未选分组时阻止提交并提示

**验证**：模拟新增「含鹌鹑（临时验证）」→ 归属「原料事实」→ 角标下拉可见 → 已清理。

### 9.3 问题：弹窗列表是扁平表，分组与词混在一起

**根因**：原弹窗用扁平列表渲染，运营容易把「原料事实」这种分组误当成标签。

**修复**：
- 改为**按分组展开的层级表格**（可折叠），并加「分组 / 标签」类型列
- 分组下还有词时，**禁用删除**并提示（避免外键 `Restrict` 报错或误删整组）

### 9.4 顺带修复：分组被当成可选标签

「健康标签」勾选区原先把**分组**也列成了可勾选项（`healthTagOptions` 用的是扁平全量列表）。

已修正为**只列分组下的词**。
线上核实：58 条标签关联中，挂在分组上的为 **0 条**，因此该修正无数据影响。
