# 生命阶段板块：文案精简 + 未匹配视觉区分

> 日期：2026-09-19
> 状态：**✅ 已实施**

---

## 一、起因

食谱详情页的生命阶段卡把「这个版本是否匹配我家狗狗」这件最重要的事，淹没在几行说明文字里：

```
14 周以上幼犬                        ← 标题
满 14 周以上的幼犬，正在快速长身体      ← 通俗补充（删）
根据敢敢的档案自动展示该生命阶段版本。   ← 保留
本品可选：小于14周幼犬 · 14周以上幼犬 · 普通成年犬 · 低能量成年犬 / 老年犬   ← 可选清单（删）
                                                          切换
```

**问题**：
1. 那两行不构成决策依据，只把这一块撑长、稀释了"匹配与否"
2. **未匹配时完全没有视觉区分** —— 与匹配状态长得一模一样

---

## 二、排查中发现的两个真实缺陷

### 缺陷 1：后端有 5 种匹配状态，前端只处理了 2 种

后端 `lifeStageMatch.matchType` 取值：

| matchType | 含义 | 改前是否有提示 |
|-----------|------|:---:|
| `MATCHED` | 完全匹配 | —（正常） |
| **`MANUAL_MISMATCH`** | **人工指定了不匹配的版本** | ❌ **完全没有** |
| `FALLBACK_ADULT` | 无完全匹配，回退到成犬版本 | ⚠️ 有一行文字 |
| `FALLBACK_FIRST` | 无完全匹配，回退到首个可用版本 | ⚠️ 有一行文字 |
| `LEGACY` | 旧数据 | — |

前端只认 `FALLBACK_ADULT / FALLBACK_FIRST`，**`MANUAL_MISMATCH` 被漏掉了** ——
这正对应截图里「14 周以上幼犬」那一屏：标题没有"已匹配"前缀，却没有任何提醒。

### 缺陷 2：「整行高亮提醒」根本没有样式

`recipe-detail/index.vue` 里有一段：

```html
<!-- 未找到完全匹配版本：整行高亮提醒 -->
<view class="life-stage-fallback-notice">
  <text class="life-stage-fallback-icon">!</text>
  <text class="life-stage-fallback-text">{{ lifeStageVersionCopy }}</text>
</view>
```

但**全项目搜不到 `.life-stage-fallback-notice` 的任何 CSS** —— 注释写着"高亮"，实际是一行裸文字。

### 缺陷 3：警告色与"信任背书色"撞车

DIY / 成品订购页的生命阶段提醒用的是 `#f6efe0 底 + #b08d4f 边`（暖金）。
但**金色在这套设计里已经被用作正向背书**：

- 「符合 FEDIAF」营养标准卡
- 「采购标准」Banner
- 售后「全额退款」保障卡

→ 同一个颜色既表示"值得信赖"又表示"警告"，读者分不清。
（项目里其实**已经定义了 `--sk-danger` / `--sk-danger-soft` 这两个警示色 token，却一直没用上。**）

## 三、改动

### 3.1 文案精简（食谱详情页）

删掉两行：
- 「通俗补充说明」（`lifeStagePlainHint` / `LIFE_STAGE_PLAIN_HINT`）
- 「本品可选：…」（`availableLifeStageSummary`）

改后：

```
已匹配：低能量成年犬 / 老年犬          切换
根据敢敢的档案自动展示该生命阶段版本。
```

同时把那个没有样式的 `.life-stage-fallback-notice` **合并进卡片** ——
用颜色承担提示，而不是再堆一行文字。

### 3.2 未匹配 → 整卡转警示色

| 状态 | 视觉 |
|------|------|
| 匹配 | 现在的浅色卡（正常） |
| **未匹配**（MANUAL_MISMATCH / FALLBACK_*） | **警示色**：`--sk-danger-soft` 底 + `--sk-danger` 描边 + 圆形 `!` 图标 + 标题与正文同色 +「切换」按钮转实心警示色 |

并对不匹配给出**明确原因**（而不是原来那句中性的"可切换查看…"）：

- `FALLBACK_*` → 「当前狗狗档案没有完全匹配版本，已展示可用替代版本。」
- `MANUAL_MISMATCH` → 「当前展示的版本与狗狗的生命阶段不一致，建议切换后再下单。」

### 3.3 推广到 DIY 制作页与成品订购页

两页的生命阶段提醒卡（`.warning-card`）同步改为警示色。

**作用域严格限定**：`.warning-text` 与「最低起送量警告」是**共用类**，
所以新增的是 `.warning-card .warning-title / .warning-text / .btn-continue` 作用域规则，
**没有**直接改共享类，避免把另一个警告也染红。

## 四、⚠️ 实施中踩的坑（记录备查）

我第一次是用**全局字符串替换**把金色改成警示色（`#f6efe0` → danger-soft 等），
结果**误伤了一大片无关样式**：卖点金条、高亮卡片、健康标签、来源方案提示……全被染红。

**教训**：**颜色/样式绝不能做全局字符串替换** —— 同一个色值在这套设计里承担了
"点缀金"和"警告金"两种语义，必须按**选择器作用域**精准修改。
已全部回退后重新按作用域实施，并逐个核对宿主选择器。

## 五、给后续的建议（未包含在本次范围）

| 建议 | 说明 |
|------|------|
| `.min-order-warning`（最低起送量）也用金色 | 语义上它同样是"当前不能直接下单"的提醒，建议一并转警示色，与生命阶段提醒统一 |
| 把警示样式抽成共享 class/组件 | 现在三处各写一遍，长期容易跑偏；可考虑 `.sk-warning-card` 全局类 |
| `--sk-danger` 已被启用 | 原先项目里定义了却从未使用，本次首次启用，后续新增警示样式应统一取这个 token |
