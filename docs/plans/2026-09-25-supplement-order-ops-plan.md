## 二、动手前先修两个真实缺口

这两个是查现状时发现的，不修的话任务一直接是错的。

### 缺口 1（严重）：加量后标签数量不对

「加量」的语义是**每个补剂多做几袋同样规格的小袋**。买 3 份，海藻粉就有 3 袋，**每一袋都要贴一张标签**。

但现在：

- 标签接口每个补剂只返回 **1 条**记录，且不含袋数
- 后台打印页是「一条记录 = 一张标签」

结果：买 3 份的订单，只会打出 1 张海藻粉标签，**另外 2 袋没标签可贴**。分装现场会直接卡住。

必须改成：每个补剂按袋数展开成 N 张标签（同规格，内容相同，可用序号区分如 `1/3`）。

### 缺口 2：状态口径不统一

后台有 8 个状态，顾客只需要看到 5 个。需要定死映射关系：

| 顾客看到 | 后台实际状态 |
|---|---|
| 未付款 | PENDING_PAYMENT |
| 已付款 | PAID、PACKING、PACKED（生产中间态不暴露给顾客） |
| 已发货 | SHIPPED |
| 已完成 | COMPLETED |
| 售后中 | AFTERSALE |
| （**已取消**） | CANCELLED |

注：你列的 5 个状态里没有「已取消」，但取消过的订单顾客应该还能查到，否则会以为订单丢了。建议保留第 6 个筛选（见第四节决策 4）。

## 三、三项任务怎么做

### 任务 1：工作台能看补剂订单，并能打标签

**做法**：工作台订单管理里加一个「补剂订单」并列入口（与鲜食订单并列，不混在一起——两者作业方式差别太大：鲜食是生产+烹饪，补剂是分装+贴标）。

要做的：

1. **补剂订单列表**（工作台）
   显示：订单号、顾客、金额、状态、袋数、下单时间。支持按状态筛选。
   后端接口已有：`GET /admin/supplement-shop/orders`、`/orders/summary`

2. **补剂订单详情**（工作台）
   补剂清单（品名、规格、分装量、袋数）、加量份数、收货信息、备注。

3. **订单操作**（后端接口全部已有，只差界面）
   确认收款 / 完成分装（填批号 + 原瓶到期日，系统自动算标签效期）/ 发货 / 取消 / 退款 / 重发 / 售后。
   其中「完成分装」必须能填数据——否则打不了标签（后端强制：未分装不允许打印）。

4. **核心：补剂标签打印**（这块是主要工作量）
   - 新建一套 **60×40mm** 的标签排版，与鲜食那套 70×100mm 完全独立（不改动鲜食排版，避免打错鲜食标签）
   - 走现有的精臣 B3S 蓝牙通道（机器不用换，换一卷 60×40mm 热敏纸即可）
   - 一单多袋时按袋展开：每个补剂打 `袋数` 张
   - 支持单张补打（现场贴坏一张是常事）
   - 打印前必须先有分装数据

**验收**：工作台能看到补剂订单 → 确认收款 → 填分装数据 → 打出标签 → 每袋一张、内容与规格一致。

---

### 任务 2：顾客「我的补剂订单」并入「我的订单」

**做法**：删掉「我的」页里的「我的补剂订单」独立入口，「我的订单」变成两类订单通吃的列表。

要做的：

1. **后端加一个统一订单列表接口**（一次返回两类订单，分页与数量统计才准确）
   > 不建议前端同时调两个接口再合并：分页会乱、状态数量统计会错。
   > 这条是本方案里唯一需要新增的后端接口。

2. **状态筛选 Tab** 按第二节的口径统一（未付款 / 已付款 / 已发货 / 已完成 / 售后中 / 已取消），数量统计含两类订单。

3. **列表项**要能一眼区分是补剂还是鲜食（补剂显示袋数，鲜食显示份数/餐数）。

4. **点击进入各自的详情页**（补剂进补剂详情，鲜食进鲜食详情），保持现有页面不动。

5. **「我的」页**移除「我的补剂订单」入口，保留「我的制作单」（制作单不是订单，不并入）。

**验收**：下 1 单补剂 + 1 单鲜食 → 「我的订单」里两条都在、状态筛选和数量正确、各自点进去详情正确。

### 任务 3：Web 后台在「订单管理」里管理补剂订单

**做法**：在「订单管理」下加一个「补剂订单」标签页，直接复用**已经存在**的补剂订单页面（列表/详情/操作都现成），不再重写一套。

要做的：

1. 「订单管理」页面顶部加两个标签：`鲜食订单` / `补剂订单`，默认停在鲜食。
2. 补剂标签页复用现有页面组件。
3. 原「补剂商城 → 补剂订单」菜单项的去留见第四节决策 2。
4. 顺带把缺口 1（标签按袋展开）在后台打印页一起修掉。

**验收**：后台「订单管理」能切到补剂订单、能看到列表与详情、能操作、能打印标签。

## 四、需要你定的 5 件事

**决策 1：工作台里补剂订单怎么放？**
- A（推荐）与鲜食订单并列成两个入口 —— 作业方式差别大，分开放不易搞混
- B 混在一个列表里加类型筛选 —— 少点一次，但两种作业容易看串

**决策 2：后台「订单管理」怎么放？**
- A（推荐）在订单管理里加「补剂订单」标签页，原「补剂商城 → 补剂订单」菜单**保留**（两条路都能进）
- B 加标签页，同时**移除**原菜单项（结构更干净，但后台同事的习惯入口会变）

**决策 3：标签尺寸 —— 这是本方案最大的实际风险**

包材方案文档定的是 **60×40mm**，但要装 9 行内容（含储存条件、原品、订单号/顾客、免责声明）。按热敏纸最小可读字号 2.3mm 估算，9 行正文加分隔线在 40mm 高度里**非常挤，很可能打出来看不清**。

- A 保持 60×40mm，**砍内容**（去掉订单号/顾客、储存条件，保留品名/数量/日期/效期/批号/免责）
- B **换更大标签纸**（如 60×60mm 或 70×50mm），内容全保留。机器不用换，只是换卷纸，成本略高
- C（推荐）**先按 60×40mm 打一张实物**看能不能读清，再定 A 还是 B

建议走 C —— 这种事纸上看不出来，打一张最省事。

**决策 4：已取消的订单要不要给顾客看？**
- A（推荐）保留，作为第 6 个筛选 —— 顾客取消过或超时关闭的单还能查到
- B 不显示 —— 严格按你说的 5 个状态，但顾客可能以为订单丢了

**决策 5：加量订单的标签要不要印「第几袋 / 共几袋」？**
- A（推荐）印上（如 `1/3`）—— 现场分装时能核对有没有漏贴
- B 不印 —— 标签更简洁，但少一道核对

## 五、建议的执行顺序

1. **先修缺口 1**（标签按袋展开）—— 它是任务 1 的前置，且是现场会出错的点
2. **决策 3 打样** —— 标签尺寸定不下来，排版就没法写，这一步最好尽早
3. 任务 1 的「订单列表 + 详情 + 操作」（不含打印）
4. 任务 1 的「标签排版 + 打印」
5. 任务 2（后端统一接口 + 我的订单合并）
6. 任务 3（后台加标签页）

任务 2 和 3 相对独立，可以在任务 1 打印部分等待打样的时候并行做。

## 六、风险与注意事项

- **鲜食标签不能被影响**：现有标签排版和打印流程是上线在用的，补剂那套必须完全独立，不能改公共配置。
- **打印机标签纸**：现用的是 70×100mm，补剂要换 60×40mm（或决策 3 定的尺寸），换纸后**鲜食标签要记得换回去**——这个操作风险要提前跟分装的人说清楚。
- **加量订单的袋数**：标签数量 = 补剂种类数 × 份数。一单 8 种补剂 × 3 份 = 24 张标签，现场要有心理准备。
- **分装数据是标签的前提**：不填批号和原瓶到期日就打不了标签，这是后端强制的，流程上要顺。
