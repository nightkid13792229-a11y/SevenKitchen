| 6 | 食材推荐不锁死在原料库 | **接受。** AI 自由推荐原料，库内库外都行，是否采用由设计师/管理员决定 |

## 一、产品架构的底线：一道菜覆盖 5 个场景

这是本版最重要的结构性判断。

**你要的形态：** 1 道菜 → 1 个系列 → 5 个生命阶段配方全部齐备。顾客不管养的是幼犬、成犬还是老年犬，点进同一道菜都能买到。

**这里有件事必须先讲清楚：「业务阶段」和「FEDIAF 场景」不是一一对应。**

系统里有两套并存的刻度，这是统计口径会打架的根源：

| 业务阶段（顾客看到的） | 对应的 FEDIAF 场景（营养标准） |
|------------------------|-------------------------------|
| 小于 14 周龄幼犬 | `EARLY_GROWTH_REPRODUCTION` |
| 大于等于 14 周龄幼犬 | `LATE_GROWTH` |
| 繁殖期母犬 | `REPRODUCTION` |
| 低能量需求成年犬（95ME） | `ADULT_MER_95` |
| 普通成年犬（110ME） | `ADULT_MER_110` |

而且实测存在**错配**：例如「鸭胸猪里脊鸡蛋青花鱼」的 `PUPPY_14_WEEKS_PLUS`（≥14 周幼犬）业务阶段，底下挂的 FEDIAF 场景有两个不同值（`LATE_GROWTH` 和 `REPRODUCTION`）。也就是说**业务阶段标了 5 个，营养口径并不等于 5 个都算对了**。

**两种口径的现状（都对，但看的是不同东西）：**

| 覆盖数 | 口径 A：FEDIAF 场景跨度 | 口径 B：业务阶段 |
|--------|------------------------|------------------|
| **5 个（完整）** | **1 道** | **6 道** |
| 4 个 | 5 道 | 2 道 |
| 2 个 | 2 道 | 15 道 |
| 1 个 | 19 道 | 6 道 |

> 口径 A 按 `design_recipe.fediaf_dog_scenario` 去重，统计范围是在售 29 个系列；
> 口径 B 按 `recipe.series_life_stage` 去重，同样是在售 29 个系列。
> 差异原因：① 有 6 个在售系列没有关联设计稿（发布路径早于设计器，或从别处录入），口径 A 看不到它们；② 部分系列一个业务阶段下重复挂了两个场景。
> 本文正文讨论**主产品线的 26 道菜**，另有 3 个系列是清理遗留与个人定制（土豆大米鳕鱼火鸡胸、糙米南瓜鸡胸肉【有机】、Lucky的最新兔肉食谱）。

**两个口径共同指向的结论：**

- **按业务阶段看**：15 道菜停在"2 个阶段"（高活动 + 低活动），只覆盖成犬——**这是最大的一堆**。
- **按营养场景看**：只有 1 道菜真的把 5 个场景都算达标了。
- 无论哪个口径，**幼犬（<14 周）和繁殖期都是最空的**。

**这不是"需要新增多少道菜"的问题，而是"现有 26 道菜基本都没做全"。** 这是本次规划的第一优先级，也是最容易见效的一件事。

我建议把「5 阶段齐备率」定为产品线的核心健康指标，挂在驾驶舱最显眼的位置——**并且要同时显示两个口径**，因为业务阶段齐了不等于营养场景算对了。

## 二、产品线怎么分：三个轴

按你的意思，不按生命阶段分。我提三个轴，**主轴是功能调理性**。

### 2.1 主轴 · 功能调理性

按「这道菜解决什么问题」分。**这个体系后台已经有了，只是没用起来**——`recipe_health_tag` 表里 45 个标签，其中「营养特性」这一类就是功能标签。

**现有在售配方（79 份）的功能标签挂载情况：**

| 功能标签 | 已挂载的配方份数 |
|----------|------------------|
| 易消化 | **27** |
| 低脂 | **23** |
| 挑食友好 | 8 |
| 其余 42 个标签 | **0** |

> 注：这里数的是**配方份数**（含各阶段版本），不是菜数。一个菜有 5 个阶段版本，5 份都会各自挂标签。

整个功能体系只用了 3 个标签。而知识库里**已经躺着 30 多个功能领域的权威条目**（胰腺炎、肾脏、泌尿结石、心脏、关节、皮肤、肝脏、内分泌、肿瘤、认知障碍、体重管理、口腔、血液……），一条都没变成产品。

**我建议的功能产品线分组（按需求端证据排序）：**

| 功能组 | 证据 | 现状 |
|--------|------|------|
| **基础均衡主食** | 26 道菜的主体 | 过密，需收敛 |
| **呵护肠胃 / 易消化 / 低脂** | 顾客反馈明确提「胰腺炎专用食谱」；已有易消化 27 + 低脂 23 的标签基础 | **有底子，可立刻升级成产品线** |
| **体重管理** | 知识库有完整 weight-management 领域；市场刚需 | **空白** |
| **皮肤毛发** | 知识库有 skin 领域；原有产品线规划里就有这 5 道疾病标签菜 | **标签存在、未体系化** |
| **关节与术后恢复** | 顾客反馈明确提「髌骨手术后适合哪款」 | **空白** |
| **心脏呵护** | 顾客反馈明确提「心脏病小狗需要额外补充」 | **空白** |
| **泌尿结石** | 知识库有 urolith 领域；原产品线原有相关菜 | **标签存在、未体系化** |
| **老年犬认知与肌少** | 顾客反馈明确提「老年犬适合的」；犬档案 7 岁以上占 **19.6%** | **空白** |
| **挑食友好** | 已有 8 份配方挂载 | 有底子 |
| **单一动物蛋白（过敏排查）** | 标签已建（`单一动物蛋白`），但 **0 份配方挂载** | **空白，且是低致敏刚需** |

### 2.2 辅轴 · 食材多样性

这个轴后台也已经有了——`recipe_health_tag` 里的「原料事实」类标签，已经建了 **24 个「含XX」标签**（含牛肉、含羊肉、含马肉、含兔肉、含鹿肉、含火鸡、含鸭胸、含鸡胸、含三文鱼、含青口贝、含生蚝、含鳕鱼、含青花鱼、含小米、含燕麦、含糙米、含红薯、含土豆、含山药、含芋头、含藜麦、含胡萝卜、含西兰花、含西葫芦、含南瓜、含卷心菜、含小麦胚芽油、含三文鱼油）。

**而且封面的角标已经在用这批标签了**（`recipe_series_cover_badge` 表，12 条记录）：

| 系列 | 角标 |
|------|------|
| 兔里脊大米土豆 | 含兔肉 |
| 小米山药猪肉 | 含猪肉 |
| 小米山药猪肉（副本） | 含猪肉 |
| 糙米西葫芦牛肉 | 含牛肉 |
| 红薯三文鱼鸡胸 | 含鸡胸 |
| 鸭胸猪里脊鸡蛋青花鱼 | 含鸭胸 |
| 马肉兔肉白米土豆 | 含马肉 |
| 鸡胸牛里脊三文鱼 | 含鸡胸 |
| 燕麦三文鱼猪肉 | 适口性优先 |
| 糙米红薯青花鱼牛肉 | 适口性优先 |
| 十字花科全谷物三文鱼鸡肉 | 符合 FEDIAF 2025 |
| 猪里脊青花鱼藜麦小米 | 符合 FEDIAF 2025 |

**看出来两个问题：**

1. **角标 12 条里 10 条在说"里面有什么"（原料事实），只有 2 条在说"对你有什么好处"（适口性优先、符合 FEDIAF）。** 这是在卖成分表，不是在卖价值。
2. **在售的 29 个系列里只有 9 个有角标（31%）。** 像十字花科全谷物三文鱼鸡肉、小米鳕鱼鸡胸、兔里脊大米土豆这些主力产品，要么没角标，要么挂的是"含XX"而不是卖点。**「含羊肉」标签建了却没有任何产品挂。**

**食材多样性轴建议这样组织：**

| 分组 | 内容 | 说明 |
|------|------|------|
| **常规蛋白** | 鸡、鸭、猪、牛 | 走量基本盘 |
| **稀有蛋白** | 兔、鹿、火鸡、**羊、马** | 换肉轮换、低致敏；羊和马标签已建、产品为零 |
| **水产** | 三文鱼、鳕鱼、青花鱼、比目鱼 | 已有覆盖 |
| **贝甲** | 生蚝、青口贝 | 已有覆盖 |
| **碳水基底** | 糙米、大米、小米、燕麦、藜麦、红薯、土豆、山药、芋头 | 已覆盖较全 |
| **蔬菜水果** | 西兰花、胡萝卜、南瓜、西葫芦、卷心菜…… | 覆盖较窄，需扩 |

**这个轴的价值：** 保证每只狗都能找到"没吃过的肉"。吃腻了、疑似过敏要排查、单纯想换口味——都要靠这个轴。

### 2.3 辅轴 · 应季轮换

按季节推荐当季食材。**这个轴不新建产品线，而是给现有菜做"应季变体"或"应季推荐位"。**

理由：应季食材本质是**同一道菜的原料替换**（秋冬换根茎类、夏季减油），不需要变成独立 SKU，否则货架会被撑爆。

**数据现状：** 本来已上线的 26 道菜里有「适合春季食用」的角标分类，但现在 12 条角标里**一条应季标签都没有**——这个轴等于完全没做。

## 三、需求端数据：我们现在真实知道什么

按你的要求，只列需求端、且可核实的数据。

### 3.1 犬档案：4569 份（最硬的需求信号）

**年龄分布（按生日实算，不依赖那个 91% 为空的生命阶段字段）：**

| 年龄段 | 犬数 | 占比 |
|--------|------|------|
| 0–3 月 | 8 | 0.2% |
| 3–6 月 | 41 | 0.9% |
| 6–12 月 | 424 | 9.3% |
| 1–2 岁 | 1229 | 26.9% |
| 2–4 岁 | **1286** | **28.1%** |
| 4–7 岁 | 685 | 15.0% |
| 7–10 岁 | 466 | 10.2% |
| 10 岁以上 | 430 | 9.4% |

**读出来的：**
- **7 岁以上合计 19.6%（896 只）**。老年犬是个大群体，而现有 26 道菜里**没有一道是老年犬专属的**。
- 1–4 岁占 55%，是绝对主力。
- 幼犬（0–12 月）占 10.4%。这个数偏低是因为**顾客通常不给幼犬建档**，实际需求被低估——但不能拿它当"幼犬不重要"的依据。

**体重分布：**

| 体重段 | 犬数 | 占比 |
|--------|------|------|
| 5kg 以下 | 1342 | **29.4%** |
| 5–10kg | 1752 | **38.3%** |
| 10–20kg | 917 | 20.1% |
| 20–30kg | 292 | 6.4% |
| 30kg 以上 | 266 | 5.8% |

**读出来的：** **小型犬占 67.7%（5–10kg 加 5kg 以下）。** 现有菜的分量设计、颗粒感、适口性偏好，应该按小型犬为主来考虑。20kg 以上的大型犬只占 12.2%——大型犬幼犬的钙磷比是特殊需求，但客群基础小。

**活动量分布：**

| 活动量 | 犬数 | 占比 |
|--------|------|------|
| NORMAL | 2464 | 53.9% |
| LOW | 1637 | **35.8%** |
| RESTING | 248 | 5.4% |
| HIGH | 216 | 4.7% |
| WORKING | 4 | 0.1% |

**读出来的：** **低活动 + 静养合计 41.2%**，高活动只有 4.7%。这意味着**"低活动成年犬"才是主力场景，不是高活动**——而现有 26 道菜里高活动版本反而比低活动更常见。这个方向可能反了。

**体况评分（BCS）：** 76.1% 是 5 分。注意这**不能当真实数据用**——生产库里 76% 的体况评分是表单默认值。真正偏胖（BCS 6–9）占 10.2%，偏瘦（1–3）占 4.9%。

## 四、AI 能力方案

### 4.1 核心原则

| 原则 | 做法 |
|------|------|
| AI 只做选择、编排、解释 | 用量和达标判定一律由现有 FEDIAF 评估引擎算 |
| AI 可以自由推荐原料 | 不锁死在原料库；库内库外都推荐，标注清楚，由人决定 |
| AI 可以新增原料 | 推荐的新原料可以直接落成新的原料条目 |
| 每句话可倒查 | 强制引用知识库条目编号（沿用现有机制） |
| 功能标签不是 AI 说了算 | 先跑营养评估 → 达标后才能挂"低脂""易消化"这类承诺性标签 |
| 人终审不可绕过 | AI 输出一律是建议 |

### 4.2 第 1 层 · 产品线驾驶舱（新建页面）

**页面布局：**

```
┌────────────────────────────────────────────────────────────┐
│ 顶部：5 阶段齐备率  业务阶段 6/26  ·  FEDIAF 场景 1/26          │
│      （两个口径都显示，因为业务阶段齐 ≠ 营养场景算对了）           │
│      （这是产品线第一健康指标）                              │
├────────────────────────────────────────────────────────────┤
│ 区块 A：功能覆盖矩阵                                         │
│   行 = 功能标签（易消化/低脂/体重管理/皮肤/关节/心脏/泌尿…）  │
│   列 = 有产品 / 标签已建但无产品 / 完全空白                   │
├────────────────────────────────────────────────────────────┤
│ 区块 B：食材多样性矩阵                                       │
│   行 = 「含XX」标签（24 个）                                 │
│   列 = 覆盖菜数 / 是否有 5 场景齐备的产品                     │
├────────────────────────────────────────────────────────────┤
│ 区块 C：应季覆盖                                             │
│   春 / 夏 / 秋 / 冬 —— 现状全空                              │
├────────────────────────────────────────────────────────────┤
│ 区块 D：需求端证据墙                                         │
│   犬档案画像（年龄/体重/活动量分布）                          │
│   收藏排行                                                   │
│   顾客反馈原文（按功能线归类，可点击"由此建线"）              │
├────────────────────────────────────────────────────────────┤
│ 区块 E：AI 规划建议区                                        │
│   [生成产品线规划建议] → 结构化建议书                         │

│              → [按此方向新建系列]                             │
```

### 4.3 AI Agent 清单

#### A1. 需求洞察 Agent
**输入**：犬档案分布（年龄/体重/活动量）+ 收藏 + 成交订单 + 顾客反馈原文 + 现有菜的功能标签挂载情况
**输出**：
- 功能需求热力（哪些功能诉求有顾客明确表达，但货架为零）
- 客群画像摘要（小型犬为主、1–4 岁为主、低活动为主、老年犬占 19.6%）
- 覆盖缺口清单（功能轴 / 食材轴 / 应季轴 三张缺口表）
- 5 阶段齐备率诊断（业务阶段口径 + FEDIAF 场景口径都要出，并标出错配的菜）

#### A2. 产品线规划 Agent
**输入**：A1 的洞察 + 45 个健康标签体系 + 24 个「含XX」标签 + 知识库 30+ 功能领域
**输出**：结构化产品线建议书
- 建议确立的功能产品线（分组、定位、目标客群、目标标签）
- 每条线建议放几道菜、主料方向是什么
- 建议收敛的重复菜（现在 26 道里 20 道是成犬场景，同质化严重）
- **每条建议必须引用数据依据**，不接受无依据建议

#### A3. 原料选型 Agent
**输入**：目标功能方向 + 知识库对应领域条目 + 原料库现状（**只作为参考，不作为约束**）
**输出**：
- 主料候选（含适口性、低致敏性、营养特点说明）
- 辅料与补剂建议（**允许推荐库里没有的**，如顾客反馈里提到的"心脏病小狗需要额外补充的补剂"）
- 每个推荐项标注：**库内已有 / 库内没有（需新增）**
- 明确说明推荐理由（引用知识条目编号）
- **最终是否采用，由设计师/管理员决定**

#### B1. 无犬设计模式（改造现有向导）⭐
**现状**：设计器支持不选狗，但 AI 向导接口是 `/dogs/:dogId/design-insight/...`，**不传狗就没法用 AI**。
**改造**：新增「按目标画像设计」入口
- 目标是某功能定位（如"低脂易消化"），不是某只狗
- 犬档案改为**聚合画像**：该客群的体重分布、活动量分布、常见健康诉求
- 保留原有"按某只狗设计"模式（定制订单还要用）

#### B2. 配比草案 + 自动迭代到达标（新增步骤）
放在「食材推荐」和「食谱审核」之间。

| 步骤 | 做什么 |
|------|--------|
| 1 | AI 输出按分组配比草案（肌肉蛋白 / 内脏 / 谷物薯类 / 蔬菜 / 水果 / 油脂种子 / 补剂） |
| 2 | 折算成每种原料的具体克数，**落成配方草稿** |
| 3 | 跑 FEDIAF 评估 → 拿到"不足 / 超标 / 缺数据"清单 |
| 4 | 差距报告喂回 AI → 调整 → 再评估，**最多 3 轮** |
| 5 | 达标则完成；未达标则输出**差距报告**（哪些指标始终没调上去、为什么） |

生产库里已有 `design_recipe_ai_generation_log` 表（含 `adjustment_log`、`gap_report`、`attempt_count`），**0 条记录**——表建好了没用起来。这一步直接激活它。

#### B3. 五场景矩阵一键扩展（新增）⭐
**这是把 26 道菜从"1 个场景"补成"5 个场景"的核心工具。**

| 步骤 | 做什么 |
|------|--------|
| 1 | 选一个已有场景作为基准（如成犬 110ME） |
| 2 | AI 生成其余 4 个场景的配比调整方案 |
| 3 | **硬约束：不换主料**（同一道菜的 5 个场景必须是同一种肉，否则就是另一道菜） |
| 4 | 每个场景单独跑 FEDIAF 评估，不达标就迭代 |
| 5 | 5 个场景全部达标 → 一次性生成 4 份草稿，进审核队列 |

现有代码已有"复制其他阶段原料"功能，但它**只复制不调整**——所以才会出现高活动版和低活动版配方一模一样的情况。这一步要把它变成"复制 + 按场景调整 + 达标校验"。

#### C1. 发布前审核 Agent（增强现有步骤③）
现在的审核只看"配方 vs 营养方案"。补上产品线视角：

| 审核维度 | 内容 |
|----------|------|
| 功能标签真实性 | 挂了"低脂""易消化"标签，评估数据是否真的支持（**硬性校验**） |
| 五场景一致性 | 同一道菜的 5 个场景是否共用主料、工艺是否一致 |
| 食材轴覆盖 | 这道菜填补了哪个「含XX」空白，或与现有菜重合 |
| 应季适配 | 当前季节是否适合 |
| 结构化输出 | 硬性规则（必须改）+ AI 建议（可斟酌）+ 引用的知识条目 |

## 八、推进顺序与验收

| 阶段 | 交付 | 验收标准 |
|------|------|----------|
| **S1** | 产品线驾驶舱 | 三张覆盖矩阵能看出缺口；5 场景齐备率可视化；AI 能出带依据的规划建议 |
| **S2** | 五场景矩阵一键扩展 | 选一道只有成犬场景的菜，能生成其余 4 个场景且全部 FEDIAF 达标 |
| **S3** | 无犬设计 + 配比草案 + 自动迭代 | 从零 AI 生成一份达标配方，不超过 3 轮迭代 |
| **S4** | 食谱审核台 | 新配方必须过审才能发布；功能标签真实性有硬性校验 |

**为什么 S2 排在 S3 前面：** 现有 26 道菜基本都没做全阶段，这是当前最大的产品结构问题，而且修复有确定的方法（原配方做基准 + 按阶段调比例 + 评估校验），AI 在这里的杠杆最大。
