## 二、程序表算出来长什么样（示例）

以一只 **2026-01-05 出生**的幼犬为例，程序表会算出这些时间窗（前几条）：

| 步骤 | 建议时间窗 | 周龄 |
|---|---|---|
| 幼犬首免 第 1 针 | 2026-02-16 ~ 2026-03-16 | 6~10 周 |
| 幼犬首免 第 2 针 | 2026-03-16 ~ 2026-04-13 | 10~14 周 |
| 幼犬首免 第 3 针 | 2026-04-13 ~ 2026-04-27 | **14~16 周** |
| 首免后补强（可选） | 2026-07-06 ~ 2026-08-03 | 26~30 周 |
| 成年加强 第 1 次 | 2027-03-28 ~ 2027-07-26 | 64~81 周 |
| 狂犬疫苗 首针 | 2026-02-28 ~ 2026-06-28 | **8~25 周** |
| 狂犬疫苗 第 2 次 | 2027-02-28 ~ 2027-06-28 | 60~77 周 |
| ……（之后每 3 年 / 每年，直到第 5 次 / 第 12 次） | | |

> 算法说明：所有"每年一次""每 3 年一次"的步骤，时间窗统一做成
> **目标日 −30 天 ~ +90 天**（前后放宽，容错）。

## 三、逐条对照：已经审核的知识 vs 代码实际算的

### 🔴 1. 首免最后一针的窗口从 **14 周龄**就开始了

| | |
|---|---|
| **已审核知识（immune-004）** | 「直到 **16 周龄或更大**，而不是"打满三针就停"。16 周龄那一针很关键——它保证在绝大多数幼犬 MDA 已经消退后**至少接种到一次**。」 |
| **代码实际** | 第 3 针窗口是 **14~16 周龄**。也就是说，一只在 **14 周龄**接种的幼犬，会被判为"这一步已完成"，程序表从此认为首免做完了。 |

**问题**：指南的核心意图正是"不要在 16 周龄前停"。现在窗口允许 14 周龄收尾，
一只 6 / 10 / 14 周接种的幼犬会显示"首免已完成"，而它很可能还有母源抗体干扰。

**请确认**：最后一针的窗口应该改成 **从 16 周龄开始**（例如 16~20 周），
还是保留 14 周龄、只在文案里提示"尽量安排到 16 周以后"？

---

### 🔴 2. 狂犬首针的窗口从 **约 8 周龄**就开始了

| | |
|---|---|
| **已审核知识（immune-010）** | 「狂犬病属强制免疫病种，按国家与当地规定接种……**各城市对登记月龄的要求不一致**，以当地规定为准。」 |
| **代码实际** | 第 1 步写的是"首针 **12 周龄以上**"，但因为统一往前放宽 30 天，实际窗口是 **12 周 −30 天 ≈ 7.7 周龄** 起。 |

**问题**：一只 8 周龄打的狂犬会被算作"已完成"。而 12 周龄这个起点本身，
在已审核的知识条目里**找不到明确依据** —— immune-010 只说"按国家与当地规定"。

**请确认两件事**：
1. **12 周龄**这个起点，依据是哪一份文件？（我们需要把它写进"依据"里，顾客和审核的人都要能查到）
2. 窗口下界要不要**卡死在 12 周龄**（不再往前放宽 30 天）？

### 🟠 3. 首免固定算 **3 针**

| | |
|---|---|
| **已审核知识（immune-004）** | 「6–8 周龄起，**每 2–4 周一次**，直到 16 周龄或更大。」 |
| **代码实际** | 按**最大间隔 4 周**排，固定得到 **3 针**（6 / 10 / 14 周）。按最小间隔 2 周排本可以是 5 针。 |

**请确认**：固定 3 针是不是可接受的简化？
（我们的理解是"只要最后一针落在 16 周龄之后、且间隔不超过 4 周就没问题"，
但这属于我们的推断，需要你确认。）

### 🟠 4. 「标签外使用需要知情同意」这条**没有进程序表**

| | |
|---|---|
| **已审核知识（immune-005）** | 「疫苗说明书上的"保护期 1 年"是注册时的最低承诺……按指南使用（**即偏离说明书**）属于"**标签外使用**"，应由兽医取得主人知情同意并记录在病历里。」 |
| **代码/界面实际** | 直接建议"三年一次"，**完全没有这句话**。界面上只在卡片底部写了一句"以执业兽医的意见为准"。 |

**问题**：这是已审核知识里明确的**合规要求**，程序表把它漏掉了。
顾客看到"三年一次"，可能会以为这是产品说明书上的建议。

**请确认**：这条提示要不要加进「成年加强」那一步的说明里？
（建议原文照搬知识条目那句话。）

### 🟠 5. 计划把"**没有记录**"当成了"**没有接种**"

| | |
|---|---|
| **已审核知识（immune-013）** | 「漏打或延迟时，**通常不需要从头再来**：成年犬补一针核心疫苗即可恢复防御。」 |
| **代码实际** | 每一步独立判定。一只 3 岁、从没用小程序记过疫苗的狗，会同时看到多条「狂犬疫苗 第 N 次：**已经过了建议时间，建议尽快安排**」。 |

**问题**：这**不是医学错误**，是产品口径问题 —— 但后果是真的：
顾客明明每年都带狗去打，只是没在小程序里记，打开却看到一串"已过期，尽快安排"，
第一反应是"我是不是漏打了"，第二反应是"这系统不准"。

**请确认**：
- 文案要不要改软一点（例如"档案里没有这一针的记录 —— 如果已经打过，记一条就好"）？
- 或者：**没有任何记录**的狗，不显示"已过期"，只显示"记录一下打过哪些"？
