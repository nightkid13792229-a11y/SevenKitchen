# 疫苗记录录入 · 方案

**日期**：2026-10-04
**范围**：小程序「健康管理 → 疫苗」里，顾客**记录狗狗已打过的疫苗**这条链路
**依据**：现有代码通读 + WSAVA 2024 正本 + 已审核的知识条目 `immune-008`
**状态**：待你评判

---

## 一、结论先行

**功能是"能用"的，但全库 4575 只狗 —— 0 条疫苗记录。**

原因不是功能缺失，是**三件小事叠在一起**：

1. 打开疫苗标签，**第一眼看到的是"疫苗计划待开放"**（计划在审，关掉了）
2. 记完**什么也不会发生**（没有回报）
3. WSAVA 要求记的六项里，**五项没有字段**，只能塞进一个自由文本框

而这件事真正该卖的东西，我们**已经有一半了**：拍照识别 + 原件留存。
我建议把它重新定位成 **「电子疫苗本」**，而不是「接种提醒」——理由在 4.1。

---

## 二、现状（读代码得到的）

**入口链路**：爱犬 → 健康管理 → **疫苗**标签（4 个标签：就诊 / 体检 / 疫苗 / 体重）→ 底部「新增记录」→ 二选一（上传图片 AI 识别 / 自己手动填）

**表单现在有的字段**（6 个）：

| 字段 | 说明 |
|---|---|
| 疫苗名称 | 输入框 + 8 个常见疫苗名标签一点即选 |
| 接种日期 | 日期选择 |
| 下次到期日 | 可选 |
| 状态 | 已接种 / 已预约 / 已逾期（**顾客手选**） |
| 备注 | 自由文本 |
| 报告原件 | 拍照留下的原图，可预览 |

**拍照识别（拍疫苗本）现在读出来的**：疫苗名称、接种日期、下次到期日、备注 —— **就这 4 项**。

---

## 三、四个问题

### 🔴 1. 打开疫苗标签，第一眼是"待开放"

现在的顺序是**计划在上、记录在下**（`VaccinePlanSection` → `VaccineManagementSection`）。

计划因为程序表待审已经关掉，所以顾客点进「疫苗」看到的第一屏是：

```
疫苗计划待开放
疫苗计划还在做专业审核，暂时只对内部开放。
```

**还没看到能用的功能，先看到不能用的。**

### 🔴 2. WSAVA 要求记的六项，五项没有字段

已审核的知识条目 `immune-008` 写得很明确（GUIDE p6「Medical records documentation」原文）：

| WSAVA 要求记录 | 现在 |
|---|---|
| 接种日期 | ✅ 有字段 |
| 疫苗名称 | ✅ 有字段 |
| **批号 / 序列号** | ❌ **只能塞进备注** |
| **有效期** | ❌ **只能塞进备注** |
| **生产厂商** | ❌ **只能塞进备注** |
| **接种的解剖部位与途径** | ❌ **只能塞进备注** |
| 执行接种的人 | ❌ 只能塞进备注 |

说句实话：备注那个框的提示文字写的就是「例如：**接种机构、批号**、接种后反应」——
**等于我们自己承认这些该有字段，只是一直没建。**

**为什么这五项重要**（不是学术要求）：
疫苗本是**凭证**。出行（飞机、高铁、住店）、寄养、换医院都要出示，
对方看的就是**厂商、批号、有效期**这几项。缺了这些，记录只是一句话，证明不了什么。

### 🟠 3. 拍照识别也只读三项

而知识条目 `immune-008` 的注意事项恰恰写着：

> 「拍疫苗本照片时，尽量把**批号、有效期、厂商**这几行拍清楚——**这几项最常在照片里糊掉**。」

**最该靠识别帮忙的，恰恰没读。** 现在顾客拍完照，批号还得自己对着照片一个字一个字打。

### 🟠 4. 「状态」让顾客手选"已逾期"，没有意义

`status` 三个取值（已接种 / 已预约 / 已逾期）**全是顾客手选的**，代码里没有任何地方自动算。
"逾期"是"今天 vs 到期日"的**事实**，不是顾客的属性——让他自己选一个"已逾期"说不通，
而且跟我们刚定的口径（**没有记录就不说"已过期"**）自相矛盾。

## 四、方案

### 4.1 重新定位：从「接种提醒」改成「电子疫苗本」

**为什么换定位**：

| | 接种提醒 | 电子疫苗本 |
|---|---|---|
| 对顾客的价值 | "提醒你下一针什么时候打" | **"疫苗本随身带，要用随时能出示"** |
| 现在能不能给 | ❌ 计划待审，关着 | ✅ **现在就能给** |
| 需要什么 | 免疫程序表（卡在审核） | 拍照识别 + 原件留存（**已经有了**） |

**纸质疫苗本的问题很具体**：一个小本子，出行前找不着、寄养时要翻箱倒柜、
换医院忘了带就得重打。**把它拍下来存好，这件事今天就有价值**，不用等程序表审完。

而且它顺手解决了问题 2 的动机：因为要"出示给外人看"，所以**厂商、批号、有效期必须记全**——
这不是我们加的负担，是这场景本来就要的。

### 4.2 表单补字段（分两层，不是七个都堆出来）

**第一层：疫苗本上印着的、出门要用的**（展开就能看到）

| 字段 | 谁来填 |
|---|---|
| 疫苗名称 | 标签一点即选（**已有**） |
| 接种日期 | 日期选择（**已有**） |
| 生产厂商 | 常见厂商标签 + 手打，**优先拍照识别** |
| 批号 | **优先拍照识别**，也可手打 |
| 有效期 | **优先拍照识别**，也可手打 |
| 接种机构 | 输入（宠物医院名） |

**第二层：收进「更多」（医生才关心的，默认收起）**

接种人 · 接种部位与途径 · 下次到期日 · 不良反应 · 备注

> **为什么不一次全摆出来**：顾客手上拿着疫苗本，能照着抄的是"印在上面的字"；
> "接种部位与途径"这种要回忆的，摆出来只会让人卡住。收进「更多」，填不填都不挡保存。

### 4.3 拍照识别扩到这六项（这一步是省力的关键）

**原则：能从照片读出来的，绝不让顾客手打——顾客只做"核对"。**

改 `VACCINE_BOOK` 的识别提示词，让 AI 把疫苗本上这几行一起读出来：
**厂商、批号、有效期**（外加现有的名称/日期），识别后直接预填进表单，顾客确认一次。

这样做的好处很直接：顾客要做的从"对着照片打 3 个字段"变成"看一眼对不对"。

### 4.4 调整打开顺序

- **记录在上，计划在下**：顾客点进「疫苗」先看到自己的疫苗本
- **计划关着的时候，那一块整块不显示**（不占位置、不说"待开放"）
  等程序表审完、开关打开，它自己会出现

### 4.5 加一个「出示」视图（可选，但建议做）

一张**疫苗本卡片**：狗名 + 已完成接种按日期倒序 + 每条的厂商/批号/有效期。
顾客在寄养前台或医院直接打开给对方看，或截个图发过去。

> 这一条是把 4.1 的定位**真正落地**。没有它，"疫苗本随身带"只是一句话。

## 六、需要你定的三件事

| # | 问题 | 我的建议 |
|---|---|---|
| **1** | **「状态」要不要砍掉"已逾期"** | **建议砍**。只留「已接种 / 已预约」，逾期由系统按到期日算，不让顾客自己选（现在三个值全是手选的，跟我们刚定的"没记录不说已过期"也冲突） |
| **2** | **厂商/批号/有效期，要不要设成必填** | **建议不必填**。它们是"出示时要用的"，但顾客可能一时找不到——不挡保存，只在记录缺这几项时轻提示一句"补上厂商和批号，出门出示更方便" |
| **3** | **「出示」卡片做不做** | **建议做**（4.5）。它是"电子疫苗本"这个定位的落点；不做的话，前面补的字段顾客没有使用的场合 |
