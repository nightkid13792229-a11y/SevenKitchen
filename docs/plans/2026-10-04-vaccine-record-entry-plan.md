# 疫苗板块 · 定位与方案（修订版）

**日期**：2026-10-04
**定位（按老板 2026-10-04 定）**：
> 用户能记录他需要的信息，也能看到疫苗计划，
> **甚至做到哪一天该打哪一个具体的疫苗产品、可以提醒到这一步**。
> 这就是疫苗板块最核心的作用。

---

## 一、先撤回我上一版的两个错误判断

**错误 1：「电子疫苗本、出示给第三方看」——这个前提不成立**

你的反问是对的：**医生和检疫机构不会认可小程序截图。**

法规依据也支持你：《狂犬病防治技术规范》5.1 写的是
「经免疫接种过的动物**发放统一的动物免疫证明**，佩戴免疫标记」——
那是**法定凭证**，由动物疫病预防控制机构发，我们做个卡片替代不了。
我把它当成卖点，是想当然了。

**错误 2：「补批号 / 有效期 / 生产厂商」——这批字段不该由我们收**

WSAVA 确实要求记这六项，但那条要求的标题是
**"Medical records documentation"（病历记录）** ——
**是给兽医的病历定的，不是给宠物家长 App 定的。** 兽医的系统里本来就有。

我们不做"出示"这个场景，这些字段对**记录、计划、提醒**三件事都没有帮助。
**所以不加。** 上一版方案里的批号/有效期/厂商/出示卡片，全部作废。

---

## 二、按你的定位，这个板块就是三件事

```
记录  ──→  计划  ──→  提醒
（打过什么） （接下来怎么打）（哪一天、打什么）
```

记录和提醒都**服务于计划**：没有记录，计划算不准；没有计划，提醒没内容。

---

## 三、三件事各自的现状

### ① 记录 —— 已经建好了，但**一个用户都没用过**

**已经有的**：疫苗标签 → 底部「新增记录」→ 二选一（拍照识别 / 手动填）
表单 5 个字段：疫苗名称（含一点即选标签）、接种日期、下次到期日、状态、备注 + 报告原件
拍照识别能读出：疫苗名称、接种日期、下次到期日

**全库 4575 只狗，0 条记录。** 不是功能缺失，是**没有回报**——
计划关着，顾客认真记完，页面上什么也不会发生。

**一个具体的不顺**（这个值得改）：

| | |
|---|---|
| 一点即选的标签是 | **病名**：犬瘟热、犬细小病毒、犬传染性肝炎、犬副流感、犬腺病毒、犬窝咳、钩端螺旋体 |
| 但顾客疫苗本上写的是 | **产品名**：卫佳伍、英特威、犬四联、幼犬保… |

**两边对不上。** 顾客拿着本子找"卫佳伍"，标签里没有；他只能手打，或者随便点一个病名。
（拍照识别那条路反而是对的——提示词里明确要求"照抄本子上的写法，如「犬四联」「卫佳伍」"。）

### ② 计划 —— 已经做好了，**卡在程序表审核**

代码是完整的（时间窗、逐条状态、顾客可以标记"接受/推迟/不做"、冲突提示）。
问题是**免疫程序表要过兽医审核**，所以顾客侧现在是关着的。

**这个板块的真正瓶颈在这里**——审完就能开。

### ③ 提醒 —— **完全没有**

| 你要的 | 现在 |
|---|---|
| **哪一天** | 只给一个**时间窗**（如 2026-04-13 ~ 2026-04-27），没有"就这天" |
| **打哪个产品** | 只给通用步骤名（"幼犬首免 第 2 针"），**不说是哪个产品** |
| **主动提醒** | **没有任何提醒**。顾客不点进疫苗标签，就什么也看不到 |

补充两个事实：
- 微信订阅消息的发送能力**后端早就实现了**（订单发货在用），但疫苗提醒那一处是**注释掉的 TODO**
- 你之前定过「提醒形式：**小程序内提醒即可**」（需求第 18 条），所以不一定非要用订阅消息

## 四、方案

### 4.1 先让记录"有回报"——把计划打开（前置：程序表审完）

**这是第一优先，其他都是它的附属。**
记录没人用，根子是记完没有下文；计划一开，"记了 → 立刻看到还差哪几针"这个闭环就成立了。

### 4.2 「哪一天」——把时间窗收窄成一个建议日

现在是 `2026-04-13 ~ 2026-04-27`，顾客看到会想"那到底哪天去？"
**改成一个明确的日子**（窗口内取一个建议日），旁边小字保留窗口作为弹性区间：

```
下一步
2026-04-20（周三）  该打 幼犬首免 第 3 针
建议区间 04-13 ~ 04-27，具体听兽医安排
```

### 4.3 「哪个产品」——需要你确认口径（见第五章）

### 4.4 主动提醒（小程序内）

- 健康管理入口、疫苗标签上给**角标/一行提示**（"有 1 针该打了"）
- 打开健康管理页就能看到，不用自己找到疫苗标签里去
- 订阅消息那条路先不动（你说过小程序内即可）

### 4.5 记录侧只做两处小修

1. **一点即选的标签改成"产品名 + 病名"混合，以本子上写的为准**
   （至少让顾客能找到本子上印的那个词）
2. **「状态」砍掉"已逾期"**——现在三个值全是顾客手选的，"逾期"是今天 vs 到期日的事实，
   不该让顾客自己选，而且和我们刚定的"没有记录就不说已过期"冲突

> **不加批号/有效期/厂商**（理由见第一章）。

## 五、需要你定的一件事：**「哪个产品」到底指什么**

这个词有两种理解，做法完全不同：

| | 理解 A：**疫苗种类** | 理解 B：**具体品牌/商品** |
|---|---|---|
| 例子 | "该打**狂犬疫苗**" / "该打**联苗**" | "该打**卫佳伍**" / "该打**英特威幼犬保**" |
| 需要什么 | 现在就有（只需把步骤名说清楚） | 要建一份**国内在售疫苗产品清单**（产品名、防哪些病、适用周龄、是否含狂犬） |
| 风险 | 无 | ⚠️ 推荐具体商品是**兽医的活**，而且各医院进的货不一样，推荐了也买不到 |
| 我的建议 | ✅ 做到这一层 | 可以先**只做"照抄顾客本子上的产品名"**，不做推荐 |

**我倾向**：提醒说清楚"该打哪一类"（A 层做到位），
同时**记录里保留顾客本子上写的产品名**（拍照识别已经在读），
这样将来如果要按产品提醒，我们手上有数据。

## 六、做事的顺序

| 顺序 | 事项 | 卡在哪 |
|---|---|---|
| **1** | 程序表审核 → 打开计划 | **卡在你和兽医**（审阅稿已给） |
| **2** | 提醒："哪一天"收窄 + 入口角标 | 等 1 |
| **3** | 记录：标签改成产品名、砍掉"已逾期" | 现在就能做 |
| **4** | 「哪个产品」按第五章定了再做 | 等你定 |

> 换句话说：**这个板块的进度主要卡在程序表审核上。**
> 第 3 项我现在就能做，第 2、4 项要等计划打开才有意义。
