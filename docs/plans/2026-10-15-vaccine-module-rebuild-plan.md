## 一、定性：这次不是"改样式"，是把整个疫苗板块重做一遍

老板 2026-10-15 的原话：

> "还有很多我不满意的地方，比如该板块的代码抽象和解耦度不够。
> 比如产品库及相关字段。再比如，疫苗排期等核心算法不够明确。
> 互相之间绕来绕去的，也有冲突。总之就是从头开始，重构整个疫苗板块。"
>
> "现有的代码及架构只作为参考，我们从头，也就是从需求端开始着手来分析，看要改到哪些地方。"

所以要动的有六层：**需求、数据模型、排期算法、接口契约、页面与视觉、组件划分与测试**。

参照物不是现有代码，而是现有注释里那 30 多条历史教训（老板 10-01 ~ 10-15 的原话）——
每一条都对应一个真实踩过的坑，它们才是这次需求清单的原料。

### 1.1 老板确认的 5 类问题（本次必须解决）

| # | 问题 | 现状证据 |
|---|---|---|
| 1 | **信息太多、层级不清**：一眼看不出"下一步打什么、什么时候" | 计划卡折叠态 3 行、展开后 5 组信息（免疫流程 / 接种时间 / 常见产品 / 依据 / 动作）；首屏被多张类别卡占满 |
| 2 | **三块关系看不出**：接种计划 / 合并窗口 / 接种记录 长得太像 | 10-14 老板原话"视觉上很难将提醒、核心疫苗和钩端螺旋体这三个板块视作同一个窗口"；当时靠加粗边框救回来，但仍是"三段拼"拼出来的 |
| 3 | **文案看不懂**：专业词多、"依据"像内部资料 | 老板连续指出"内部提醒文案打到页面上"（10-13 两处、10-14 一处）；现在只加了守卫"擦掉"，没重写 |
| 4 | **操作路径绕**：录入、确认归类、保存要点好几次 | 10-13「确认」与「保存」重复、10-14 又出现一次；录一个字段先后经历 3 个控件 |
| 5 | **首屏太长**：重点被埋在下面 | 计划卡最多 4 张（早期核心 / 核心 / 钩端 / 狂犬）+ 记录列表 + 疫苗本原件 |

### 1.2 老板补的 3 条（这次的主线）

| # | 老板原话 | 我要做的 |
|---|---|---|
| 6 | "代码抽象和解耦度不够" | 把"算"和"画"彻底分开：算法只在后端一份，前端零计算；组件按"计划 / 记录 / 录入 / 识别"四件事拆开 |
| 7 | "产品库及相关字段" | 病种、类别、产品库、字段标签全部**单一来源**（现在同一份事实最多有 3 处副本） |
| 8 | "排期算法不够明确……也有冲突" | 产出一份《免疫程序规格》+ 把散落的 if 收敛成"程序表 + 引擎"两层；每条冲突给出裁决并落成用例 |

### 1.3 首要照顾的人

**首次使用疫苗功能的家长**（老板 2026-10-15 修正）。

⚠️ 注意区分：是"首次用我们的功能"，**不是**"狗没打过疫苗"。
他们的狗很可能已经有一整套免疫史（商家的记录、上一家医院的本子、前主人的记忆），
只是在我们这边是空的。所以这个页面要承担的是"**把免疫史交给我们，然后告诉他接下来怎么打**"，
而不是"从零告诉他怎么打"。

配套事实：建档流程明确**不收集疫苗信息**（`miniapp/src/pages/dog-create/index.vue:1330`）。

## 三、目标形态

### 3.1 三条不变的原则

1. **算法只有一份，且在后端。** 前端不算排期、不判合并、不推状态 —— 只渲染。
2. **页面只说顾客语言。** 内部说明、系统口径、解释我们怎么实现的文字，一律不进页面（沿用并扩大现有守卫）。
3. **一眼看得出"下一步"。** 首屏第一块永远是"接下来该做什么"，其余都是它的支撑材料。

### 3.2 目标信息架构（首屏从上到下）

| 顺序 | 区块 | 内容 | 说明 |
|---|---|---|---|
| 1 | 狗狗摘要 | 名字、年龄/体重（复用现状，不动） | — |
| 2 | **「接下来」卡**（新增） | 一句话：`下一步：核心疫苗 · 首免（一针）· 建议 10-29 ~ 11-12 之间` + 两个动作：`记录这一针` / `拍疫苗本` | 零记录时换成引导语（"6 周龄起打第一针，现在开始也来得及"） |
| 3 | **接种计划** | 固定顺序 3 张类别卡（核心 → 钩端 → 狂犬）；折叠态**只有一行**：状态角标 + 步骤名 + 建议时间；展开才出现免疫流程 / 常见产品 / 依据 / 动作 | 「依据」默认只留一句话 + 「更多」 |
| 4 | **接种记录** | 默认最近 3 条 + 「查看全部」；一行一条：名字 + 日期 + 状态；点开进编辑 | 空态只有一句 |
| 5 | 疫苗本原件 | 一条入口：`查看原件（N 张）` | 不占首屏 |

**高度预算**：零记录家长首屏 ≤ 1.2 屏；有计划无记录 ≤ 1.5 屏。（现状轻松超过 2 屏。）

### 3.3 视觉规范（写成 token，全部走变量）

| 组 | 取值数量 | 约束 |
|---|---|---|
| 类别色 | 3（核心/钩端/狂犬）+ 1（其他） | 只用于类别标识，不用于状态 |
| 状态色 | 4（已完成 / 待接种 / 逾期 / 待核对） | 角标必须四档都能区分，不能只有一档 |
| 疫苗模块主色 | 1 个紫 | 时间线、分享页、记录卡**必须同一个紫**（现状 3 个值） |
| 计划 vs 记录 | 计划绿 / 记录紫 | 保留 10-12 老板定的"两块一眼区分" |
| 字号 | 4 档（32 / 28 / 26 / 22rpx） | 禁止再出现 21/24/30/700 这类散值 |
| 间距 | 4 档 | 卡片间距统一，不再靠负边距拼容器 |
| 卡片语言 | 3 种：单条待办 / 成组窗口 / 历史记录行 | **必须一眼可分**（这条写成守卫，防止 10-14 的问题回来） |

## 五、测试与验收

**验收样本**：生产库 50 只测试档案（测01~测49）+ 新建一只零记录档案。

| 场景 | 期望 |
|---|---|
| 零记录新家长 | 首屏 3 秒内能说出"下一针打什么、大概什么时候" |
| 33 号（窗口已过） | 显示"尽快补种（原窗口 2026-09-27 ~ 2026-10-11 已过）" |
| 合并窗口档案 | 两类同框、与狂犬卡一眼可分；点「记录接种信息」在正确的框内开录入 |
| 冲突档案 | 提示"与建议不一致"，措辞不越界（不替顾客拍板） |
| 卫佳捌（组合苗） | 记录一针 → 核心与钩端**两张卡同时消失**（验证分类按产品算） |
| 忽略 / 恢复 | 忽略后不再出现、可一键恢复 |
| 识别链路 | 拍疫苗本 → 逐条确认 → 只存已确认的 → 回执说清存了几条、跳了几条、还差几条 |
| 失败模式 | 加载失败 ≠ 没有记录；保存失败常驻可重试；未确认就切标签要拦 |

**测试策略调整**：
新能力下沉到 `domain/vaccine/*` 做真正的单元测试（输入输出可判定）；
组件层只保留少量结构契约（钉"存在某个语义标记"，不钉中文措辞）。
旧的源码文本断言作为回归网**保留不动** —— 它们挡住过很多次真机才炸的错；
但当旧断言与正确行为冲突时，**以行为为准并同步改断言**。

**成功标准**：算法只有一处实现；页面零内部文案；首屏高度达标；2.3 的 12 条全部销账；
两个仓库测试全绿；关键档案逐只对比通过。

## 六、风险、回退、明确不做

**风险**
1. 疫苗记录影响狗狗安全，改动直接进影响面 → P2 必须"行为不变"，P3 之后每期都做真机对比。
2. 后端拆文件 + 部署有风险 → 算法**先拆不重写**，重写只针对裁决过的条目，一条一个提交。
3. 联调期间不跑后端 `npm run build`（`deleteOutDir` 会删掉 `dist` 弄死本机后端），自检只跑 `npx tsc --noEmit`。

**回退**：每期一个提交，前端可单独回退；后端先 push 后部署，按提交回退。

**明确不做**
- 不改数据库表结构（当前字段够用；若 P0 确认需要新字段，单独走 Prisma migration）
- 不把产品库从代码表迁进数据库
- 不做订阅消息推送（只做页内提醒，沿用老板 10-01 的决定）
- 不做猫
- 不推荐国产苗，但顾客仍可自由记录
- 不做长图分享
