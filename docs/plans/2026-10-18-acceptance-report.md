## 二、为什么 4/5/6 没达成 —— **标准定得不现实**

拿详情页实测拆解（840 行）：

| 类别 | 行数 |
|---|---|
| 生命阶段 / 选狗 | 119 |
| 菜品 / 营养展示 | 100 |
| 加载 / 错误态 | 30 |
| 分享 | 20 |
| 收藏 | 15 |
| 埋点 / 统计 | 10 |
| 付费 / 下单 | 7 |
| **其它（import / 类型 / 工具函数）** | **539** |

**跟这次重构直接相关的只有约 219 行，占 26%。**

也就是说 `<250` 这个目标暗含了一个假设：
**"页面主要就是那套共享 UI，抽出去就只剩一点"**。

实际不是 —— 页面里有**大量跟展示无关的东西**（类型定义、工具函数、加载态、支付、分享、埋点）。
这些**本来就不在这次重构的范围里**（需求文档 §七「不做什么」也没说要动它们）。

**所以 4/5/6 不是"没做到"，是"目标从一开始就定错了"。**

## 三、为什么 9 没归零

四页里还剩 6 个 `computed`/`ref`：

**界面已经统一**（四页都用同一个组件），剩下的是**数据层的重复**，
已在 `useLifeStageVersion.ts` 注释与重构文档里写明原因。
