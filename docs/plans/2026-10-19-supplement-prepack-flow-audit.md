# 预分装补剂 · 需求文档自查报告（2026-10-19）

> **审查对象**：`docs/plans/2026-10-19-supplement-prepack-requirements-v1.md`（840 行）
> **审查方法**：按“顾客进入 → 下单 → 支付排产 → 生产分装 → 发货 → 售后 → 完成对账”逐段核对；同时对照现有代码与页面，检查规则是否可落地、是否有冲突。

## 一、总体结论

### 1.1 已经覆盖得比较好的

| 方面 | 评价 |
|---|---|
| 本轮目标与边界 | 清楚：先打通 DIY 入口、排产、分装、发货、售后两端、预计发货时间；定价/产能/包材库存等明确不做 |
| 角色与权限 | 顾客/员工/管理员三角色；售后资金动作仅管理员；入口收拢方向明确 |
| 排期规则 | 截单时间、30 天可选、营业日顺延、分装日=发货日、改期通知，规则基本可执行 |
| 库存时机 | 排产预占、分装扣减、取消释放、改期移动、补发重占，口径完整 |
| 售后模型 | 多次售后、诉求/结论分离、状态机、退款/补发/登记/驳回、累计退款上限 |
| 字段查重 | 第四章对复用/扩展/新增做了明确边界，新增对象控制得比较克制 |
| 上线检查 | 包材档案、规则、日历、模板、迁移回填、回滚都有清单 |

### 1.2 还不完整的

| 方面 | 缺什么 | 影响 |
|---|---|---|
| **端到端业务流程** | 文档按“规则主题”写，没有按“谁在什么时点做什么、看到什么页面、系统做什么、失败怎么办”串起来 | 开发和原型容易各做各的，漏掉交接点 |
| **页面全景** | 只列了新增/改造页，没有把所有相关页面按“新增/改造/复用/下线”列全；A7 不是独立页面却占了一个编号 | 原型可能漏页；旧页面下线后找不到替代入口 |
| **页面状态** | 只写“每页要有默认/空/加载/错误/权限态”，没有逐页定义状态和跳转 | 前端实现会各自发挥 |
| **状态机** | 订单履约、排期、库存占用、售后四套状态没有正式状态迁移表 | 容易出现“前端隐藏按钮、后端没校验” |
| **后台非功能** | 支付/退款幂等、排产事务、库存并发、订单中心分页、通知重试、审计、迁移、回滚 | 上线后最容易出问题的地方 |
| **异常目录** | 只列了 11 条边界，缺少地址变更、订单完成、售后重复、补发取消、日历变更、打印失败等 | 客诉和现场问题无处安放 |
| **数据迁移** | 只写了补剂订单回填，没有写售后/退款/补发存量的映射和回滚 | 上线后旧数据可能“消失”或重复 |
| **权限到接口** | 只有角色矩阵，没有逐接口的归属校验/角色校验 | 可能出现越权退款/看别人订单 |

## 二、端到端业务流程（建议补进需求文档）

> 这一节回答“业务流程细节是否系统梳理”。建议按下面 10 个阶段补进需求文档，作为第二章之前的“流程总览”。

### 2.1 流程总表

| 阶段 | 谁 | 触发 | 顾客看到 | 员工/管理员看到 | 系统做什么 | 主要异常 |
|---|---|---|---|---|---|---|
| 0 配置上线 | 管理员 | 上线前/日常 | — | 补剂上架清单、包材配置、营业日历、商城设置 | 建包材档案、配规则、配截单/日历/模板、体检 | 缺价/缺效期/单位不可换算/包材未配/模板未配 |
| 1 进入制作单 | 顾客 | 食谱详情→自己做→生成制作单 | 制作单、补剂清单、购买入口 | — | 算补剂用量、查商城状态、给入口 | 商城关闭/查询失败/无补剂/计算失败/已买过 |
| 2 补剂下单 | 顾客 | 点“购买预分装补剂” | 下单页：勾选、地址、发货日期、金额 | — | 报价、校验可售、生成待付款订单、快照 | 补剂下架/无价/日期失效/无地址/重复提交 |
| 3 支付与排产 | 顾客/系统 | 支付成功/人工确认 | 支付结果 + 预计发货日期 | 待排期/已排期列表 | 确认收款、算分装日、预占库存、写事件、发通知 | 金额不一致/重复回调/排期失败/预占失败 |
| 4 顾客订单管理 | 顾客 | 进“我的订单” | 列表、详情、物流、售后 | — | 状态映射、售后标签、事件时间线 | 逾期/延迟/地址要改/要取消/要售后 |
| 5 生产准备 | 员工/管理员 | 上班/看工作台 | — | 订单中心补剂筛选、分装汇总 | 汇总单数/袋数/补剂总量/包材/缺料 | 缺料/包材未配/日历临时停发/订单逾期 |
| 6 分装与标签 | 员工（强制分装仅管理员） | 打开补剂订单 | — | 分装表单、标签打印 | 校验效期、算标签效期、扣库存、状态→PACKED、写事件 | 原瓶效期不足/缺料/并发分装/打印失败 |
| 7 发货 | 员工/管理员 | 点发货 | 物流单号、状态→已发货 | 填单号/承运商 | 写发货时间、通知、物流同步 | 单号错/承运商异常/当天未发 |
| 8 售后 | 顾客/管理员 | 申请/处理 | 售后申请、进度、结果 | 售后记录、处理弹窗 | 建售后记录、退款/补发/登记/驳回、通知 | 重复申请/退款失败/金额超限/补发缺料/窗口过期 |
| 9 完成与对账 | 系统/管理员 | 发货后 N 天/人工 | 已完成 | 订单中心、退款管理、库存 | 自动完成、退款对账、库存对账、异常告警 | 长期未完成/退款不一致/负库存 |

### 2.2 关键决策点（流程里必须写清楚“走哪条”）

1. **顾客已付款但未分装，要退款**：走“取消订单”还是“申请售后”？
2. **顾客已付款、已开始分装（PACKING）**：能否取消？谁有权？
3. **订单已分装未发货，顾客要退款/补发**：售后是否允许？退款后库存是否释放？
4. **同一订单已经退款，又要补发**：允许吗？补发单和原单关系怎么显示？
5. **补发单库存不足**：先生成再标红，还是直接拒绝？
6. **分装日已过仍未分装**：系统自动改期，还是只标红等管理员？
7. **营业日历临时关闭某天，已有订单排在那天**：自动顺延，还是提示管理员手动改？
8. **顾客选了发货日期，支付时日期已失效**：自动顺延并通知，还是让顾客重选？
9. **订单发货后长期未完成**：自动完成（几天）还是人工点完成？
10. **顾客要改收货地址**：自助改、客服改、还是不允许？
11. **员工打印标签失败/贴坏**：能否单张补打？补打是否留痕？
12. **退款接口失败**：订单是否显示“退款中”？能否重试？谁负责？
13. **补发单被取消**：原售后记录回到处理中还是关闭？
14. **售后被驳回后顾客再次申请**：允许吗？有没有次数限制？

> 这 14 个决策点，v1 只回答了部分。建议在 v1.1 中逐条给结论，否则开发和客服会各自解释。

### 2.3 建议的泳道图（文字版）

```
顾客：  进入制作单 → 一键购买 → 选日期/地址 → 支付 → 看订单/物流 → 申请售后 → 看结果
系统：  算补剂 → 报价 → 建单 → 确认收款 → 排分装日 → 预占库存 → 通知 → 售后记录 → 通知
员工：                          ← 看当天汇总 ← 备料/备包材 → 分装 → 打标签 → 发货
管理员：配置上架/包材/日历/截单 → 监控待排期/逾期/缺料 → 改期/强制分装 → 处理售后/退款/补发 → 对账
```

## 四、冲突与矛盾清单

> 以下每条都标了 v1 的章节/代码位置。**P0 是开发前必须定的，P1 可以进技术方案再定。**

| # | 冲突/矛盾 | 证据 | 影响 | 建议处理 | 级别 |
|---|---|---|---|---|---|
| X01 | 已付款未分装，既可以“取消订单”又可以“申请售后退款” | v1 3.6.3 允许 `PAID` 申请售后；3.6.5 允许 `PAID` 取消 | 两条路径都能退款，状态/库存/统计会分叉 | **未分装只走“取消订单”；已分装后才走售后**。售后申请条件改为 `PACKED` 及之后 | P0 |

## 五、缺口清单（P0/P1）

### 5.1 P0（开发前必须定/必须做）

| # | 缺口 | 为什么重要 | 建议 |
|---|---|---|---|
| G01 | 补剂订单没有完成规则 | `COMPLETED` 永不出现；售后窗口、统计、列表都不完整 | 发货后 7 天自动完成；后台可配；也可管理员手动完成 |
| G02 | 取消 vs 售后边界不清 | 两条退款路径，库存/状态/统计分叉 | 未分装只走取消；已分装才走售后（X01） |

| G14 | 并发/幂等未定义 | 两个人同时分装/退款/改期会重复扣库存/重复退款 | 状态机条件更新 + 幂等键 + 事务；分装/退款/补发/改期都要 |

| G17 | 通知模板/linkType/重试未定义 | 顾客收不到或点不开 | 定义两个模板、消息 `linkType=SUPPLEMENT_ORDER`、失败重试/去重 |
| G18 | 售后窗口未定 | 无法写校验；上线阻塞 | 建议发货后 7 天，后台可配 |

## 七、状态机（建议补进需求文档）

### 7.1 补剂履约状态（建议去掉 PACKING）

```
PENDING_PAYMENT --支付成功/人工确认--> PAID
PAID --完成分装--> PACKED
PACKED --发货--> SHIPPED
SHIPPED --自动完成/人工完成--> COMPLETED
PENDING_PAYMENT --超时/取消--> CANCELLED
PAID --取消(未分装, 退款+释放)--> CANCELLED
```

- `PACKING` 本轮建议只作为旧数据兼容，不再新写。
- 退款/补发**不改变**上述状态；售后记录单独表达。
- `PAID` 未排期（异常）仍是 `PAID`，用 `packingDate=null` + 待排期标记。
- `PACKED` 超过计划发货日未发货 → 标红“逾期发货”。

### 7.2 排期状态

| 状态 | 条件 | 可做 |
|---|---|---|
| 未排期 | `PAID` 且 `packingDate=null` | 自动重试、管理员手工排 |
| 已排期 | `packingDate` 有值 | 改期、分装、取消 |
| 逾期 | `packingDate` < 今天且未 PACKED | 改期、催办、售后 |
| 已完成 | `SHIPPED/COMPLETED` | 不再改期 |

### 7.3 库存占用状态

| 状态 | 触发 | 说明 |
|---|---|---|
| ACTIVE | 排产 | 占用可用库存 |
| RELEASED | 取消/未分装退款 | 释放 |
| CONSUMED | 分装完成 | 转库存流水 |
| 缺料 | 需求 > 可用 | 不阻塞排产，标红 |
| 强制 | 管理员强制分装 | 留痕，允许负库存 |

### 7.4 售后记录状态

| 当前 | 动作 | 下一状态 | 谁 |
|---|---|---|---|
| PENDING | 受理 | PROCESSING | 管理员 |
| PENDING | 直接退款/补发/登记 | RESOLVED | 管理员 |
| PENDING | 驳回 | REJECTED | 管理员 |
| PENDING | 顾客撤回 | CANCELLED | 顾客 |
| PROCESSING | 退款成功/补发单发货 | RESOLVED | 系统/管理员 |
| PROCESSING | 驳回 | REJECTED | 管理员 |
| PROCESSING | 补发单取消 | PROCESSING | 系统（回到处理中） |
| RESOLVED/REJECTED/CANCELLED | 再次申请 | 新记录 PENDING | 顾客（受次数/窗口限制） |

## 八、接口与后端能力缺口

### 8.1 必须新增/重写的服务

| 能力 | 现状 | 要做什么 |
|---|---|---|
| 排期服务 | 无 | `SupplementSchedulingService`：算日期、事务内写 `packingDate` + 预占 + 事件；幂等；失败重试 |
| 库存占用 | 鲜食用 `InventoryAllocation` | 加 `sourceType`；补剂创建/移动/释放/消费；事务/并发 |
| 售后记录 | 无 | `AftersaleCase` CRUD、状态机、退款/补发关联、累计金额 |
| 退款 | 单次、写在订单上 | 改为按 case 退款；支持多次/部分；累计校验；回调关联 case；失败重试 |
| 补发 | 单次、写订单状态 | 改为按 case 生成；允许多次但每 case 一次；取消补发单回退 case |
| 取消 | 管理员单次、无退款 | 顾客取消：校验 PAID、退款、释放、事件；管理员取消同口径 |
| 完成 | 无 | 定时任务：SHIPPED + N 天 → COMPLETED；或管理员手动 |
| 订单中心 | 无 | 读模型/视图；类型/状态/日期/关键词/售后；分页/计数/权限裁剪 |
| 通知 | 有发送能力 | 模板、订阅授权、站内消息、linkType、重试/去重 |
| 审计 | 无 | `SupplementOrderEvent` 写入/查询；不可变 |
| 迁移 | 无 | 存量订单/售后/退款/补发映射；dry-run；幂等；回滚方案 |

### 8.2 必须补的非功能

- **事务边界**：支付确认 + 排期 + 预占必须一个事务；分装 + 扣库存 + 状态必须一个事务；退款 + case 状态必须一个事务。
- **幂等**：支付回调、退款回调、售后提交、补发生成、分装提交。
- **并发**：条件更新（`WHERE status=...`）+ 版本号/updatedAt 检查；失败返回明确错误。
- **权限**：每个接口校验角色 + 订单归属；员工不能调管理员动作；顾客只能看自己的。
- **可观测**：日志带 orderId/orderNo/actor/action；指标（待排期数、逾期数、缺料数、退款失败数、售后超时）；告警。
- **特性开关**：自动排期、库存预占、客户售后、订单中心、自动完成。
- **回滚**：新表只加不删；旧接口保留一版；过渡期双写旧售后字段；必要时关闭客户售后入口。
- **数据保留/隐私**：售后照片、地址、退款记录的访问控制与留存。
