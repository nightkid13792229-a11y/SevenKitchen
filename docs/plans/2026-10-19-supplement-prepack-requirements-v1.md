## 零、一页纸

**卖什么**：顾客在 DIY 制作单里看到本次需要的补剂，一键买齐；我们按用量分装成小袋，**当天分装、当天发货**，独立于鲜食发货。

**本轮要解决的 6 件事**：

1. **顾客买得顺**：DIY 制作单 →「购买预分装补剂」→ 补剂下单页；可选发货日期，未选则按截单时间自动排。
2. **顾客看得见**：下单页、订单列表、订单详情都显示「预计发货日期」；分装日变更、售后进度有通知。
3. **生产排得清**：已付款订单自动排到分装日；后台/员工可改期；当天有汇总视图（单数、袋数、补剂总用量、缺料、包材）。
4. **库存管得住**：确定分装日即预占原料，分装完成扣减，取消/退款释放；缺料标红，管理员可强制分装并留痕。
5. **售后两端都能办**：顾客可申请退款/补发/其他问题并看进度；管理员在网页和小程序都能处理；员工只读。
6. **入口收拢**：后台、员工工作台、顾客「我的」都只保留**一个订单入口**，用类型筛选区分鲜食/定制/补剂。

**本轮不碰**：补剂定价算法、鲜食/定制现有售后数据的迁移、包材库存扣减、完整产能算法、作业单打印。

**关键数字**（均可在后台调整）：

| 项 | 本轮默认 | 可改 |
|---|---|---|
| 截单时间 | 每天 17:00 | ✅ 后台 |
| 顾客可选发货日期 | 今天起 30 天内 | ✅ 后台 |
| 分装日 = 发货日 | 是（当天做当天发） | 规则固定 |
| 每个补剂 | 1 袋（加量则每个补剂 N 袋） | 现有规则 |
| 每袋 | 1 包干燥剂 + 1 张标签 | 现有规则 |
| 缺料 | 允许排产，标红；分装时管理员可强制 | 规则固定 |
| 售后动作 | 仅管理员 | 权限固定 |

### 1.2 六个真实缺口

| # | 缺口 | 影响 |
|---|---|---|
| 1 | 补剂订单没有「分装日」，无法自动排产、无法回答“今天做哪些单” | 生产端只能一单一单翻 |
| 2 | 没有当天生产汇总（单数/袋数/补剂总用量/包材/缺料） | 备料、备包材靠人脑 |
| 3 | 分装/退款没有库存联动 | 可能超卖，或接了单才发现原料不够 |
| 4 | 员工工作台不能退款/补发；后台售后散落在补剂订单抽屉里 | 售后两端不一致 |
| 5 | 顾客补剂订单没有详情页，也不能申请售后/看进度 | 售后全压到客服私聊 |
| 6 | 后台/员工/顾客三端订单入口不统一；补剂与制作单没有真正绑定（`diySheetId` 未落库） | 管理成本高，追溯断 |

### 1.3 本轮的根本原则

1. **入口收拢，数据不重复**：订单中心是“看”的统一，不新建订单表；售后记录是“存”的统一，但不是新入口。
2. **能复用就不新建**：包材复用 `Ingredient(PACKAGING)`；日历复用定制排期；库存占用复用 `InventoryAllocation`。
3. **金额与日期由服务端算**：前端只渲染，不自己推算截单/排期/金额。
4. **售后进度独立于订单状态**：订单保留付款/分装/发货/完成，售后用单独记录表达。
5. **所有人工越权动作必须留痕**：改分装日、强制分装、退款、补发都要记录操作人/时间/原因。

## 三、业务规则

### 3.1 分装日与发货日期

#### 3.1.1 一个日期，两个叫法

- **系统内部**：`分装日（packingDate）`。
- **顾客侧**：`预计发货日期`。因为顾客只关心什么时候发货，不关心我们哪天分装。
- 本轮规则：**分装日 = 发货日**，当天分装、当天交快递。只存一个日期字段，不拆成两个。

#### 3.1.2 顾客怎么选

| 场景 | 规则 |
|---|---|
| 顾客不选 | 默认「尽快发货」，系统按 3.1.3 自动算 |
| 顾客选 | 可选 **今天起 30 天内**；只允许选营业日；已过去的日期、停发日不可选 |
| 今天能不能选 | 截单时间前且今天是营业日 → 可选；否则今天不可选 |
| 选了更晚的日期 | 下单页、支付结果、订单列表、订单详情都必须显示这个日期 |
| 支付时日期已失效 | 服务端重新校验；若已过截单/已停发，自动顺延到下一个营业日，并在支付结果页说明 |
| 支付后想改 | 顾客不能自己改，联系客服；管理员可改（3.1.4） |

#### 3.1.3 自动排期规则

**输入**：付款时间、截单时间、营业日历、顾客是否选了日期。

```
若顾客选了日期：
    分装日 = 顾客选的日期（服务端校验：≥今天、是营业日、在 30 天内）
否则：
    若 付款时间 < 当天截单时间 且 今天是营业日：
        分装日 = 今天
    否则：
        分装日 = 下一个营业日
```

补充规则：

1. **付款时间取真实支付时间**（微信回调里的 `paidAt`），不取回调到达时间；人工确认收款取确认时间。
2. 若算出的日期是停发日，**自动顺延到下一个营业日**，不报错。
3. 顾客选的日期若在支付时已不可用，按“无选择”重算，并提示“原选日期已不可用，已顺延到 X 月 X 日”。
4. 截单时间默认 **17:00**，后台可改；时区固定 Asia/Shanghai。
5. 自动排期在**支付成功/人工确认收款时立即执行**；另外每天截单时刻跑一次兜底任务，把仍未有分装日的已付款订单补排。

#### 3.1.4 管理员改期

- 管理员可在补剂订单详情里改分装日。
- 只能改到**营业日**；若目标日停发，提示先去「营业日历」打开该日，或另选日期。
- 改期必须填/可选填原因；系统记录操作人、原日期、新日期、原因、时间。
- 改期后给顾客发站内消息 + 微信订阅消息（若已授权）。
- 改期不改变订单金额，不重新报价。

#### 3.1.5 逾期

- 分装日已过、订单仍未分装 → 列表标红「逾期」。
- 逾期不影响顾客侧展示；顾客看到的是“预计发货日期已过，正在处理”，并可直接申请售后/联系客服。
- 员工/管理员可按「逾期」筛选。

#### 3.1.6 补发单

- 补发单生成时，分装日 = **下一个营业日**（不是原单日期）。
- 补发单同样预占库存、同样可改期。
- 补发单金额 0 元，顾客可见，标注“补发”。

### 3.2 排产

#### 3.2.1 什么叫“排产”

本轮排产 = **把已付款订单落到一个分装日**，不是产能算法。系统不做“每天最多多少单/多少袋自动顺延”；产能靠管理员看汇总后手动改期。

#### 3.2.2 自动排产

- 支付成功 / 人工确认收款时自动执行。
- 顾客选了日期 → 用顾客日期；否则按截单规则。
- 排产成功即**预占库存**（3.3）。
- 排产结果写入订单，并记一条订单事件（3.10）。

#### 3.2.3 生产汇总视图

**目的**：当天备料、备包材、看缺料，不是作业单，不打印。

**内容**：

| 区块 | 内容 |
|---|---|
| 概况 | 当天订单数、总袋数、补剂品种数、缺料品种数、逾期单数 |
| 补剂总用量 | 每种补剂：品名、规格、总用量（按分装单位）、涉及订单数、是否有缺料 |
| 包材需求 | 按规格：6×8 / 8×11 / 10×15 / 13×18 各多少只；干燥剂多少包；标签多少张 |
| 缺料预警 | 每种补剂的现有库存、已占用、可用、当日需求、缺口；红色标出 |
| 订单清单 | 订单号、顾客、袋数、状态、是否缺料；点进去处理 |

**口径**：

- 只统计**分装日 = 所选日期**且状态为 `PAID` / `PACKING` 的订单；`PACKED` 及之后不算“待分装”。
- 加量订单按 `bagCount` 计袋数。
- 补剂总用量 = 每条订单行的 `packedAmount × 份数`（现有 `bags` 已表达份数），按补剂汇总。
- 包材按 3.3.5 的规则选规格。
- 缺料判断用“可用库存 = 现有库存 − 已占用”，与库存占用口径一致。

#### 3.2.4 汇总视图在哪

- 后台「订单中心 → 补剂 → 分装汇总」。
- 员工工作台「订单 → 补剂 → 分装汇总」手机版。
- 默认今天，可切换日期。

### 3.3 分装与库存

#### 3.3.1 库存动作时机

| 时点 | 动作 | 说明 |
|---|---|---|
| 确定分装日（排产） | **预占** | 按订单行 `packedAmount` 预占原料；顾客选远期日期也立即占 |
| 分装完成 | **扣减** | 把预占转为实际消耗，写库存流水 |
| 取消订单 / 退款且未分装 | **释放** | 释放预占，库存回到可用 |
| 改分装日 | **移动占用** | 占用数量不变，目标日期改为新日期 |
| 已分装后退款 | **不释放** | 实物已分装，原料已消耗；走售后 |
| 补发单 | **重新预占** | 按补发单重新占库存 |

#### 3.3.2 缺料

- **排产时**：允许排，但汇总视图和订单列表标红；不阻止排产。
- **分装时**：默认阻止“完成分装”；管理员可**强制完成**，必须填原因，系统记录强制人/时间/原因，并允许库存出现负值/差异。
- 强制分装后，库存流水照常写负向消耗；差异在库存流水/审计里可查。
- 员工不能强制分装，只能看到“缺料，请联系管理员”。

#### 3.3.3 计量单位

- 库存按原料基准单位记账（G / ML / PCS）。
- 补剂订单行保存的是**展示单位 + 分装量**（g / 片 / 粒 / 平勺）。
- 上架前必须校验：展示单位能换算到基准单位；不能换算的补剂**不允许上架/下单**。
  - 基准 G：展示单位必须是 g/克（或可换算的 kg/mg）。
  - 基准 PCS：展示单位必须是 片/粒/勺/颗/袋/包/支/滴 等计数单位。
  - 液体（ML）本轮不支持分装，继续禁止上架。
- 该校验在「补剂上架清单」里作为 `ERROR` 级问题呈现，并在下单报价/下单接口再次拒绝，避免绕过前端。

#### 3.3.4 库存占用模型

- 复用现有 `InventoryAllocation` / `InventoryAllocationLine`，不新建第二张占用表。
- 给 `InventoryAllocation` 增加 `sourceType`：
  - `PRODUCTION`：鲜食生产（存量，默认值）
  - `SUPPLEMENT_PACK`：补剂分装（本轮新增）
- 补剂占用：`sourceOrderIds = [补剂订单 id]`，`targetDate = 分装日`，行数量 = 订单行 base 数量。
- 现有 `getAvailabilityByIngredientIds` 会自然把补剂占用算进“已占用”，因此可用库存口径自动统一。
- 消费/释放按 `sourceType + 订单 id` 精确匹配，避免与鲜食订单串。
- 新增补剂专用方法：创建占用、移动日期、释放、消费；不直接复用鲜食按 `purchaseListId` 的方法。

#### 3.3.5 包材汇总规则

**包材主数据**：复用 `Ingredient`（`type = PACKAGING`）。补剂需要的三种/四种袋、干燥剂、标签纸都建成 PACKAGING 原料档案。

**补剂包材配置**：新增一张小配置表，明确“哪些包材归补剂用、什么条件下选哪一档”。

| 配置字段 | 含义 |
|---|---|
| 角色 `role` | `POUCH`（袋）/ `DESICCANT`（干燥剂）/ `LABEL`（标签） |
| 关联原料 `ingredientId` | 指向 `Ingredient` 的 PACKAGING 档案 |
| 形态 `physicalForm` | POWDER / TABLET / CAPSULE（袋规则用；干燥剂/标签可空） |
| 最小量 `minAmount` / 最大量 `maxAmount` | 分装量区间（袋规则用；可空表示不限） |
| 优先级 `priority` | 多条命中时取优先级最高/区间最精确的一条 |
| 启用 `enabled` | 停用后不参与选型 |

**默认选袋规则**（可在后台改）：

| 形态 / 分装量 | 袋子 |
|---|---|
| 片剂、胶囊 | 6×8 |
| 粉剂 ≤10g | 6×8 |
| 粉剂 10–40g | 8×11 |
| 粉剂 40–120g | 10×15 |
| 粉剂 >120g | 13×18；若未配置 13×18，则标红“需拆袋/补配置” |

**每袋固定量**：

- 干燥剂：1 包/袋。
- 标签：1 张/袋。
- 袋子：1 只/袋。

**本轮边界**：

- 汇总视图只算“需要多少”，**不扣包材库存**。
- 包材档案建好后，后续可直接接入预占/扣减，不需要改模型。
- 若包材未配置，汇总视图显示“包材未配置”，并在后台设置页给出体检提示；不阻塞已有订单分装，但阻塞“新配置上线”检查项。

### 3.4 分装与标签

- 员工在补剂订单详情里看到：每个补剂的品名、规格、分装量、袋数、用量单位。
- 员工填写：批号（可选）、原瓶到期日（必填，每个补剂一条；同一补剂多袋共用）。
- 系统算：标签效期 = min(原瓶到期日, 分装日 + 该形态效期系数)。
- 守卫：原瓶剩余保质期低于配置下限 → 拒绝分装，提示退款/换货。
- 完成分装后生成标签；**一袋一张**；加量订单按袋展开。
- 标签仍走现有 60×40mm 排版和精臣 B3S 通道；网页 A4 备用保留。
- 本轮不需要打印“作业单”。

### 3.5 发货

- 只有 `PACKED` 才能填单号发货。
- 发货后状态 `SHIPPED`，记录快递单号/承运商/发货时间。
- 顾客在订单详情看到物流单号；站内消息/订阅消息可通知（若模板配置）。
- 发货后不再允许取消，只能走售后。

### 3.6 售后

#### 3.6.1 售后记录模型

- 新增一张**通用售后记录表**（`AftersaleCase`），本轮只写补剂；鲜食/定制继续用原记录，第二批迁移。
- 一张补剂订单可以有多条售后记录（退款后又补发、多次部分退款）。
- 同一张订单**同时只允许一条未完结售后**（防止重复提交）。
- 售后记录不是新入口：在订单中心/订单详情里看和处理。

#### 3.6.2 售后类型与状态

**顾客申请类型**：

| 类型 | 含义 |
|---|---|
| `REFUND` | 申请退款 |
| `RESHIP` | 申请免费补发 |
| `OTHER` | 其他问题/投诉，由管理员判断 |

**管理员处理结论**：

| 结论 | 含义 |
|---|---|
| `REFUND` | 退款（可全额/部分） |
| `RESHIP` | 免费补发（生成 0 元补发单） |
| `REGISTER_ONLY` | 仅登记，线下处理，不改钱/不补发 |
| `REJECT` | 驳回 |

**状态**：

```
PENDING（待受理）
  → PROCESSING（处理中）
  → RESOLVED（已完成）
  → REJECTED（已驳回）
  → CANCELLED（顾客撤回/作废）
```

- 管理员可以把 `PENDING` 直接改成 `RESOLVED` 或 `REJECTED`。
- `PROCESSING` 用于退款已发起但微信结果未回、或补发单已生成但未发货。
- 退款/补发结果出来后置 `RESOLVED`。

#### 3.6.3 顾客怎么申请

入口：补剂订单详情 →「申请售后」。

可申请条件：

- 订单已付款（`PAID` 及之后），且未取消。
- 没有未完结的售后记录。
- 在售后窗口内（窗口天数待确认，见第十章）。

表单：

- 诉求：退款 / 补发 / 其他问题。
- 原因：必填，最多 500 字。
- 凭证：最多 6 张图（可选；破损/发错建议上传）。
- 期望说明（可选）。

提交后：

- 生成 `PENDING` 售后记录。
- 顾客在订单详情看到“售后处理中”，可看当前状态和处理结果。
- 顾客可在 `PENDING` 阶段撤回（`CANCELLED`）。
- 站内消息 + 订阅消息通知管理员受理/结果（订阅消息需授权）。

#### 3.6.4 管理员怎么处理

入口：后台订单中心/补剂订单详情；小程序工作台仅管理员可见操作。

动作：

1. **受理**：`PENDING → PROCESSING`。
2. **改处理方式**：顾客选退款，管理员可改为补发/仅登记/驳回；反之亦然。
3. **退款**：
   - 可全额或部分退款；金额不得超过“实付 − 已退”。
   - 微信支付订单走原路退回；非微信支付可“仅登记”，线下退款。
   - 退款成功 → `RESOLVED`；退款失败 → 保留 `PROCESSING` 并显示失败原因，可重试。
4. **补发**：
   - 生成 0 元补发单，关联原单；分装日 = 下一个营业日；重新预占库存。
   - 补发单发货后 → 原售后记录 `RESOLVED`。
5. **仅登记**：填处理说明 → `RESOLVED`，不动钱、不补发。
6. **驳回**：填驳回原因 → `REJECTED`。

强制规则：

- 退款/补发/登记结论**仅管理员**可提交。
- 所有动作记录操作人、时间、金额/补发单号、原因。
- 同一订单多条售后记录时，退款累计不得超过实付。

#### 3.6.5 取消未分装订单

- 顾客在补剂订单详情可对 `PAID`（已付款、尚未开始分装）的订单点「取消订单」。
- `PACKING`（已开始分装）不允许顾客直接取消；需联系管理员，由管理员判断能否中止并走售后/退款。
- 系统直接取消 + 原路退款（微信支付）或登记线下退款，并释放库存。
- 取消不是售后记录，记一条订单事件；若退款失败，订单转“取消中/待退款”，提示联系客服。
- 已分装（`PACKED`）及之后只能走售后，不能直接取消。

#### 3.6.6 售后与订单状态

- **售后进度不改变订单履约状态**：已发货还是已发货，已完成还是已完成。
- 订单列表/详情用 `售后中` 标签 + 售后记录展示进度。
- 旧 `SupplementOrderStatus.AFTERSALE` 保留兼容，但**新售后不再写这个状态**；存量数据迁移时按需转成售后记录。
- 补发单是独立订单，顾客可见；原单仍保留，关联补发单号。

  - `WECHAT_TEMPLATE_SUPPLEMENT_SCHEDULE`

### 3.8 订单状态与展示口径

#### 3.8.1 补剂履约状态（不变）

```
PENDING_PAYMENT → PAID → PACKING → PACKED → SHIPPED → COMPLETED
        ↘ CANCELLED
```

- `PACKING` 表示已开始分装但未完成；顾客侧可归入“已付款/处理中”。
- `PACKED` 表示分装完成、待发货。
- 售后不再新增 `AFTERSALE` 状态。

#### 3.8.2 订单中心统一状态组

| 统一组 | 鲜食 | 定制 | 补剂 |
|---|---|---|---|
| 待处理 | INIT | — | — |
| 待付款 | PENDING_PAYMENT | PENDING_PAYMENT | PENDING_PAYMENT |
| 处理中 | PAID / PURCHASING / IN_PRODUCTION | PAID / IN_PROGRESS | PAID / PACKING |
| 待发货 | FREEZING（冷冻待发） | — | PACKED |
| 已发货 | SHIPPED | — | SHIPPED |
| 已完成 | COMPLETED | DELIVERED（显示“已交付”）/ COMPLETED | COMPLETED |
| 售后中 | AFTERSALE 或有未完结售后 | 有未完结售后 | 有未完结售后记录（含旧 AFTERSALE） |
| 已取消 | CANCELLED | CANCELLED | CANCELLED |

> 具体映射以实现时后端返回的 `statusGroup` 为准；前端不自己拼。

#### 3.8.3 顾客侧显示

- 补剂订单卡片：订单号、补剂种数/袋数、预计发货日期、状态、金额、售后标签。
- 补剂详情：预计发货日期、分装进度（已付款→分装中→已分装→已发货）、补剂明细、收货信息、物流、售后记录、操作按钮。
- 不再显示“生产日期/分装日期”给顾客，只显示“预计发货日期”。

### 3.12 异常与边界

| 场景 | 处理 |
|---|---|
| 支付成功但排期失败（如日历服务异常） | 订单仍为 PAID，`packingDate` 为空；进入“待排期”列表，定时任务/管理员补排 |
| 顾客选的日期在支付时已停发 | 顺延到下一个营业日，支付结果页说明 |
| 30 天内全是停发日 | 下单页提示“暂无可选发货日期，请联系客服”；服务端拒绝下单 |
| 同一订单重复提交售后 | 拒绝，提示已有未完结售后 |
| 退款金额超过可退 | 拒绝，提示剩余可退 |
| 退款接口失败 | 售后保持 PROCESSING，显示失败原因，可重试；订单状态不变 |
| 补发单库存不足 | 允许生成补发单但标红；分装时按缺料规则处理 |
| 员工尝试强制分装/退款 | 后端 403；前端不显示按钮 |
| 分装完成并发提交 | 后端状态机校验，第二次拒绝 |
| 包材规则未配置 | 汇总显示“包材未配置”；不阻塞分装，但上线检查项不通过 |
| 顾客取消已分装订单 | 拒绝，提示走售后 |

### 4.2 扩展（在现有表加字段）

| 表 | 新增字段（建议名） | 用途 | 为什么必须加 |
|---|---|---|---|
| `SupplementOrder` | `packingDate` | 分装日/发货日 | 排产的核心字段，没有就无法排、无法按日期筛 |
| `SupplementOrder` | `packingDateSource` | AUTO / CUSTOMER / ADMIN | 当前状态：区分自动排、顾客选、管理员改；重算/客服判断要用。历史变更仍进事件表，不在这里重复记 |
| `SupplementShopConfig` | `dailyCutoffTime` | 截单时间 | 业务要求可配置 |
| `SupplementShopConfig` | `advanceBookingDays` | 可选天数 | 业务要求 30 天可调 |
| `SupplementShopConfig` | `autoScheduleEnabled` | 自动排期开关 | 出问题时可临时关闭 |
| `SupplementShopConfig` | `aftersaleWindowDays` | 售后窗口 | 待确认后加 |
| `InventoryAllocation` | `sourceType` | 区分鲜食/补剂占用 | 防止两条业务串库存 |

> 刻意**不在订单表加** `scheduledAt` / `packedBy` / `rescheduledReason`：这些属于历史事件，统一进 `SupplementOrderEvent`，避免“当前状态字段 + 事件表”两套记录各写一半。订单表只保留查询/筛选必需的 `packingDate` 与 `packingDateSource`。

> 说明：`aftersaleWindowDays` 在 `custom_recipe_config` 已经存在，但那是**定制交付后**的售后窗口；补剂是**发货后**的窗口，起算点和业务都不同。两条产品线不共用一个值（与 `paymentTimeoutMinutes` 同理）。若评审认为本轮不需要后台可调，可以先写死 7 天、不加这个字段，避免为“待确认项”提前加列。
>
> 说明：`SupplementOrder` 上已有的 `aftersaleType/aftersaleReason/aftersaleAt/refund*` 字段**本轮不再写入新数据**，标记为兼容字段；新售后写 `AftersaleCase`。第二批迁移后删除（或保留只读）。

### 4.3 新增（必须说明为什么不能复用）

| 新对象 | 用途 | 为什么不能复用现有 |
|---|---|---|
| `AftersaleCase`（通用售后记录） | 一张订单多次售后、退款/补发/登记/驳回、进度 | 鲜食售后字段在 `Order` 上、定制在 `CustomRecipeAftersale`、补剂在 `SupplementOrder` 上，三套都无法表达“一单多次 + 统一展示”；本轮只写补剂，表结构通用，第二批迁移另外两类 |
| `SupplementOrderEvent`（补剂订单事件） | 排期/改期/强制分装/取消/发货审计与顾客时间线 | 现有只有鲜食 `OrderStatusHistory`；补剂没有事件表；用字段堆审计会不断加列 |
| `SupplementPackagingRule`（补剂包材规则） | 绑定包材档案 + 形态/克重选袋规则 | 现有 `PackagingService` 是鲜食真空袋/泡沫箱逻辑；`Ingredient` 只有物料主数据，没有“归补剂用 + 选型规则”；不建规则只能写死代码 |

> `AftersaleCase` 的边界：**通用表，但本轮只有补剂写入**。鲜食/定制仍用原记录，订单中心读模型统一展示；第二批迁移。这样既不重复建三张表，也不做一次性大迁移。

### 4.4 明确不新增

- ❌ 不新建补剂订单表（现有 `SupplementOrder` 够用）。
- ❌ 不新建包材主数据表（复用 `Ingredient`）。
- ❌ 不新建营业日历表（复用定制排期）。
- ❌ 不新建库存流水/占用表（扩展现有）。
- ❌ 不新建“售后工作台”页面/菜单（并入订单中心）。
- ❌ 不新建“排产作业单”表（汇总视图实时算，不落快照）。
- ❌ 不新增“生产日期”和“发货日期”两个字段（本轮同一天，只存一个 `packingDate`）。

### 4.5 现有字段的废弃计划

| 字段/状态 | 处理 |
|---|---|
| `SupplementOrder.aftersaleType` | 新售后不再写；存量保留；第二批迁移后删除 |
| `SupplementOrder.aftersaleReason` | 同上 |
| `SupplementOrder.aftersaleAt` | 同上 |
| `SupplementOrder.refundStatus/refundAmount/refundOutNo/refundId/refundReason/refundRequestedAt/refundedAt` | 新退款记录写 `AftersaleCase`；存量保留；第二批迁移后删除 |

### 7.1 顾客场景

| # | 场景 | 期望 |

| 5 | 选了停发日 | 日期不可选；若接口被绕过，服务端顺延并说明 |
| 6 | 30 天内全停发 | 下单页提示不可下单；服务端拒绝 |
| 7 | 已付款未分装，取消 | 订单取消、原路退款、库存释放 |

| 6 | 售后窗口天数确认 | 老板 | 设置页保存成功 |

| 8 | 现有补剂订单盘点 | 运营 | 待处理订单已排期/预占 |

### 8.2 数据迁移/回填

- 新增字段默认空；对存量补剂订单：
  - `SHIPPED` / `COMPLETED`：`packingDate = shippedAt` 的日期（无则 `createdAt`）。
  - `PAID` / `PACKING` / `PACKED`：按付款时间 + 截单规则回填；`PACKED` 可用 `packedAt` 日期。
  - `CANCELLED`：不回填。
  - `AFTERSALE`：尝试生成售后记录；无法判断的保留原字段并标记“待人工核对”。
- 存量 `PAID`/`PACKING` 订单是否补预占库存：由上线脚本按开关执行；先 dry-run 出清单，老板确认后再执行。
- 回填脚本必须可重复执行（幂等），并输出变更明细。

### 8.3 部署顺序

1. 后端 migration + 代码（先部署，保持旧前端兼容）。
2. 后台 Web（订单中心、设置、包材、日历）。
3. 小程序构建 + 上传体验版（不发布正式版）。
4. 生产验证：下单 → 排期 → 分装 → 发货 → 售后 → 库存对账。
5. 观察 1~2 天；无异常再考虑第二批。

> 按项目规则：后端与 admin-web 可直接部署生产；小程序只上传体验版，不发布正式版。

### 8.4 回滚

- 代码可回滚到上一提交；新增表/字段保留（只加不删），旧代码不受影响。
- 若自动排期异常：后台关闭「自动排期开关」，改为人工排期；不影响已排订单。
- 若售后新流程异常：旧退款/补发接口保留一个版本，可切回。
- 若包材汇总异常：汇总视图可降级为“只显示袋数”，不阻塞分装。

### 8.5 监控与对账

- 每日检查：待排期订单数、逾期订单数、缺料订单数、退款失败数、补发单数。
- 每周对账：补剂订单实付/退款/补发金额；库存流水与订单消耗。
- 告警：排期失败、退款失败、库存负值、售后超时未处理。
