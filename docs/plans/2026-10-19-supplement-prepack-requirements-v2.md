## 零、一页纸

**卖什么**：DIY 食谱里“这顿饭缺的补剂”，按用量分装成小袋，跟着食谱一起买、独立发货。

**顾客为什么买**：配得准、不用自己算；不用买整瓶、不浪费；一次买齐省事。顾客省的是**整单支出**，不是我们单价更低。

**怎么卖**：DIY 制作单里一键买齐本次推荐补剂，可逐项取消；不加购、不换品牌。

**怎么收钱**：

| 项 | 首发值 | 可改 |
|---|---|---|
| 加价倍率 | 2.5 倍（商品毛利 60%） | ✅ 后台 |
| 分装服务费 | ¥10/单（每单固定，不按袋） | ✅ 后台 |
| 运费 | ¥6/单（经济快递） | ✅ 后台 |
| 免服务费 | 商品满 ¥99 | ✅ 后台 |
| 包邮 | 商品满 ¥129 | ✅ 后台 |
| 最低商品金额 | 不设 | 规则 |
| 目标 | 商品毛利 60% + 单均贡献 35%–45%（平均） | 经营目标 |

**怎么交付**：

- 截单（默认 17:00）前付款 + 当天营业 → 当天分装、当天发；否则下一个营业日。
- 每天最多 **30 单**（按订单数，补发单也算）；Web 可配；超过顺延；管理员可超排留痕。
- 顾客侧只显示**确定的预计发货日期**，不能自选更晚日期。

**怎么售后**：

- 发货后 **7 天**内，缺货/发错/破损/量不对 → 退款或免费补发，不要求寄回。
- 售后资金动作仅管理员；员工只读。
- 售后进度独立于订单状态。

**怎么让顾客敢用**：

- 40×60mm 竖版标签，直接印：品名、分装量、分装日期、有效期、储存、原品、分装者、用法、干燥剂提示。
- 制作单首次下单补剂时冻结**整张制作单快照**；食谱改版不影响旧单。
- 正常发货、延迟、排期、售后都发站内消息 + 微信订阅消息。

## 一、生意模型结论

### 1.1 产品与顾客

| 项 | 结论 |
|---|---|
| 产品定位 | DIY 食谱的配套增值服务；只卖本次食谱推荐的补剂 |

## 二、顾客旅程与服务蓝图（结论）

> 详细版见服务蓝图；这里只写执行口径。

| 阶段 | 顾客要什么 | 我们给什么 | 失败点 |
|---|---|---|---|
| 认知 | 知道“自己做”会带补剂清单、不扣款 | 食谱详情按钮副文案“含补剂清单，不扣款” | 不知道、不敢点 |
| 考虑 | 知道生成制作单不产生订单 | DIY 配置页说明 | 怕扣款 |
| 制作单 | 知道补剂是什么、是否强制、怎么买 | 清单 + 可购数量 + “不买也能保存”；**不显示价格** | 入口太深、商城关闭不解释 |
| 下单 | 看清明细/服务费/运费/发货日 | 明细 + 服务费解释 + 运费 + 合计 + 每天约 + 预计发货日 | 价格超预期、日期不可选、部分缺货 |
| 支付 | 确认付成功、什么时候发 | 支付结果 + 预计发货日 | 支付成功排期失败 |
| 等待 | 知道进度、别忘了我 | 排期确认、**正常发货**、延迟：站内+订阅 | 延迟不通知、物流不动 |
| 收货 | 知道怎么用/怎么存/卫生 | 40×60 标签直接印用法/储存/原品/分装者/干燥剂 | 标签看不清、不会用 |
| 使用 | 每次加多少、能放多久 | 标签用法 + 食谱回看 | 用量对不上、受潮 |
| 售后 | 能退吗、麻烦吗 | 详情页入口 + 7 天承诺 + 进度 | 找不到、要寄回、处理慢 |
| 复购 | 怎么再买 | 订单详情“再次购买”，按快照清单/用量 | 价格变了、缺货 |

**三个关键时刻**：第一次看到“预分装”、看到价格、收到货。对应的文案与标签是本轮硬要求。

## 三、业务规则

### 3.1 商品、选品与卖法

1. **只卖本次食谱推荐的补剂**；不能加购食谱之外的补剂，不能换品牌/规格。
2. **默认全选**，顾客可逐项取消；至少选 1 项才能下单。
3. **部分不可买**：允许买可买的，缺的标灰并写原因；全部不可买时不显示购买入口/不允许下单。
4. **一个补剂一袋**；加量 = 同一补剂多做 N 袋同样规格；每袋一张标签。
5. **份数上限**：沿用现有 `maxPortionMultiplier` 与 `maxTotalDays`；总天数不超过效期安全线。
6. **商品快照**：下单时快照品名/品牌/规格/分装量/单价/成本/效期/储存条件；之后档案变化不影响已下单。

### 3.2 DIY 制作单快照

#### 3.2.1 什么时候冻结

- 顾客**第一次为这张制作单下单补剂**时，冻结整张制作单快照。
- 不为“生成了但没买”的制作单占存储。
- 冻结后不随食谱改版；想要最新食谱，重新生成新制作单，旧单保留。
- **边界**：如果顾客先用制作单做饭、之后食谱改版、再第一次买补剂，快照会以下单时看到的版本为准，不是最初生成制作单的版本。若必须保留“最初版本”，要改成制作单生成时冻结（当前决定不是）。

#### 3.2.2 快照内容（必须全）

| 区块 | 内容 |
|---|---|
| 食谱 | id、version、名称、营养标准、生产损耗率、营养详细数据 |
| 食材 | 每种食材的 ingredientId、名称、比例/示例重量、制备方法、营养状态 |
| 补剂 | ingredientId、名称、品牌、规格、用量、单位、选用商品、可购状态 |
| 狗狗 | id、名字、参与计算的体重/餐次等字段 |
| 制作单 | 周期天数、每餐克数、每日摄入、分装计划、采购清单、制作步骤 |
| 元数据 | 生成时间、食谱版本、快照版本 |

#### 3.2.3 快照后的行为

- 制作单页面展示快照，不再实时重算。
- 再次购买按快照的补剂清单/用量重新报价；价格/可售性以本次为准。
- 补剂订单必须落 `diySheetId` 与快照版本；**修复现有 `diySheetId` 未传的问题**。
- 如果顾客改狗/改天数：生成新制作单，旧单不变。
- 快照不复制支付/售后记录。

#### 3.2.4 再次购买

- 入口：补剂订单详情 →「再次购买」。
- 不要求有当前 DIY 制作单；按上一单/快照的补剂清单与用量重新报价。
- 价格、可售性以本次为准；缺货标灰，允许只买可买的。
- 地址重新选；发货日按新单重新排（占新单产能）。
- 生成新订单，不复制支付/售后记录；记录来源订单号（`reorderFromOrderNo`）。
- 页面不额外弹“价格可能变化”的提示；结算页本身显示本次价格。

### 3.3 价格与费用

#### 3.3.1 计价结构

```
商品小计 = Σ(每种补剂分装量 × 单位成本) × 2.5
分装服务费 = ¥10/单（每单固定；商品满 ¥99 免）
运费 = ¥6/单（商品满 ¥129 免）
合计 = 商品小计 + 服务费 + 运费
每天约 = 合计 ÷ 覆盖天数
```

- **不设最低商品金额**；小单可下，但后台要标记并监控贡献率。
- **目标单均贡献 35%–45% 是按周/按月平均，不是每单保证**；小单允许低于此。
- **不按袋收服务费**；按单收，鼓励一键买齐。
- **不做一口价套餐作为计价基础**；套餐只能做展示摘要。
- 价格由服务端算；前端不算乘法、不写死费率。
- 下单时快照价格；支付后不重新报价。
- 售后/退款按实付与累计退款校验。

#### 3.3.2 展示规则

| 位置 | 展示 |
|---|---|
| DIY 制作单 | **不显示价格**；只讲“按用量分好、不用买整瓶、不买也能保存” |
| 下单页 | 商品明细（每项可取消）+ 服务费 + 运费 + 合计 + 每天约 + 预计发货日 |
| 服务费解释 | 一行小字：“含称重/数片、分装袋、干燥剂、标签、人工；商品满 ¥99 免” |
| 运费解释 | “经济快递；商品满 ¥129 免” |
| 支付结果/订单详情 | 合计、预计发货日、售后承诺 |

#### 3.3.3 小单监控

- 小单定义：商品金额 < ¥29（内部标记，不拦单）。
- 后台订单中心显示“小单”标签；按周看小单占比与贡献率。
- 如果小单拖垮整体，第二批再评估“小单服务费/最低金额”，不在本批临时改。

### 3.4 排期、截单与产能

#### 3.4.1 一个日期

- 内部：`packingDate`（分装日）。
- 顾客：`预计发货日期`。
- 本轮分装日 = 发货日；只存一个日期字段。

#### 3.4.2 自动排期

```
若付款时间 < 当天截单时间 且 当天是营业日 且 当天未满产能：
    packingDate = 今天
否则：
    packingDate = 下一个有产能的营业日
```

- 截单时间默认 **17:00**，Web 可配。
- 时区 Asia/Shanghai。
- 付款时间取真实支付时间（微信 `success_time`）；人工确认取确认时间；拿不到才用回调时间。
- 顾客**不能自选更晚日期**；下单页只显示算出的最早发货日。
- 排期失败（日历/产能/库存服务异常）：订单仍为 PAID，`packingDate=null`，进入“待排期”；定时重试 + 后台告警；顾客看到“预计发货日待确认”。
- 每天截单时刻跑兜底任务，把未排期的已付款订单补排。

#### 3.4.3 产能

- 上限：**30 单/天**，Web 可配（`dailyPackingCapacity`）。
- 计数口径：**按订单数**，不是袋数；补发单也算一单。
- 超过上限：自动顺延到下一个有产能的营业日。
- 管理员手动改期：可以超排，但标红并记录原因/操作人。
- 降上限：已排订单不自动挪；超容日期标红，管理员处理。
- 取消/退款（未分装）释放当天名额。
- 产能检查与排期必须在同一事务/幂等逻辑内，避免并发超卖。

#### 3.4.4 改期

- 管理员可改分装日；只能改到营业日；停发日禁止，先去营业日历打开。
- 改期原因**选填**；必须记录操作人/原日期/新日期/时间。
- 改期后：库存占用日期跟着移动；通知顾客；不重新报价。
- 逾期：分装日已过仍未 PACKED → 列表标红；顾客看到“预计发货日已过，正在处理”。

#### 3.4.5 补发单

- 生成时排到**下一个有产能的营业日**，重新预占库存。
- 补发单金额 0 元；顾客可见；标注“补发”。
- 补发单取消：释放名额/库存，售后记录回到处理中。

### 3.5 库存

#### 3.5.1 动作时机

| 时点 | 动作 |
|---|---|
| 确定分装日 | 预占原料（按订单行 base 数量） |
| 分装完成 | 预占转实际消耗，写库存流水 |
| 取消/退款且未分装 | 释放预占 |
| 改期 | 移动占用日期，数量不变 |
| 已分装后退款 | 不释放（实物已消耗） |
| 补发单 | 重新预占 |

#### 3.5.2 缺料

- 排产时：允许排，标红；汇总显示缺口。
- 分装时：默认阻止完成分装；**管理员可强制完成**，必须填原因，留痕；允许负库存/差异。
- 员工不能强制分装。

#### 3.5.3 计量单位

- 库存按原料基准单位（G/ML/PCS）记账。
- 补剂订单行是展示单位 + 分装量；上架前必须校验**展示单位与基准单位 1:1 可对应**。
- **平勺可以作为库存单位**：`baseUnit=PCS`、`unitDisplayLabel=平勺`、`purchaseUnit=瓶`、`purchaseToBaseRatio=2000`，表示 1 平勺=1 PCS、2000 平勺/瓶；库存按 2000 PCS 记，不需要换算成克。
- 只有配方按克/半勺、无法整勺计数时，才用 `baseUnit=G`、显示单位 `g`；不在运行时猜密度。
- 不能换算的补剂：上架清单 `ERROR`，报价/下单接口拒绝；液体继续禁止。
- 库存占用复用 `InventoryAllocation`，新增 `sourceType`（`PRODUCTION` / `SUPPLEMENT_PACK`）；不新建占用表。

#### 3.5.4 包材

- 包材主数据复用 `Ingredient(type=PACKAGING)`；补剂袋/干燥剂/标签纸都建档案。
- 新增 `SupplementPackagingRule`：角色（POUCH/DESICCANT/LABEL）、关联原料、形态、最小/最大量、优先级、启用。
- 默认选袋：片剂/胶囊 → 6×8；粉剂 ≤10g → 6×8；10–40g → 8×11；40–120g → 10×15；>120g → 13×18（未配置则标红）。
- 每袋：1 袋 + 1 干燥剂 + 1 标签。
- 本轮汇总**不扣包材库存**；只算需求量。
- 包材未配置：汇总提示；不阻塞已排订单分装；上线检查项失败。

### 3.6 分装与标签

1. 员工在补剂详情看到每个补剂的品名、规格、分装量、袋数、用量单位。
2. 员工填写批号（可选）+ 原瓶到期日（必填，每个补剂一条；同补剂多袋共用）。
3. 标签效期 = **min(原瓶到期日, 实际分装日 `packedAt` + 形态效期系数)**。
4. 原瓶剩余保质期低于配置下限 → 拒绝分装，提示退款/换货。
5. 完成分装：状态 `PAID → PACKED`；扣库存；写事件；**不使用 `PACKING`**（仅旧数据兼容）。
6. 标签：**40×60mm 竖版**；一袋一张；加量按袋展开。
7. 标签必印：品名、原品（品牌·规格）、分装量+袋序、分装日期、有效期至、储存条件、分装者、用法、分装小样非直接食用、内含干燥剂请勿食用。
8. 不放二维码、不放纸质说明卡。
9. 标签/打印机/后端三处尺寸统一 40×60；修正现有 60×40 与 70×100 的不一致。
10. 支持补打；补打留痕，不重复扣库存。
11. 本轮不打印作业单。

### 3.7 发货与改地址

#### 3.7.1 发货

- 只有 `PACKED` 才能填单号发货。
- 发货后 `SHIPPED`；记录单号/承运商/发货时间。
- 正常发货、延迟都发站内 + 订阅消息。
- 发货后不能取消，只能售后。

#### 3.7.2 顾客自助改地址

- 入口：补剂订单详情。
- 允许状态：`PENDING_PAYMENT` / `PAID` / `PACKED`（未发货）。
- **`SHIPPED` 及之后禁止**；提示联系快递改派/客服。
- 只改本单收货快照；可选择“同时设为默认地址”。
- 后台记录原地址、新地址、操作人、时间。
- 如果已打包/已打印面单：提示“需要重新打印面单”；不静默。
- 地址必须属于当前用户；校验手机号/收件人/区域完整性。

#### 3.7.3 完成

- `SHIPPED` 后 **10 天自动完成**（后台可配 `autoCompleteDays`，默认 10）；管理员也可手动完成。
- 售后窗口从 `shippedAt` 起算，不依赖订单是否已完成；自动完成前有 3 天缓冲（售后 7 天 / 自动完成 10 天）。

#### 3.7.4 资金到账 vs 订单完成

- **钱不是等自动完成才到账**：微信支付成功后，货款按微信结算周期进入商户账户；`COMPLETED` 只是订单生命周期关闭，不是收款条件。
- 退款仍按售后窗口（从 `shippedAt` 起算）处理；退款从商户账户/待结算资金原路退回，与订单是否 `COMPLETED` 无关。
- 只有未来改用“平台担保交易/确认收货后结算”时，才需要等顾客确认；当前直连商户模式不适用。
- 对账口径：收款看支付成功/结算单；收入确认可按发货/完成；两者不要混。

### 3.8 售后

#### 3.8.1 边界

| 订单状态 | 顾客能做什么 |
|---|---|
| PENDING_PAYMENT | 付款/取消（未付款取消） |
| PAID（未分装） | **只能取消订单**（退款+释放库存）；不能申请售后 |
| PACKED / SHIPPED / COMPLETED | **只能申请售后**；不能直接取消 |
| CANCELLED | 只读 |

- 未分装取消与售后退款**不并存**；避免两条退款路径。
- `PACKING` 不再新写；旧数据按 `PAID` 处理。

#### 3.8.2 售后记录

- 新增通用 `AftersaleCase`；本轮只写补剂；鲜食/定制第二批迁移。
- 一张订单可多条售后；同一订单同时只允许一条未完结。
- 顾客申请类型：退款 / 补发 / 其他问题。
- 管理员结论：退款 / 补发 / 仅登记 / 驳回。
- 状态：`PENDING → PROCESSING → RESOLVED / REJECTED / CANCELLED`。
- 退款可全额/部分；累计不超过实付；退款失败保持 PROCESSING，可重试。
- 补发：每个售后记录最多一张补发单；不同售后记录可再次补发；补发单走正常排期/库存。
- 原始订单状态不变；售后用记录和“售后中”标签表达。
- 顾客可在 PENDING 撤回；驳回后可按规则再次申请（默认允许，同原因最多 2 次，管理员可放开）。
- 售后窗口：发货后 7 天（可配）；凭证选填，破损/发错提示上传。
- 售后资金动作仅管理员；员工只读。

#### 3.8.3 退款

- 微信支付：原路退回；非微信支付：仅登记/线下退款，不调微信退款。
- 退款金额 ≤ 实付 − 已退。
- 退款成功 → 售后记录 RESOLVED；退款失败 → PROCESSING + 失败原因 + 可重试。
- 退款回调按 `outRefundNo` 关联售后记录；幂等。
- 退款管理页（如保留）按来源筛选补剂退款，或订单中心售后视图可查；不重复建两套账。

#### 3.8.4 补发

- 生成 0 元补发单；继承原单商品/地址/清单；价格 0；分装日=下一个有产能营业日；重新预占。
- 补发单发货后，原售后记录 RESOLVED。
- 补发单取消：售后记录回到 PROCESSING，可重新补发/退款。

| **正常发货** | ✅ | ✅ |

  - `WECHAT_TEMPLATE_SUPPLEMENT_SHIPPED`

- 通知失败重试/去重；不阻塞主流程。

### 3.10 订单状态与展示

#### 3.10.1 补剂履约状态

```
PENDING_PAYMENT --支付--> PAID --完成分装--> PACKED --发货--> SHIPPED --7天/手动--> COMPLETED
PENDING_PAYMENT --超时/取消--> CANCELLED
PAID --取消(未分装,退款+释放)--> CANCELLED
```

- `PACKING` 仅旧数据兼容，不再新写。
- 售后不改变上述状态。
- `PAID` + `packingDate=null` = 待排期。
- `PACKED` + 超过计划发货日 = 逾期发货（标红）。

#### 3.10.2 订单中心统一状态组

| 统一组 | 鲜食 | 定制 | 补剂 |
|---|---|---|---|
| 待处理 | INIT | — | — |
| 待付款 | PENDING_PAYMENT | PENDING_PAYMENT | PENDING_PAYMENT |
| 处理中 | PAID / PURCHASING / IN_PRODUCTION | PAID / IN_PROGRESS | PAID（含待排期） |
| 待发货 | FREEZING | — | PACKED |
| 已发货 | SHIPPED | — | SHIPPED |
| 已完成 | COMPLETED | DELIVERED / COMPLETED | COMPLETED |
| 售后中 | AFTERSALE 或有未完结售后 | 有未完结售后 | 有未完结售后记录 |
| 已取消 | CANCELLED | CANCELLED | CANCELLED |

- 状态映射由后端返回；前端不自己拼。
- 售后中 = 有未完结售后记录（或旧 `AFTERSALE`），与履约状态并存。

#### 3.10.3 顾客侧显示

- 补剂卡片：订单号、补剂种数/袋数、预计发货日期、**履约状态 + 售后标签**（两者同时显示，不能用售后标签替代履约状态）、金额。
- 补剂详情：预计发货日期、分装进度、明细、收货地址（可改）、物流、售后记录、再次购买、快照入口。
- 不显示“分装日”，只显示“预计发货日期”。

### 3.14 异常目录

| 场景 | 处理 |
|---|---|
| 支付成功但排期失败 | PAID + packingDate=null；待排期；重试；顾客“待确认” |
| 当天产能满 | 顺延到下一个有产能营业日 |
| 管理员改到停发日 | 拒绝；先去营业日历打开 |
| 管理员改到满员日 | 允许，标红，填原因，留痕 |
| 连续 60 天无可排营业日/产能 | 下单页提示暂不可下单；服务端拒绝；联系客服 |
| 排期日期变化（日历/产能/改期） | 主动通知顾客；订单详情显示新日期 |
| 分装时缺料 | 员工不能完成；管理员可强制，填原因，留痕，允许负库存 |
| 原瓶效期不足 | 拒绝分装；转退款/换货 |
| 并发分装 | 状态条件更新，第二次拒绝；不重复扣库存 |
| 并发排期 | 产能检查+落日期事务/幂等，避免超卖 |
| 退款金额超可退 | 拒绝，提示剩余可退 |
| 退款接口失败 | 售后 PROCESSING + 失败原因；可重试；订单状态不变 |
| 同一订单重复售后 | 拒绝；提示已有未完结售后 |
| 补发单库存不足 | 允许生成但标红；分装按缺料规则 |
| 补发单取消 | 释放名额/库存；售后回 PROCESSING |
| 顾客取消已分装 | 拒绝；提示走售后 |
| 顾客改已发货地址 | 拒绝；提示联系快递/客服 |
| 面单已打印后改地址 | 允许改，提示重打面单 |
| 制作单快照缺失（旧单） | 回退实时数据，标“旧单无快照”；新单必须冻结 |
| 快照里的补剂下架 | 再次购买标灰；不可买；不静默替换 |
| 包材未配置 | 汇总提示；不阻塞已排订单分装；上线检查失败 |
| 订阅未授权 | 站内消息兜底；不报错 |
| 无收货地址/地址失效 | 下单前拦截；提示新增/修改地址；不生成订单 |
| 支付超时/重复提交 | 超时关单；重复提交幂等，不生成第二单 |
| 全部补剂不可售/商城关闭 | 下单页提示；服务端拒绝；制作单仍可保存 |
| 标签打印失败/打歪 | 可补打；不重复扣库存；记录补打次数/操作人 |
| 补发单重复生成 | 同一售后记录只允许一张补发单；重复请求返回已有单 |
| 退款回调丢失/延迟 | 售后保持 PROCESSING；主动查询/重试；不重复退款 |
| 消息发送失败 | 站内消息为主；订阅失败只记日志，不影响订单 |
| 售后窗口 7 天 / 自动完成 10 天 | 售后从 `shippedAt` 起算；自动完成前有 3 天缓冲；第 7 天 23:59:59 前可申请 |
| 员工越权调用管理员接口 | 后端 403；记录审计；前端不显示入口 |
| 顾客看别人订单 | 404/403；不泄露 |

## 七、状态机

### 7.1 履约

```
PENDING_PAYMENT --支付/人工确认--> PAID
PAID --完成分装--> PACKED
PACKED --发货--> SHIPPED
SHIPPED --7天/手动--> COMPLETED
PENDING_PAYMENT --超时/取消--> CANCELLED
PAID --取消(未分装,退款+释放)--> CANCELLED
```

### 7.2 排期

- 未排期（PAID + null）→ 已排期（有日期）→ 逾期（日期过 + 未 PACKED）→ 完成。
- 满产能 → 下一个有产能营业日。
- 超排 → 管理员留痕。

### 7.3 库存占用

- ACTIVE → RELEASED（取消/未分装退款）
- ACTIVE → CONSUMED（分装完成）
- 缺料：不阻塞排产，标红；强制分装允许负库存。

### 7.4 售后

| 当前 | 动作 | 下一状态 | 谁 |
|---|---|---|---|
| PENDING | 受理 | PROCESSING | 管理员 |
| PENDING | 直接退款/补发/登记 | RESOLVED | 管理员 |
| PENDING | 驳回 | REJECTED | 管理员 |
| PENDING | 顾客撤回 | CANCELLED | 顾客 |
| PROCESSING | 退款成功/补发发货 | RESOLVED | 系统/管理员 |
| PROCESSING | 驳回 | REJECTED | 管理员 |
| PROCESSING | 补发单取消 | PROCESSING | 系统 |
| RESOLVED/REJECTED/CANCELLED | 再次申请 | 新 PENDING | 顾客（受窗口/次数） |
