# 预分装补剂 · 服务蓝图（v1 · 2026-10-19）

> **这份文档回答**：顾客从第一次看到“预分装补剂”，到下单、收货、使用、出问题、复购，每一步经历什么；我们前台给他看什么，后台要做什么；哪里会流失。
>
> **不谈**：数据库、接口、排产算法。那些等这份蓝图确认后，再写进需求 v2。
>
> 配套：`2026-10-19-supplement-business-model-v1.md`（生意模型）。

---

## 零、一页纸

**顾客的完整旅程**：

```
食谱详情页（第一次听说）
  → DIY 配置页（决定自己做）
  → 制作单（看到补剂清单和“一键买齐”）
  → 补剂下单页（看价、选地址、看发货日）
  → 支付（确认）
  → 等待发货（收通知、查物流）
  → 收货开箱（看标签、知道怎么用）
  → 使用（按量加）
  → 出问题（申请售后）
  → 吃完（复购）
```

**三个最容易流失的地方**：

1. **第一次看到“预分装补剂”**：不知道是什么、为什么要买、是不是强制。
2. **看到价格**：商品 + 服务费 + 运费，觉得“怎么还有服务费/运费”。
3. **收到货**：不知道怎么用、怎么存、干燥剂能不能吃；标签不清楚就不敢用。

**三个最能建立信任的地方**：

1. 制作单上明确说“**不买也能保存制作单，不扣款**”。
2. 下单页明确说“**按用量买，整单更省；不用买整瓶**”。
3. 标签/说明写清“**分装量、分装日期、有效期、储存条件、分装者、内含干燥剂**”。

## 二、分阶段展开

### 2.1 阶段 1：认知（食谱详情页）

**顾客场景**：顾客在食谱详情页，看到“买成品”和“自己做”两个按钮。他可能第一次听说“自己做还能买补剂”。

**顾客心里的问题**：

- “我自己做，是不是要自己买一大堆补剂？”
- “点‘自己做’会不会直接扣钱？”
- “补剂是不是强制的？”

**我们前台要给**：

- “自己做”按钮下加一行小字：**“含补剂清单，不扣款”**。
- 不需要在食谱详情页讲“预分装”细节；一句话够了。

**我们后台要做什么**：无。

**失败点**：

- 顾客不知道“自己做”会带补剂清单 → 不会为了补剂点进去。
- 顾客怕点“自己做”就扣钱 → 不敢点。

**文案建议**：

> 自己做
> 含补剂清单，不扣款

---

### 2.2 阶段 2：考虑（DIY 配置页）

**顾客场景**：顾客选狗、选天数，准备生成制作单。

**顾客心里的问题**：

- “生成制作单要不要钱？”
- “补剂大概多少钱？”
- “我能不能先看看，不买？”

**我们前台要给**：

- 一句说明：**“生成制作单不产生订单、不扣款；补剂可在下一步自愿购买。”**
- **不显示价格**；只讲“按用量分好、不用买整瓶、不买也能保存”，价格到结算页看。

**我们后台要做什么**：算饭量、算补剂用量；失败时给明确原因和重试。

**失败点**：

- 计算失败，按钮灰着不说原因 → 顾客流失。
- 顾客以为生成制作单就要买补剂 → 不敢点。

**文案建议**：

> 生成制作单不产生订单、不扣款；补剂可在下一步自愿购买。

---

### 2.3 阶段 3：制作单（补剂清单 + 一键买齐）

**顾客场景**：顾客看到制作单，里面有食材表和补剂表，底部/清单区有“购买预分装补剂”。

**顾客心里的问题**：

- “这些补剂是什么？我认识吗？”
- “必须买吗？不买能不能只做饭？”
- “大概多少钱？”
- “买了之后是我自己分，还是你们分？”
- “多久能到？”

**我们前台要给**：

1. **入口标题**：不要只写“购买预分装补剂”，要写清楚价值：
   - “这顿饭缺的补剂，按用量分好，一次买齐”
2. **副文案**：
   - “不用买整瓶；用多少买多少，整单更省”
   - “独立发货；预计 X 月 X 日发”
   - “不买也能保存制作单”
3. **可下单数量**：
   - “共 N 种，其中 K 种可直接下单”
   - 不可买的标灰并写原因（缺货/未定价/不支持分装）。
4. **不显示价格**：老板已确认制作单不显示预计价格，到结算页再看；入口只讲“按用量分好、不用买整瓶”。
5. **信任点**：
   - “按食谱用量分装，一袋一用；标签写清分装日期和有效期。”

**我们后台要做什么**：

- 查商城状态（开/关/失败）。
- 算报价、可售性、预计发货日。
- 保存购买草稿，绑定制作单。

**失败点**：

- 入口藏太深（现在在清单区，需滚动）→ 看不到。
- 商城关闭/查询失败，入口消失不解释 → 以为没有这个功能。
- 价格不透明 → 点进去被吓退。
- 顾客以为“买了补剂 = 必须买饭” → 不敢点。

**文案建议**：

> **这顿饭缺的补剂，按用量分好，一次买齐**
> 不用买整瓶；用多少买多少，整单更省。
> 共 8 种，其中 6 种可直接下单
> 独立发货 · 不买也能保存制作单

---

### 2.4 阶段 4：下单（补剂下单页）

**顾客场景**：顾客进入补剂下单页，勾选补剂、选地址、看价格、提交。

**顾客心里的问题**：

- “为什么有服务费？”
- “运费怎么这么贵？能不能包邮？”
- “什么时候发货？”
- “能不能只买其中几样？”
- “地址能不能改？”

**我们前台要给**：

1. **商品明细**：每种补剂一行，显示品名、规格、分装量、袋数、价格；可逐项取消。
2. **不可买**：标灰 + 原因。
3. **价格三行**：
   - 商品小计
   - 分装服务费（每单固定；满 ¥99 免）
   - 运费（¥6；满 ¥129 免）
   - 合计 + 每天约
4. **服务费解释**：一行小字：“含称重/数片、分装袋、干燥剂、标签、人工。”
5. **预计发货日**：一个确定日期，不是“尽快”。
6. **发货说明**：“截单前付款当天发，之后下一个营业日；独立发货。”
7. **地址**：可选/新增；未发货可自助改地址，已发货不可改；已打面单提示重打。
8. **提交按钮**：明确金额和发货日。

**我们后台要做什么**：

- 校验商城开关、补剂可售、地址归属、发货日、最低金额（本轮不设）。
- 生成待付款订单，快照价格/地址/分装日。
- 支付超时自动关单。

**失败点**：

- 服务费/运费没有解释 → 顾客觉得被坑。
- 日期不可选/全部停发 → 没有说明。
- 部分缺货 → 顾客不知道少了什么。
- 地址错误 → 下单后无法改。

**文案建议**：

> 分装服务费 ¥10/单：含称重/数片、分装袋、干燥剂、标签、人工；商品满 ¥99 免。
> 运费 ¥6：经济快递；商品满 ¥129 免。
> 预计发货：X 月 X 日（周三）。截单前付款当天发，之后下一个营业日。

#### 2.4.1 改地址（顾客自助）

- 顾客在补剂订单详情可自己改收货地址，不需要联系客服。
- **未发货都可改**（待付款/已付款/已分装）；**已发货不能改**，只能联系快递改派/客服。
- 改地址只改订单收货快照，不改默认地址；可勾选“同时设为默认地址”。
- 如果已经打包/打印面单，改地址后提示“需要重新打印面单”，不静默。
- 后台记录原地址、新地址、操作人、时间。

---

### 2.5 阶段 5：支付（确认与预期）

**顾客场景**：顾客支付成功/取消支付/支付失败。

**顾客心里的问题**：

- “付成功了吗？”
- “什么时候发货？”
- “接下来我要做什么？”

**我们前台要给**：

- 支付成功：
  - “支付成功”
  - 订单号、金额
  - **预计发货日期**
  - “可在‘我的订单’查看进度”
- 支付未完成：
  - “订单已保留，请在 X 分钟内完成支付”
  - 不要写“我们会尽快确认收款”这种让顾客等的话（除非是人工确认模式）。
- 支付失败：
  - 区分“用户取消/网络失败/通道不可用”，给不同文案和“继续支付”。

**我们后台要做什么**：

- 确认收款、排期、预占库存、发通知。
- 如果排期失败：订单仍为已付款，标记“待排期”，给顾客“预计发货日待确认”，后台告警。

**失败点**：

- 支付成功但页面没反应 → 顾客重复支付。
- 排期失败但顾客看到“今天发” → 信任崩。
- 支付失败文案误导 → 顾客以为平台会来收款。

---

### 2.6 阶段 6：等待与发货

**顾客场景**：顾客付完钱，等收货。

**顾客心里的问题**：

- “什么时候发？”
- “会不会忘了我？”
- “物流到哪了？”

**我们前台要给**：

- 排期确认消息：“已安排 X 月 X 日分装发货。”
- 发货消息：“已发货，快递单号 XXX。”
- 延迟消息：“原定 X 月 X 日发货，因 XX 顺延到 X 月 X 日。”
- 订单详情可查物流。

**我们后台要做什么**：

- 按分装日汇总、备料、分装、贴标、发货。
- 逾期/延迟主动通知，不等顾客问。
- 售后入口保持可见。

**失败点**：

- 延迟不通知 → 顾客反复问客服。
- 物流单号填错 → 顾客查不到。
- 分装日到了没发，系统不标红 → 内部也忘。

#### 2.6.1 通知（正常发货也要发）

- 排期确认：站内 + 订阅。
- **正常发货**：站内 + 订阅（不是只有延迟才发）。
- 延迟：站内 + 订阅。
- 售后受理/完成/驳回/退款到账/补发发货：站内 + 订阅。
- 未授权订阅：站内消息兜底；不报错。

---

### 2.7 阶段 7：收货与开箱

**顾客场景**：顾客收到快递，拆开看到若干小袋。

**顾客心里的问题**：

- “这是什么？怎么用？”
- “一次加多少？”
- “能放多久？怎么存？”
- “干燥剂能不能吃？”
- “这是你们自己分的？卫生吗？”

**我们前台要给**（实物 + 标签）：

- **40×60mm 竖版标签**，每袋一张，标签上直接印：
  - 品名、原品（品牌·规格）
  - 每袋分装量 + 第几袋/共几袋
  - 分装日期、有效期至
  - 储存条件
  - 分装者名称
  - **用法**：“按本次食谱用量添加；开封后密封防潮”
  - “分装小样，非直接食用”
  - “内含干燥剂，请勿食用”
- **不放二维码、不放纸质说明卡**：老板已确认用法/产品说明都打在标签上。
- 外包装：极简合规，快递袋/盒；不需要定制盒。
- ⚠️ 现有后端标签图是 60×40、打印机传 70×100，三处不一致；必须统一改成 40×60，并实测长品名/长提示是否换行放得下。

**我们后台要做什么**：

- 分装卫生、称量准确、标签正确、干燥剂齐全。
- 标签效期 = min(原瓶到期日, 实际分装日 + 形态效期)。
- 出库前抽检。

**失败点**：

- 标签看不清/信息不全 → 不敢用。
- 没有使用说明 → 加错量/受潮。
- 干燥剂提示不明显 → 误食风险。
- 分装量不准 → 售后。

---

### 2.8 阶段 8：使用

**顾客场景**：顾客按食谱做饭，按量加补剂。

**顾客心里的问题**：

- “每次加一袋还是半袋？”
- “能不能和饭一起加热？”
- “受潮了还能用吗？”

**我们前台要给**：

- 标签写清“每袋是多少、够几次/几天”。
- 食谱页/制作单可回看用量。
- 使用说明写清“怎么加、能不能加热、怎么存”。

**我们后台要做什么**：

- 标签/说明与食谱用量一致。
- 售后可回答“用量/储存”问题。

**失败点**：

- 标签只写克数，不写“怎么用” → 顾客不会用。
- 食谱改版后，旧标签/旧订单对不上 → 困惑。

---

### 2.9 阶段 9：售后

**顾客场景**：顾客发现缺货/发错/破损/量不对/不会用。

**顾客心里的问题**：

- “能退吗？要寄回吗？”
- “找谁？麻烦吗？”
- “多久有结果？”

**我们前台要给**：

- 订单详情显眼的“申请售后”。
- 一句话承诺：“7 天内，缺货/发错/破损/量不对，直接退款或免费补发，不用寄回。”
- 表单：诉求（退款/补发/其他）、原因、照片（选填）。
- 进度：待受理/处理中/已完成/已驳回；结果通知。

**我们后台要做什么**：

- 管理员受理；退款/补发/登记/驳回。
- 补发单重新排期、预占库存。
- 通知顾客；记录售后历史。

**失败点**：

- 找不到售后入口 → 找客服私聊。
- 要求寄回 → 顾客嫌麻烦。
- 处理慢/没通知 → 差评。
- 同一单多次售后没有记录 → 重复退款/补发。

---

### 2.10 阶段 10：复购

**顾客场景**：补剂吃完了，想再买。

**顾客心里的问题**：

- “去哪再买？”
- “能不能按上次再来一份？”

**我们前台要给**：

- 补剂订单详情 → **“再次购买”**（第一批就做）。
- 点击后按上一单清单/份数重新报价；缺货标灰；地址重选；发货日按新单算。
- **不要求有当前 DIY 制作单**；不额外弹“价格可能变化”的提示，结算页本身显示本次价格。
- 不做订阅（本轮）。

**我们后台要做什么**：

- 生成新订单，不复制支付/售后记录；记录“从哪张单再来”。
- 记录复购率。

**失败点**：

- 价格变了/缺货 → 顾客觉得“和上次不一样”；结算页要清楚。
- 复购要重新走一遍 DIY → 太麻烦。

### 2.11 制作单快照（解决食谱改版）

**顾客场景**：顾客之前按某道食谱生成了制作单，也买过补剂；后来食谱改版，补剂种类/用量变了。顾客还想按当时的制作单做、按当时的清单再买。

**规则**：

- 顾客**第一次为这张制作单下单补剂**时，系统冻结一张制作单快照。
- 快照包括：食谱版本/名称/食材/补剂/用量/营养目标/制作步骤、狗狗参与计算的字段、周期天数、每餐克数、每日摄入、分装计划、采购清单、生成时间。
- 冻结后制作单页面展示快照，不随食谱改版；再次购买按快照的补剂清单/用量重新报价。
- 想要最新食谱：重新生成一张新制作单；旧单保留。
- 快照不复制支付/售后记录，只冻结“这次要做什么、买什么”。

**已确认**：

- 快照时点：**首次下单补剂时冻结**。如果先用制作单做饭、之后食谱改版、再第一次买补剂，快照以下单时版本为准。
- 快照范围：**整张制作单**（食谱+食材+补剂+狗狗+周期+每餐克数+分装计划+采购清单+制作步骤）。
- 冻结后不随食谱改版；想要最新食谱，重新生成新制作单。
- 必须同时修：补剂订单目前没有把 `diySheetId` 传下去。

```
顾客：  看食谱 → 点自己做 → 选狗/天数 → 看制作单 → 点买补剂 → 勾选/地址/看价 → 支付
```

## 四、三个关键时刻（MOT）

### MOT 1：第一次看到“预分装补剂”

- **顾客问题**：这是什么？必须买吗？
- **我们要做到**：一句话说清“按用量分好、不用买整瓶、不买也能保存制作单”。
- **失败后果**：不点、不理解、怕扣款。
- **负责页面**：食谱详情页、DIY 配置页、制作单。

### MOT 2：看到价格

- **顾客问题**：为什么有服务费/运费？值不值？
- **我们要做到**：明细价 + 服务费解释 + 每天成本 + “不用买整瓶，整单更省”。
- **失败后果**：价格吓退、觉得被坑。
- **负责页面**：制作单入口、下单页。

### MOT 3：收到货

- **顾客问题**：怎么用？怎么存？卫生吗？
- **我们要做到**：标签清楚 + 使用说明 + 分装日期/效期 + 干燥剂提示。
- **失败后果**：不敢用、用错、受潮、售后。
- **负责页面**：实物标签、使用说明（QR/卡片）。

### MOT 4：出问题

- **顾客问题**：能退吗？麻烦吗？
- **我们要做到**：订单详情显眼入口 + 7 天无理由 + 不用寄回 + 进度通知。
- **失败后果**：差评、客服压力、复购流失。
- **负责页面**：订单详情、售后申请、售后进度。

### MOT 5：吃完想再买

- **顾客问题**：去哪买？
- **我们要做到**：第二批做“再次购买”；本轮至少让顾客能回制作单。
- **失败后果**：复购流失。
- **负责页面**：订单详情、制作单列表。

| # | 问题 | 结论 | 影响 |
