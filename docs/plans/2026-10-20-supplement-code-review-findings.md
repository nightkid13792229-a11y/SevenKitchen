# 预分装补剂 · 代码审查发现（第一轮）

日期：2026-10-20  
审查方式：需求 v2 + 三端原型 + 当前 `main` 代码逐项对照；只审查，不改业务代码。  
结论：主流程代码已落地、构建和自动化测试通过，但**还不算“可以放心交给顾客和员工用”**。下面 P0 项建议先修再让真实顾客下单。

## P0 · 上线前必须修

### 1. 员工可以直接调用管理员资金/取消/排期接口
- 证据：`backend/src/interfaces/controllers/admin-supplement-shop.controller.ts:60` 整个控制器只挂 `AuthGuard + StaffGuard`；`orders/:id/cancel`（281-290）、`refund`（328-351）、`reship`（353-375）、`aftersale`（377-393）、`schedule`（233-257）都没有 `AdminGuard`。
- 需求：需求 v2 第 440-442 行明确“改分装日 / 强制分装 / 退款补发登记驳回 = 员工 ❌，管理员 ✅”；第 449 行要求员工端不展示金额、后端 DTO 脱敏。
- 影响：员工即使界面上没有按钮，直接调接口也能退款、补发、取消订单、改分装日；排期接口还会把操作人记成 `ADMIN`（251 行）。
- 另外：`pack`/`ship`/`cancel`/`schedule`/`markAftersale` 的返回值是完整订单（如 255、266、277、288、391 行），员工调用动作接口后仍能从响应里看到金额/退款金额，和“后端脱敏”不一致。
- 建议：资金/补发/取消/排期全部加 `AdminGuard`；员工动作接口返回 staff DTO 或只返回状态；补一条“员工直调接口 403”的测试。

### 2. 生产补剂配置不是首发目标值
- 生产实测 `supplement_shop_config`：`flatShippingFee=8`、`freeShippingThreshold=49`。
- 需求 v2 第 480-481 行：运费 **¥6**、包邮门槛 **¥129**；第 34-36 行服务费 ¥10、免服务费 ¥99。
- 影响：所有新订单运费和包邮门槛都按旧值算，顾客看到的价格与老板定的首发价不一致。
- 建议：后台「补剂商城设置」改为 6 / 129 后保存，再用报价预览核对一单；不要直接改库。

### 3. 展示单位与库存基准单位没有在“上架/报价/下单”阶段做 1:1 校验
- 证据：`backend/src/application/supplement-shop/supplement-catalog.service.ts:418-478` 的 ERROR 只检查价格、形态、保质期，没有检查 `baseUnit` 与 `unitDisplayLabel` 是否 1:1；`supplement-inventory.service.ts:196` 的 `toBaseQuantity` 只在排期预占/分装时才调用。
- 需求 v2 第 263-266 行：上架前必须校验 1:1；不能换算的必须 `ERROR`，报价/下单接口拒绝。
- 影响：例如 `baseUnit=G`、显示“平勺”的档案仍可上架、报价、付款；到排期时才失败，顾客已付钱但订单排不出去。
- 建议：把单位校验抽成公共方法，上架体检、报价、下单三处都调用；补一个“G + 平勺”拒绝用例。

### 4. 库存缺料没有“默认阻止分装 / 管理员强制分装”
- 证据：`backend/src/application/supplement-shop/supplement-inventory.service.ts:140-190` 的 `consumeForOrder` 只检查有没有预占，没有查可用库存；直接写负 ledger。`PackSupplementOrderDto` 没有 `force/forceReason`，`packOrder` 也没有强制分支。
- 需求 v2 第 253-258 行：缺料默认阻止分装；管理员可强制，必须填原因、留痕、允许负库存；员工不能强制。
- 影响：库存不足时仍能“正常”完成分装，账面直接变负，现场缺料无法在系统里被拦住；也没有强制留痕。
- 建议：分装前按 allocation lines 汇总可用量，不足则拒绝；新增管理员强制分装接口/按钮 + 原因 + 事件。

### 5. 顾客在主入口「我的订单」里用不到新增的补剂操作
- 证据：`miniapp/src/pages/orders-list/index.vue:141-187` 只展示补剂卡片；250-269 行只给未付款“去支付”；848-858 行补剂卡片点击不跳转，也没有详情页。取消/改地址/申请售后/再次购买只写在 `miniapp/src/pages/supplement-orders/index.vue`，而需求 v2 第 546 行明确旧独立页要下线/重定向，不是主入口。
- 需求 v2 第 534-535 行：C2 我的订单要显示补剂预计发货日/售后标签；C3 要新增补剂订单详情（进度、地址、物流、售后、再次购买、快照）。
- 影响：顾客从“我的 → 我的订单”进来后，看不到预计发货日、售后中标签，也点不进改地址/售后/复购；新做的顾客能力实际不可达。
- 建议：至少先给补剂卡片加“管理订单”跳旧列表；完整做法是补 C3 详情页，再把动作搬过去。

### 6. 站内消息 / 微信订阅消息没有实现
- 需求 v2 第 57、298、373-389 行：排期、正常发货、延迟、售后都要发站内 + 订阅；正常发货通知是本轮第一批范围。
- 代码：全局搜索未发现补剂订单的 `CustomerMessage`/订阅消息发送；`shipOrder` 只改状态，不发消息。
- 影响：顾客收不到排期确认、发货、延迟、售后通知；第一批范围缺一块。
- 建议：先接站内 `CustomerMessage`（`linkType=SUPPLEMENT_ORDER`），订阅失败只记日志；发货/排期/售后三处触发。

## P1 · 强烈建议本轮修

### 7. 包材规则、分装汇总、员工备料汇总缺失
- 需求 v2 第 554/556/580 行：A3 分装汇总、A5 包材配置、S4 员工分装汇总都是新增页；原型 `admin.html#a-summary/#a-packaging`、`staff.html#s-summary` 都有。
- 代码：schema 有 `SupplementPackagingRule`，但没有 service/controller/API；`admin-web/src/router/index.ts:78-106` 没有分装汇总/包材路由；员工端没有汇总页。
- 影响：每天不知道要备多少袋/干燥剂/标签，也不知道哪些原料缺料；包材规则无法配置。这是生产现场每天要用的，不是“以后再说”。
- 建议：先做只读汇总（订单数/袋数/原料总量/包材需求量/缺料），再做包材规则 CRUD；包材未配置只提示，不阻塞分装。

### 8. 后台补剂订单详情缺排期、强制分装、改地址、快照
- 需求 v2 第 553 行 A2 要求：排期/改期/分装/强制分装/标签/发货/售后/地址审计/快照。
- 代码：`admin-web/src/views/SupplementShop/components/SupplementOrdersPanel.vue` 只有分装、发货、取消、登记售后；没有排期、强制分装、改地址、快照区块。排期接口目前只被员工端调用，而后台没有入口。
- 影响：管理员日常处理“改期/缺料强制/顾客电话改地址/查快照”只能调接口或找开发。
- 建议：在补剂订单详情补齐这 4 块；改地址接口同时补管理员入口和地址审计。

### 9. 审计事件不完整，改地址没有记录原/新地址
- 需求 v2 第 456-465 行：排期、开始/完成/强制分装、发货、取消、改地址、再次购买、售后关联都要留事件；改地址必须能追溯到人、原地址、新地址。
- 代码：`supplement-order.service.ts:654-671` 分装不写事件；`695-703` 发货不写事件；`771-781` 取消不写事件；`833-841` 改地址事件只有 `{needsReprint}`，没有原/新地址和操作人；`createReshipForCase` 也没有原单事件。
- 影响：出现纠纷时无法还原“谁在什么时候改了什么”；不符合老板确认的审计要求。
- 建议：补 `PACKED/SHIPPED/CANCELLED/REORDERED/RESHIPPED` 事件；改地址事件写 `oldAddress/newAddress/actorType/actorId`；分装记录操作人（同时用于标签“分装者”）。

### 10. 员工/后台订单列表看不到“新售后 case”
- 证据：新售后只写 `aftersale_case`，不再写订单 `aftersaleType`；但 `miniapp/src/pages/staff-supplement-orders/index.vue` 和 `admin-web/.../SupplementOrdersPanel.vue` 仍按 `order.aftersaleType` 显示售后。
- 需求 v2 第 3.8.2 行：售后进度独立于订单状态；员工只读但应能看到“售后中”。
- 影响：新售后提交后，员工/后台在补剂订单列表和详情里看不到，只有单独的售后页能看到；现场会以为没售后。
- 建议：列表/详情查询补剂未完结 case（批量查，避免 N+1），显示“售后中/退款中”标签；员工端只读。

### 11. 包邮文案与真实计价相反
- 证据：`admin-web/src/views/SupplementShop/Config.vue:274` 写“商品金额（补剂费 + 服务费 + 包材费）达到该金额即免运费”；`supplement-pricing.service.ts:451` 实际只按纯商品小计算。
- 影响：后台配置人员会按错误口径理解，顾客看到的门槛解释也可能不一致。
- 建议：文案改成“仅补剂商品小计（不含服务费/包材/运费）”。

### 12. 手动完成、自动完成口径
- 需求 v2 3.7.3：10 天自动完成，管理员也可手动完成；售后从 `shippedAt` 起算。
- 代码：`supplement-scheduling.service.ts:160` 用 `Date.now() - days*24h`，不是上海自然日；后台没有“手动完成”入口/接口。
- 影响：跨时区/跨天边界会提前或延后完成；管理员遇到异常订单无法手动关闭。
- 建议：按上海自然日计算；补管理员手动完成接口 + 按钮；完成写事件。

## P2 · 可排后续迭代

- 标签“分装者”现在印的是品牌名（`packerName: config.labelBrandName`），不是实际操作人；标签长品名没有压力测试，商品名行不会自动换行。
- 标签边距当前左右 2mm/底部 4mm，技术方案写 3mm 全边；建议打样后统一。
- 顾客 C1 角标只加了补剂总数，没有“售后中”角标；C6 制作单没有“已购买/已冻结快照”标识；C7 没有补剂支付结果页；C14 旧补剂列表没有重定向。
- 后台订单中心没有导出/批量、没有旧页面重定向；定制食谱的售后标记目前固定 false。
- 非微信支付的 PAID 订单，顾客端取消会直接报“请联系客服线下退款”，没有“仅登记”路径。
- `SupplementAftersaleService.createForAdmin` 复用顾客校验，事件 actor 仍记 CUSTOMER；旧后台详情仍显示旧 `aftersaleType` 字段。
- 退款回调重复到达时会重复写 `REFUNDED` 事件（幂等只挡了状态，没挡事件）。
- 订单中心 `dateFrom/dateTo` 的 DTO 允许 ISO 日期时间，服务只接受 `YYYY-MM-DD`，异常输入可能 500。

## 已验证通过的部分

- P0-P6 主流程代码、生产 migration 192/192、后端健康检查、admin-web 构建、miniapp 构建、体验版上传均已完成。
- 补剂相关自动化测试最近一次 16 suite / 188 用例通过；标签 40×60 尺寸、定价门槛、库存预占/扣减、售后 case、订单中心/看板均有单测。
- 员工列表/详情前端已移除金额展示；读取接口有 staff 脱敏（问题在动作接口响应和权限，不在读取页）。

## 建议修复顺序

1. 生产配置 6/129（不改代码，后台保存）。
2. 员工接口权限 + 动作响应脱敏 + 排期权限。
3. 单位 1:1 校验（上架/报价/下单）。
4. 顾客 C3 详情/入口（至少先让动作可达）。
5. 缺料阻止 + 强制分装。
6. 包材/分装汇总 + 后台 A2 缺的 4 块。
7. 通知 + 审计事件。
