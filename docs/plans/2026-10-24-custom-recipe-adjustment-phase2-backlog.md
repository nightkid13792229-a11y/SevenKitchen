## 1. 已交付的调整总结 + 最新食谱

- [ ] 后台“处理完成”时继续要求填写 `handleNote`，并在顾客端显示为“**调整总结**”。
- [ ] 重新交付后把新交付的 id 写回售后单：`CustomRecipeAftersale.linkedDeliveryId`。
- [ ] 顾客卡“**查看最新食谱**”必须指向这次新交付；没有新交付时不显示这个入口，或不要显示“已交付”。
- [ ] 把后台“处理完成”和“重新交付”串成一个动作（或至少约束：没有重新交付不能标已交付），避免只点“完成”。
- [ ] 多份订单：新交付可能有多份，`linkedDeliveryId`/最新入口要能落对份；至少要落到订单详情让顾客自己选。
- [ ] 回归：顾客卡显示调整总结；点“查看最新食谱”打开的是新版本；旧单没有 `linkedDeliveryId` 时不报错。

## 2. 后台订单中心 → 食谱设计器

- [ ] 订单中心售后申请详情显示：顾客需求文字、附件、涉及的食谱（多份时列清楚）。
- [ ] 加“**进入食谱设计器**”入口。
- [ ] 食谱设计器展示“顾客调整需求”和附件（只读面板，避免营养师来回切页面）。
- [ ] 营养师改完并交付新版本后：售后单写 `linkedDeliveryId`、状态置 `RESOLVED`。
- [ ] 多份订单：设计器能按选中的份分别处理/重新交付；不要把整单当成一份。
- [ ] 回归：从售后进设计器 → 改 → 交付 → 顾客看到已交付和总结；后台售后单状态、交付 id 对得上。
