# AI 封面 · 风格系统（2026-11-07）

> 老板 2026-11-07 定的方向：把「拍成什么样」拆成固定模板 + 少量变量，
> 解决三件事：陈列感不足、风格每个都不一样、食材漏画/多画。

## 1. 为什么改

旧链路：DeepSeek 自由写一段话 → 直接当图片提示词。
系统提示词只有 5 句，没写机位、台面、陈列、道具、光线，
Seedream 只能按默认审美走：深色石板 + 灰色影棚背景 + 食材堆成一堆。

## 2. 现在的分工

| 层 | 谁决定 | 内容 |
| --- | --- | --- |
| 品牌层 | 代码写死 | 正俯拍 90°、窗光、分组留缝、四周留白 10%、无文字、全部生鲜 |
| 预设层 | 代码里的 3 套预设 | 台面 + 道具 + 色调（都用浅色，和首页橱窗的奶油白 UI 搭） |
| 骨架层 | 代码里的 3 种骨架 | 中心环绕 / 平行三行 / 对角三段 |
| 内容层 | DeepSeek | 每样食材一句「形态说明」（整块/切片/堆成圆锥……） |

拼装顺序（`buildCoverPrompt`）：

```
清单（必须且只能出现这 N 种）
→ 机位（看不到桌沿、没有透视）
→ 台面 / 骨架
→ 每样食材一行：形态 + 位置 + 用量档位
→ 道具 + 安全区
→ 光线 / 色调
→ 负面词
→ 机位复述（结尾再压一次）
```

清单和机位由代码写死，模型改不了；模型只填「形态」这一格。

## 3. 一次出 3 张

- 后台点一次「AI 生成封面」→ 并发出 3 张（约 0.6 元，40–70 秒）；
- 三张分别是三种预设 × 骨架，运营挑一张，没选中的自动进回收站；
- 部分失败不整体报错：成功几张返回几张；
- 同一份食谱最近用过的组合会被记住，下一次优先避开。

## 4. 预设与骨架

预设：`CREAM_STONE`（米白石材，默认）/ `WHITE_MARBLE`（白大理石，冷调）/
`LIGHT_OAK`（浅橡木，奶油调）。

骨架：`RING`（中心主料 + 环形）/ `ROWS`（平行三行，图鉴式）/
`DIAGONAL`（对角三段）。

都在 `backend/src/application/recipe-designer/cover-style.ts`，改文案即可，
不碰数据库。

## 5. 接口

```
POST /api/v1/recipe-designer/drafts/:draftId/ai-cover?variants=3
POST /api/v1/admin/recipe-series/:seriesId/ai-cover?variants=3
```

响应新增 `candidates[]`（url + 预设/骨架标签），`url` 仍等于第一张，
老调用方不受影响。`variants` 夹在 1–3。

## 6. 系统提示词（DeepSeek）

默认值在 `recipe-cover-config.service.ts` 的 `DEFAULT_RECIPE_COVER_PROMPT`，
只要求模型写「名称｜形态」，不写摆位/机位/负面词。
线上旧版默认（2026-10-31 那段）会被识别为「没改过」，自动回退到新版。

## 7. 已知边界

- 「相机跑偏」靠提示词约束，没有做生成后的图像检测；如果以后还要更稳，
  可以加一步视觉校验（视角/缺项/文字），不达标自动重跑。
- 深色石板版（A）没有进这套预设，留给活动 Banner / 详情页首图。
- 发布抽屉（SeriesReleaseDrawer）只出 1 张，避免白花钱生成用不到的候选。
