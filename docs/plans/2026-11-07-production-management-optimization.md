# 生产管理优化方案（2026-11-07）

> 状态：Phase 0–3 全部审核完成；Phase 3 PASS WITH ISSUES（0 阻塞），修复后合并 main
> 已合并基线：`43162595`（首批 4 项修复已进 `main`）
> 适用页面：生产管理（鲜食生产 / 补剂分装）、任务详情、制作单/标签打印、
> 补剂订单列表 / 详情 / 补剂标签

---

## 1. 背景

2026-11-07 对生产管理模块做了一轮 UI / 交互审查，结论是：

- 方向是对的：鲜食和补剂合并成一个入口、跨天未完成继续显示、按锅次生产。
- 但现场使用会踩坑：首屏数字和列表打架、顶部标题看不见、删除按钮的实际范围
  大于它看起来的范围、待制作详情页没有“开始制作”、照片没传成功也能完成。
- 另有一批一致性和打磨问题：字号偏小、触控区偏小、卡片层次弱、术语混用。

本方案把全部问题拆成 5 个阶段，每阶段独立分支、独立验收、独立审核。
目标不是“一次改完”，而是**每一阶段都能单独合并、单独回滚**。

## 2. 已确认的产品规则（老板 2026-11-07 拍板）

1. **删除按生产批次执行，不按锅。** 同一次排单产生的几锅共用一个批次，
   点任意一张锅卡的删除，整批一起删。
2. **已完成的生产任务不允许删除。** 批次里只要有一锅已完成，整批都不给删。
3. **完工必须拍至少 2 张照片**，不允许“先完工、后补照片”。
4. **照片上限从 3 张改为 5 张**，只有上传成功的照片才算数。
5. **首屏 4 个数字是“今日全部待办”**，包含跨天未完成的锅，不能再出现
   “四格 0、列表 2”这种自相矛盾。
6. **补剂分装是看板**，看板上要能直接进“打印标签”页，不要先进订单详情。

## 3. 目标与非目标

### 目标

- 厨房员工打开页面就知道“今天要做什么、先做哪锅、下一步点哪里”。
- 危险操作（删除整批、完成制作）的范围和后果一眼可见，不能误触。
- 网络失败、没有数据、加载中三种状态能被区分，不能把“加载失败”显示成“今天没活”。
- 页面符合团队《员工端 UI 规范》：深色导航、字号 ≥ 24rpx、触控 ≥ 88rpx、
  卡片纯白、对比度达标。
- 每个阶段都有回归测试和构建证据，合并前由独立 Agent 审核。

### 非目标（本方案不做）

- 不重做排单算法、锅次拆分、成本核算等后台业务逻辑。
- 不改顾客端页面。
- 不做“补剂分装记录进度 / 一次打印当天全部标签”这类新功能，
  除非老板单独拍板（见第 8 节）。
- 不做深色模式、国际化。

## 6. 每阶段执行与审核流程

1. 从最新 `origin/main` 开工位（`bash scripts/session.sh start "..."`）。
2. 先改回归测试，看它红；再实现，看它绿。
3. 跑该阶段相关测试 + `npm run build:mp-weixin`。
4. 派一个**全新上下文的独立 Agent** 审核：
   - 只给：本文件、分支名、阶段范围、验收标准；
   - 让它自己读 diff、跑测试、检查边界；
   - 输出 `PASS / PASS WITH ISSUES / FAIL`，每条带文件 / 行为证据；
   - 审核 Agent 只审不改，避免“自己改自己审”。
5. 按审核意见修；FAIL 必须复审。
6. `session.sh merge` 合并（拿门禁），必要时上传体验版。
7. 更新本文件第 9 节，进入下一阶段。

**独立 Agent 能审什么**：代码正确性、回归、边界、与规范的一致性、测试覆盖。
**不能替代什么**：真机视觉、厨房手感、产品取舍。所以 Phase 1 后保留一次
老板检查点，Phase 4 再做最终验收。
