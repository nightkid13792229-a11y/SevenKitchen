# AI 封面 · 编辑摄影版（2026-11-18）

> 老板 2026-11-18 定：把「原料标本图」改成「编辑摄影」——
> 斜上方 45–55°、自然窗光、一个整块主料当主角、配角在周围排成松散弧形、
> 小料/补剂只放边缘小碟，不出现品牌包装和瓶子。

## 1. 为什么改

2026-11-07 版把封面拆成「正俯拍 + 环形/三行/对角 + 每样食材一个格子」，
解决了「每张一个样、漏画/多画」，但带来了三个新问题：

- 14–20 种食材一视同仁，没有主角，画面像原料清单；
- 正俯拍 + 一句「左上 45° 柔光」被模型打成均匀平光，像影棚目录图；
- 食谱里的「打碎/切丁/绞肉」被写进形态，鸡胸变肉糜、牛肉变小方块，
  失去「整块食材」的新鲜感。

老板给的 Gemini 参考图是另一种语言：一个整块主料（整块牛霖/整条鱼/整块鸡胸）当主角，
其余食材围绕它，自然窗光有亮面/暗面/长影子，画面有留白。

## 2. 新的分工

| 层 | 谁决定 | 内容 |
| --- | --- | --- |
| 品牌层 | 代码写死 | 斜上方 45–55°、自然窗光、主料弧形、无文字、清理照做/切碎不做 |
| 预设层 | 代码里的 3 套 | 石板暖窗光 / 大理石冷调 / 橡木奶油调（台面 + 背景 + 道具 + 色调） |
| 摆法层 | 代码写死 | 只有一种：主料在前景中央偏左，配角在周围排成松散弧形 |
| 内容层 | DeepSeek | 每样食材一句「封面形态」（整块/大块/整条/整颗…）；只给名称，不读预处理 |
| 补剂层 | 代码 | 最多 3 个小碟/小勺，只表现粉/胶囊/油，不出现包装/瓶子/标签 |

拼装顺序（`buildCoverPrompt`）：

```
品牌句 → 清单（必须且只能出现这 N 种）→ 主料（整块/大块）
→ 配角（最多 9 个，松散弧形）→ 边缘小料 → 补剂小碟
→ 道具 → 台面/背景 → 摆法 → 机位 → 光线 → 色调
→ 安全区 → 生鲜/低加工规则 → 负面词 → 真实质感
```

## 3. 数据与规则

- 食材：食品类按占比降序；主角优先选最大的肉/鱼/内脏（蛋白 <10% 时退回整体最大）。
- 配角：主角之外最多 9 个给独立位置；其余进「边缘小料」，不再逐个排格子。
- 补剂：设计草稿/系列都单独取，按克数取最多 4 个；只用来决定小碟里放粉/胶囊/油。
- 预处理：**完全不读** `preparationMethod`；工具结果只给食材名称，
  封面只按名称写自然、原始、完整形态（整块肉、整条鱼、带壳贝、整颗蛋、整粒谷物）。
  理由（老板 2026-11-18）：封面是食欲图，不是生产切配图；整条鱼/带壳贝反而更真实。
- 负面词：文字、标签、LOGO、包装、补剂瓶、人手、熟食、肉糜、切碎小丁、血水、黏液。

## 4. 三张候选

还是并发出 3 张（约 0.6 元），但三张只换台面/背景/色调，不换摆法：
石板暖窗光 / 大理石冷调 / 橡木奶油调。运营挑一张，没选中的自动进回收站。

## 5. 接口与兼容

- `GenerateRecipeCoverInput` 新增可选 `supplements?: RecipeCoverSupplement[]`。
- `DesignRecipeCoverImageService` / `SeriesCoverImageService` 各自取补剂并传入；
  `foodNames` 仍然只含食品，前端展示不变。
- 旧的 `buildRecipeCoverPrompt`（无 `loadIngredients` 的兼容路径）保持不动。
- `DEFAULT_RECIPE_COVER_PROMPT` 更新为 2026-11-18 版；线上旧的
  2026-11-07 默认会被 `LEGACY_PROMPT_MARKERS` 识别并自动回退。

## 6. 已知边界

- 还没有生成后的图像自检（视角跑偏/缺项/文字），目前靠提示词约束。
- 封面不体现食谱预处理（去皮/去骨/切碎），运营不要用封面判断实际切配状态。
- 补剂形态从名称推断（粉/油/胶囊/片），没有读 `physicalForm`；
  如果以后要更准，可以在取数时带上 `physicalForm`。
- 封面只展示占比最大的 9+ 种，其余进边缘小料；完整配方仍在食谱页。
