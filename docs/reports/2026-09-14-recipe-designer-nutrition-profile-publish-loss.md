# 食谱设计器发布导致「营养档案（生/熟）丢失」问题 —— 处理说明

日期：2026-09-14（生产数据核查时间）
影响面：设计器发布到后台的正式食谱
状态：代码已修复并通过测试；**历史数据仅生成修复清单，尚未写库**；生产尚未部署。

## 一、问题现象

在 Web 端「食谱设计器」里给原料选定的营养档案（例如「红甜椒（水煮沥干，不加盐）」，状态=熟），
发布到后台后，在食谱详情编辑页里显示的却是「红甜椒（生）」。

## 二、根因

1. **发布环节丢字段**：设计器发布正式食谱时，原料项只写入了用量、占比、制备方法、排序、示例重量，
   **没有写入「营养档案」**（`nutrition_food_id`）。营养档案正是生/熟状态的来源。
   因此刚发布出来的正式食谱，每一项原料的营养档案都是空的。
2. **保存环节静默顶替**：食谱详情编辑页保存时，后端会对空的营养档案**自动回填该原料的主档案**。
   红甜椒的主档案恰好是「红甜椒（生）」，于是生/熟状态被改写；同时因原料项被判定为变化，食谱版本号自动 +1。

证据（生产只读核查）：

| 环节 | 红甜椒营养档案 | 生熟 |
| --- | --- | --- |
| 设计器草稿 / 发布快照（发布那一刻） | 红甜椒（水煮沥干，不加盐） | 熟 |
| 后台正式食谱（当前版本） | 红甜椒（生）（= 该原料主档案） | 生 |

另外，未被后台保存过的设计器发布食谱（例如「小米三文鱼猪里脊(烟花)」）16 项原料的营养档案
全部为空，而其来源草稿 16 项均有档案 —— 直接印证「发布丢字段」。

## 三、代码修复

| 位置 | 改动 |
| --- | --- |
| `backend/src/application/recipe-designer/recipe-designer.service.ts` | 发布正式食谱时写入设计器选定的营养档案；若档案与原料不匹配则明确报错，不再静默发布 |
| `backend/src/application/recipe/recipe.service.ts` | 保存食谱时：仅当该原料只有**唯一**候选档案才自动回填；有多个候选（生/熟不同）时明确报错并列出原料名，不再静默取主档案 |
| `admin-web/src/views/Recipes/RecipeForm.vue` | 「营养状态」列缺档案时显示「未设置」（橙色高亮）；编辑弹窗不再为历史原料预选主档案；保存前校验并提示具体原料 |
| `backend/tests/application/recipe-designer/recipe-designer.service.spec.ts` | 新增：发布必须携带营养档案；档案未映射到原料时拒绝发布 |
| `backend/tests/application/recipe/recipe-nutrition-state.spec.ts` | 新增：多候选档案未指定时拒绝保存；显式指定时正常保存 |
| `backend/scripts/repair-published-recipe-nutrition-profiles.ts` | 历史数据修复脚本（默认 dry-run） |
| `backend/tests/scripts/repair-published-recipe-nutrition-profiles.spec.ts` | 修复判定逻辑单测 |

## 五、历史数据修复方式

修复判定规则：

- 当前为空（发布后从未被保存）→ 按设计意图修复
- 当前等于该原料主档案且与设计意图不同 → 按设计意图修复（典型被顶替）
- 其它不一致 → 只报告，不自动改

执行方式（默认只读，加 `--apply` 才写库）：

```bash
cd backend
npx ts-node -r tsconfig-paths/register scripts/repair-published-recipe-nutrition-profiles.ts \
  --env-file=.env.production.readonly --out=../docs/reports          # dry-run，生成清单
npx ts-node -r tsconfig-paths/register scripts/repair-published-recipe-nutrition-profiles.ts \
  --env-file=.env.production --apply                                 # 实际修复（需审批后在服务器执行）
```

说明：脚本默认只处理每个食谱的最新版本（`--all-versions` 可覆盖历史版本）；
修复为就地更新原料项的营养档案，不改动用量等其它字段，也不改变版本号。
