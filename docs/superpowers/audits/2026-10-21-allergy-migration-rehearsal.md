## 三、重点风险

1. **不能把“无”迁成过敏原**  
   42 只狗的文本是“无 / 没有 / 正常吃”，如果自动迁移会制造 42 条假过敏原。

2. **结构化记录本身有脏数据**  
   7 条记录的内容是“无 / 没有过敏食物 / 暂时没有发现过敏源”，不是过敏原。

3. **有些记录包含多个过敏原**  
   6 条记录需要拆分，例如“羊肉、牛肉”“鸡肉，牛肉，海鲜”。

4. **报告结论不是标准过敏原**  
   如“弱阳性：* 腐食酪螨 * 菠菜……”，不能直接拆成一个个字段，需人工确认。

5. **订单双写仍在继续**  
   付款同步仍会把订单文本写进狗狗旧文本，把数组写进结构化记录；迁移前必须先改写入路径。

## 四、订单同步现状

订单付款后会：

- 订单过敏数组 → 结构化过敏记录；
- 订单过敏文本 → 狗狗档案过敏文本；
- 订单报告草稿 → 正式过敏报告 + 过敏记录。

因此同一份信息会留在订单和狗狗档案两处。
