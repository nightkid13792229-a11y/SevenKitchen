# Agent 营养档案草稿入口实施计划

## 目标

在标准原料的营养档案管理器中加入“Agent 添加档案”入口。用户输入目标档案要求后，系统从本地 USDA/CFCT/NZFCD 中间库召回候选，Agent 负责排序和说明，用户在同一抽屉内确认主档案或次级档案后才正式入库。

第一版不让 Agent 直接创建正式档案，也不接入任意互联网抓取；联网来源后续只作为白名单数据源接入。

## 实施步骤

1. 增加回归测试
   - 在原料管理中心测试中覆盖“营养档案管理器可以打开 Agent 添加档案抽屉”。
   - 检查对现有候选、排序、校验、保存、拒绝和 USDA 导入 API 的复用。

2. 嵌入现有审批抽屉
   - 在 `IngredientNutritionDialog.vue` 中增加“Agent 添加档案”按钮。
   - 引入 `IngredientNutritionWorkbenchDrawer`，以当前标准原料作为上下文打开。
   - 将抽屉文案调整成“Agent 添加档案草稿”，保持候选仍为草稿/待确认语义。

3. 接通候选和 Agent 操作
   - 打开抽屉时加载当前原料全部候选和已确认档案。
   - 支持按用户要求调用 `rankFoodCandidatesWithAgent`。
   - 支持导入 USDA FDC ID、拒绝候选、校验营养、保存主/次档案配置。
   - 保存后关闭抽屉并刷新当前原料数据。

4. 交互防护
   - 补剂暂不启用食材候选 Agent 添加入口，继续走补剂标签/手工档案。
   - “Agent 添加档案”只生成待确认候选，不自动覆盖主档案。
   - 使用现有确认弹窗提示用户保存后才正式入库。

5. 验证
   - 先运行新增测试确认红灯，再实现。
   - 运行相关 node 测试。
   - 运行 `admin-web` 构建。
