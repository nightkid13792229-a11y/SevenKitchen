# 营养库数据验收清单（P1.2 前置）

> 状态：第 1–3 项已完成（2026-10-28）；第 4–5 项待执行
> 目标：把“主要库都导进去了”变成“数据可验收、可复现、可解释”
> 适用范围：`backend/` 营养库与检索；不含小程序/前端
> 通过标准：本清单 5 项全部有自动化检查且为绿，才在文档里把营养库标记为「已就绪」

---

## 为什么需要这份清单

现在本地库有 7 个库、27,038 条记录，主库都已导入，但“准备好了”目前是一种**感觉**，不是一条可复现的证据：

- 三套白名单互相对不上，没人能一句话说清“允许用哪些库”；
- 同库同名 139 组、跨库同名 677 个，检索会出现重复候选；
- CNF 的矿物质曾经整组丢失，是靠人工翻数据才发现的；
- MEXT 2,478 条没有英文名，英文检索永远命中不了。

这 5 项做完之前，P1.2 的检索效果会被数据问题污染：测出来“查不到”时，分不清是检索逻辑的锅还是数据的锅。

## 验收项 1：白名单唯一化 ✅

**要解决的问题**：数据库枚举、导入策略、线上域名三套名单各说各的。

**做什么**

1. 新建一份登记表（代码常量），每个库一条：
   - `sourceType`（数据库枚举值）、`sourceCode`（注册口径）、中文名、权威等级（A/B）、许可、`local`（是否有本地库）、`onlineHosts`（线上域名）、`role`（主库/长尾/候选）。
2. 检索（`listNutritionNames`）、导入策略（`source-policy`）、线上抓取（`trusted-nutrition-web-search`）都改为读这份登记表；删除各自硬编码的名单。
3. 明确 L1 本地主库 = 7 个（USDA、CNF、NZFCD、MEXT、TFDA、KO_RDA、CFCT）；NEVO 移出 L1（只保留线上长尾）；COFID/CIQUAL 标为「未导入」。

**验收标准**

- [ ] 全仓 `grep` 不到第二份“允许来源”清单（除登记表外）。
- [ ] 单测断言：登记表里 L1 恰好 7 个；每个 `sourceType` 都能被 `getNutritionSourceDefinition` 解析；NEVO 不在 L1；COFID/CIQUAL 标记为未导入。
- [ ] 检索只返回登记表内 L1 的记录：用一个不存在的来源类型构造记录，确认被排除。
- [ ] 文档 §三「三套名单」一表更新为「一份登记表」。

**落地结果（2026-10-28）**：`nutrition-source-registry.ts` 15 个库（L1 7 / L2 5 / CANDIDATE 3）；检索、导入策略、线上域名、discovery 均从登记表派生；NEVO 不再进入本地检索。测试 532 条全绿；生产 discovery 覆盖 美/加/澳/新/英/芬。

**工作量**：约半天。

## 验收项 2：去重规则 + 移除 NEVO 噪音 ✅

**要解决的问题**：同名/近名记录让候选列表重复，模型难以选择；NEVO 3 条让“每库命中数”失真。

**做什么**

1. 定一条 canonical 规则（写进代码，不只写文档）：
   - 归一化名称（去括号、标点、空格、全半角）；
   - 同一 `sourceType` + 同一归一化名称 + 同一生熟状态 = 同一组；
   - 组内保留顺序：来源优先级（登记表）→ 字段更全 → `updatedAt` 更新。
2. 在候选检索返回前做**折叠**：同组只出一条，附 `alsoIn: [sourceType...]`，让用户知道别的库也有。
3. NEVO 从 L1 移除；若线上仍需要，保留在 L2。

**验收标准**

- [ ] 新增一个审计脚本，输出：同库同名组数、跨库同名组数、折叠前后候选数；当前基线 139 / 677 记录在案。
- [ ] 单测：构造两条同名不同库记录，检索返回 1 条且 `alsoIn` 含另一库；两条同名同库不同生熟状态时返回 2 条。
- [ ] 线上抽查“猪肉”“鸡蛋”“冬瓜”，确认候选不再出现重复同名项。
- [ ] NEVO 不出现在本地检索结果（但仍可在线上白名单）。

**落地结果（2026-10-28）**：`candidate-name-dedup.ts` + 候选折叠 + `alsoIn`；生产审计 27,038 条 → 26,102 条（同库同名 164 组、跨库同名 734 组），734 条带 `alsoIn`。名称列表按名字折叠；`findCandidates` 仍按 sampleState 区分生熟。

**工作量**：约半天。

## 验收项 3：每库覆盖率基线 + 自动验收 ✅

**要解决的问题**：数据坏了没人知道；CNF 矿物质丢失是人工发现的。

**做什么**

1. 新增 `scripts/audit-nutrition-coverage.ts`：按来源输出
   - 记录数、唯一键数；
   - 能量/蛋白/脂肪/碳水、至少一种矿物质、至少一种维生素的覆盖率；
   - `sourceCode` 可解析比例；
   - 空库/异常库清单。
2. 新增一组**验收测试**（Jest），阈值先按当前实测值下浮 5–10% 设定，例如：
   - USDA ≥ 8,000；CNF ≥ 5,800；NZFCD ≥ 2,700；MEXT ≥ 2,400；TFDA ≥ 2,100；KO_RDA ≥ 3,200；CFCT ≥ 1,800；
   - 每个 L1 库能量覆盖 ≥ 85%、蛋白 ≥ 80%、至少一种矿物质 ≥ 75%；
   - `sourceCode` 可解析比例 100%；
   - 登记表内不得有空库（COFID/CIQUAL 标记为未导入，不计入）。
3. 这组测试接入部署前检查（与后端测试一起跑）。

**验收标准**

- [ ] `npx jest tests/domain/nutrition-governance/nutrition-coverage.spec.ts` 全绿。
- [ ] 故意把某库阈值调高 1 条，测试应红（证明它真的在检查）。
- [ ] 审计脚本输出一份当前基线报告，存入 `docs/reports/`。
- [ ] 部署脚本跑测试时包含这组检查。

**落地结果（2026-10-28）**：`nutrition-coverage-thresholds.ts` + SQL 聚合审计 + 7 条验收测试；生产基线 27,038 条、7 库全部通过（能量 96–100%、蛋白 98.6–100%、矿物质 96.7–100%）。基线报告存 `docs/reports/nutrition-coverage-2026-10-28.json`；部署脚本 Step 3 已加 `--assert` 门禁，低于基线直接中止部署。

**事故记录**：首版审计脚本把 2.7 万条完整档案读进 Node，导致生产 OOM、服务器重启；已改为纯 SQL 聚合 + OOM 守门，事故写入脚本头注释。

**工作量**：约半天。

## 验收项 4：CNF 其余字段审计

**要解决的问题**：CNF 只修了矿物质；维生素 C、叶酸、胆碱、部分脂肪酸是否也漏映射，未知。

**做什么**

1. 用 CNF 原始 `rawData.amounts` 的营养素编码，对照 `usda-nutrient-nbr-to-fdc-id.json` 与 `USDA_NUTRIENT_MAP`：
   - 统计每个目录字段“原始有值但归一化为空”的记录数；
   - 找出未映射但属于 60 字段的编码（维生素 C 401、叶酸 417/435、胆碱 421、脂肪酸 6xx/8xx 等）。
2. 对确认漏映射的编码补映射，写重算脚本（复用 CNF 回填脚本），先 dry-run 再 apply。
3. 重算后把 CNF 覆盖率纳入验收项 3 的阈值。

**验收标准**

- [ ] 审计报告列出“原始有值 / 归一化有值 / 差值”按字段的表；差值 >5% 的字段必须解释（库本身没有 or 映射漏了）。
- [ ] 确认漏映射的字段补齐后，CNF 对应覆盖率 ≥90%，抽样值与原始码一致。
- [ ] 重算脚本幂等（第二次 `changed=0`）。
- [ ] 备份表保留一天，可回滚。

**工作量**：半天–1 天（取决于漏的字段数量）。

## 验收项 5：MEXT 展示名 / 语种路由

**要解决的问题**：MEXT 2,478 条没有英文名，英文检索命中不了；中文用户也读不懂日文名。

**做什么（二选一，建议 B）**

- **A. 补展示名**：给 MEXT 每条补中文或英文展示名（可从日文名翻译/官方英文表导入），写入 `foodNameEn` 或新增展示字段。
- **B. 语种路由（P1.2 的一部分）**：检索时按库的语种生成候选词——英文库用英文、MEXT 用日文、CFCT/TFDA 用中文、KO_RDA 用韩文；中文原名始终兜底。
  - 需要：每个库在登记表里声明 `language`；
  - 一次模型调用生成多语种候选（每语种 3–6 个）；
  - 机械归一化（大小写、全半角、空格、日文假名、英文单复数/词序）。

**验收标准**

- [ ] 英文查询 `chicken` 能命中 MEXT 的「にわとり」相关记录（或明确返回“该库无英文名，已用日文检索”）。
- [ ] 中文查询「鸡肉」在 MEXT 里能命中对应日文词条。
- [ ] 检索结果每条都标注来源库与命中词，便于解释“为什么是这条”。
- [ ] 原有中文/英文库的检索结果不回归（既有测试全绿）。

**工作量**：A 约 1 天；B 约 1–2 天（属 P1.2）。
