# 工作台「成品调整 / 退款」入口（2026-10-31）

**目标：** 员工在生产现场发现成品缺口/余量后，不用回电脑后台，在手机工作台就能记一笔「退多少钱 / 补多少钱、为什么、顾客是否可见」，顾客端随之出现「成品调整」卡。

**结论：** 不需要新造接口。后端已有的「订单财务汇总」和「结算调整」能力已经具备，本轮只做三件事：把它接进员工订单详情、补上操作人审计、补上防重复提交。

---

## 一、可行性核对（对着代码逐条核过）

| 环节 | 现状 | 判定 |
|---|---|---|
| 生产完成记缺口/余量 | 工作台「生产 → 生产任务详情 → 完成生产」可填正常/余量/缺口克数，落在分装单元上 | ✅ 已通，不动 |
| 缺口变成金额 | 生产结算按「订单实收 × 缺口 / 计划成品」算出建议退差价，写进订单成本结算 | ✅ 已通，不动 |
| 员工读到缺口和建议金额 | `GET /admin/orders/:id/financial-summary` 返回计划/实际/缺口、建议金额、已有调整 | ✅ 员工本来就有权读（接口守卫允许 STAFF/ADMIN），只是页面没调 |
| 员工建一条调整 | `POST /admin/orders/:id/settlement-adjustments` 生成 PENDING 记录 | ⚠️ 接口本来允许 STAFF，但操作人写死成“admin”，审计不准；本轮补 |
| 顾客看到卡 | 顾客端详情页读 `/orders/:id/financial-summary`，只在有“待退/待补”且 `visibleToCustomer` 时显示 | ✅ 已通，不动 |
| 标记已处理 | `PATCH /admin/orders/:id/settlement-adjustments/:id/status` | ⚠️ 本轮加“仅管理员”限制 |
| 直接退钱 | 微信原路退款是另一个接口，且只允许管理员 | 本轮不接（老板拍板：只记账） |

### 数据流（员工视角）

```
完成生产（缺口 120g）
  → 订单成本结算（计划/实际/缺口 + 建议退 ¥X）
  → 员工订单详情「成品调整」看到缺口与建议金额
  → 录：退款 ¥X、原因、顾客可见 → 生成 PENDING 调整
  → 顾客详情出现「成品调整」卡
  → 管理员在后台/工作台走原退款流程
  → 回工作台点「标记已处理」→ 顾客端不再提示
```

## 二、老板拍板的三件事

| 事项 | 决定 | 落地方式 |
|---|---|---|
| 权限 | 员工可录入，只有管理员能标记“已处理” | 建单沿用 STAFF+ADMIN；标记接口加 AdminGuard |
| 退款 | 只记账 + 给顾客看，不直接动钱 | 建单只写 PENDING；文案明确“不会直接退钱” |
| 金额 | 按缺口自动算建议值，允许修改 | 打开表单时按建议退差价预填，可改；退款不超过订单实付 |

## 三、实现

### 后端（复用现有能力，只补三处）

1. **操作人审计**：建单接口从当前登录人取 `createdBy`（admin/staff）与 `createdById`，不再写死 `admin/null`。
2. **权限**：建单仍是 STAFF+ADMIN；标记状态加 `AdminGuard`，员工调用会被拒。
3. **幂等**：建单接受客户端 `requestId`，作为 `sourceId` 写入；命中 `(orderId, sourceType, sourceId)` 唯一索引时返回原记录。弱网/连点不会重复记账。
4. **余量**：财务汇总补 `surplusG`（按订单在批次里的计划占比折算），供工作台显示“余量”。

### 小程序（员工订单详情）

位置：`pages/staff-orders/detail.vue`，在「费用」卡下面新增「成品调整」卡，只在订单已生产结算且存在缺口/余量/已有调整时出现。

卡内内容：
- 计划成品 / 实际成品 / 缺口（或余量）；
- 一句人话提示：顾客端现在会看到什么、建议退多少；
- 已有调整列表：原因、状态、谁录的、顾客是否可见、金额；
- 「录入成品调整」：类型（退款/补收）、金额（预填建议值，可改）、原因、顾客可见开关、提交；
- 管理员才看得到每条待处理记录旁的「标记已处理」。

入口路径：
```
小程序 → 工作台 → 生产 → 生产任务详情 → 完成生产（填缺口）
小程序 → 工作台 → 订单（订单中心）→ 打开这一单 → 费用下面的「成品调整」
```

### 顾客端

不用改。员工提交后，顾客刷新订单详情，在「售后」上方看到「成品调整」卡：少了多少克、退多少钱、当前待处理/已处理。标记已处理后，因为不再有“待退/待补”，这张卡会收起，顾客端不再反复提示。

## 五、与预期的偏差

- **没有在工作台直接退钱**：按老板决定只记账，实际退款仍走原流程。
- **“余量”只做提示**：系统不会自动算出补收金额（补收没有统一口径），需要员工手填。
- **标记已处理后顾客卡会消失**：当前顾客端规则是“只有待处理才显示”，所以顾客看不到“已处理”的留痕；如果希望顾客长期看到“已退 ¥X”，需要另改顾客端规则，本轮未做。
- **真机整链未跑**：本机没有可直接使用的“已生产结算”测试单，等体验版由老板用真实测试单验收。
