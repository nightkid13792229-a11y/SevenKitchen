# 原料标签分类进核验门禁（2026-11-21）

## 背景

- 小程序首页橱窗的「避开」筛选直接读原料标签（`ingredient_tag` 关联，含父子分组）。
- 2026-11-20 一次性补齐了 25 个标签、135 条 FOOD 原料关联，当时 121 种 FOOD 原料 0 种未标；但这是脚本补的数据，不是门禁保证的。
- 原料档案核验原来没有「标签分类」规则：为空只会进 `FIELDS_EMPTY` 的完整度提醒（warning，不阻断）。结果是新食材漏标也能授权上线，顾客选「避开鸡肉 / 内脏 / 谷物」时，含它的食谱不会被排除。

## 改动

1. 原料档案核验新增 `TAGS_REQUIRED`（`blocking`，排在 `NAME_DUPLICATE` 之后）：
   - 标签分类至少要有 1 个标签；
   - 只有标签名、没有标签库 id 同样阻断（真正写关联表的是 id，避免「页面看着有、线上没关联」）。
2. 规则版本 `ingredient-card-v3` → `ingredient-card-v4`：旧报告不能当新规则的依据，进行中的草稿要重跑核验。
3. `tags` 从「完整度提醒」字段移到「有独立必填规则」字段，`FIELDS_EMPTY` 不再重复列它。
4. 页面与 AI 提示同步：
   - 原料卡「标签分类」加提示「至少一个，决定首页「避开」筛选」；
   - 审核页脚改为「至少选一个，空着核验会阻断授权」；
   - `writeIngredient` 工具说明补上「授权前至少挂一个；拿不准留空由人工选，不要编造」。

## 影响与边界

- 已上线原料不受影响；只有正在走的草稿在授权前会被拦住，补选标签、重跑核验即可。
- 规则版本升级后，未按新规则重跑的旧核验报告一律失效，这是预期行为。
- 手动新建 / 编辑原料页（`IngredientForm`）不经过这套授权门禁，本次未改；若也要拦住，需要另做。
- 系统里其他入口（批量导入等）同样不在本次范围。

## 验证

- 原料卡核验单测 26 个全过（含两个新用例：空标签阻断、有名字无关联阻断）。
- 建档域相关测试（核验运行 / 授权 / 控制器）47 个全过。
- 后端全量：9 个失败套件 / 87 个失败用例，失败套件名单与 `origin/main` 基线完全一致（`diff` 为空），均为既有问题；其中 `supplement-link-preview.service.spec.ts` 的 iHerb 域名断言在基线同样红。
- 前端 `vitest run`：1229 个用例，1227 过；2 个失败（`nutritionReport.regression.spec.ts`、`orderDesignList.regression.spec.ts`）在主工作区 `origin/main` 上同样失败，属基线。
- `vue-tsc -b` 通过；后端 `tsc --noEmit` 在本次改动文件上无错误（全仓既有 test 类型错误未新增）。

## 回滚

删除 `TAGS_REQUIRED` 规则、把 `CHECK_RULES_VERSION.INGREDIENT` 改回 `ingredient-card-v3`，并还原对应文案与测试。
