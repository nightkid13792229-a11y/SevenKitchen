# 经营财务中心设计方案

## 1. 背景与目标

SevenKitchen 当前已经具备订单、采购、报销、库存、价格快照等基础能力，但这些能力仍然分散在不同模块中，管理员还无法在一个统一板块里直接看到：

1. 今天、本周、本月到底赚没赚钱
2. 钱具体花在了哪些地方
3. 哪些费用出现异常上涨或超支
4. 接下来 7-30 天是否存在付款压力

本方案的目标，是在 `admin-web` 中建设一个面向管理员的“经营财务中心”，帮助小作坊、小团队阶段的经营管理者看清真实财务状况，并为后续升级为更完整的财务能力预留结构基础。

本方案强调两点：

1. 第一版优先解决经营管理问题，而不是直接做成正式会计系统
2. 第一版所有正式财务结果必须尽量基于真实发生数据，不把预计值伪装成真实财务结果

## 2. 已确认的业务口径

### 2.1 双视角

第一版同时支持两种视角：

1. `经营视角`
   - 收入按发货时间确认
   - 固定费用按归属期间或分摊期间确认
   - 用于判断今天、本周、本月到底赚没赚钱

2. `现金流视角`
   - 收入按实际收款时间确认
   - 支出按实际付款时间确认
   - 用于判断账户压力和未来付款风险

### 2.2 员工垫付与公司应付分开

第一版明确区分两类支出来源：

1. `员工垫付型`
   - 走现有报销流程
   - 例如原料代买、临时行政支出、小额杂费

2. `公司应付型`
   - 走新增费用单 / 待支付流程
   - 例如房租、水电、宽带、工资、服务器、域名、证书、备案等

### 2.3 现有报销状态语义沿用真实业务

当前系统里的 `REIMBURSED` 在业务上等于：

1. 管理员已经完成打款
2. 管理员已经上传报销转账记录

因此第一版不新增“已批准待付款”中间状态，报销类正式财务入账规则直接使用当前业务语义：

1. `PENDING_REVIEW`、`REQUIRES_RESUBMIT`、`REJECTED` 不进入正式财务实绩
2. `REIMBURSED` 才进入正式费用统计和现金流流出

### 2.4 订单预计成本不作为正式财务实际成本

当前订单中的 `pricingBreakdownSnapshot` 主要用于订单定价解释和预计成本拆分，不代表真实已经发生的订单成本。

因此第一版明确区分：

1. `财务实绩`
   - 只使用真实收入、真实费用、真实付款、真实待支付
   - 不把订单预计成本直接计入正式财务成本

2. `经营贡献分析`
   - 允许基于订单收入和规则归集结果观察订单 / 食谱表现
   - 页面必须明确标注：用于经营判断，不等同正式财务利润

### 2.5 收入侧不拆商品收入与客户运费收入

当前系统内没有稳定记录“顾客实际支付金额中商品金额和运费金额的真实拆分”，订单页面中的商品金额与运费仍属于定价计算结果，不适合用于正式财务拆分。

因此第一版收入侧只看：

1. 实际收款总额
2. 实际退款 / 损失
3. 净收入

但费用侧单独保留 `物流配送费` 一级分类，因为这部分支出对宠物鲜食经营至关重要。

### 2.6 超支判断以历史对比和业务目标为主

第一版超支预警优先依据：

1. 历史对比
   - 今天 vs 近 7 天平均
   - 本周 vs 上周
   - 本月累计 vs 上月同期 / 近 30 天均值

2. 业务目标
   - 例如物流配送费占比、原料采购支出占比、整体经营结余偏弱等

预算型预警不是第一版主轴，但后续应保留可扩展空间。

## 3. 第一版范围

### 3.1 第一版必须实现

1. `财务总览`
2. `费用与待支付`
3. `费用分析`
4. `经营贡献分析`
5. 统一费用分类体系
6. 费用单 / 待支付能力
7. 首页预警和异常提示
8. 报销数据接入财务中心
9. 固定费用模板与周期自动生成草稿

### 3.2 第一版纳入的费用

第一版纳入，但不限于以下费用：

1. 原料采购
2. 包材耗材
3. 工资
4. 房租
5. 水电燃气
6. 宽带通信
7. 服务器 / 域名 / 证书 / 备案
8. 物流配送费
9. 行政采购
10. 售后退款 / 经营损失
11. 其他杂项

### 3.3 第一版不做或不承诺

第一版暂不做以下能力，或只保留扩展空间：

1. 正式会计分录体系
2. 完整科目系统
3. 复杂预算审批流
4. 多层级财务审批
5. 外部账单自动同步
6. 发票自动识别
7. 单笔订单或单个食谱的严格真实财务利润
8. 基于库存计价和实际领用的真实 COGS 体系

## 4. 模块边界

第一版遵循原则：

`业务操作入口留原处，财务中心统一看结果`

### 4.1 保持原位置的模块

1. `采购管理`
   - 管采购清单、采购记录、原料相关流程

2. `报销管理`
   - 管员工垫付、报销提交、管理员审核、管理员打款凭证上传

### 4.2 新增的财务中心负责

1. 统一展示真实经营结果
2. 统一展示现金流
3. 统一展示待支付压力
4. 统一展示费用结构与异常
5. 新增费用单 / 待支付管理
6. 提供经营贡献分析

### 4.3 付款动作的归属

第一版不新增独立“付款核销模块”或单独菜单。

付款动作归属如下：

1. 员工报销打款
   - 在现有报销管理里完成
   - 变成 `REIMBURSED` 时自动形成付款事实

2. 公司直接费用付款
   - 在费用单页面内完成“已付款”动作
   - 自动形成付款事实

财务中心只统一展示结果、待办和最近付款记录。

## 5. 财务中心页面结构

### 5.1 菜单结构

第一版建议在 `admin-web` 中新增一级菜单：`财务中心`

包含 4 个子页：

1. `财务总览`
2. `费用与待支付`
3. `费用分析`
4. `经营贡献分析`

### 5.2 财务总览

财务总览是管理员默认首页，支持 `今天 / 本周 / 本月` 切换。

顶部核心卡片建议展示：

1. 实际收款总额
2. 实际费用总额
3. 真实经营结余
4. 现金流入
5. 现金流出
6. 待支付金额

页面中部展示：

1. 费用异常提醒
2. 待支付提醒
3. 经营贡献提醒
4. 钱花去哪了

页面底部展示：

1. 待审核报销数量
2. 本周到期费用数量
3. 逾期待支付数量
4. 最近新增异常费用

### 5.3 费用与待支付

此页为财务中心的主要操作页，采用两个页签：

1. `费用单`
2. `待支付`

页面支持：

1. 新建费用单
2. 按费用类别筛选
3. 按状态筛选
4. 按归属月份筛选
5. 标记已付款
6. 上传付款凭证
7. 查看已付款记录

### 5.4 费用分析

该页重点回答：

1. 钱花去哪了
2. 哪些费用相比历史异常上涨
3. 哪些费用结构对经营压力最大

建议包含 3 个主要区域：

1. 费用结构
2. 历史对比
3. 异常列表

重点观察费用类别：

1. 原料采购
2. 物流配送费
3. 工资
4. 房租
5. 水电燃气
6. 宽带通信
7. 服务器 / 域名 / 证书 / 备案
8. 行政采购
9. 其他杂项

### 5.5 经营贡献分析

该页用于辅助经营判断，不提供正式财务利润结论。

页面固定说明：

`以下结果用于经营判断，基于收入与规则归集后的分析结果，不等同正式财务利润。`

页面提供视角：

1. 按时间段看经营贡献变化
2. 按食谱看贡献偏强 / 偏弱
3. 按订单类型或订单批次看贡献变化

## 6. 第一版核心流程

### 6.1 员工垫付 -> 报销 -> 正式财务实绩

1. 员工在现有入口提交报销
2. 管理员审核
3. 管理员完成打款并上传转账记录
4. 报销单进入 `REIMBURSED`
5. 系统将该报销单纳入正式费用和现金流流出

### 6.2 公司应付 -> 费用单 -> 待支付 -> 已付款

1. 员工或管理员创建费用单草稿
2. 管理员确认费用分类、金额、归属期间、应付日期
3. 费用单进入 `待支付`
4. 实际付款后在费用单内标记 `已付款`
5. 系统将该费用单纳入真实费用归属统计和现金流流出

### 6.3 订单收入进入财务中心

1. 订单实际收款 -> 进入现金流流入
2. 订单实际发货 -> 进入经营收入统计

### 6.4 退款 / 损失进入财务中心

1. 确认发生退款或经营损失 -> 进入费用 / 损失统计
2. 实际退款付款 -> 进入现金流流出

## 7. 第一版底层财务对象

第一版不应直接通过扫业务表拼装出全部财务结果，而应建立面向财务中心的统一对象。

### 7.1 费用分类

建议建立统一一级分类：

1. 原料采购
2. 包材耗材
3. 工资
4. 房租
5. 水电燃气
6. 宽带通信
7. 服务器 / 域名 / 证书 / 备案
8. 物流配送费
9. 行政采购
10. 售后退款 / 经营损失
11. 其他杂项

### 7.2 费用单

费用单承接公司直接应付费用，建议包含：

1. 费用分类
2. 费用名称
3. 金额
4. 发生日期
5. 归属期间
6. 应付日期
7. 收款方
8. 是否分摊
9. 分摊起止时间
10. 状态
11. 凭证与备注

### 7.3 付款事实

第一版底层仍需保留付款事实记录，但不需要暴露为独立菜单。

付款事实来源：

1. 报销单变成 `REIMBURSED`
2. 费用单标记 `已付款`
3. 退款 / 损失实际支付

### 7.4 经营收入事实

用于经营视角收入统计，来源于订单发货。

### 7.5 现金流事实

用于现金流统计，来源于：

1. 订单收款
2. 已报销支出
3. 已付款费用单
4. 已退款支出

### 7.6 每日财务汇总

为了让页面查询稳定快速，建议建立每日汇总事实，至少包括：

1. 当日实际收款
2. 当日实际费用确认
3. 当日真实经营结余
4. 当日现金流入
5. 当日现金流出
6. 当日待支付变化
7. 各费用类别金额
8. 异常标记

## 8. 真实财务实绩与经营贡献分析分层

### 8.1 真实财务实绩层

该层只读取真实发生值，用于：

1. 财务总览
2. 费用分析
3. 现金流分析
4. 待支付管理

必须使用真实值的指标：

1. 实际收款总额
2. 实际退款金额
3. 已报销金额
4. 已付款费用金额
5. 待支付金额
6. 各费用类别实际支出
7. 现金流入
8. 现金流出
9. 本期真实经营结余

### 8.2 经营贡献分析层

该层用于观察订单、食谱、时间段的经营表现，但不应冒充正式财务利润。

允许使用规则归集的分析内容：

1. 食谱贡献偏强 / 偏弱
2. 订单贡献表现
3. 某类订单成本压力
4. 某时间段经营表现变化

系统必须避免在同一指标里混用真实财务值和预计值。

### 8.3 第一版的重要限制

第一版需要明确接受以下限制：

1. 由于现有报销状态语义中 `REIMBURSED` 等于“已打款并已上传转账记录”，员工垫付类费用第一版将按“付款完成后正式入账”处理，而不新增“已批准待付款”中间状态
2. 当前订单成本快照属于定价和预计拆分结果，不能直接作为正式财务实际成本
3. 第一版可以真实反映公司整体经营结果与现金流，但不能产出严格财务口径的单笔订单或单个食谱真实利润
4. 第一版的经营贡献分析只能用于经营判断，不能替代正式财务结论

## 9. 超支预警设计

第一版将“超支”拆为两种提醒：

### 9.1 财务实绩超支

基于真实费用和真实付款，重点回答：

1. 哪类费用比历史明显更高
2. 哪类费用占比异常
3. 哪些大额费用突然出现
4. 哪些待支付正在形成压力

### 9.2 经营异常提醒

用于经营贡献分析层，重点回答：

1. 哪类订单贡献偏弱
2. 哪种食谱成本压力较高
3. 哪段时间业务结构表现变差

### 9.3 第一版建议上线的 8 条核心提醒

1. 物流配送费较近 30 天均值上涨超过阈值
2. 原料采购支出较近 30 天均值上涨超过阈值
3. 杂项费用本月累计显著偏高
4. 本月工资 / 房租 / 服务器等固定费用到期未付
5. 本周现金流出高于现金流入
6. 本月真实经营结余为负
7. 某类食谱经营贡献连续偏弱
8. 某周期整体经营贡献下降明显

## 10. 录入与审核设计

### 10.1 角色分工

员工负责提交事实：

1. 提交报销
2. 补充凭证
3. 填写用途说明
4. 必要时创建费用单草稿

管理员负责确认入账：

1. 审核报销
2. 创建或确认费用单
3. 标记费用已付款
4. 查看财务总览和分析结果

### 10.2 第一版保留的 3 个录入入口

1. 现有报销入口
2. 费用单入口
3. 报销单 / 费用单内的付款动作

### 10.3 字段控制原则

第一版员工录入字段必须尽量少，重点保留：

1. 金额
2. 费用类别
3. 发生日期
4. 用途说明
5. 凭证
6. 是否关联采购
7. 备注

## 11. 落地优先级

### 11.1 第一优先级

先跑通真实财务总盘子：

1. 财务中心菜单与总览页
2. 真实收入
3. 真实费用
4. 真实现金流
5. 待支付
6. 费用分类
7. 首页基础预警

### 11.2 第二优先级

做固定费用与待支付能力：

1. 费用单
2. 归属期间
3. 待支付
4. 已付款
5. 固定费用模板
6. 周期生成草稿

### 11.3 第三优先级

做费用分析与异常：

1. 费用结构
2. 历史对比
3. 异常提醒

### 11.4 第四优先级

做经营贡献分析：

1. 按订单观察
2. 按食谱观察
3. 按时间观察

## 12. 第一版可信度验证

### 12.1 上线前核对的 4 组核心数字

1. 财务中心实际收款总额 vs 订单系统真实收款总额
2. 财务中心已报销金额 vs 报销管理中 `REIMBURSED` 总金额
3. 财务中心待支付金额 vs 费用单待支付总金额
4. 财务中心现金流流出 vs 已报销金额 + 已付款费用金额 + 已退款金额

### 12.2 上线后前两周的验证重点

1. 每个大数字都能追溯到来源单据
2. 异常提醒是否靠谱
3. 历史对比是否有解释力
4. 页面是否真的帮助管理员快速找到问题

### 12.3 页面固定说明

财务总览页应明确说明：

`本页展示真实收款、真实费用、真实付款与待支付结果，用于判断经营状况与现金流压力。`

经营贡献分析页应明确说明：

`本页用于经营分析和成本压力判断，结果不等同正式财务利润。`

## 13. 结论

如果按本方案落地，第一版经营财务中心将帮助管理员：

1. 看清今天 / 本周 / 本月真实经营结果
2. 看清真实现金流和待支付压力
3. 看清钱主要花在哪些费用类别
4. 快速发现哪些费用异常上涨
5. 管理固定费用和周期费用
6. 在不伪造真实利润的前提下，看订单和食谱的经营贡献趋势

该方案适合 SevenKitchen 当前小作坊、小团队阶段的经营管理需求，同时保留未来升级到更完整财务能力的结构空间。
