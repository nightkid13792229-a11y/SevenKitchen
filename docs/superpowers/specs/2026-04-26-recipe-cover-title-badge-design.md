# 小程序首页食谱封面标题优化设计

## 背景

本次优化覆盖微信小程序首页 `pages/home/index` 的食谱橱窗卡片。当前卡片本身已经在封面图下方展示完整食谱名称、浏览/收藏/DIY 次数、适用标签和主要原料。

部分食谱封面图左上角还展示 `coverTitle`，视觉上接近一行大号白字叠在图片上。这个处理会让封面图、主题标签和卡片标题互相争抢注意力，尤其在食材图比较亮或信息比较多时，左上角文字容易显得像临时贴字。

## 目标

- 保留食谱卡片的快速扫读效率。
- 让完整食谱名称继续作为卡片主标题，位于封面图下方。
- 将 `coverTitle` 降级为封面主题标签，而不是第二个标题。
- 降低图片上文字的视觉重量，让封面食材图保持主视觉地位。
- 兼容没有 `coverTitle`、没有封面图、封面图亮暗差异较大的食谱。

## 非目标

- 不调整首页筛选栏、狗狗档案区或底部导航。
- 不改后端字段含义，也不改变 `coverTitle` 的录入方式。
- 不重新生成或批量重做食谱封面图。
- 不调整详情页结构；详情页封面标题可在后续单独统一。

## 推荐方案

采用“底部轻渐隐 + 小主题标签”的方案。

卡片封面图保持完整展示，不在左上角放大号标题。若食谱有 `coverTitle`，在封面图底部左侧展示一个小型半透明标签，例如：

```text
肿瘤预防
```

封面图底部叠加一层很浅的纵向渐隐，只覆盖底部区域，用来保证标签在浅色食材图上也可读。完整食谱名称仍然放在图片下方的信息区，作为用户点击和辨认食谱的主标题。

## 视觉规则

- `coverTitle` 标签定位在封面图底部左侧，离边缘保持稳定内边距。
- 标签采用低饱和、半透明深色底或柔和毛玻璃效果，文字使用白色或接近白色。
- 标签高度应小于主标题字号产生的视觉高度，避免被误解为食谱名称。
- 标签最多单行显示，超长时省略。
- 底部渐隐只为提升可读性，不应明显压暗整张图片。
- 食谱名称、统计信息、适用标签和主要原料仍位于图片下方，保持现有信息层级。

## 组件与数据流

首页食谱列表继续使用现有 `renderedRecipes` 数据。

`recipe.coverTitle` 作为可选字段进入卡片：

- 有 `displayCoverUrl` 时，封面图正常展示。
- 同时有 `displayCoverUrl` 和 `coverTitle` 时，在封面图内渲染底部标签和渐隐。
- 没有 `coverTitle` 时，只展示封面图，不出现空占位。
- 没有 `displayCoverUrl` 时，沿用现有占位封面，不渲染 `coverTitle` 标签。

## 错误与降级

- 图片加载失败仍走现有 `handleRecipeCoverError(recipe)` 逻辑。
- `coverTitle` 为空、空字符串或字段不存在时不渲染标签。
- 标签文本过长时用省略号处理，不撑开封面图或卡片。
- 样式只依赖小程序端支持的基础 CSS 能力，避免使用不稳定的滤镜效果作为唯一方案。

## 测试与验收

- 静态回归测试应覆盖首页模板存在 `recipe.displayCoverUrl && recipe.coverTitle` 条件渲染。
- 静态回归测试应确认封面图仍使用 `recipe.displayCoverUrl` 和加载失败兜底逻辑。
- 人工验收至少检查三类卡片：
  - 有封面图且有 `coverTitle`
  - 有封面图但无 `coverTitle`
  - 封面图缺失或加载失败
- 视觉验收标准：主标题在图片下方最醒目，封面图上的 `coverTitle` 只是轻量主题标签，不再像左上角大标题。
