# 原料管理中心合并设计

## 背景

当前 Web 管理端把标准原料相关能力拆成三个侧边栏入口：

- `原料管理`：维护标准原料、SKU、采购、DIY 推荐和手动营养数据。
- `原料营养治理`：维护 USDA/CFCT 候选、Agent 审核、营养档案确认和补剂标签草稿。
- `原料标签管理`：维护原料标签树、标签颜色、父子标签和排序。

这三个入口都围绕同一个业务对象：标准原料。拆开后，用户需要在多个页面之间跳转，尤其在审核某个原料的营养档案时，很难同时看到它的标签、类型、SKU 和当前主档案状态。

本设计把三者合并为一个 `原料管理` 入口，形成一个面向日常运营和营养数据治理的原料管理中心。

## 目标

1. 侧边栏只保留一个 `原料管理` 入口。
2. 原料管理页面内部承载标准原料、营养档案、标签体系；数据源与 Agent 设置合并进营养档案标签页。
3. 日常审核以标准原料为中心，而不是以候选词条为中心。
4. 原料标签管理不再作为独立页面出现，但保留完整标签树维护能力。
5. 原料营养治理不再作为独立页面出现，但保留批量匹配、Agent 设置、候选审核、补剂标签草稿等能力。
6. 旧路由在第一阶段保留为重定向，避免已有书签和开发调试入口直接失效。
7. 合并后页面文案要让用户能清楚区分：标准原料、来源词条、待审核候选、已入库档案、当前主档案、备用档案。

## 非目标

- 不在本次设计中重写营养数据模型。
- 不在本次设计中改变已确认营养档案的业务含义。
- 不在本次设计中让 Agent 自动确认营养档案。
- 不在本次设计中改变标签 API 或标签数据结构。
- 不在本次设计中开放给小程序用户。
- 不把所有内容堆到一个长页面里；页面内部仍需要清晰分区。

## 总体方案

将 `/ingredients` 改造成原料管理中心。页面顶部使用内部标签页：

1. `标准原料`
2. `营养档案`
3. `标签体系`

侧边栏保留：

- `原料管理`

侧边栏移除：

- `原料营养治理`
- `原料标签管理`

旧地址处理：

- `/nutrition-governance` 重定向到 `/ingredients?tab=nutrition`
- `/ingredient-tags` 重定向到 `/ingredients?tab=tags`

## 页面结构

### 标准原料

这是原来的原料管理主表，但需要补齐营养治理入口和状态。

表格保留现有字段：

- 原料名称
- 类型
- 采购策略
- SKU 状态
- 标签分类
- CFCT 分类
- DIY 推荐
- 采购 SKU
- 备注

新增或优化字段：

- `营养档案`
  - 无主档案
  - 已有主档案
  - 有待审核候选
  - 校验失败
  - 需重新匹配
- `当前主档案`
  - 展示来源类型和来源编号，例如 `USDA:168409`
  - 展示简短状态，例如 `生 / 带皮 / 未加工`

操作区建议保留：

- 编辑
- 营养审核
- 手动营养
- 复制新增
- 删除

其中：

- `营养审核` 打开标准原料营养审核台。
- `手动营养` 进入现有手动营养数据编辑器，但应在文案上说明它是人工维护入口，不是候选审核入口。

### 营养档案

这是原 `原料营养治理` 的主要工作区，但不再以候选词条作为页面主行。

页面按标准原料聚合展示：

- 标准原料
- 当前主档案
- 备用档案数量
- 待审核候选数量
- Agent 建议状态
- 营养校验状态
- 下一步操作

常用筛选：

- 全部
- 无主档案
- 有待审核候选
- 需人工处理
- 校验失败
- 已入库

主要操作：

- 批量生成候选
- 批量生成 Agent 审核建议
- DeepSeek Agent 设置
- API Key 保存和测试连接
- USDA 来源导入
- CFCT 本地数据状态
- 最新任务进度和错误摘要
- 打开营养审核台
- 刷新状态

原来的候选表可以保留为内部实现，但前台不再让每个候选词条占一行标准原料。

### 标准原料营养审核台

审核台是合并后的核心组件，可从 `标准原料` 和 `营养档案` 两个标签页打开。

顶部展示：

- 标准原料名称
- 原料类型
- 当前主档案
- 备用档案数量
- 待审核候选数量
- 营养校验状态

审核台分区：

1. `已入库档案`
   - 当前主档案
   - 备用档案
   - 来源词条
   - 状态/规格/加工标记
   - 查看营养
   - 校验营养
   - 设为当前主档案
   - 停用档案

2. `待审核候选`
   - Agent 推荐
   - 自动确认条件
   - 来源词条
   - 状态/规格/加工标记
   - 备注
   - 入库为当前主档案
   - 入库为备用档案
   - 排除候选

3. `重新查找`
   - 输入自然语言要求，例如 `去皮黄瓜、生、USDA 优先`
   - 系统从本地 USDA/CFCT 数据中召回候选
   - Agent 对候选做语义排序和理由说明
   - 结果分为：
     - 已入库可用档案
     - 新候选
     - 不推荐

4. `营养明细与校验`
   - 展示标准化营养字段
   - 展示来源数据库原字段名
   - 展示换算说明
   - 展示缺失项、异常值、单位风险

典型场景：黄瓜。

- 当前主档案是 `Cucumber, with peel, raw`。
- 备用档案是 `Cucumber, peeled, raw`。
- 用户搜索 `去皮黄瓜`。
- 审核台展示它已经是已入库备用档案。
- 用户点击 `设为当前主档案`。
- 系统提示：这会把去皮黄瓜设为默认营养档案，并把带皮黄瓜降为备用档案，不会改变原始营养值。

### 标签体系

这是原 `原料标签管理` 的迁移版。

保留能力：

- 标签树展示
- 新增根标签
- 新增子标签
- 编辑标签名称
- 编辑描述
- 编辑父标签
- 编辑颜色
- 编辑排序
- 删除标签

建议布局：

- 左侧为标签树。
- 右侧为选中标签详情与编辑区域。
- 顶部保留 `新增标签`。

该标签页不直接编辑标准原料和标签的绑定关系。标准原料绑定标签仍在标准原料编辑表单或主表快捷入口中完成。

## 文案规范

合并后统一使用以下词：

- `来源词条`：USDA、CFCT、产品标签或其他数据库中的原始记录。
- `待审核候选`：来源词条和标准原料建立了候选关系，但尚未入库。
- `已入库档案`：已经人工确认并可用于业务计算的营养档案。
- `当前主档案`：默认写入 `Ingredient.nutritionProfile` 并被食谱计算优先使用的档案。
- `备用档案`：已入库但非默认，可用于不同状态、规格或后续人工切换。
- `Agent 建议`：模型给出的语义判断和审核建议，只作辅助。
- `自动确认条件`：原 `硬闸门`，表示系统是否认为候选满足一键确认条件。

按钮文案：

- `审批` 改为 `营养审核`
- `按要求 Agent 排序` 改为 `按要求查找并推荐`
- `确认为主档案` 改为 `入库为当前主档案`
- `确认为次级档案` 改为 `入库为备用档案`
- `拒绝候选` 改为 `排除候选`
- `保存原料配置` 改为 `确认入库所选档案`
- `批量 Agent 匹配` 改为 `批量生成 Agent 审核建议`

## 技术设计

### 前端组件拆分

新增或抽取组件：

- `IngredientManagementCenter.vue`
  - 作为 `/ingredients` 页面主体。
  - 管理内部 tab 和 URL query。

- `StandardIngredientsPanel.vue`
  - 承载现有原料管理主表。
  - 增加营养状态列和营养审核入口。

- `IngredientNutritionGovernancePanel.vue`
  - 承载营养档案聚合视图和批量操作。

- `IngredientNutritionWorkbenchDrawer.vue`
  - 改造为标准原料营养审核台。
  - 同时支持从标准原料表和营养档案 tab 打开。

- `IngredientTagsPanel.vue`
  - 从原 `IngredientTags/index.vue` 抽取。

保留现有：

- `IngredientNutritionEditor.vue`
- `IngredientNutritionDialog.vue`
- `TagForm.vue`
- 现有 nutrition governance 的 API 封装和类型定义

### 路由

`/ingredients` 支持 query：

- `/ingredients?tab=standard`
- `/ingredients?tab=nutrition`
- `/ingredients?tab=tags`

默认：

- 无 query 时进入 `standard`。

旧路由：

- `/nutrition-governance` 重定向到 `/ingredients?tab=nutrition`
- `/ingredient-tags` 重定向到 `/ingredients?tab=tags`

### 数据流

标准原料 tab：

```text
加载原料列表
  -> 展示基础字段、标签、SKU 状态
  -> 同步加载或按需加载营养摘要
  -> 点击营养审核
  -> 打开营养审核台
```

营养档案 tab：

```text
加载营养治理总览
  -> 按标准原料聚合展示
  -> 批量生成候选或 Agent 建议
  -> 保存/测试 DeepSeek 设置
  -> 导入 USDA 来源或查看数据源状态
  -> 点击某个原料
  -> 打开营养审核台
```

标签体系 tab：

```text
加载标签树和标签平铺列表
  -> 新增/编辑/删除
  -> 保存后刷新标签树
```

## 权限和安全

- 合并页面不改变现有后台鉴权方式。
- DeepSeek API Key 仍只在后端加密保存。
- 前端只展示 API Key 是否已配置和尾号。
- 旧路由重定向不绕过权限。
- Agent 仍不能自动确认营养档案。

## 分阶段实施

### 阶段一：导航与页面合并

1. 把 `/ingredients` 改为内部 tab 页面。
2. 抽取 `IngredientTagsPanel`。
3. 抽取或迁移营养治理主面板。
4. 删除侧边栏中的 `原料营养治理` 和 `原料标签管理`。
5. 为旧路由增加重定向。

阶段一完成后，用户从视觉和导航上只看到一个 `原料管理` 入口。

### 阶段二：营养审核台重构

1. 按标准原料聚合营养档案。
2. 审核台拆分为 `已入库档案`、`待审核候选`、`重新查找`、`营养明细与校验`。
3. 支持已入库备用档案设为当前主档案。
4. 统一文案，去掉容易混淆的 `硬闸门`、`次级档案`、`审批` 等表达。

阶段二完成后，用户能在单个原料上下文内完成匹配、审核、切换主档案和营养校验。

### 阶段三：质量和批量治理

1. 营养档案 tab 改为按标准原料聚合。
2. 批量 Agent 任务展示进度、错误和结果分组。
3. 标准原料主表增加营养档案摘要列。
4. 增加筛选：无主档案、有待审核、校验失败、需人工处理。

阶段三完成后，批量数据录入和日常人工审核都可以在原料管理中心完成。

## 验收标准

1. 侧边栏只显示一个 `原料管理` 入口。
2. 访问 `/nutrition-governance` 会进入 `/ingredients?tab=nutrition`。
3. 访问 `/ingredient-tags` 会进入 `/ingredients?tab=tags`。
4. 原 `原料标签管理` 的新增、编辑、添加子标签、删除能力仍可用。
5. 原 `原料营养治理` 的 Agent 设置、候选生成、批量建议和审核入口仍可用。
6. 在标准原料表中可以直接打开某个原料的营养审核台。
7. 营养审核台能清楚展示当前主档案、备用档案、待审核候选。
8. 对已入库备用档案可以执行 `设为当前主档案`。
9. Agent 建议不会自动写入正式营养档案。
10. 手动营养编辑入口仍可用，并与候选审核入口区分清楚。

## 风险与应对

### 页面过重

合并后三个原页面进入同一个路由，可能导致首屏加载变慢。

应对：

- tab 内容按需加载。
- Agent 任务、候选列表、标签树不要在首次进入标准原料 tab 时全部加载。

### 用户误以为 Agent 会自动入库

合并后 Agent 设置和审核入口更近，可能让用户误解 Agent 会直接写入营养档案。

应对：

- 文案统一为 `Agent 建议`。
- 入库按钮必须由用户点击。
- 保存确认弹窗明确说明写入影响。

### 原料管理主表过宽

增加营养档案列后，表格可能更拥挤。

应对：

- 只展示摘要状态。
- 详细营养信息放入审核台。
- 不在主表直接展示完整候选列表。

### 旧代码耦合

现有 `Ingredients/index.vue` 和 `NutritionGovernance/index.vue` 都比较重，直接搬运容易变成巨型文件。

应对：

- 先抽组件，再组合页面。
- 原有业务逻辑逐步迁移，不在一个提交里大规模重写所有交互。
