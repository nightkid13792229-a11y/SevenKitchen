# Agent 营养档案草稿生成设计

## 背景

标准原料已经支持多个营养档案，并且可以通过 USDA、CFCT、NZFCD 等来源入库。现在需要新增一个入口，让 Agent 根据人工输入的要求，自动查找可信营养来源、选择合适词条、生成营养档案草稿，并等待人工确认后再入库。

## 目标

- 在标准原料的营养档案管理器中新增“Agent 添加档案”入口。
- 用户输入自然语言要求，例如“生的新西兰绿唇贻贝，优先 NZFCD；缺失字段可用可信近似来源补充，但必须标明字段来源”。
- 系统优先查询本地 USDA、CFCT、NZFCD 中间库。
- 本地库找不到合适来源时，允许查询白名单互联网来源。
- Agent 对候选来源做语义匹配、排序和解释。
- 系统把 Agent 选择的来源转换为 `NutritionProfileV2` 草稿。
- 草稿必须包含来源编号、字段级来源、换算说明、缺失字段说明和营养校验结果。
- 第一版只生成草稿，不自动确认入库。

## 非目标

- 第一版不允许 Agent 绕过人工确认直接入库。
- 第一版不开放任意网页抓取，只允许配置过的可信白名单来源。
- 第一版不让 Agent 自行发明营养数值；每个非空营养字段必须来自数据库原始值、可信标签、可信文献或明确标注的近似来源。
- 第一版不做配方设计器自动选档案，只解决营养档案草稿生成和确认。

## 推荐流程

1. 用户在营养档案管理器点击“Agent 添加档案”。
2. 用户填写档案要求、目标状态、可食部、加工方式、来源优先级。
3. 后端创建一个草稿任务。
4. 系统搜索本地来源库，生成候选来源池。
5. 如果候选不足，系统按白名单来源搜索互联网，保存来源摘要和引用链接。
6. Agent 对候选做语义匹配，输出推荐主来源、可选补充来源、拒绝理由和置信度。
7. 系统把推荐来源映射成 `NutritionProfileV2` 草稿。
8. 系统运行营养校验，检查字段覆盖、单位换算、原始值一致性和近似来源标记。
9. 前端展示草稿详情，用户可以确认、编辑或拒绝。
10. 用户确认后，系统创建 `NutritionFood` 并挂载到当前标准原料；可选择设为主档案或次级档案。

## 数据模型

新增 `NutritionProfileDraft` 草稿概念，用于保存 Agent 生成但未确认的档案。

核心字段：

- `ingredientId`: 标准原料 ID。
- `status`: `DRAFT`、`CONFIRMED`、`REJECTED`。
- `requestText`: 用户输入的自然语言要求。
- `targetState`: 目标状态，例如 `RAW`、`COOKED`。
- `targetEdiblePortionLabel`: 目标可食部，例如“带皮”“去皮”“标准可食部”。
- `targetProcessingLabel`: 目标加工方式，例如“未加工”“水煮”。
- `sourcePriority`: 来源优先级，例如 `["NZFCD", "USDA", "CFCT"]`。
- `candidateSources`: 系统检索出的候选来源。
- `agentReview`: Agent 的推荐结果、语义分析和拒绝理由。
- `draftNutritionData`: 待确认的 `NutritionProfileV2`。
- `validationReport`: 营养校验报告。
- `confirmedNutritionFoodId`: 确认后生成的 `NutritionFood` ID。

## 来源策略

第一优先级是本地结构化中间库：

- USDA FDC 本地中间库。
- CFCT OCR/结构化中间库。
- NZFCD FOODfiles 本地导入数据。

第二优先级是可信白名单互联网来源：

- 官方食品成分数据库。
- 学术机构、政府机构或明确可追溯的公开数据库。
- 产品标签来源仅用于补剂或明确商品化食材。

互联网来源进入草稿前必须保存来源标题、来源链接、访问时间、提取字段和 Agent 判断理由。

## Agent 分工

系统负责：

- 本地数据库检索。
- 候选池生成。
- 原始营养值读取。
- 单位换算。
- 字段级来源落库。
- 校验报告生成。

Agent 负责：

- 把用户要求转成搜索词、别名和排除词。
- 判断候选来源是否匹配标准原料。
- 判断生熟、可食部、加工、野生/养殖等描述是否冲突。
- 选择主来源和补充来源。
- 输出中文解释、置信度和人工关注点。

Agent 不负责：

- 直接写入最终营养档案。
- 在没有来源的情况下编造数值。
- 绕过校验和人工确认。

## 前端交互

在营养档案管理器中增加“Agent 添加档案”按钮。

抽屉内容：

- 档案要求输入框。
- 目标状态、可食部、加工方式。
- 来源优先级选择。
- “开始生成草稿”按钮。
- 生成后的候选来源列表。
- Agent 推荐摘要。
- 营养数据预览，按宏量、矿物质、维生素、脂肪酸、氨基酸分组。
- 字段级来源和校验报告。
- “确认入库为主档案”“确认入库为次级档案”“拒绝草稿”操作。

## 错误处理

- 未配置 Agent API：提示去 Agent 设置配置。
- 本地库无候选：提示可以放宽要求或允许白名单联网搜索。
- Agent 超时：保留候选池，允许重试 Agent 排序。
- 营养校验失败：草稿可保存，但确认按钮需要显示明确风险。
- 字段来源缺失：对应字段不能自动填值。

## 测试重点

- 用户输入要求后能生成草稿，不会直接入库。
- 本地 USDA/CFCT/NZFCD 候选能进入候选池。
- Agent 返回的推荐能保存为草稿。
- 字段级来源能保留到 `draftNutritionData.meta.fieldSources`。
- 确认草稿后才创建 `NutritionFood` 和 mapping。
- 拒绝草稿不会影响已有营养档案。
- 未配置 Agent 时返回可读错误。

## 自查

- 没有允许 Agent 直接自动入库。
- 没有允许无来源数值进入营养档案。
- 草稿、确认、拒绝三种状态边界明确。
- 第一版范围聚焦在营养档案草稿生成，不扩展到配方设计器。
