# 食谱设计器营养评估 UI 改版设计

## 背景

当前移动端食谱设计器的营养评估抽屉以平铺列表和四格统计展示达标、缺口、超标、缺数据数量。这个结构能表达总体结论，但不能让营养师快速理解每个营养素属于哪个营养板块、当前配方含量在标准范围中的位置，以及同一个营养素在能量口径和干物质口径下的值。

本设计聚焦小程序编辑页的营养评估抽屉，不改变配方计算、标准选择、发布审核或后端接口语义。

## 已确认决策

1. 评估抽屉按 5 个固定分类展示：宏量、氨基酸、脂肪酸、微量、维生素。
2. 分类标签固定显示在一行，不横向滚动。
3. 分类标签右上角用红色气泡显示该分类内需要关注的数量。
4. 气泡数量统计缺口、超标、缺数据，不统计达标；数量为 0 时隐藏。
5. 顶部不再展示达标、缺口、超标、缺数据四格统计。
6. “营养评估”标题同行右侧展示本次评估依据：营养标准名称及对应生命阶段。
7. 营养行显示营养素名称、能量口径、干物质占比和状态。
8. 营养素名称后只展示能量口径，例如“每1000 kcal ME”，不再附带含量单位。
9. 当前含量只在含量条上标注，不再在营养行里重复展示。
10. 含量条上方标注标准下限和上限；含量条下方标注当前值。
11. 如果标准只有下限或只有上限，只展示已有边界。
12. 干物质占比与营养素名称同行展示；若数据缺失显示“干物质 -”。
13. “按需关注优先”等解释文案不在界面展示，排序作为系统行为处理。

## 目标

1. 让营养师在手机屏幕上更快定位异常营养板块。
2. 让每个营养素行同时表达当前值、标准范围位置和干物质占比。
3. 减少重复说明文字，提高抽屉信息密度。
4. 保持现有评估数据兼容：优先读取 `groupedEntries/details`，无新增字段时优雅降级。

## 非目标

1. 不改后端评估计算公式。
2. 不改配方草稿保存、原料添加、发布流程。
3. 不新增营养标准管理界面。
4. 不把原始后端分类扩展成超过 5 个可见标签。
5. 不在本次实现里强制后端补齐干物质字段；前端先读取已有干物质口径 detail，缺失时显示 `-`。

## UI 结构

营养评估抽屉展开后从上到下为：

1. 标题行
   - 左侧：`营养评估`
   - 右侧两行：营养标准名称、生命阶段。
   - 第一版标准名称可展示为 `FEDIAF 2025 犬标准`；生命阶段使用当前草稿 scenario 对应中文标签。

2. 分类标签行
   - 固定 5 等分：`宏量`、`氨基酸`、`脂肪酸`、`微量`、`维生素`。
   - 当前分类使用轻量底色区分。
   - 红色气泡显示该分类异常数量。

3. 当前分类标题
   - 展示完整分类名，例如 `宏量营养素`。
   - 不展示排序说明。

4. 营养素列表
   - 第一行：营养素名、能量口径、干物质占比、状态。
   - 第二行：含量条。
   - 含量条上方：下限、上限。
   - 含量条下方：当前值。

## 数据映射

### 分类

后端分类映射到 5 个前端分类：

- `MACRO` -> 宏量
- `AMINO_ACID` -> 氨基酸
- `FATTY_ACID` -> 脂肪酸
- `MINERAL` -> 微量
- `VITAMIN` -> 维生素

`RATIO` 和 `COMBINATION` 不新增可见分类。第一版按营养素名称或字段语义做保守归类：钙磷比等矿物相关条目进入微量；EPA/DHA 等脂肪酸组合进入脂肪酸；蛋氨酸-胱氨酸等氨基酸组合进入氨基酸；无法判断时进入宏量，避免条目丢失。

### 营养行代表值

`groupedEntries` 中同一营养素可能有多个 `details`。前端按以下规则选择展示值：

1. 含量条优先使用 `PER_1000_KCAL_ME` detail。
2. 若没有 `PER_1000_KCAL_ME`，使用该 grouped entry 自身代表值。
3. 干物质占比优先读取同组 `PER_100G_DRY_MATTER` detail 的 `currentValue`。
4. 若无干物质 detail，显示 `干物质 -`。
5. 状态沿用 grouped entry 的 worst-status 代表状态。

### 标准范围和位置

含量条读取展示 detail 的 `minValue`、`maxValue`、`currentValue` 和 `unit`。

- 当前值为空：不渲染含量条，显示缺数据说明。
- 下限为空：不显示下限标签。
- 上限为空：不显示上限标签。
- 当前值相对于下限、上限换算为 0% 到 100% 的位置。
- 只有下限时，条形范围保留“低/适宜”结构，当前值低于下限显示在左侧，达标值显示在适宜段。
- 只有上限时，条形范围保留“适宜/过高”结构。

## 交互

1. 默认选中第一个有异常数量的分类；如果所有分类都无异常，选中宏量。
2. 点击分类标签切换当前列表。
3. 分类内按状态优先级排序：缺数据、超标、缺口、达标。
4. 同状态下保持后端返回顺序。
5. 抽屉展开和收起行为保持现状。

## 验收标准

1. 评估抽屉不再出现四格摘要统计。
2. 五个分类标签固定显示且无需横向拖动。
3. 分类红色气泡数量只统计缺口、超标、缺数据。
4. 标题行右侧展示标准名称和当前生命阶段。
5. 营养素行展示 `每1000 kcal ME`，不展示 `g/1000 kcal ME` 这类混合口径。
6. 干物质占比与营养素名称同行展示。
7. 当前含量和标准上下限直接标在含量条上。
8. `npm test -- src/pages/recipe-designer.regression.spec.ts` 通过。
9. `npm run preview` 生成并验证 `miniapp/dist/dev/mp-weixin`，不使用 `dist/build/mp-weixin` 作为开发验证目录。
