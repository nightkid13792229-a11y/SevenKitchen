# 搜索治理与别名词库设计

## 背景

小程序和后台中有多处高频搜索入口：食谱设计器添加原料、采购/库存选择原料、营养档案搜索、犬种搜索、订单搜索等。当前这些搜索大多由各自页面或服务直接做关键词匹配，能力不一致，无法统一处理“鸡胸肉搜鸡胸”“西蓝花搜西兰花”“犬种中英文名/俗称”“订单状态词”等场景。

本设计把搜索能力从单点功能升级为后台可治理能力：统一记录搜索行为，统一配置归一化、别名、相似度和排序策略，并通过 Agent 生成高频同义词和搜索优化建议。Agent 只能生成待审批建议，不能绕过人工审批直接修改线上词库。

## 已确认决策

1. 后台新增“搜索治理”页面，集中管理小程序和后台可治理搜索能力。
2. 一期纳入原料搜索、营养档案搜索、犬种搜索、订单搜索、采购/库存原料搜索。
3. 搜索治理按领域隔离，避免原料同义词污染订单、犬种等搜索场景。
4. 原料/营养搜索一期启用归一化、双向包含、中文近似匹配、别名扩展、排序打分和 Agent 建议。
5. 犬种搜索一期启用归一化、别名扩展、中文/英文/俗称匹配、排序打分和 Agent 建议。
6. 订单搜索一期启用日志、归一化、订单号片段匹配、手机号后四位匹配、昵称/狗狗名匹配、状态词映射和排序优化；不启用开放式语义同义词。
7. 采购/库存原料搜索复用原料搜索治理能力。
8. Agent 生成词库变更建议，用户审批后系统自动应用变更，并记录审计日志。
9. 第一期不引入向量搜索或语义搜索引擎；保留后续扩展空间。

## 目标

1. 降低高频搜索入口的无结果率。
2. 让用户用自然叫法也能找到目标对象，例如 `鸡胸肉` 命中 `鸡胸`，`西蓝花` 命中 `西兰花`。
3. 让搜索结果排序更符合业务直觉，减少用户翻找。
4. 让别名词库可被后台维护、审批、回滚和审计。
5. 让 Agent 帮助整理高频同义词和搜索失败案例，但最终由人工审批。
6. 为多个搜索入口提供统一底层能力，避免每个页面重复实现。

## 非目标

1. 不在一期引入向量数据库、embedding 或全文搜索引擎。
2. 不让 Agent 自动越权修改词库；所有变更必须经过后台审批。
3. 不把所有领域共用一套别名词库。
4. 不改变订单、原料、犬种等核心业务模型的主流程语义。
5. 不一次性重写所有历史搜索接口；一期按高频入口逐步接入共享搜索能力。

## 领域模型

搜索治理使用领域隔离的配置模型。第一期领域包括：

- `INGREDIENT`：原料搜索，用于食谱设计器、采购、库存等原料选择场景。
- `NUTRITION_FOOD`：营养档案搜索，用于营养档案管理和食谱设计器营养档案选择。
- `BREED`：犬种搜索，用于小程序建档、档案编辑和后台品种管理。
- `ORDER`：订单搜索，用于小程序员工端和后台订单管理。

每个领域可以独立配置启用能力：

- 搜索日志
- 文本归一化
- 双向包含
- 中文近似匹配
- 别名扩展
- 状态词映射
- 排序打分
- Agent 建议

## 数据模型

### SearchAliasGroup

表示一个可维护的别名组。

- `id`
- `domain`：搜索领域。
- `canonicalTerm`：标准词，例如 `西兰花`。
- `aliases`：别名列表，例如 `['西蓝花', '青花菜', '绿花椰菜', 'broccoli']`。
- `status`：`ACTIVE`、`DISABLED`。
- `riskLevel`：`LOW`、`MEDIUM`、`HIGH`。
- `notes`
- `createdBy`
- `updatedBy`
- `createdAt`
- `updatedAt`

约束：

- 同一领域内，`canonicalTerm` 不允许重复。
- 同一领域内，一个别名不允许同时出现在多个启用中的别名组。
- 高风险别名组可以启用，但审批页面必须展示风险提示。

### SearchQueryLog

记录搜索行为，用于统计和 Agent 建议。

- `id`
- `domain`
- `source`：入口标识，例如 `miniapp.recipe-designer.ingredient-picker`。
- `rawQuery`
- `normalizedQuery`
- `resultCount`
- `selectedEntityType`
- `selectedEntityId`
- `selectedEntityName`
- `userId`
- `createdAt`

记录策略：

- 对订单搜索的手机号、昵称等敏感字段只记录归一化摘要或脱敏值。
- 高频统计只依赖查询词、结果数量和最终选择，不存储完整敏感订单内容。

### SearchAliasSuggestion

表示 Agent 或人工创建的待审批建议。

- `id`
- `domain`
- `action`：`CREATE_GROUP`、`ADD_ALIAS`、`MERGE_GROUPS`、`DISABLE_ALIAS`、`UPDATE_CANONICAL`。
- `status`：`PENDING`、`APPROVED`、`REJECTED`、`APPLIED`、`FAILED`。
- `payload`：结构化变更内容。
- `evidence`：搜索日志、无结果词、用户选择等证据摘要。
- `riskLevel`
- `agentRationale`
- `reviewerId`
- `reviewedAt`
- `appliedAt`
- `createdAt`

审批通过后由服务端事务应用变更，并写入审计记录。

### SearchAliasAuditLog

记录词库变更历史。

- `id`
- `domain`
- `action`
- `before`
- `after`
- `suggestionId`
- `operatorId`
- `createdAt`

## 搜索能力

### 文本归一化

共享搜索服务对输入和候选字段做保守归一化：

- 去首尾空格。
- 英文转小写。
- 全角转半角。
- 去除常见分隔符、括号和重复空白。
- 保留中文主体词，不做激进拆词。

### 双向包含

用于解决短名/长名差异：

- 候选字段包含查询词。
- 查询词包含候选字段。

例子：

- 查询 `鸡胸肉` 可以命中候选 `鸡胸`。
- 查询 `熟鸡胸` 可以命中候选 `鸡胸`，但排序低于精确命中。

### 中文近似匹配

对较短中文词启用保守相似度匹配：

- 只对 2 到 8 个中文字符的查询词启用。
- 使用编辑距离或相似字符覆盖率计算。
- 命中阈值按领域配置。
- 近似命中排序低于精确、别名和双向包含命中。

例子：

- `西蓝花` 可以命中 `西兰花`。
- `鸡胸肉` 可以命中 `鸡胸`，但优先由双向包含处理。

### 别名扩展

查询词命中启用中的别名组时，搜索服务会扩展该组内所有词。

例子：

- `西蓝花` 扩展为 `西蓝花`、`西兰花`、`青花菜`、`绿花椰菜`、`broccoli`。
- `鲑鱼` 扩展为 `鲑鱼`、`三文鱼`、`salmon`。

### 排序打分

搜索服务返回候选时计算匹配分，用于排序和调试。

推荐优先级：

1. 主字段精确命中。
2. 别名组精确命中。
3. 主字段前缀命中。
4. 主字段双向包含命中。
5. 主字段中文近似命中。
6. 关联字段命中，例如营养档案名、英文名、品牌、型号。
7. 历史选择频率高的结果。

不同领域可以覆盖权重。订单搜索中，订单号精确/前缀命中权重最高；原料搜索中，原料名和标准别名权重最高。

## 入口接入

### 原料/营养搜索

接入入口：

- 小程序食谱设计器添加原料弹窗。
- 小程序采购添加原料。
- 小程序库存盘点选择原料。
- 后台原料管理搜索。
- 后台营养档案搜索。

行为：

- 只在业务要求的候选集合内搜索，例如食谱设计器仍只显示有 `VERIFIED` 营养映射的 `FOOD`/`SUPPLEMENT`。
- 空状态提示需要说明业务过滤条件，例如“仅显示已维护并验证营养档案的原料”。

### 犬种搜索

接入入口：

- 小程序新建档案犬种搜索。
- 小程序档案编辑犬种搜索。
- 后台品种管理搜索。

行为：

- 犬种别名包含中文名、英文名、简称、俗称。
- 用户最终选择犬种后记录搜索词和犬种 ID，用于发现高频别名。

### 订单搜索

接入入口：

- 小程序员工端订单搜索。
- 后台订单管理搜索。

行为：

- 支持订单号精确、前缀、片段搜索。
- 支持手机号后四位搜索。
- 支持狗狗名、用户昵称归一化搜索。
- 支持状态词映射，例如 `未付款`、`待支付` 映射到对应订单状态。
- 不启用开放式语义同义词，避免召回过宽造成误操作。

## Web 管理页面

后台新增路由：`/search-governance`，菜单名称为“搜索治理”。

页面使用 Tab 组织：

1. **搜索概览**
   - 展示各领域搜索次数、无结果率、低结果率、审批待处理数量。
   - 展示最近高频无结果词。

2. **词库管理**
   - 按领域筛选别名组。
   - 支持新增、编辑、禁用别名组。
   - 展示标准词、别名、风险等级、启用状态、最近修改人。
   - 保存时校验同领域别名冲突。

3. **搜索洞察**
   - 展示高频搜索词。
   - 展示无结果搜索词。
   - 展示“搜索词 -> 用户最终选择对象”的统计。
   - 支持从洞察直接创建别名建议。

4. **Agent 建议**
   - 运行 Agent 分析。
   - 查看待审批建议。
   - 展示证据、建议动作、风险等级和 Agent 理由。
   - 支持审批通过、拒绝、编辑后通过。

5. **应用范围**
   - 展示每个搜索入口接入的治理能力。
   - 支持按领域调整能力开关。
   - 第一版可以只读展示，变更开关通过配置文件或后端常量控制。

## Agent 工作流

Agent 输入：

- 最近一段时间的高频搜索词。
- 无结果搜索词。
- 低结果搜索词。
- 搜索词与最终选择对象的配对。
- 当前别名词库。
- 当前领域候选对象名称。

Agent 输出：

- 建议动作。
- 结构化变更 payload。
- 证据摘要。
- 风险等级。
- 推荐理由。
- 是否需要人工重点复核。

审批规则：

1. Agent 建议默认进入 `PENDING`。
2. 审批人可以直接通过、编辑后通过或拒绝。
3. 审批通过后服务端事务应用词库变更。
4. 应用成功后建议状态变为 `APPLIED`。
5. 应用失败时建议状态变为 `FAILED`，保留错误信息。

安全约束：

- Agent 不直接写 `SearchAliasGroup`。
- 高风险建议必须显示风险标记。
- 同领域别名冲突必须阻止应用。
- 所有变更写入审计日志。

## API 设计

后台 API：

- `GET /admin/search-governance/overview`
- `GET /admin/search-governance/alias-groups`
- `POST /admin/search-governance/alias-groups`
- `PUT /admin/search-governance/alias-groups/:id`
- `POST /admin/search-governance/alias-groups/:id/disable`
- `GET /admin/search-governance/query-insights`
- `GET /admin/search-governance/suggestions`
- `POST /admin/search-governance/suggestions/generate`
- `POST /admin/search-governance/suggestions/:id/approve`
- `POST /admin/search-governance/suggestions/:id/reject`

内部搜索服务接口：

- `expandQuery(domain, rawQuery)`
- `buildSearchPredicate(domain, fields, rawQuery)`
- `rankResults(domain, rawQuery, candidates)`
- `recordSearchEvent(event)`

第一期实施计划内按顺序接入共享服务：先接入 `INGREDIENT`，再接入 `BREED`，最后接入 `ORDER`。三类领域都属于一期范围；排序只表示实施顺序和风险控制顺序。

## 迁移策略

1. 新增搜索治理表，不修改现有核心业务表。
2. 将当前代码中已有的原料别名组迁移为初始 `INGREDIENT` 别名组。
3. 为犬种已有 `aliases` 字段生成初始 `BREED` 别名组，原业务字段仍保留。
4. 为订单状态词创建初始 `ORDER` 映射配置。
5. 接入日志时先保证不影响原有查询结果，再逐步启用扩展匹配和排序。

## 验收标准

1. 后台出现“搜索治理”页面，并能按领域查看和维护别名组。
2. 词库保存时能阻止同领域别名冲突。
3. 小程序食谱设计器添加原料中，搜索 `鸡胸肉` 可以召回 `鸡胸`，搜索 `西蓝花` 可以召回 `西兰花`。
4. 犬种搜索可以通过别名命中对应犬种。
5. 订单搜索支持订单号片段、手机号后四位和状态词搜索。
6. 搜索日志能记录领域、入口、查询词、结果数量和最终选择对象。
7. Agent 能基于搜索日志生成待审批别名建议。
8. 审批通过后系统自动应用建议并写入审计日志。
9. Agent 建议被拒绝后不会修改词库。
10. 原料/营养搜索仍遵守已有业务过滤，例如只返回食谱设计器允许选择的原料。
