# 普通用户食谱设计器私有草稿开放设计

## 背景

现有移动端食谱设计器已经具备生命阶段系列、设计草稿、原料编辑、FEDIAF 2025 犬标准评估、管理员发布为正式食谱等能力。它最初按内部营养师/员工工具建设，后端 `RecipeDesignerController` 当前整体挂载 `AuthGuard + StaffGuard`，小程序入口也只在员工工作台。

现在需要把食谱设计器开放给普通用户，并在小程序首页提供入口。普通用户使用场景不是为某一只狗狗定制专属配方，而是按生命阶段设计通用食谱草稿。普通用户创建的草稿必须保持私有，不能发布成正式食谱，也不能进入首页食谱橱窗、推荐、订单、采购或生产链路。

## 已确认决策

1. 采用“同一设计器底座，分离 C 端入口与员工能力”的方案。
2. 普通用户复用现有 `DesignRecipe`、`DesignRecipeItem`、`RecipeSeries` 数据模型。
3. 普通用户草稿只作为用户自己的私有设计草稿或私有食谱使用。
4. 普通用户草稿绝对不能发布成正式 `Recipe`，也不能显示在小程序正式食谱列表中。
5. 首页快捷功能区新增 `食谱设计` 入口，放在 `建议反馈` 右侧。
6. 普通用户设计器不绑定某一只狗狗档案，不使用“专属”“为某只狗设计”等文案。
7. 管理员现有正式发布能力保留，但普通用户永远不能调用成功。

## 目标

1. 普通登录用户可以从首页进入食谱设计器。
2. 普通用户可以按生命阶段创建、编辑、评估、保存和删除自己的私有草稿。
3. 普通用户只能看到和操作自己创建的私有设计系列与草稿。
4. 员工/管理员现有内部食谱设计流程不回退。
5. 管理员发布正式食谱的能力继续存在，并仍只面向管理员。
6. 小程序正式食谱橱窗、推荐、收藏、下单、订单、采购和生产链路不读取普通用户草稿。

## 非目标

1. 不新增按狗狗档案定制食谱的流程。
2. 不把普通用户草稿发布为正式食谱。
3. 不让普通用户维护补剂库、识别补剂标签或创建正式补剂选项。
4. 不让普通用户基于已发布正式食谱创建修订草稿。
5. 不新增独立 `UserRecipeDraft` 表。
6. 不在本轮实现分享、上架、审核、购买或生产私有草稿。

## 权限模型

### 普通用户

普通用户只需要登录即可访问用户模式食谱设计器。

允许能力：

- 查看自己的食谱设计系列列表。
- 新建食谱系列。
- 为某个生命阶段创建或继续编辑草稿。
- 添加、删除和调整原料。
- 查看 FEDIAF 2025 评估。
- 保存自己的私有草稿。
- 删除自己的未发布私有草稿或系列。

禁止能力：

- 发布为正式食谱。
- 访问或编辑他人未发布草稿。
- 访问员工/管理员内部系列。
- 创建补剂选项。
- 上传补剂标签并执行 AI 识别。
- 从已发布正式食谱创建修订草稿。

### 员工与管理员

员工/管理员保留内部设计器能力。发布正式食谱仍仅允许管理员。

管理员发布接口必须继续使用服务端硬权限判断。前端隐藏发布入口只是体验优化，不能作为安全边界。

## 后端设计

### 控制器守卫

`RecipeDesignerController` 从整类 `@UseGuards(AuthGuard, StaffGuard)` 调整为整类只要求 `AuthGuard`，再按方法增加角色限制。

所有登录用户可访问：

- `GET /api/v1/recipe-designer/ingredient-options`
- `GET /api/v1/recipe-designer/series`
- `POST /api/v1/recipe-designer/series`
- `PATCH /api/v1/recipe-designer/series/:seriesId`
- `DELETE /api/v1/recipe-designer/series/:seriesId`
- `POST /api/v1/recipe-designer/series/:seriesId/stage-drafts`
- `GET /api/v1/recipe-designer/drafts`
- `GET /api/v1/recipe-designer/drafts/:id`
- `POST /api/v1/recipe-designer/drafts`
- `PATCH /api/v1/recipe-designer/drafts/:id`
- `DELETE /api/v1/recipe-designer/drafts/:id`
- `POST /api/v1/recipe-designer/drafts/:id/items`
- `PATCH /api/v1/recipe-designer/items/:itemId`
- `DELETE /api/v1/recipe-designer/items/:itemId`
- `POST /api/v1/recipe-designer/drafts/:id/assess`

员工或管理员可访问：

- `POST /api/v1/recipe-designer/supplement-options`
- `POST /api/v1/recipe-designer/supplement-label/extract`
- `POST /api/v1/recipe-designer/drafts/:id/revisions`

管理员可访问：

- `POST /api/v1/recipe-designer/drafts/:id/publish`

### 服务层归属校验

服务层继续以 `createdBy` 作为草稿所有权字段。所有读取、编辑、删除操作都必须验证当前用户有权访问目标记录。

关键规则：

- 普通用户 `listSeries` 只返回 `createdBy = 当前用户` 的 active series。
- 普通用户 `listDrafts` 只返回 `createdBy = 当前用户` 的草稿，不返回已发布内部设计或他人设计。
- 普通用户 `getDraft` 只能读取自己的草稿；已发布正式设计不可作为普通用户可见模板。
- 普通用户 `createSeriesStageDraft` 必须校验 series 存在且 `createdBy = 当前用户`。
- 普通用户 `renameSeries`、`deleteSeries` 必须校验 series 归属。
- 普通用户 `updateDraft`、`deleteDraft`、`addItem`、`updateItem`、`removeItem` 继续校验 draft 或 item 所属草稿的 `createdBy`。
- 普通用户调用 `publishDraft` 必须被控制器或服务层拒绝，不能依赖前端隐藏按钮。

员工/管理员的列表范围应避免泄露普通用户私有草稿。内部设计器列表可以继续显示内部创建的系列；如果需要管理员查看用户私有草稿，应另建明确的管理审计入口，不复用本轮公开入口。

### 正式食谱隔离

普通用户草稿保存在 `DesignRecipe` 体系中，但不写入 `Recipe` 表。现有正式食谱查询继续只读取 `Recipe`，因此普通用户草稿不会进入：

- 首页食谱橱窗。
- 专属/通用推荐。
- 食谱详情。
- 收藏。
- DIY 制作单。
- 下单、订单、采购、库存、生产。

实现时仍需增加回归测试，锁定普通用户没有发布路径，避免未来误把私有草稿纳入正式食谱查询。

## 小程序设计

### 首页入口

`miniapp/src/pages/home/index.vue` 的快捷功能区从 4 个入口扩展为 5 个入口：

1. 饭量计算
2. 体重管理
3. 健康记录
4. 建议反馈
5. 食谱设计

`食谱设计` 位于 `建议反馈` 右侧，点击跳转 `/pages/recipe-designer/list`。未登录时先跳转登录页。

入口文案使用 `食谱设计`。图标新增 `/static/home-actions/recipe-designer.png`，样式保持和现有快捷入口一致。

### 用户模式列表页

普通用户进入 `pages/recipe-designer/list` 后，页面保持生命阶段系列结构，但文案调整为用户私有草稿语气：

- 标题：`食谱设计器` 或 `我的食谱设计`。
- 副标题：`按生命阶段维护通用食谱草稿`。
- 空状态：`暂无食谱草稿`，`点击新建食谱开始设计`。
- 新建按钮：`新建食谱`。

普通用户模式隐藏：

- `补剂库` 入口。
- 与正式发布相关的状态解释。
- 从已发布阶段复制模板的入口，如果模板来自内部正式食谱。
- 任何“后台草稿”“审核”“发布”文案。

生命阶段仍展示：

- 小于 14 周龄幼犬。
- 大于等于 14 周龄幼犬。
- 低能量需求成年犬 MER 95。
- 普通成年犬 MER 110。
- 繁殖期母犬。

### 用户模式编辑页

普通用户编辑页保留：

- 食谱名称。
- 生命阶段。
- 原料列表。
- 添加原料。
- 克数编辑。
- 营养评估。
- 保存状态。

普通用户编辑页隐藏：

- 发布入口。
- 审核说明。
- 后台草稿提示。
- 修订正式食谱提示。
- 补剂维护入口。

评估内容继续保持专业，但要表达为“当前草稿评估结果”，不能暗示该草稿已经被平台认可或可上架销售。

## 错误处理

1. 未登录点击首页入口：跳转登录页。
2. 普通用户访问他人草稿或系列：后端返回 404，前端提示 `食谱草稿不存在或无权访问`。
3. 普通用户调用发布接口：后端返回 403，前端不显示入口；如果异常触发，提示 `当前账号不能发布正式食谱`。
4. 普通用户访问补剂维护接口：后端返回 403。
5. 列表加载失败：沿用现有 toast，并避免展示空白误导状态。

## 测试计划

### 后端

- 控制器权限测试：`RecipeDesignerController` 整类要求登录，发布接口要求 `ADMIN`。
- 控制器权限测试：补剂创建、补剂标签识别、创建修订草稿要求 `STAFF` 或 `ADMIN`。
- 服务层测试：普通用户 `listSeries` 只返回自己创建的 series。
- 服务层测试：普通用户不能读取、编辑、删除他人未发布草稿。
- 服务层测试：普通用户不能对他人 series 创建阶段草稿、重命名或删除。
- 服务层测试：普通用户不能发布为正式 `Recipe`。
- 回归测试：管理员发布能力仍可调用服务层发布流程。

### 小程序

- 首页回归测试：快捷功能区包含 `食谱设计`，位置在 `建议反馈` 之后，跳转 `/pages/recipe-designer/list`。
- API 回归测试：普通设计器仍调用 `/recipe-designer/series`、`/stage-drafts`、`/drafts`、`/items`、`/assess`。
- 页面源码回归测试：普通用户模式隐藏 `补剂库` 与发布入口。
- 页面源码回归测试：列表页出现 `按生命阶段维护通用食谱草稿` 文案。
- 页面源码回归测试：没有使用“专属”“为某只狗设计”等狗狗绑定表达。

## 验收标准

1. 普通用户登录后可从首页 `建议反馈` 右侧进入 `食谱设计`。
2. 普通用户可创建生命阶段通用食谱系列，并进入各生命阶段草稿编辑。
3. 普通用户只能看到自己的私有系列和草稿。
4. 普通用户无法通过界面或接口发布正式食谱。
5. 普通用户草稿不出现在小程序首页食谱橱窗和推荐列表。
6. 管理员仍可发布管理员/员工创建的设计草稿为正式食谱。
7. 现有食谱详情、DIY 制作单、订单、采购和生产链路不读取普通用户私有草稿。

## 实施顺序

1. 增加后端权限与归属测试，先锁定普通用户私有边界。
2. 调整控制器守卫与服务层 series/draft 归属过滤。
3. 增加小程序首页入口与普通用户模式文案/显隐。
4. 补充小程序源码回归测试。
5. 跑后端与小程序 targeted tests。
6. 做一次手动冒烟：普通用户创建草稿、管理员发布内部草稿、首页正式食谱列表不出现普通用户草稿。
