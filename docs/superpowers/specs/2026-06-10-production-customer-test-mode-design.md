# 生产体验版普通用户测试模式设计

## 背景

管理员需要在手机上的微信小程序体验版中，连接生产环境，验证首页 `食谱设计` 入口在普通用户权限下的真实行为。由于管理员微信登录后生产后端会签发 `ADMIN` token，单纯修改前端本地角色无法验证后端权限；同时也没有长期可用的普通用户微信账号。

本设计提供一个管理员专用的全局普通用户测试模式：管理员在体验版中通过隐藏入口切换到固定的 `CUSTOMER` 测试身份，完整小程序请求都以普通用户 token 访问生产后端。测试完成后可恢复管理员身份。

## 目标

1. 管理员可以在手机体验版中进入真实普通用户权限环境。
2. 切换后全局生效，不只影响首页或食谱设计器。
3. 不需要手动清微信缓存。
4. 生产后端只允许切换到固定测试用户，不支持任意用户模拟。
5. 退出测试模式后能恢复原管理员登录态。
6. 提供清理测试用户食谱设计数据的安全方式，避免生产环境测试数据累积。

## 非目标

1. 不允许管理员模拟任意真实客户。
2. 不把测试模式暴露给普通用户、员工或未登录用户。
3. 不在首页显示测试开关。
4. 不修改正式微信登录逻辑。
5. 不把测试身份用于真实下单、支付或生产履约验证。

## 用户体验

### 入口

测试入口放在 `我的` 页面隐藏区域。管理员登录后连续点击版本号或 Logo 多次，打开 `测试身份` 面板。

首页不显示测试开关。切换成功后自动回到首页，让管理员从真实首页入口开始测试。

### 测试身份面板

面板包含：

- 当前身份状态：管理员模式 / 普通用户测试模式。
- `进入普通用户测试模式`。
- `退出普通用户测试模式`。
- `重置测试用户数据`。

当处于普通用户测试模式时，在 `我的` 页显示明显提示：`当前为普通用户测试模式`，并提供退出入口。

### 切换流程

进入普通用户测试模式时，小程序自动执行：

1. 备份当前管理员 `token`、`user`、`userInfo`。
2. 调用生产后端管理员专用接口，获取固定测试用户的 `CUSTOMER` token。
3. 将本地登录态替换为测试用户。
4. 清理用户相关缓存，例如狗狗列表缓存、首页用户数据缓存、登录触发器等。
5. 标记当前处于测试模式。
6. 跳回首页并重新加载。

管理员不需要手动清缓存。

### 退出流程

退出普通用户测试模式时，小程序自动执行：

1. 恢复之前备份的管理员 `token`、`user`、`userInfo`。
2. 清理测试用户相关缓存。
3. 删除测试模式标记和备份数据。
4. 跳回首页或 `我的` 页并重新加载。

如果备份数据不存在或已损坏，小程序提示重新登录管理员账号。

## 权限与数据范围

切换后是全局生效：

- 首页、我的狗狗、订单、收藏、反馈、食谱设计器等请求都使用测试用户 token。
- 食谱设计器只能看到测试用户自己的私有草稿。
- 补剂库、正式食谱修订、发布正式食谱等员工/管理员能力不可用。
- 测试用户草稿不会进入首页食谱橱窗、推荐、下单、采购或生产链路。

这保证手机体验版测到的是生产后端真实 `CUSTOMER` 权限，而不是前端局部伪装。

## 后端设计

新增管理员专用测试身份接口：

- `POST /api/v1/admin/test-identity/customer-mode`
- 需要 `AuthGuard + AdminGuard`。
- 只返回固定测试用户 token，不接收目标用户 id。
- 如果固定测试用户不存在，则创建或恢复该用户。
- 固定测试用户角色必须是 `CUSTOMER`，状态必须是 `ACTIVE`。
- 固定测试用户带测试手机号或 `phoneBound` 等价信息，避免体验版自动跳转到手机号绑定。

响应返回：

- `token`
- `user`
- `mode: CUSTOMER_TEST`

固定测试用户建议：

- 昵称：`生产体验版普通用户测试号`
- 角色：`CUSTOMER`
- 状态：`ACTIVE`
- 手机号：使用明确的测试号段或内部约定手机号，避免和真实客户混淆。

### 重置测试数据

新增管理员专用重置接口：

- `POST /api/v1/admin/test-identity/customer-mode/reset`
- 需要 `AuthGuard + AdminGuard`。
- 只清理固定测试用户产生的食谱设计测试数据。

首期清理范围：

- 测试用户创建的 `DesignRecipeItem`。
- 测试用户创建的未发布 `DesignRecipe`。
- 测试用户创建的 `RecipeSeries`。

不清理真实 `Recipe`、订单、支付、采购、生产等业务数据。

## 小程序设计

新增测试身份工具模块，统一处理：

- 备份管理员登录态。
- 应用测试用户登录态。
- 恢复管理员登录态。
- 清理用户相关缓存。
- 判断当前是否处于普通用户测试模式。

`我的` 页面负责隐藏入口、状态展示和操作按钮。首页不承载切换功能，只作为切换后的测试起点。

切换状态存储使用独立 key，例如：

- `customer_test_mode_active`
- `customer_test_mode_admin_session_backup`

缓存清理保持白名单式，仅清理用户相关缓存，不清除网络配置、分享配置或其他设备级设置。

## 安全约束

1. 后端接口必须只允许 `ADMIN` 调用。
2. 后端接口不能接受任意用户 id。
3. 测试用户必须固定且可识别。
4. 小程序隐藏入口只是体验保护，不能作为安全边界。
5. 退出测试模式必须清理测试 token，避免管理员误以普通用户身份继续操作。
6. 重置数据只允许清理固定测试用户的数据。

## 验收标准

1. 管理员在手机体验版中可以进入普通用户测试模式。
2. 进入后首页 `食谱设计` 入口可用。
3. 食谱设计器显示普通用户文案，不显示补剂库。
4. 普通用户测试身份不能发布正式食谱。
5. 普通用户测试身份不能访问员工/管理员接口。
6. 测试草稿不出现在首页正式食谱橱窗或推荐中。
7. 退出后恢复管理员身份。
8. 切换和退出过程不要求手动清缓存。
9. 重置测试数据只影响固定测试用户的食谱设计数据。

## 测试策略

后端：

- 管理员可获取固定测试用户 token。
- 员工、普通用户、未登录用户不能获取测试 token。
- 接口不能模拟任意用户。
- 重置接口只删除固定测试用户设计器数据。

小程序：

- 隐藏入口只对管理员可见或可用。
- 切换时正确备份管理员登录态。
- 切换后本地用户角色为 `CUSTOMER`。
- 退出时恢复管理员登录态。
- 进入测试模式后食谱设计器按普通用户模式展示。

手工验收：

- 使用手机打开微信小程序体验版。
- 管理员登录。
- 从隐藏入口切换到普通用户测试模式。
- 从首页进入 `食谱设计` 并完成创建、编辑、评估、保存草稿。
- 验证发布、补剂库、内部修订入口不可用。
- 退出测试模式并确认管理员身份恢复。
