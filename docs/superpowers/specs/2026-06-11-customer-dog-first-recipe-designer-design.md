# 普通用户狗狗优先食谱设计器优化方案

## 背景

小程序首页已经向普通用户开放 `食谱设计` 入口。现有移动端食谱设计器复用了管理员/营养师工作台模型：列表展示食谱系列，每个系列固定展开五个 FEDIAF 犬生命阶段。这对管理员很清晰，因为管理员维护的是可发布的通用系列；但普通用户的目标不同，他们通常只想“给我的某只狗设计一份可继续使用的食谱”。

当前体验存在四个断点：

1. 普通用户列表仍暴露“食谱系列 + 五个生命阶段”的专业维护结构。
2. 新建食谱要求用户直接选择生命阶段，理解门槛高。
3. 新建时默认 `未命名食谱`，不符合用户对个人草稿资产的预期。
4. 设计完成后缺少自然的下一步，不能顺滑进入成品订购或 DIY 制作单。

本方案调整普通用户模式的交互心智：普通用户不再管理“全生命周期食谱系列”，而是围绕“我的狗狗的一份食谱设计”完成创建、编辑、保存和转化。管理员模式继续保留现有系列视图和五阶段维护能力。

## 与既有设计的关系

本方案延续 `2026-05-31-multi-life-stage-recipe-series-design.md` 中管理员端的系列模型，不改变管理员维护五个生命阶段版本的工作方式。

本方案更新 `2026-06-09-recipe-designer-public-private-drafts-design.md` 中“普通用户不绑定某一只狗狗档案”的阶段性决策。新的产品目标要求普通用户降低生命阶段选择门槛，并从设计器直接进入订购/DIY，因此普通用户设计必须持久化狗狗上下文。狗狗上下文不参与营养计算本身，但参与：

- 新建时自动推导 FEDIAF 犬场景。
- 列表展示和筛选。
- 完成后跳转成品订购或 DIY 配置。
- 私有食谱快照的访问控制。

## 已确认决策

1. 普通用户采用“狗狗优先”的食谱设计流程。
2. 管理员/员工继续使用“食谱系列 + 五个生命阶段”的列表。
3. 普通用户列表不展示每个系列下的五个生命阶段，只展示用户自己的食谱设计卡片。
4. 普通用户新建食谱时先选择狗狗，系统自动推导适用生命阶段和 FEDIAF 犬场景。
5. 普通用户可手动修正系统推导的生命阶段，但默认不要求理解专业枚举。
6. 普通用户新建食谱时提供命名输入，并提供基于狗狗名称和日期的默认名称。
7. 普通用户设计完成后提供 `订购成品`、`生成 DIY 制作单`、`仅保存` 三个下一步。
8. 为了进入现有订购/DIY 页面，设计完成后需要生成或更新“私有可用食谱快照”。
9. 私有可用食谱快照只对创建者本人和内部员工/管理员可见，不进入公开食谱橱窗、公开推荐或普通搜索结果。

## 目标

1. 普通用户从首页进入设计器后，看到的是“我的食谱设计”，而不是管理员式系列维护台。
2. 普通用户新建食谱时只需选择狗狗，系统自动选择最可能正确的营养标准。
3. 用户能给食谱命名，并在列表里稳定识别自己的草稿和已完成食谱。
4. 设计完成后能直接进入成品订购或 DIY 配置，形成业务闭环。
5. 普通用户私有食谱不会污染公开食谱库。
6. 管理员现有系列、发布、审核、阶段管理能力不回退。

## 非目标

1. 不重做食谱编辑器的原料编辑、营养计算和 FEDIAF 评估算法。
2. 不让普通用户维护五个生命阶段版本。
3. 不让普通用户把食谱发布到公开橱窗。
4. 不在本轮引入 AI 自动配方生成。
5. 不在本轮实现多人共享、公开分享或营养师远程审核协作。
6. 不用狗狗档案的体重、活动量、过敏信息直接改变配方营养标准；本轮只用狗狗档案推导生命阶段和承接后续订购/DIY计算。

## 用户体验设计

### 首页入口

首页快捷入口继续使用 `食谱设计`。普通登录用户点击后进入 `/pages/recipe-designer/list`。

未登录用户点击入口时跳转登录页。没有狗狗档案的登录用户可以进入列表页，但空状态和新建流程都优先引导创建狗狗档案。

### 普通用户列表页

普通用户列表页标题调整为 `我的食谱设计`。

页面结构：

1. 顶部标题区：展示 `我的食谱设计` 和简短副标题 `为爱犬保存草稿、继续调整或进入订购`。
2. 狗狗筛选区：横向展示 `全部` 和用户的狗狗 chip。
3. 主操作按钮：`新建食谱`。
4. 食谱卡片列表：展示用户自己的设计草稿和已生成的私有食谱快照。

普通用户卡片展示：

- 食谱名称。
- 关联狗狗名称。
- 系统采用的生命阶段文案，例如 `普通成年犬（110ME）`。
- 设计状态：`草稿`、`营养达标`、`需继续调整`、`可订购`。
- 最近编辑时间。
- 主要操作：`继续编辑`。
- 达到可用条件后展示快捷操作：`订购成品`、`生成 DIY`。

普通用户列表隐藏：

- 五个生命阶段行。
- 系列已发布数量。
- 管理员状态筛选。
- 补剂库入口。
- `复制整个系列` 和 `复制此生命阶段`。
- `发布`、`后台草稿`、`审核` 等内部工作台文案。

管理员/员工进入同一路由时继续看到现有食谱系列列表和五阶段状态。

### 新建食谱流程

点击 `新建食谱` 后打开底部面板或独立轻流程。

步骤一：选择狗狗

- 展示当前用户狗狗列表。
- 每只狗展示名称、年龄/阶段、体重。
- 若没有狗狗档案，展示 `创建狗狗档案` 按钮，并说明创建后可自动判断生命阶段。

步骤二：确认生命阶段

- 用户选择狗狗后，系统根据狗狗生日、品种成年月龄、老年月龄、生命阶段覆盖值和活动水平推导业务生命阶段。
- 推导结果映射到设计器 FEDIAF 犬场景：
  - `PUPPY_UNDER_14_WEEKS` -> `EARLY_GROWTH_REPRODUCTION`
  - `PUPPY_14_WEEKS_PLUS` -> `LATE_GROWTH`
  - `LOW_ACTIVITY_ADULT_OR_SENIOR` -> `ADULT_MER_95`
  - `HIGH_ACTIVITY_ADULT` -> `ADULT_MER_110`
  - `REPRODUCTION` -> `REPRODUCTION`
- 默认展示用户友好的文案，例如 `Star 当前适用：普通成年犬（110ME）`。
- 提供 `修改` 入口，用户可手动选择其他阶段。
- 手动修正后记录该草稿的设计场景，不自动改写狗狗档案。

步骤三：命名食谱

- 输入框标题为 `食谱名称`。
- 默认名称：`{狗狗名} 的鲜食食谱 {MM/DD}`。
- 用户可编辑。
- 名称为空时禁止开始设计。

确认后调用创建接口，创建带狗狗上下文和场景的设计系列/草稿，并跳转编辑器。

### 编辑器上下文

普通用户进入编辑器时，顶部上下文从“系列 + 生命阶段”调整为用户语义：

- 第一行：食谱名称。
- 第二行：`为 {狗狗名} 设计 · {生命阶段文案}`。

编辑器继续保留：

- 原料列表。
- 克数编辑。
- 添加原料。
- 营养评估。
- 自动保存。
- 撤回/前进。

普通用户编辑器隐藏：

- 补剂库入口。
- 发布到后台草稿入口。
- 管理员审核入口。
- 从公开正式版恢复相关文案。

当评估结果达到“可用”条件后，页面底部或评估页展示下一步动作区。

### 完成后动作

完成后动作区展示三项：

1. `订购成品`
   - 生成或更新私有可用食谱快照。
   - 跳转 `/pages/recipe-order/index?recipeId={privateRecipeId}&dogId={dogId}`。
   - 订购页使用现有狗狗档案计算每日饭量、分装和最低订购量。

2. `生成 DIY 制作单`
   - 生成或更新私有可用食谱快照。
   - 跳转 `/pages/recipe-diy/index?recipeId={privateRecipeId}&dogId={dogId}`。
   - DIY 页继续使用现有狗狗选择、饭量计算、周期配置和制作单生成能力。

3. `仅保存`
   - 返回 `我的食谱设计` 列表。
   - 列表卡片保留草稿状态和最近编辑时间。

如果草稿尚未达到可用条件：

- `订购成品` 和 `生成 DIY 制作单` 禁用。
- 文案展示关键原因，例如 `当前还有 3 项营养指标需调整后才能进入订购`。
- 用户仍可 `仅保存`。

### 可用条件

第一期中，普通用户草稿必须同时满足以下条件，才能生成私有可用食谱快照并进入订购或 DIY：

1. 草稿属于当前用户，并绑定了当前用户的狗狗档案。
2. 草稿至少包含一个纳入评估的原料。
3. 总重量大于 0，且能量密度大于 0。
4. 所有纳入评估的原料都有可用于计算的营养档案。
5. 当前 FEDIAF 评估结果为达标，即 `isCompliant = true`。
6. 当前评估不存在阻断型缺失数据报告。

如果后续业务希望允许“未完全达标但可人工确认”的配方进入私有订购，必须另行设计营养师审核或用户风险确认流程。本期不开放该例外。

## 数据与架构设计

### 普通用户设计资产

普通用户仍复用 `RecipeSeries` 和 `DesignRecipe` 作为设计草稿底座，但需要增加狗狗上下文。

建议新增字段：

- `RecipeSeries.customerDogId`：普通用户设计系列绑定的狗狗 ID，管理员通用系列为空。
- `DesignRecipe.customerDogId`：草稿绑定的狗狗 ID，创建阶段草稿时从系列继承。
- `Recipe.customerOwnerId`：私有可用食谱快照的拥有者用户 ID，公开食谱为空。
- `Recipe.customerDogId`：私有可用食谱快照绑定的狗狗 ID，公开食谱为空。
- `Recipe.sourceDesignRecipeId`：私有快照来源设计草稿 ID，用于重复生成时更新同一来源快照。

字段命名可在实现时按后端命名规范转换为 snake_case 数据库列。

### 私有可用食谱快照

`DesignRecipe` 是编辑态草稿，现有订购/DIY 页面读取的是 `Recipe`。为避免大改订购/DIY 页面，普通用户点击 `订购成品` 或 `生成 DIY` 前，后端将当前设计草稿转换为私有 `Recipe` 快照。

快照规则：

- `Recipe.status = PRIVATE_CUSTOM`。
- `Recipe.isCustomRecipe = true`。
- `Recipe.customerOwnerId = 当前用户 ID`。
- `Recipe.customerDogId = 草稿绑定狗狗 ID`。
- `Recipe.seriesId` 和 `Recipe.seriesLifeStage` 继承设计草稿上下文。
- `Recipe.applicableLifeStages` 写入与当前 FEDIAF 场景对应的业务生命阶段。
- `Recipe.items` 从 `DesignRecipeItem` 转换而来。
- `Recipe.nutritionDetailedData`、`energyDensityKcalPerKg`、`nutritionStandard` 使用草稿当前评估结果。
- 同一 `sourceDesignRecipeId` 重复生成时更新或新建版本，避免每次点击产生不可控重复资产。

访问规则：

- 普通用户只能读取自己的 `PRIVATE_CUSTOM` 食谱快照。
- 员工/管理员可读取用于客服、生产和问题排查。
- 公开食谱橱窗、公开推荐、收藏列表默认不返回普通用户私有快照。
- 订购页和 DIY 页允许读取当前用户自己的 `PRIVATE_CUSTOM` 快照。

### 生命阶段推导

前端可复用 `miniapp/src/utils/life-stage-match.ts` 的 `resolveDogRecipeLifeStage` 逻辑展示推导结果。后端创建草稿时必须再次计算或校验，后端结果作为最终写入值，避免前端被篡改。

设计器使用的 FEDIAF 犬场景仍是：

- `EARLY_GROWTH_REPRODUCTION`
- `LATE_GROWTH`
- `ADULT_MER_95`
- `ADULT_MER_110`
- `REPRODUCTION`

狗狗档案推导出的业务生命阶段和 FEDIAF 犬场景之间使用固定映射，不让普通用户直接面对枚举名。

### 狗狗成长后的处理

草稿和私有快照记录的是创建/设计时采用的 FEDIAF 场景，不会因为狗狗生日变化自动改写。

列表页加载时可以根据当前狗狗档案重新推导当前推荐阶段。如果当前推荐阶段和草稿设计阶段不一致，卡片展示提醒：

`Star 当前阶段已变化，建议新建当前阶段食谱`

第一期不自动迁移旧草稿，避免无声改变营养标准。

## API 设计

### 列表

`GET /recipe-designer/series`

普通用户返回自己的用户模式卡片。响应中增加：

- `customerDogId`
- `customerDogName`
- `scenario`
- `scenarioLabel`
- `primaryDraftId`
- `privateRecipeId`
- `customerStatus`
- `actionAvailability`

管理员/员工响应可继续保留现有系列和 `stages` 结构。

### 创建

`POST /recipe-designer/series`

普通用户请求体：

- `name`
- `dogId`
- `scenario` 可选，用于用户手动修正

后端行为：

1. 校验狗狗属于当前用户。
2. 根据狗狗推导默认场景。
3. 如果请求带 `scenario`，校验它在允许范围内并记录为用户选择。
4. 创建 `RecipeSeries`、初始 `DesignRecipe`，写入 `customerDogId`。
5. 返回 `initialDraftId`。

管理员/员工仍可按原有 `name + scenario` 创建通用系列。

### 生成私有快照

新增：

`POST /recipe-designer/drafts/:draftId/private-recipe-snapshot`

请求体：

- `target`: `ORDER` 或 `DIY`

后端行为：

1. 校验草稿属于当前用户。
2. 校验草稿绑定了 `customerDogId`。
3. 校验草稿满足可用条件。
4. 创建或更新私有 `Recipe` 快照。
5. 返回 `recipeId`、`dogId`、`targetUrl`。

### 私有快照读取

`GET /recipes/:id`

新增允许：

- `Recipe.status = PRIVATE_CUSTOM`
- 当前用户 ID 等于 `customerOwnerId`

公开查询仍默认排除 `PRIVATE_CUSTOM`，除非明确按 ID 读取且权限通过。

## 错误处理

1. 没有狗狗档案：新建面板展示创建档案入口，不允许创建无狗狗上下文的普通用户食谱。
2. 狗狗不属于当前用户：后端返回 404 或 403，前端提示 `未找到可用狗狗档案`。
3. 生命阶段无法推导：提示用户检查狗狗生日、品种和生命阶段信息，并允许手动选择阶段。
4. 食谱名称为空：前端阻止提交并提示 `请输入食谱名称`。
5. 草稿未达可用条件：禁用订购/DIY动作，并展示最主要的营养差距。
6. 私有快照生成失败：保留草稿，提示 `食谱已保存，但暂时无法进入下一步`。
7. 订购/DIY读取私有快照无权限：提示 `食谱不存在或无权访问`。

## 测试计划

### 后端

1. 普通用户创建设计系列时必须传入属于自己的 `dogId`。
2. 普通用户不能用他人的狗狗创建设计系列。
3. 后端能从狗狗档案推导默认 FEDIAF 犬场景。
4. 用户手动传入合法 `scenario` 时可覆盖默认推导，但不修改狗狗档案。
5. 普通用户 `listSeries` 只返回自己的系列，并包含狗狗上下文字段。
6. 管理员/员工 `listSeries` 继续返回五阶段系列结构。
7. 私有快照接口只能处理当前用户自己的草稿。
8. 未达可用条件的草稿不能生成私有快照。
9. 私有快照生成后 `GET /recipes/:id` 对拥有者可读，对其他普通用户不可读。
10. 公开食谱列表和推荐接口不返回普通用户私有快照。

### 小程序

1. 普通用户列表页标题为 `我的食谱设计`，不展示五个生命阶段行。
2. 员工/管理员列表页仍展示五阶段系列结构。
3. 新建面板先展示狗狗选择，再展示推导阶段和食谱命名。
4. 无狗狗档案时展示创建档案引导。
5. 默认食谱名包含狗狗名和日期。
6. 选择狗狗后展示正确的生命阶段文案。
7. 普通用户编辑器顶部展示狗狗上下文。
8. 达到可用条件后展示 `订购成品`、`生成 DIY 制作单`、`仅保存`。
9. 点击 `订购成品` 跳转订购页并携带 `recipeId` 和 `dogId`。
10. 点击 `生成 DIY 制作单` 跳转 DIY 配置页并携带 `recipeId` 和 `dogId`。
11. 未达可用条件时订购/DIY按钮禁用并展示原因。

## 分期建议

第一期：

- 普通用户列表改为狗狗优先卡片。
- 新建流程改为选择狗狗、确认阶段、命名。
- 新增狗狗上下文字段。
- 编辑器展示狗狗上下文。
- 实现私有快照生成接口。
- 打通订购和 DIY 跳转。
