# Web 管理后台食谱列表多生命阶段发布设计

## 背景

当前 Web 管理后台食谱列表页按食谱系列展示，每个系列只有一个发布按钮。小程序食谱编辑器把某个生命阶段提交到后台后，会在正式食谱列表里形成待发布的 DRAFT 阶段版本。现有列表聚合只暴露整个系列里的一个待发布版本，因此当同一系列有多个生命阶段待发布时，运营只能先发布其中一个，再刷新后继续处理下一个。

## 目标

1. 食谱列表页每个食谱系列仍只保留一个发布按钮。
2. 点击发布按钮后，在该按钮位置附近展开小浮层，而不是打开页面中央弹窗。
3. 小浮层列出该系列下所有待发布生命阶段。
4. 运营可以发布勾选的生命阶段，也可以一键发布全部待发布生命阶段。
5. 发布成功或失败后，列表状态要清晰刷新和提示。

## 非目标

1. 不改变小程序食谱编辑器的提交流程。
2. 不重新设计食谱列表页整体布局。
3. 不新增数据库字段或迁移。
4. 不在本次改动中重做食谱设计器发布逻辑。
5. 不把每个生命阶段拆成列表中的独立发布按钮。

## 推荐方案

采用前端小浮层选择 + 复用现有单个发布接口的方案。

后端列表接口补充每个生命阶段的待发布版本信息。Web 列表页仍展示一个发布按钮。点击按钮后，使用贴近按钮的小浮层展示待发布生命阶段，默认全选。用户可以取消部分阶段后发布所选，也可以直接一键发布全部。

发布执行时，前端按待发布阶段逐个调用现有发布接口。这样可以满足业务诉求，同时避免新增重型批量发布接口。

## 用户流程

1. 运营进入 Web 管理后台食谱列表页。
2. 某个食谱系列存在至少一个待发布生命阶段时，该行显示一个发布按钮。
3. 运营点击发布按钮。
4. 发布按钮旁展开小浮层，展示待发布阶段列表。
5. 小浮层内的待发布阶段默认全部勾选。
6. 运营可以取消不想发布的阶段。
7. 点击“发布所选”后，系统依次发布已勾选阶段。
8. 点击“一键发布全部”后，系统忽略当前勾选状态，发布该系列所有待发布阶段。
9. 发布完成后刷新列表。
10. 如果部分阶段失败，提示失败阶段名称，并保留列表刷新后的真实状态。

## 数据设计

现有正式食谱版本已经包含系列和生命阶段信息：

- `seriesId`：所属食谱系列
- `seriesLifeStage`：所属生命阶段
- `status`：正式食谱版本状态，DRAFT 表示待发布，PUBLIC 表示已发布

列表接口需要在系列阶段摘要中补充待发布版本信息。每个生命阶段摘要至少包含：

- 生命阶段标识
- 生命阶段名称
- 阶段状态
- 当前可操作食谱版本 id
- 待发布食谱版本 id
- 版本号
- 更新时间

前端以“待发布食谱版本 id”判断该阶段能否出现在发布小浮层中。

## 界面行为

发布按钮仍位于表格操作列中原有位置。

按钮行为：

- 没有待发布阶段时，不显示发布按钮。
- 有待发布阶段时，显示一个发布按钮。
- 点击后在按钮附近展开小浮层。
- 小浮层不遮挡整页，也不使用居中确认框。

小浮层内容：

- 标题：选择要发布的生命阶段
- 阶段复选列表
- 每个阶段展示生命阶段名称和版本号
- 操作按钮：发布所选、一键发布全部

加载状态：

- 发布过程中禁用小浮层内按钮。
- 发布按钮可显示加载状态，防止重复点击。
- 发布完成后关闭小浮层并刷新列表。

## 后端行为

后端继续保留现有单个食谱发布接口。列表接口只增强返回数据，确保前端能拿到同一系列下所有待发布阶段。

发布接口保持原有状态校验：

- 只能发布 DRAFT 版本。
- 发布后版本状态变为 PUBLIC。
- 发布后同步系列业务状态。
- 如果请求的版本已不是 DRAFT，返回业务错误。

## 错误处理

发布多个阶段时可能出现部分成功、部分失败。

前端处理规则：

- 每个阶段独立发布。
- 成功阶段不回滚。
- 失败阶段收集阶段名称和错误原因。
- 全部成功时提示发布成功。
- 部分失败时提示“部分发布失败”，并列出失败阶段。
- 无论成功或部分失败，最后都刷新列表，展示真实状态。

## 测试范围

后端测试：

- 系列列表返回所有待发布生命阶段，而不是只返回一个待发布版本。
- 每个待发布阶段包含可发布版本 id。
- 已发布阶段不出现在待发布列表中。

前端测试：

- 有多个待发布阶段时，列表只显示一个发布按钮。
- 点击发布按钮后，小浮层在按钮附近展开。
- 小浮层默认勾选所有待发布阶段。
- 发布所选只发布被勾选阶段。
- 一键发布全部发布所有待发布阶段。
- 部分失败时展示失败阶段并刷新列表。

## 验收标准

1. 同一食谱系列有多个生命阶段待发布时，列表页仍只显示一个发布按钮。
2. 点击发布按钮后，选择层从该按钮位置附近弹出。
3. 可以只发布勾选的待发布生命阶段。
4. 可以一键发布全部待发布生命阶段。
5. 发布完成后，生命阶段状态与后端真实状态一致。
6. 发布失败时，运营能看到具体失败的生命阶段。
