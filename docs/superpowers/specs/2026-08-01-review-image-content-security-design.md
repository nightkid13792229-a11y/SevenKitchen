# 食谱评价图片内容安全校验设计

## 目标

在现有评价文字微信审核的基础上，阻止违规评价图片进入公开访问地址和评价记录，并提供文字、图片统一的复审测试路径。

## 方案

文字继续使用微信 `msg_sec_check`。图片使用腾讯云 COS 的图片审核能力：服务端先把文件放入只用于审核的临时对象，调用 COS 审核；仅在审核通过后复制到 `review-photos` 公开目录并返回图片地址。

微信异步图片审核需要接入结果回调、审核中状态和延后发布，改造范围更大，因此本次不采用。

## 发布流程

1. 用户选择图片后，小程序调用既有评价图片上传接口。
2. 后端校验文件类型与大小，上传至 COS 临时审核目录。
3. 后端请求 COS 图片审核。
4. 审核通过：复制到公开评价目录，删除临时对象，返回公开 URL。
5. 审核不通过：删除临时对象，返回“图片含违规或不适宜信息，请更换后重试”。
6. COS 上传、审核或清理失败：返回“图片安全验证暂不可用，请稍后重试”，不返回公开 URL。

## 边界与配置

- 审核覆盖 `POST /reviews/upload-photos`，因此任何评价图片都必须经过该流程。
- COS Bucket 必须启用 CI 图片审核；生产环境继续使用既有 COS 凭据。
- 现有已公开的历史评价图片不做回溯扫描，本次只约束新上传图片。

## 测试与复审

- 自动化测试覆盖：审核通过时才获得公开 URL；审核拒绝或异常时不会返回 URL，并清理临时对象。
- 真机验收覆盖：正常文字、违规文字、正常图片、违规图片四种样例。
- 复审演示中，任一违规内容均提示用户修改，并且评价列表没有新增记录或图片。
