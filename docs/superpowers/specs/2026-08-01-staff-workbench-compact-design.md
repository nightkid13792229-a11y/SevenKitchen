# 小程序员工工作台紧凑化设计

**日期：** 2026-08-01  
**范围：** `miniapp/src/pages/staff-workbench/index.vue`、订单页售后入口及工作台静态图标

## 目标

将员工工作台从九张纵向功能卡片改为更紧凑、可持续扩展的九宫格首页。员工进入后先获得当天的工作量概览，再以较少滚动找到业务入口；不按业务分组，不保留“管理员工作台 / 欢迎语”Banner。

## 首页信息架构

1. 顶部直接展示“今日概览”，取消现有紫色欢迎 Banner、角色文案和昵称。
2. 概览保留三个实时指标：今日订单、待处理、待发货。数据继续来自 `/staff/workbench/summary`。
3. 概览下展示无分组标题的三列九宫格。入口固定为：采购管理、生产管理、订单管理、客户与狗狗、库存管理、食谱管理、报销管理、食谱设计器。
4. 入口顺序以一线履约流程优先：采购、生产、订单位于首行；客户、库存、食谱居中；经营与设计工具位于后续位置。
5. 后续新增模块只在末尾追加格子，网格自动换行；不新增第二层分组或“更多”抽屉。
6. 采购、生产、订单、库存、报销保留现有待处理角标。角标仅表示数量；无待办时不显示。退款不再单列角标：管理员的待审核退款数合并计入“订单管理”角标。

## 退款与订单合并

工作台移除“退款管理”入口。退款仍是管理员专属、高风险操作，但其入口并入订单管理：

1. 订单页已有 `AFTERSALE`（售后中）状态筛选，作为退款审核的统一入口。
2. 管理员在该筛选中看到“退款待审核”数量和对应订单；普通员工不显示审核动作。
3. 审核操作继续调用既有退款审核接口，保留退款理由、凭证、二次确认、审核人记录与微信原路退款流程。
4. 已有订单详情中的管理员“退款/退差价”能力不受影响。
5. 现有独立退款页可在迁移完成并通过回归验证后删除页面注册与入口；不改动后端退款领域逻辑。

## 图标系统

工作台不再使用 emoji。全部入口使用本地 PNG 资源，原因是微信真机渲染一致、无需网络请求，并与项目现有静态资源方式一致。

- 复用：`purchasing.png`、`production.png`、`orders.png`、`inventory.png`、`recipes.png`、`reimbursement.png`。
- 新增：`customers.png`（客户与狗狗）、`recipe-designer.png`（食谱设计器）。
- 存放目录：`miniapp/src/static/ui-icons/`。
- 规格：透明背景、64×64 PNG、单色深绿线性图标、统一约 2px 视觉线宽；页面通过 CSS 提供低饱和圆角底色，不把颜色烘焙进图标。
- 红色只用于待办角标，避免成为每个图标的色彩。

## 组件和状态

页面保留现有权限检查和 `loadStats` 数据加载方式。模板将由一个入口配置数组驱动，配置包含标题、静态图标、跳转函数、可选 badge key、管理员可见条件，以避免继续复制粘贴八个入口模板。管理员专属退款入口将被删除；后端摘要将管理员的待审核退款数合并至 `badges.orders`，并继续只计入 `pendingTasks` 一次。

如果概览请求失败，现有静默失败行为保持：页面仍显示静态入口，指标以 `0` 回退；不阻止员工进入功能页。

## 验证

1. 为工作台添加/更新回归测试：验证无欢迎 Banner、九宫格入口、图标路径、退款入口已移除、管理员与员工的可见性。
2. 验证工作台摘要：管理员的退款待审核数合并计入订单 badge 和首页“待处理”一次；员工不看到退款数量。
3. 为订单页补充回归测试：售后中筛选可定位退款待审核订单，审核操作仍仅管理员可用。
4. 运行小程序相关 Vitest 测试与微信小程序构建，检查静态 PNG 都被打包。

## 非目标

- 不重做采购、生产、库存、食谱或订单详情页的业务流程。
- 不改变后端退款审核、微信支付退款或审计记录的数据模型。
- 不为工作台引入在线图标服务或第三方字体文件。
