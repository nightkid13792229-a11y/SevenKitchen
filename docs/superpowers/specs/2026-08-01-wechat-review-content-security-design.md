# 微信评价内容安全校验设计

## 目标

满足微信小程序对用户生成内容的审核要求：用户提交食谱评价前，服务端调用微信文本内容安全接口；风险内容不保存，并向用户显示可理解的修改提示。

## 范围

- 覆盖客户和后台创建食谱评价时的文字内容。
- 复用现有 `WechatService` 的小程序凭据和 `access_token` 缓存。
- 不在小程序端保存或调用小程序密钥。
- 本次不改变图片上传的存储策略。图片审核需要将现有“直接公开上传”的流程改为私有暂存、审核后发布，作为独立后续改动处理。

## 方案选择

采用在 `WechatService` 中封装微信 `msg_sec_check` 调用，并由评价控制器在任何写入前调用。

备选方案是仅在前端做关键词拦截，不能证明接入了平台内容安全接口；另一备选是审核接口错误时仍放行，会形成未校验内容，均不采用。

## 数据流与错误处理

1. 客户端提交评价文字。
2. 后端取得当前用户的 `openid`，调用微信内容安全接口。
3. 微信判定风险时，后端返回“发布失败：内容含违规或不适宜信息，请修改后重试”，且不写入评价。
4. 微信正常通过时，继续既有资格校验和数据库写入。
5. 微信接口不可用或响应异常时，生产环境拒绝本次发布并记录错误；本地微信模拟模式返回通过，保证本地和自动化测试可用。

## 测试

- 微信服务：验证请求地址、请求体、风险结果和异常结果。
- 评价接口：验证风险内容不会调用数据库创建；正常内容仍可创建。
- 执行现有微信服务和评价控制器相关测试。

## 复审证据

复审时演示：普通评价可提交；使用平台测试违规文本时，页面显示违规提示且评价列表没有新增记录。部署环境必须配置有效的 `WECHAT_APP_ID` 与 `WECHAT_APP_SECRET`。
