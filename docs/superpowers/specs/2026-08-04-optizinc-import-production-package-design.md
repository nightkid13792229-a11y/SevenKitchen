# L-OptiZinc 标准原料导入包设计

## 目标

将已审核的 NOW Foods L-OptiZinc 30mg 补剂资料作为可审查、可回滚的标准原料生产导入包提交；同时修复生产 SQL 导出器对 Prisma Decimal 数值的序列化，避免数值被写成 JSON 字符串字面量。

## 范围

- 纳入 L-OptiZinc 的原料清单、对齐审计、本地写入审计及生产导入包（含 `up.sql`、`down.sql`、审计与评审文件）。
- 纳入 Decimal-like 值以 SQL 数值输出的实现与回归测试。
- 不纳入食谱设计内容修订 migration，也不纳入食谱系列分页索引 migration；二者属于独立业务变更。

## 方案比较

1. 将所有当前未提交内容合并到一个 PR：实现最快，但会混合补剂导入和无关 schema 变更，回滚与审核风险较高。
2. 只提交导入产物、不修复导出器：范围小，但生成的生产 SQL 可能把 Decimal 价格字段错误地变成字符串。
3. 推荐：导入产物与其必要导出器修复进入同一 PR，独立的 migrations 保持分离。该边界与业务依赖一致，并保留导入包的可回滚性。

## 架构与数据流

`ingredient.manifest.json` 记录包装标签来源、每粒营养值和操作者确认。导入流程产生本地审计记录；生产包生成器依据该审计收集有限范围内的数据，生成确定性的 SQL 和评审材料。`sqlLiteral` 在遇到 Decimal-like 对象时调用 `toJSON()`，将有限数值写成未加引号的 SQL 数值，否则写为 `NULL`。

## 错误处理

- `toJSON()` 的结果为空、非数值或无穷大时，不输出可疑数值，改为 `NULL`。
- 补剂导入包不包含采购 SKU，且评审摘要应保留补剂证据状态。
- `down.sql` 保持按依赖反序删除，使导入包可以回滚。

## 验证

- 添加/保留导出器测试：Decimal-like 的 `"0"` 序列化为 SQL 数值而非 JSON 字符串。
- 运行生产导入包单元测试。
- 检查生产包 SQL、审计文件和 manifest 在同一限定目录内，且未包含无关 migration。
