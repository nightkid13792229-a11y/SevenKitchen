# 代客定制食谱订单设计

**日期：** 2026-10-21  
**状态：** 业务方向已确认；页面与上线细节待确认  
**范围：** 自助下单 + 员工代客下单（有账号/无账号）从下单到设计、交付、售后

## 1. 业务事实

- 顾客可以自己在小程序下单并微信支付。
- 老板/客服也会帮助微信或企业微信咨询的顾客下单。
- 代客顾客的钱由老板通过微信/支付宝线下收取，不走小程序微信支付。
- 部分代客顾客有小程序账号和狗狗档案；部分没有。
- 目前没有账号的顾客，老板用自己的账号创建狗狗档案并下单。
- 代客顾客的食谱通过微信/企业微信发送。

## 2. 目标

1. 自助单和代客单共用同一套订单、设计、交付、售后流程。
2. 不用老板个人账号代替顾客建档，避免狗狗归属、售后、统计混乱。
3. 代客单能记录线下收款方式、金额、操作人和外部流水。
4. 没有账号的顾客也能拿到可阅读的食谱/制作单。
5. 顾客以后注册小程序时，可以认领代客客户档案和订单。

## 3. 非目标

- 不接支付宝自动支付/自动退款；支付宝只做线下收款登记。
- 不把代客单变成另一套订单表或另一套状态机。
- 本次不重建设计器；设计器仍按现有流程设计 N 份。
- 不做代客顾客自动登录；无账号顾客仍由员工服务。
- 不做历史订单认领：无账号顾客以后注册小程序，不自动/手工认领旧订单。

## 4. 核心决策

### 4.1 一套订单，两个入口

`CustomRecipeOrder` 增加：

- `orderSource`：`SELF` / `ASSISTED`；默认 `SELF`。
- `createdByStaffId`：代客单的操作人（员工/管理员用户 id）。
- `paymentChannel`：`WECHAT_ONLINE` / `OFFLINE_WECHAT` / `OFFLINE_ALIPAY` / `OTHER`。
- `externalPaymentRef`：线下微信/支付宝流水号或备注。
- `actualPaidAmount`：实际收到的金额；用于线下对账。
- `externalPaymentRef`：线下流水号，**可选**，不要求每单都录。
- `priceOverrideReason`：实际收款与系统报价不同时，管理员必须填写的原因。
- `assistedForGuest`：是否为无账号代客客户下的单。

订单状态、报价、设计、交付、售后仍共用现有 `CustomRecipeOrder` / `CustomRecipeDeliveryBatch` / `CustomRecipeAftersale`。

### 4.2 代客客户是独立用户，不挂在老板账号下

给 `User` 增加：

- `isGuest`：是否为代客客户；默认 `false`。
- `guestContactName`：代客联系人姓名。
- `guestContactPhone`：代客联系电话。
- `guestContactWechat`：微信号/企微标识。
- `guestCreatedByStaffId`：谁建的代客客户。

代客客户：

- 没有 openid/password，不能自己登录；
- 可以拥有狗狗档案（`Dog.ownerId` 指向代客用户）；
- 可以拥有代客订单；
- 员工/管理员可在后台查看和维护。

不使用老板账号建狗。这样：

- 狗狗归属正确；
- 不同顾客的狗不混；
- 以后可把代客客户绑定到真实小程序账号。

### 4.3 线下收款

代客单有两种创建方式：

1. **已收款代客单**：创建订单时直接写 `PAID`、`paymentConfirmedAt`、`paymentChannel`、`externalPaymentRef`、`actualPaidAmount`。
2. **待收款代客单**：先建 `PENDING_PAYMENT`；后台确认收款后改为 `PAID`，同时写收款字段。无账号顾客不能自己在线支付。

线下收款金额允许与系统报价不同（管理员手动填写实际收款并记录原因）；订单的应收/退款以实际收款为准，报价快照仍保留系统报价。
线下流水号可选，不强制每单录入。

线下收款单：

- 不调用微信支付退款；
- 后台取消/退款走“线下退款登记”，记录退款方式、金额、操作人、时间；
- 只有 `WECHAT_ONLINE` 的自助单才走微信原路退款。

### 4.4 交付方式

- 有账号的代客顾客：订单出现在其小程序订单列表，可查看 N 份食谱、DIY 和售后。
- 无账号代客顾客：后台生成**只读交付分享链接**，通过微信/企微发送；链接需要短期 token，不能枚举订单。
- 分享页展示：
  - 本单 N 份食谱；
  - 每份的喂食、食材、营养；
  - 采购与制作单；
  - 售后联系方式。
- 分享链接**默认不自动过期**（交付内容归顾客所有），但必须可撤销、可重新生成；
- 链接使用高熵 token，不暴露其他订单和顾客信息，不被搜索引擎索引；
- 如链接外泄，管理员可撤销旧链接并生成新链接。

### 4.5 设计、交付、售后

与自助单完全一致：

- 后台设计器按狗设计 N 份；
- 后台一次性交付 N 份；
- 顾客确认收到；
- 后台按选中份重新交付；
- 售后按份选择。

代客单额外记录：

- 操作员工；
- 线下收款/退款；
- 分享链接发送记录。

## 5. 页面流程

### 5.1 顾客自助单

首页 → 食谱定制 → 确认订单 → 微信支付 → 后台设计 → 一次性交付 → 顾客看到 N 份 → DIY → 确认收到 → 按份售后 → 后台重新交付。

### 5.2 代客单（有账号）

后台订单中心 → 新增代客定制单 → 选择顾客/狗 → 填写需求 → 报价 → 记录线下收款 → 创建已付款单 → 设计器设计 N 份 → 一次性交付 → 顾客小程序查看 → 售后。

### 5.3 代客单（无账号）

后台订单中心 → 新增代客客户 → 新建狗狗档案 → 新增代客定制单 → 填写需求 → 报价 → 记录线下收款 → 设计 → 交付 → 生成分享链接 → 微信/企微发送 → 客服代客售后。

## 6. 验收标准

### 自助单

- 单份、2 份、5 份均能下单；
- 优惠与交期正确；
- 后台交付 N 份；
- 顾客看到 N 份、每份独立 DIY；
- 售后/重新交付/退款正常。

### 代客单（有账号）

- 后台能选顾客和狗；
- 能创建已收款单；
- 订单出现在顾客小程序；
- 设计/交付/售后正常。

### 代客单（无账号）

- 后台能建独立代客客户和狗；
- 不污染老板账号；
- 订单能创建、设计、交付；
- 分享链接可打开、可撤销；
- 线下退款有记录，不调用微信退款。

## 7. 已确认

1. 无账号顾客以后注册小程序，**不认领历史订单**。
2. 线下退款**仅管理员**操作。
3. 交付内容归顾客所有，分享链接**不设自动过期**；但必须可撤销/重新生成，并防止被枚举。
