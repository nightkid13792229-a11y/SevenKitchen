# AI 添加标准原料 · 第一步设计方案（输入与理解）

> 状态：待确认（2026-10-23）
> 背景：线上那版六站流程“AI 感太弱”，已隐藏入口，从头按步骤重做。
> 本文只覆盖**第一步**：一个输入框 + 类型选择 + AI 产出「理解卡」。

## 一、这一步要解决什么

用户只输入一个词（牛肉 / 红苋菜 / 锌 / 胆碱），系统要把它变成一份**可以确认的判断**，而不是让用户填表。

- 食材要判断：**部位、加工态、生熟、可食部**
- 补剂要判断：**化学形态、哪种形态对狗更合适、常见商品方向**

这一步**不查营养库、不写库、不生成营养档案**。它只产出判断。

## 二、入口形态

- 页面只有一个输入框 + 一个「开始」按钮。
- 输入框右侧一个下拉：**食材 / 补剂**。由用户选，不让 AI 猜——这个操作成本极低，猜错反而要来回改。
- 两条线主题色不同：食材绿、补剂紫；placeholder、示例词、说明文案都跟着变。
- 类型一旦选定，整个后续流程的配色与文案都沿用它。

## 三、AI 怎么配置

| 项 | 取值 |
|---|---|
| 调用方式 | 复用现有 `AgentProviderConfig`，新增用途 `INGREDIENT_INTAKE` |
| 模型 | **主模型 + 备模型链**：主模型（如 deepseek-v4-pro）失败/超时/限流时自动切备模型；至少配 2 个，来自不同服务商，避免一家挂了全停 |
| 温度 | 0.2（要稳定，不要创意） |
| 最大输出 | 约 1200 tokens |
| 超时 | 12 秒 |
| 失败重试 | 同模型重试 1 次 → 切换备模型 → 全链失败则**停止并明确报错** |
| 缓存 | 同 `type + text` 24 小时内命中缓存，不重复花钱 |
| 单次成本 | 每次输入 **1 次调用**，不做多轮对话 |

## 四、AI 的工作方式

一次调用、一次输出，**不做工具调用、不查库**。提示词分三层：

1. **角色与任务**：你是宠物鲜食配方师，正在把用户的一个词变成一份可确认的判断。
2. **硬约束**（写进提示词，逐条校验）：
   - 不输出任何营养数值（热量、蛋白、矿物质含量等）——这些必须来自数据库。
   - 不确定就列多个候选并说明理由，**不许编一个看起来合理的答案**。
   - 每个判断字段都带置信度：`high` / `medium` / `low`。置信度**不是让模型自己说了算**，见第七节。
   - 只输出 JSON，不输出解释性散文。
3. **任务差异**：食材与补剂是**两张不同的提示词**，输出结构也不同（见下）。

```json
  "searchTerms": ["zinc glycinate supplement", "zinc amino acid chelate"]

```

> `elementalFactor` 是化学事实（葡萄糖酸锌约 14.3% 是元素锌），第一步只负责把它列出来。
> **标签相关的提醒不放在第一步**——第一步还没有标签。等第二步读到商品标签时，再用这个系数去判断“标签写的是化合物还是元素”。

## 六点五、置信度怎么定（不靠模型自评）

模型自报的置信度不可靠（它经常“很自信地错”）。所以置信度由**确定性信号**算出，模型只提供候选：

| 级别 | 食材判定信号 | 补剂判定信号 |
|---|---|---|
| high | 名字与库中词条唯一且完全同名；部位无歧义（如“牛肝”） | 该补剂只有一种主流形态，或模型候选只有 1 个 |
| medium | 有 2–3 个合理候选；需要中译英；部位有多个常见选择 | 有 2–3 种形态且差异明确 |
| low | 候选 ≥4；存在易混词（牛肉 vs 牛腩）；库里同名多条 | 形态 ≥4 或模型自己给出的理由互相矛盾 |

实现上：模型输出候选与理由 → 规则打分（候选数、是否同名、是否有易混词、库匹配分布）→ 得出置信度。模型输出的 `confidence` 只作参考，不直接展示。

## 七、人的确认点

理解卡以「已填 + 可改」的形式呈现，只有低置信度的项会高亮：

| 类型 | 必须确认 | 高亮提示 |
|---|---|---|
| 食材 | 部位、生熟、可食部 | 部位是 `medium` 时默认展开候选 |
| 补剂 | 形态推荐 | 形态对比表默认展开，推荐项高亮 |

确认后进入第二步（检索词条 / 找商品）。**未确认不能往下走**，但可以一键接受全部默认。

## 八、降级与失败

**总原则（2026-10-23 老板定）：不做“规则版理解”兜底。AI 不可用就明确停下，不假装能理解。**

| 情况 | 行为 |
|---|---|
| 主模型失败 | 自动切备模型（可配多个），页面上不打扰用户 |
| 全链失败 / 都没配 | 停在第一步，明确显示“AI 当前不可用，无法继续”，提供重试；**不生成退化的理解卡** |
| 输出不是合法 JSON | 重试一次 → 切备模型 → 仍失败按“全链失败”处理 |
| 输出缺字段 | 缺的标 `null` 并降置信度，不补默认值假装成功 |
| 类型与内容明显不符（选了食材却输入“葡萄糖酸锌”） | 不自动改类型，提示一句“这看起来像补剂，要切换吗？” |

## 九、这一步不做什么

- 不查营养数据库、不联网找商品（那是第二步）。
- 不产出任何营养数值。
- 不创建草稿、不写库（确认后才创建）。
- 不替用户选部位/形态的最终答案——只给候选和推荐。

```ts
POST /admin/ingredient-creation/intake/preview

```

```ts
  body: { type; text; card }   // 卡片的最终值随草稿落库
```
