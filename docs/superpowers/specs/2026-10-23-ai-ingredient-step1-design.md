# AI 添加标准原料 · 第一步设计方案（输入守门）

> 状态：待确认（2026-10-23 修订）
> 这一版按老板的口径重写：**第一步只做一件事——判断输入够不够精确，能不能拿去数据库做精准搜索。**

## 一、这一步做什么、不做什么

**做**：你对 AI 说一个词（牛肉 / 牛肝 / 锌 / 葡萄糖酸锌），它回答一个问题：

> 这个说法，够不够精确到可以去营养库里搜出确定的词条？

- **够** → 放行，进入第二步（去本地库检索，列出待选词条）。
- **不够** → 拦下，说清楚差在哪、让你先改输入（给出可点的补全建议）。

**不做**：

- 不查营养库（那是第二步；第二步才知道库里到底有没有）
- 不判断营养数据完整度
- 不生成营养档案
- 不替用户改写输入（只给建议，改不改由你）

## 二、页面形态

一个**简易对话框**，跟 AI 助手一样：

- 输入框左侧一个类型选择：**食材 / 补剂**（由人选，不让 AI 猜），两条线主题色不同。
- 可以多轮：你说“牛肉”被拦，点建议或自己改成“牛后腿”，再发一次。
- 只有 `PASS` 的回复里出现「进入下一步」按钮。

## 三、判定标准（模型就按这张表判）

食材要同时满足：

1. **是单一食材**，不是菜名、不是品牌、不是泛称（“牛肉炖土豆”不行，“某牌牛肉”不行，“肉”更不行）
2. **部位明确**（有部位差异的食材必须指到部位：牛肉→里脊/后腿；鸡→胸/腿）
3. **加工态明确**（有加工态差异的必须说明：土豆→带皮/去皮/切片；米→生/熟）
4. 没有明显多义（“鱼”不是一种鱼；“内脏”不是一种内脏）

补剂要同时满足：

1. **是化学形态，不是元素名**（“锌”不行，“葡萄糖酸锌”可以）
2. **不是品类统称**（“鱼油”不行，要说清 EPA/DHA 或形态；“益生菌”不行，要说到菌株）

任一条不满足 → `NEED_REFINEMENT`，并给出 2–3 个**可直接点的补全建议**。

## 四、输出格式

```json
{ "verdict": "PASS", "reason": "部位明确、加工态默认生，可以精准匹配。", "suggestions": [] }
```

```json
{
  "verdict": "NEED_REFINEMENT",
  "reason": "「牛肉」没说明部位。库里会同时命中里脊、后腿、牛腩、牛腱等十几条。",
  "suggestions": ["牛里脊", "牛后腿", "牛腩"]
}
```

三个字段，够用。不加置信度——这是**是/否**判断，不是程度判断；判不准就归到 `NEED_REFINEMENT`，让你补一句，代价很小。

## 五、AI 怎么配置

| 项 | 取值 |
|---|---|
| 用途 | `INGREDIENT_INTAKE`（新增，复用现有 `AgentProviderConfig`） |
| 主模型 | DeepSeek（后台「原料营养治理 → Agent 设置」可改） |
| 备选模型 | **至少 2 个**，尽量不同服务商；主模型超时/报错/限流时按顺序切换 |
| 温度 | 0.2（同样输入给同样判断，不要发挥） |
| 超时 | 8 秒（这一步只是判断，不需要很久） |
| 重试 | 同模型 1 次 → 切备模型 → 全失败则明确报错 |
| 缓存 | 同 `type + text` 24 小时缓存，避免重复花钱 |
| 成本 | 每次输入 1 次调用 |

**不做规则兜底**（2026-10-23 老板定）：模型全挂就停在这一步，明确显示“AI 当前不可用”，不生成假的判断。

## 六、提示词要点

角色：宠物鲜食配方师，负责把用户说的原料名变成“能不能精准检索”的判断。

硬约束：

- 只回答这一个问题，不要顺带评价营养、不要推荐做法。
- 不要替用户改写输入，只给候选建议。
- 不要输出任何营养数值。
- 判断不了（生僻词）就判 `NEED_REFINEMENT`，在 reason 里说“这个词我不确定指什么”，不要硬猜 PASS。
- 只输出 JSON。

## 七、一个必须先对齐的边界

**第一步只判“说法够不够具体”，不判“库里有没有”。**

- 「兔肝」在语义上是精确的（部位明确），第一步应当放行；
- 但本地库没有兔肝词条，这是**第二步**才会发现的事；
- 反过来，「红苋菜」很具体，但库里未必有——同样交给第二步。

如果你希望第一步连“库里有没有”一起判，那它就得先查一次库，第一步和第二步就合并了。这一点需要你拍板。

## 八、与第二步的合同

```ts
POST /admin/ingredient-creation/intake/check
  body: { type: 'FOOD' | 'SUPPLEMENT'; text: string }
  resp: { verdict: 'PASS' | 'NEED_REFINEMENT'; reason: string; suggestions: string[] }

// 放行后
POST /admin/ingredient-creation/search
  body: { type; text }
  resp: { candidates: [...], excludedCount, coverage }
```

第二步只读最终确认的那句话，不再重新理解一次。
