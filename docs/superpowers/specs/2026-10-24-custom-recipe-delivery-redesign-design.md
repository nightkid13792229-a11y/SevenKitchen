# 定制食谱交付流程重构 · 设计定稿

> 日期：2026-10-24
> 范围：`miniapp/src/pages/custom-recipe/delivery.vue`、`delivery-shopping.vue`、`recipe-diy`、`diy-sheet`，以及后端的食谱版本解析与补剂解析
> 线框：`docs/prototypes/2026-10-24-delivery-wireframe.html`

---

## 一、为什么改

当前交付流程有三个结构性问题：

1. **同一份食材清单出现两次。** 交付第 2 页的“每种食材要用多少”把 3 样补剂也算成了食材，下面“额外补充的营养素”又列一遍；总净重因此把补剂也称了进去（1712.3 克，实际食材 1681.4 克）。
2. **“采购与制作”页与 DIY 配置页、DIY 制作单高度重复。** DIY 制作单已经有食材表（原料/推荐产品/制备方法/净用量/合计）、补剂表（名称/推荐产品/时机/总量）、步骤、设备推荐、保存图片、分享、购买预分装补剂。交付第 2 页等于把同一套东西又画了一遍，只是数字来自冻结快照。
3. **顾客不能自己决定做多少。** 交付时的“按 7 天配的”把营养师的建议写成了固定计划，顾客想按自己的喂食习惯调整、想一次多做或少做，都没有入口。

同时，客服入口在整个定制流程里只有 2 处能点（提交成功页、订单列表每张卡），订单详情、交付页、售后页都只有文字没有按钮；列表那个“联系客服”还不带订单号。

---

## 二、两条线要先分清

| | 定制食谱 | DIY 制作单 |
|---|---|---|
| 谁做的 | 营养师按这只狗设计（付费 ¥300） | 顾客按某道食谱生成 |
| 内容 | 配方组成、营养目标、喂食建议、营养评估 | 这一批要买多少、怎么处理、怎么做、怎么存 |
| 可否复用 | 只属于这一只狗/这一单 | 任何食谱都可以生成，可反复生成 |
| 名字 | **我的定制食谱** | **我的制作单** |

这次改名的目的就是让顾客一眼分清：**定制食谱是“给我的配方”，制作单是“我这次要做的量”。**

## 三、核心决策

| # | 决策 | 说明 |
|---|---|---|
| D1 | “我的专属食谱”改名“我的定制食谱” | 交付页标题、订单详情卡片、交付物标签、打印单、通知文案、订单列表占位文案同步 |
| D2 | 删除“采购与制作”页 | 底部按钮“开始采购与制作”改为进入 DIY 配置页；第 2 页整页删除 |
| D3 | 版本锁定 | 从交付页进入 DIY 时带 `orderId`，后端按**交付快照里的 recipeVersion** 取食谱；橱窗流程不带参数，行为不变 |
| D4 | 补剂锁营养目标，不锁产品/原料 | 配方锁“补什么、补多少、什么时候加”；买哪个品牌/原料、浓度多少、有没有货，实时解析 |
| D5 | 客服身份统一为“Seven爸爸” | 不再出现“客服”“营养师”这类机构称呼；一页最多一个入口 |
| D6 | 视觉最后做 | 内容与交互 → 结构 → 硬伤 → 视觉，避免视觉被内容变更推翻 |
| D7 | 成品鲜食入口写“订购成品” | 已确认可按定制配方生产；放在交付页**固定底栏**，与「自己做」「找 Seven爸爸」并列；制作单保留一条文字入口 |
| D8 | 补剂等价按“等价组”维护 | 组定义在**原料层**（营养素 + 形态/来源），一次定义、全库复用；配方默认继承，只有例外才逐条覆盖。组是可增删改的实体，分组依据必须引用权威文献并经营养师审核 |

## 四、两层模型（D4 的核心）

| 层 | 是否锁定 | 内容 | 数据来源 |
|---|---|---|---|
| 配方层 | **锁**（按交付版本） | 主食材组成、每 kg 营养目标、补剂添加时机、喂食建议、营养结论、制作步骤 | 交付快照 / 指定 recipeVersion |
| 商品层 | **不锁**（实时） | 用哪个原料/品牌/规格、有效成分浓度、价格、库存、购买链接 | 当前商品库 |

### 补剂解析规则

1. 配方只要求“每 kg 食物补 2192 mg 钙”，不要求“必须用鸡蛋壳粉”。
2. 生成制作单时，按目标从**当前可售且被认可**的原料里选一个，克数 = 目标 ÷ 该原料有效成分浓度。
3. 鸡蛋壳粉缺货 → 自动落到碳酸钙，克数重算；顾客看到的仍是“补钙 2192 mg/kg”。
4. 顾客可切换候选；候选列表实时，不读冻结快照。
5. 主食材**不适用**：牛霖换鸡胸不是等价替换，是另一份配方，必须重新交付。
6. 等价关系用**等价组**维护：组定义在原料层（营养素 + 形态/来源），一次定义、全库复用；不允许全库任意匹配——锌、碘等不同形态的吸收与耐受不同。
7. 浓度缺失或不可信的原料不参与换算；算不出来就显示“暂时买不到，找 Seven爸爸”。

### 三类变化的处理

| 变化 | 处理 |
|---|---|
| 同一补剂换品牌/规格/供应商、旧产品下架 | 实时生效，不重新交付 |
| 换补剂种类，或有效成分浓度变化 | 配方变了，**必须重新交付** |
| 某补剂当前完全买不到 | 制作单标“暂时买不到”，不给死链 |

### 维护成本：为什么不是逐食谱圈

真实数据（2026-10-24 本地库）：

- 58 条补剂行，只用到 **12 种**补剂原料；原料库里的补剂一共 **35 种**。
- 逐食谱圈：今天 58 条、每接一单还在增长；每换一次产品都要回改历史配方，运营成本随订单线性上涨。
- 等价组：35 种原料各归一次组；新产品入库时选一次组；换产品只改组的成员。**配方默认继承所选原料的组，只有例外才在配方里覆盖**（比如医嘱要求特定形态）。

组 taxonomy 举例（最终由营养师定稿，系统只执行）：

| 组 | 成员举例 | 可否互换 |
|---|---|---|
| 钙 · 矿物盐 | 碳酸钙、柠檬酸钙、鸡蛋壳粉 | 组内可换 |
| 钙 · 骨源 | 骨粉 | 不与矿物盐组换 |
| 锌 · 有机盐 | 葡萄糖酸锌 | 组内可换 |
| 锌 · 螯合 | L-OptiZinc | 不与有机盐组换 |
| 碘 · 天然 | 海藻粉 | 单独一组 |
| 碘 · 盐类 | 碘化钾 | 不与天然组换 |

**关键点：** 组不是“营养素”，是“营养素 + 形态/来源”。“同样含钙”不等于“可以互换”，边界由营养师定一次，系统只负责在组内替换。

### 分组要“扩大化”，不是只给现有 35 种原料打标签

组是一套**分类体系**，不是现有库存的清单。定义时按“营养素 × 形态”铺开，新人原料进来只要归组，不需要改代码：

- 钙：碳酸盐、有机酸盐（柠檬酸/乳酸/葡萄糖酸）、骨源、蛋壳源
- 锌：无机盐（硫酸锌/氧化锌）、有机盐（葡萄糖酸锌）、螯合（双甘氨酸锌）、酵母锌
- 碘：碘化物、碘酸盐、天然藻类
- 铁、铜、锰、硒、镁：无机盐 / 有机盐 / 螯合 / 酵母
- 维生素：A、D3、E、K、B 族
- 其他：Omega-3（EPA/DHA）、牛磺酸、胆碱、关节类（葡萄糖胺/软骨素）、益生菌、膳食纤维

这套体系要能**增、删、改**：

- 新增组：必须填营养素、形态、定义、分组依据、文献引用、审核人；
- 改名/改说明：随时可改，留审计记录；
- 停用：组内还有原料时只能停用，不能删除；
- 删除：只有组内无原料、且无历史配方引用时才允许（或软删除）。

### 分组依据必须可追溯

每个组存以下字段，缺一不可上线：

| 字段 | 说明 |
|---|---|
| 营养素规范 key | calcium / zinc / iodine…，中英别名先归一 |
| 形态类别 | 无机盐 / 有机盐 / 螯合 / 天然矿物 / 维生素 / 脂肪酸 / 氨基酸 / 其他 |
| 分组依据 | 一句话说明“为什么这几种可以互换” |
| 有效成分浓度 | 每种原料的 element 含量，用于克数换算 |
| 安全边界 | 上限、相互作用、禁忌（如钙影响锌吸收、骨粉含磷） |
| 文献引用 | 至少一条权威来源，记录标题/年份/链接或 DOI |
| 审核人 / 审核日期 / 状态 | 草稿 / 已审核 / 已停用；草稿不参与线上替换 |

**来源等级（从高到低）：**

1. NRC《Nutrient Requirements of Dogs and Cats》、FEDIAF 营养指南、AAFCO 官方出版物、EFSA FEEDAP 意见；
2. 同行评审的综述与随机对照试验（如钙盐吸收、锌形态生物利用度、藻类碘含量）；
3. 兽医营养学教材（如 Small Animal Clinical Nutrition）。

**不接受**：品牌商页面、博客、论坛、电商详情页。每条依据都要能点开原文；营养师签字后才从“草稿”变“已审核”。

参考起点（待营养师逐条核对）：

- FEDIAF Nutritional Guidelines 2024（犬猫营养基准）
- 钙盐吸收差异的随机对照试验（柠檬酸钙 vs 碳酸钙）
- 藻类碘含量与生物利用度综述（海藻粉与碘化钾不能默认等价）

> 系统不替营养师做“能不能换”的判断；系统只保证：没依据的组不能上线，上线后的每次替换都能追溯。

## 五、流程

### 5.1 定制食谱（新）

```
我的定制订单
  → 订单详情（卡片：你的定制食谱 / 查看完整内容）
  → 我的定制食谱（第 1 页）
      封面 · Seven爸爸的一句话 · 喂食建议 · 配方组成 · 补剂 · 核心营养 · 页脚
      固定底栏：[找 Seven爸爸] [自己做] [订购成品]（订购成品实心）
  → DIY 配置页（带业务 recipeId + dogId + orderId）
      选狗（已预选）· 确认每日饭量 · 选天数/分装 · 生成制作单
  → 我的制作单
      食材表 · 补剂表 · 步骤 · 存储 · 设备 · 保存/分享 · 购买预分装补剂
      文字入口：不想自己做？订购成品
```

**底栏定稿（2026-10-24）：**

- `[找 Seven爸爸]`：图标 + 小字，视觉最轻；
- `[自己做]`：描边次级，进 DIY 配置页；
- `[订购成品]`：实心主按钮，进成品订购页。

文案用“自己做”而不是“采购与制作”，与“订购成品”形成一组反义，顾客一眼知道两条路的区别；交付物标签仍叫“采购与制作单”，两者不冲突（一个是动作，一个是文档）。

三颗按钮总宽按 375pt 屏校过，字不挤。小屏若仍紧，退化为两行：上行客服文字入口，下行两个操作。

### 5.2 食谱橱窗（不变）

```
食谱详情 → 自己做 → DIY 配置页（不带 orderId）→ 制作单
```

**版本解析规则：**

- 带 `orderId`：校验该订单属于当前用户，从交付记录取 `recipeVersion`，按该版本取食谱；查不到就返回 404，**不回退最新版**。
- 不带 `orderId`：取最新版，与今天完全一致。
- 同一页所有取数（详情、制作单、生命阶段匹配）必须走同一版，不允许一半新一半旧。

### 5.3 喂食建议

- 第 1 页标题改“喂食建议”，只给“每天多少克、分几餐”，**不再写“按 X 天配的”**。
- 附一句“份量可以按你的习惯调整，点下面自己配”。
- DIY 配置页负责让顾客决定天数、每餐克数、分装方式。
- 营养师给的数字与 DIY 页计算出的数字若不一致，以页面上的“Seven爸爸建议”为准做默认值；实现细节在第二期处理。

## 六、数据现状与兼容

| 事实 | 数值 | 影响 |
|---|---|---|
| 补剂行有营养目标 | 58 / 58（定制 12 / 12） | 目标层已就绪，不需要补数据 |
| 补剂“替代”候选（逐食谱） | 0 条 | 不再依赖逐食谱维护；改用原料级等价组，等于把维护量从“58 条且增长”降到“35 种原料一次性分组” |
| 交付快照含 `targets` | 是 | 第 1 页可直接显示目标；新逻辑不需要改快照结构 |
| 旧交付快照含 `totalG`/`perKgG` | 是 | 老订单继续按冻结数字显示，不重算 |
| 营养目标 key 中英混用 | 是（钙/calcium、碘/iodine、锌/zinc） | 等价组必须用规范 key，P2 先做一次 key 归一 |

**兼容原则：**
- 老订单：页面结构统一换成新流程，但数字继续用老快照，不重算。
- 新订单：配方层按交付版本，商品层实时。
- 旧链接：`delivery-shopping` 目前没有被任何站外消息或分享引用，删除路由不会留下外部死链。

## 九、验收标准（业务口径）

1. 同一页不再出现两份食材/补剂清单；每一行用量都带单位。
2. 交付页底栏三件事都在、都可点：找 Seven爸爸、自己做、订购成品；只有一个实心主按钮。
3. 从交付页点“自己做”，落到 DIY 配置页，狗和食谱已预选，天数可改。
4. 橱窗进入 DIY 的流程与今天完全一致。
5. 营养师交付后改了配方，老交付的制作单仍按交付那一版生成。
6. 补剂缺货时能在**等价组内**自动替换并重算克数；跨组不自动替换；没有可用原料时给出“找 Seven爸爸”的出口。
7. 等价组能增删改；没有文献依据或未审核的组不能上线；每次替换能追溯到组与文献。
8. “订购成品”落到成品订购页并带上定制食谱与这只狗。
9. 视觉统一后，同一屏字号不超过 4 档、主操作唯一、间距有节奏。
