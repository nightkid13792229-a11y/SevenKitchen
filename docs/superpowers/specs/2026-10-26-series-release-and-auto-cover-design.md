# 产品线「发布 / 更新」与封面展示归属 · 设计

- 日期：2026-10-26
- 状态：已确认（老板 2026-10-26 批准）
- 说明：文件名沿用第一版（带 auto-cover 字样）；2026-10-26 老板确认 AI 自动封面移到下个阶段，本期正文已不含自动封面实现。
- 范围：`admin-web/`（食谱设计器列表、编辑器、发布抽屉、上线检查抽屉）、`backend/`（食谱设计器发布领域与接口）、`miniapp/`（首页/详情页的封面角标显示，一处小改）
- 不在本次范围：**AI 自动封面（下个阶段单独做）**、目标健康标签的筛选与推荐、订单定制发布流程、产品线 CRUD、详情描述/详情图/视频的归属

## 0. 一页话总结

1. **新建菜发布不需要勾生命阶段**：打开发布页，把当前已入库的阶段一次全发。
2. **已发布过的系列，入口从「发布」变成「更新」**：更新页里勾选这次要更新哪几个阶段；没改动的阶段显示「已是最新」，不参与。
3. **目标健康标签本期拿掉**：它和封面角标是两回事，留给以后的推荐/筛选项目。
4. **封面角标搬进系列发布设置**：系列级、合规词表、最多 2 个、选填。
5. **封面文字分场景**：小程序首页/详情页只显示角标，没选角标就不显示；定制食谱交付页显示的是食谱名和交付版本，不是角标，本次不动。
6. **AI 自动封面放到下个阶段**：本期不做；这份设计只解决发布流程和展示字段归属。

## 1. 这份设计要解决什么

老板在 2026-10-26 提出并确认了三件事：

1. 新建产品线食谱时，发布页不需要再勾「必做生命阶段」；已经发布过的系列，发布入口应改为「更新」，更新页才需要选择要更新的阶段。
2. 目标健康标签不是封面角标；本期从「上线检查」和「发布 / 更新」两个抽屉里拿掉，等做食谱推荐/筛选模板时再统一处理。
3. 封面角标是系列级的，应该放进「发布 / 更新」的发布设置；封面文字要分场景：
   - 小程序首页橱窗、食谱详情页的封面：只显示合规词表里的角标；没选角标就什么都不显示；
   - 定制食谱交付页的封面：显示食谱名、交付版本等信息，不显示系列封面角标，本次不动。

同时确认：**AI 自动生成封面放到下个阶段**，本期不做。这份设计不再包含生图、自动上传与相关接口。

## 2. 已确认的决定（老板 2026-10-26）

1. 新建菜发布：不勾生命阶段，全部已入库阶段一次发布。
2. 已发布系列：入口改「更新」，更新页里选择要更新的阶段。
3. 目标健康标签本期从两个抽屉拿掉，后续做推荐/筛选。
4. 角标放「发布 / 更新」的发布设置；小程序首页/详情页只显示角标，没选就不显示。
5. 定制交付页的封面标题/版本信息不动。
6. AI 自动封面下一阶段再做。

## 3. 目标 / 非目标 / 反目标

### 目标

1. 发布范围由数据现状决定，不再要求人重复勾选「哪些阶段必做」。
2. 首次发布：一次发完当前已入库（READY）的阶段；**只要有 1 个阶段就绪就能发，不要求 5 个齐全**；更新：只发勾选的有改动阶段。
3. 展示资料（封面图、封面角标、一句话卖点）只有一个维护入口——系列级的「发布 / 更新」；阶段抽屉里只读。
4. 封面角标可在设计器里维护，不再依赖旧的「编辑食谱」页。
5. 小程序首页/详情页的封面文字只来自合规角标，没配就不显示。
6. 发布抽屉能看到「顾客看到的样子」，避免盲填。

### 非目标

1. 不做 AI 自动生成封面（下个阶段）。
2. 不重做目标健康标签的数据模型、接口、AI 写入和筛选逻辑；本期只从后台界面与发布校验里移除。
3. 不强制「一道菜必须覆盖 5 个阶段」；覆盖情况只做提示。
4. 不改造订单定制（ORDER）的发布与展示资料流程；只从它的展示面板里移除目标健康标签。
5. 不处理「详情描述 / 详情图 / 视频」的归属（见第 10 节已知问题）。
6. 不改定制食谱交付页的封面标题/版本展示。

### 反目标（做了就算失败）

1. 保存展示资料时误改配方内容、营养数据或版本号。
2. 勾选更新 A 阶段，却把未勾选的 B 阶段新版本也发出去。
3. 用自由文本替代合规角标，重新引入违规宣传词风险。
4. 阶段抽屉和系列抽屉出现两个都能编辑的同一字段。
5. 小程序首页/详情页在没配角标时又回退显示封面标题，和老板确认的「没选就不显示」相反。

## 4. 现状与证据（为什么要改）

### 4.1 「阶段清单」勾选不是发布范围

- 勾选写入 `RecipeSeries.requiredLifeStages`，含义是「这些阶段必须就绪」，是**发布门槛**，不是发布范围。
- 真正的发布范围：`releaseSeries` 会取系列仓库里**每个阶段的最新一版**，不论是否勾选；抽屉底部的提示文案也明确写了「未勾选但已经保存进系列仓库的阶段也会一并发布」。
- 重新发布时，所有「有更新草稿」的阶段会一起发，无法只发其中一个。
- 因此：
  - 新建菜时，勾选只是把已设计好的阶段再声明一遍，没有可见作用；
  - 更新时，勾选又不能用来挑阶段，反而误导；
  - 它原本想防的「只做了一个阶段就上线」，靠勾选也防不住（不勾也能发）。

### 4.2 展示字段的归属是混的

| 字段 | 阶段草稿 `DesignRecipe` | 系列 `RecipeSeries` | 发布后 `Recipe` | 顾客能看到吗 |
|---|---|---|---|---|
| 封面图 `coverImageUrl` | 有 | 有 | 有 | 是（首页/详情页封面） |
| 封面标题 `coverTitle` | 有 | 有 | 有 | **2026-10-26 起不再用于小程序展示**（原因见下） |
| 一句话卖点 `sellingPoint` | 有 | 有 | 有 | 是（详情页卖点） |
| 目标健康标签 `targetHealthTags` | 有 | 有 | 有 | 否（用于筛选，本期不管） |
| 封面角标 `coverBadges` | 无 | **有（独立表）** | 由系列关联带出 | 是（首页/详情页封面左下角） |

### 4.3 封面文字到底来自哪里

| 场景 | 封面上的文字 | 数据来源 | 本次是否改 |
|---|---|---|---|
| 小程序首页橱窗 | 左下角角标 | 系列 `coverBadges`（合规词表，最多 2 个） | **改**：没配就不显示，不再回退封面标题 |
| 小程序食谱详情页 | 左下角角标 | 同上 | **改**：同上 |
| 定制食谱交付页 | 食谱名 + 「第 N 版 · 交付时间」 | `recipe.name` + 交付批次信息（`RecipeCover` 组件自带） | 不改 |
| 后台旧「编辑食谱」页 | 表单里的封面标题 | `Recipe.coverTitle` | 本期保留入口，列入已知问题 |

关键事实：

1. **封面标题不是「标题」**。首页/详情页的封面文字由 `resolveCoverBadgeText()` 决定：优先取系列角标，没有角标时**回退到 `coverTitle`**。老板 2026-10-26 确认：这个回退不要了，没角标就空着。
2. **封面角标是系列级的独立设置**，引用合规词表（`recipe_health_tag`），最多 2 个；目前只能在旧的「编辑食谱」页修改，设计器里没有入口。
3. **目标健康标签不是角标**。它是给顾客按健康需求筛选用的维度，不显示在封面上；当前在发布时只是「提醒」，不阻断。
4. **定制交付页的「食谱标题」是 `recipe.name`，不是 `coverTitle`**；它还有自己的「第 N 版 · 交付时间」角标。本次角标改造不影响它。
5. 发布时系列展示资料会覆盖阶段上的同名值：封面图/封面标题/卖点必覆盖；目标健康标签只在系列非空时覆盖。
6. 已知问题（本期不修）：目标健康标签在系列上设置后，顾客筛选实际用的是阶段食谱上的标签关联，两处没有同步，可能出现「标签设了却筛不到」。

### 4.4 AI 封面现状

后端已有 `RecipeCoverImageService`（glm-image → 下载 → 转存 COS），但只被旧「编辑食谱」页调用，设计器没有入口。本期不接；下阶段再按第 13 节的建议做。

## 5. 设计总览

把「一条产品线」拆成两层，各自只有一个负责人：

| 层 | 管什么 | 谁维护 | 什么时候对顾客生效 |
|---|---|---|---|
| **系列（门面）** | 封面图、封面角标、一句话卖点 | 「发布 / 更新」→ 发布设置 | 点「保存发布设置」立即生效（已上线阶段） |
| **阶段（配方）** | 原料、克数、营养、报告、预处理、制作步骤 | 各阶段编辑器 + 上线检查 | 首次全发；更新时勾选后发布 |

原则：**谁共用，谁在系列；谁各写各的，谁在阶段。**

## 6. 界面设计

### 6.1 入口与命名

- 系列卡片底部的「系列发布 / 重新发布系列」改名为 **「发布 / 更新」**；具体文案随状态：
  - 未上线：**发布**；
  - 已上线：**更新**（有待更新时显示「更新 N 个阶段」）。
- 抽屉标题改为 **「发布 / 更新」**，副标题保留「产品线 · 整条系列一次性发布」。
- 编辑器顶部新增 **「发布 / 更新」** 入口（仅 CATALOG 系列），打开同一个抽屉；这样在编辑器里完成阶段入库后就能直接发布/更新，不必先回列表。
- ORDER 系列不显示该入口（沿用现有的订单交付流程）。

### 6.2 发布范围（替换现在的「阶段清单」）

不再有「必做阶段」勾选。抽屉打开后按数据现状分组：

| 分组 | 判定 | 是否可勾选 | 展示 |
|---|---|---|---|
| 待发布 | `status = READY`（已入库、还没上线） | 首次发布：不显示勾选框；更新：可勾选 | 「待发布」+ 版本号 |
| 有更新 | `status = PUBLIC` 且 `hasPendingUpdate` | 是，默认勾选 | 「有更新 v3 → v4」 |
| 已是最新 | `status = PUBLIC` 且无更新 | 否 | 「已上线 v3」 |
| 未入库 | `status = DRAFT`（有设计稿，没走阶段发布） | 否 | 「未入库」，提示先完成上线检查并发布为阶段食谱 |
| 未设计 | `status = EMPTY` | 否 | 「未设计」，灰显 |

规则：

1. **首次发布（系列还没上线）**：发布范围 = 当前已就绪（READY）的全部阶段，不显示勾选框；**只要有 1 个 READY 就能发布，不要求 5 个齐全**；按钮文案「发布 N 个阶段」。
2. **更新（系列已上线）**：发布范围 = 全部可操作阶段（READY + 有更新），显示勾选框、默认全选；运营可取消勾选，只更新其中几个；按钮文案「更新 N 个阶段」。
   - 「可操作」包括后来新加、还没上线过的 READY 阶段；它和「有更新」一起出现在可选列表里。
3. **下架后重新上线**按首次发布处理：整条系列已经下线，重新上线时把当前已 READY 的阶段一起恢复（**1 个就绪也能恢复**，同样不要求 5 个齐全），不提供「只恢复几个阶段」，避免顾客只看到一部分阶段。判定用当前 `businessStatus`，不额外记「历史上是否发布过」。
4. 未勾选的「有更新」阶段保持待更新，下次还能再发；未勾选的 READY 阶段保持未上线。
5. 未设计/未入库的阶段只作覆盖参考，不阻断发布。
6. 一个可操作阶段都没有时，主按钮不可用，提示「还没有可发布的阶段」；**后端也必须拒绝空发布（400），不能只靠按钮禁用**。已全部最新的系列沿用现有文案「系列已上线，所有阶段都是最新版本，无需重新发布」，不显示成红色阻断。
7. 覆盖提示只做提醒：「发布后覆盖 3 / 5 个生命阶段」（已上线 + 本次发布），不阻断。

### 6.3 发布设置（门面）

字段收敛为三个：

| 字段 | 必填 | 说明 |
|---|---|---|
| 封面图 | 是 | 手动上传（JPG / PNG / WebP，≤5MB）；不提供外链粘贴，避免过期链接、防盗链和绕过上传校验（本期不做 AI 生成） |
| 封面角标 | 否 | 从合规词表选，最多 2 个；不选就不显示 |
| 一句话卖点 | 是 | 最多 200 字，顾客在详情页看到 |

> 「必填」是**发布/更新时**的门槛；未上线的系列可以先把资料存成空的，边设计边补（见 6.3 后面的保存规则）。

**封面标题（`coverTitle`）不再出现在发布设置里，也不再作为发布必填。** 原因见 4.3：

- 首页/详情页不再回退它；没配角标就空着；
- 定制交付页用的是食谱名，不是它；
- 数据保留（DB 列、API 字段、旧页面入口），不迁移、不清空；
- AI 的 `set_copy` 本期不改，仍可能写它，但不再影响首页/详情页展示；
- 未设置角标时给一条提醒（不阻断）：「封面左下角将没有文字」。

**保存即生效**：点「保存发布设置」后，封面图/封面角标/卖点立即对已上线的阶段生效，不需要再点一次「发布/更新」。抽屉里要写清楚这一点。保存只改展示资料，不动配方版本、营养数据、`contentRevision`。

保存规则：

- 保存顺序：先存发布设置（封面图/卖点），再存封面角标；角标失败不回滚已保存的设置，提示「设置已保存，但角标未保存成功，请重试」。
- 只有角标变化时也要能单独保存，不能因为发布设置没变就提前返回「没有修改」。
- 已上线系列保存时，封面图和一句话卖点不能清空（清空请求 400）；未上线系列允许先留空。
- **必填只在发布/更新时校验**：未上线系列保存门面时不要求封面/卖点齐全，也不要求已经有 READY 阶段。
- 顾客侧没有长缓存：保存后顾客下次打开/刷新页面就能看到新封面/角标/卖点，不需要重新发布（这里说「立即」是指无需再点发布，不是实时推送）。

### 6.4 顾客预览

在发布设置下方加一块只读预览，按小程序首页卡片的样子展示：

- 封面图；
- 左下角角标（只显示选中的角标；没选就不显示，不回退封面标题）；
- 食谱名（系列名）；
- 一句话卖点。

预览用当前表单值实时渲染，让运营在保存前就能看到顾客看到的样子。定制交付页是另一套封面（食谱名 + 版本/交付时间），不在这个预览里。

### 6.5 阶段「上线检查」抽屉

- CATALOG：不出现任何可编辑的展示资料字段（现状如此）。新增一块只读的 **「系列资料（共用）」**：
  - 封面图 ✓ / ✗；
  - 一句话卖点 ✓ / ✗；
  - 封面角标：已设置 / 未设置（未设置时封面左下角为空）；
  - 右侧按钮 **「去发布 / 更新」**，打开同一个抽屉；
  - 数据来自 `GET /recipe-designer/series/:id/release-readiness`，与发布抽屉同源，不额外读一份。
- ORDER：保留现有「订单展示」面板（封面图/标题/卖点/描述），只移除「目标健康标签」字段。
- 阶段抽屉的检查项保持：名称、原料参与评估、营养评估、完整报告（含过期）、总重/能量密度、补剂目标、预处理、制作步骤；ORDER 另加订单号/份数/顾客爱犬。

### 6.6 小程序封面角标显示

- `miniapp/src/utils/cover-badge.ts`：`resolveCoverBadgeText()` **只返回系列角标**，删除 `coverTitle` 回退；角标为空时返回空串。
- 首页卡片、详情页封面已经用 `v-if="... && resolveCoverBadgeText(recipe)"` 控制显示，空串时自然不渲染角标。
- 定制交付页 `custom-recipe/delivery.vue` 的 `RecipeCover` 用的是 `recipeName` + 「第 N 版 · 交付时间」badge，不经过这个函数，**不改**。
- 影响：老系列如果只配过封面标题、没配过角标，更新小程序后左下角会空出来；运营可在「发布 / 更新」里补角标。这是老板确认的行为。
- 同步更新 `cover-badge` 相关单测与首页/详情页回归 spec。

```
│ │ 图 + 角标 │  卖点：……                                  │
│ └──────────┘                                            │
│                                                         │
│ 检查结果：✔ 封面 ✔ 卖点 ⚠ 未设置角标                    │
│                                     [保存发布设置]      │
│                             [发布 3 个阶段 / 更新 2 个] │
└─────────────────────────────────────────────────────────┘
```

## 7. 发布 / 更新动作

### 7.1 首次发布

- 范围：当前已就绪（READY）的全部阶段；**1 个 READY 就能发，不要求 5 个齐全**；
- 校验：门面齐全（封面图、卖点）；至少一个 READY 阶段；
- 动作：把这些阶段最新一版的 `Recipe.status` 从 DRAFT 改为 PUBLIC；写入门面资料；系列 `businessStatus` → PUBLIC；
- 返回：发布的阶段代码、发布条数、系列状态。

### 7.2 更新

- 范围：勾选的可操作阶段；
- 校验：门面齐全；至少勾选一个；勾选的阶段必须属于可操作集合；
- 一个可操作阶段都没有（或首次发布 0 个 READY）→ 400，不允许 no-op release；只改门面走 8.3「保存发布设置」，不走 release；
- 动作：只把勾选阶段的最新 DRAFT 改为 PUBLIC；未勾选的「有更新」阶段保持 DRAFT；门面资料写入所有 PUBLIC 阶段 + 本次发布的阶段；
- 部分更新后系列仍是 `NEEDS_UPDATE`（还有未发的更新），直到所有待更新阶段都发出去；
- 返回：本次更新的阶段代码、新发布条数、更新条数。

### 7.3 只改门面

- 保存发布设置时立即把封面图/卖点写入该系列所有 PUBLIC 食谱；
- 封面标题随保存/发布同步：只在系列值非空时覆盖，避免清掉旧数据（虽然小程序已不展示它）；
- 这个「立即同步线上」只由**人点「保存发布设置」**触发；AI 的 `set_copy` 调同一个服务方法时不带这个开关，避免 AI 改文案立刻影响线上；
- 不需要点「发布/更新」，也不产生新的配方版本；
- 抽屉底部提示：「展示资料保存后立即对已上线阶段生效」；
- 已上线系列保存时，封面图和一句话卖点不能清空（400）；
- 顾客侧没有长缓存：下次打开/刷新页面即可看到（不是实时推送）。

### 7.4 下架

保持现状：整系列 PUBLIC → DRAFT，系列 → DRAFT；数据不删。

### 7.5 门面写入规则（保存和发布共用）

| 字段 | 写入规则 |
|---|---|
| 封面图 | 必写（系列值必填） |
| 一句话卖点 | 必写（系列值必填） |
| 封面标题 | 只在系列值非空时写；为空时保留食谱原值 |
| 目标健康标签 | 保持现状：系列非空时才写 |
| 封面角标 | 系列级独立表，不写食谱行，随系列读取 |

## 11. 已知问题（本期不做，记录在案）

1. **目标健康标签与筛选关联不同步**：系列上设置后，顾客筛选用的是阶段食谱的 `healthTagAssignments`，两处可能不一致；等推荐/筛选项目统一。
2. **详情描述 / 详情图 / 视频没有产品线入口**：它们存在阶段草稿上，但 CATALOG 的发布设置和上线检查都没有编辑入口；本次不迁移，后续单独定归属。
3. **ORDER 的 `coverTitle` 仍是必填**：交付页实际用 `recipe.name` 展示标题，`coverTitle` 在订单流程里是否还有用需后续确认；本次不动订单流程。
4. **AI 的 `set_copy` 仍会写 `coverTitle` / `targetHealthTags`**：前者已不参与首页/详情页展示，后者等筛选项目处理；本期不改 Agent 工具。
5. **旧「编辑食谱」页仍有封面/角标/卖点入口**：它操作单个 `Recipe`（角标是同一张系列表），与设计器的系列级设置并存。本次不下线旧页（订单详情、客服还会打开它），以设计器为主入口；旧页的系列角标入口等旧页整体退休时一起处理。
6. **老系列可能失去封面文字**：只配过封面标题、没配过角标的老系列，小程序更新后左下角会空出来；需要在「发布 / 更新」里补角标。

## 12. 验收场景

1. 新建一条产品线，设计 3 个阶段并入库 → 打开发布页：只列 3 个待发布，无勾选框，按钮「发布 3 个阶段」；发布后 3 个阶段都上线，另外 2 个显示「未设计」。只入库 1 个阶段时同样可以发布这 1 个——不要求 5 个齐全。
2. 已上线系列改了 2 个阶段的配方并入库 → 打开更新页：2 个「有更新」默认勾选，其余「已最新」；取消 1 个后点「更新 1 个阶段」：只有勾选的阶段出现新版本，另一个仍保持待更新。
3. 已上线系列后来又新入库 1 个从未上线的阶段 → 更新页把它列进可勾选（和「有更新」一起），默认勾选。
4. 只改封面图/角标/卖点并保存 → 已上线阶段的详情页/首页下次打开立即显示新图新角标，配方版本号不变。
5. 角标为空 → 预览和小程序首页/详情页都不显示封面文字；配了角标 → 显示角标（最多 2 个）；不再回退封面标题。
6. 角标保存失败 → 发布设置已保存，提示单独重试角标。
7. 定制交付页 → 封面标题仍是食谱名，badge 仍是版本/交付时间，不受角标改造影响。
8. CATALOG 的阶段上线检查不出现可编辑的门面字段，只显示系列资料状态与跳转。
9. ORDER 的上线检查不再出现目标健康标签，其余展示字段与交付流程不变。
10. 系列未上线时保存门面 → 不报错，不要求先有 READY 阶段，也不要求卖点已经填好；发布时才拦。
11. 下架后重新上线 → 按首次发布处理，当前 READY 阶段一次恢复（1 个就绪也能恢复）。
12. 首次发布 0 个 READY → 后端 400「还没有可发布的阶段」，系列不会被置 PUBLIC；已上线且全部阶段都最新时调用 release → 后端 400「当前没有可更新的阶段」，不会空刷新门面。
13. 本期没有任何生图接口调用、没有自动上传封面。
