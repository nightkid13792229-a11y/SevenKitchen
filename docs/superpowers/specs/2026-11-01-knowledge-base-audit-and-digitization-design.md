**老板 2026-11-01 的三条指令**

- 不改配方编辑器的流程（不做"必须先查知识库"这类卡口）。

## 1. 为什么第一版作废

| 第一版假设 | 实际 | 结论 |
|---|---|---|
| 老板要"点出处 → 跳到 PDF 第 N 页" | 老板不看 PDF | 整块砍掉：页标题索引、签名跳转链接、PDF 流式服务 |
| 原文只是"留档备查" | 原文要能被 AI 读、被网页展示 | 从"存文件"升级成"**全文数字化 + 段落级索引**" |
| 猫 / 犬混排是边缘问题 | **猫关键词占全库约四成** | 物种必须成为知识库的一等维度，且要段落级判定 |

一句话：第一版把力气花在"怎么打开原文"，而真正的瓶颈是"**原文根本不是数据**"。

## 3. 阶段一 · 来源审计（3 天）

**目标**：在花钱花时间做数字化之前，先确认"这份资料还该不该留"。

### 3.1 每个来源出一张卡

| 字段 | 判断方式 |
|---|---|
| 权威性 | 学会共识 / 教科书 / 厂商资料 / 二手转引，四档 |
| 物种适用 | 纯犬 / 犬猫混合 / 纯猫 / 异宠 |
| 版本有效性 | 现行 / 已被取代（如 AAHA 2014 体重管理 → 2021 取代） |
| 完整性 | 有没有缺章、缺页、只有摘要没正文（**MMVD 就是这种**） |
| 可读性 | 有文字层 / 扫描件 |
| 处理结论 | 保留 / 只留犬段 / 剔除 / 待补 |

### 3.2 三张清单

1. **整份剔除**：15 份（见 §2.2-A）
2. **段落级筛**：约 40 份犬猫混排
3. **要补**：ACVIM 3 份 + WSAVA 英文疼痛指南

### 3.3 扫描件怎么处理

WSAVA 中文疼痛指南 42 页是扫描件，而疼痛是引用最多的主题之一（23 处出处指向它）。

处置顺序：

1. **优先抓英文正本**（英文版通常有文字层，而且是原始出处，权威性更高）
2. 抓不到再 OCR。本机没装 OCR 工具，但有 macOS 自带的 Vision（`swift` 可用），写个小脚本就能读中文，**不用装任何东西**
3. 都不行就标成"仅存档、AI 不可用"，并在知识条目上明确提示

### 3.4 产出

- `docs/knowledge-base/source-audit.csv`：164 行，每行一张卡
- `docs/knowledge-base/source-audit-report.md`：人读的结论（剔除哪些、补哪些、哪些有问题）
- 更新 `source-register.md` 和代码里的来源登记表（加"物种适用""完整性""是否可用"）

## 4. 阶段二 · 全文数字化（4 天）

**目标**：把 164 份文件变成"机器能读、能搜、能精确定位"的段落。

### 4.1 切分粒度

```
文档（164 份）
 └ 章节（按标题层级切，如「第 37 章 慢性肾病」→「蛋白尿管理」）
    └ 段落（最小的可引用单位，通常 100–500 字）
```

每个段落带这些坐标：

| 坐标 | 用途 |
|---|---|
| 所属文档 / 章节路径 | 人看得懂 |
| 页码（PDF 才有） | 需要回原文时能对上 |
| 段序号 + 字符位置 | 精确定位、原文高亮 |
| 物种标记 | 犬 / 猫 / 犬猫通用 / 无关 |
| 内容类型 | 正文 / 表格 / 图注 / 参考文献 / 页眉页脚 |

### 4.2 各类型的处理方式

| 类型 | 份数 | 怎么处理 |
|---|---|---|
| PDF（有文字层） | 132 | 按字号/行距找标题，按空行切段；去掉页眉页脚；表格单独抽成「表 N：行1 / 行2…」 |
| PDF（扫描件） | 1–3 | 英文正本替换，或 Vision OCR |
| ACVIM XML（JATS 全文） | 23 | 按 `<sec>/<title>` 切章节，天然带结构，质量最好 |
| Merck TXT | 5 | 按空行切段；对应的 HTML 是网页壳子，不用 |
| NRC EPUB | 1 | 按 EPUB 章节切，219 万字符，是最大的一份 |

### 4.3 质量怎么保证

数字化最怕"看着成功、其实丢了一半"。四条硬指标：

| 指标 | 标准 |
|---|---|
| 字符保留率 | 每份文件抽出的字符数 ÷ 按页数估算的期望值 ≥ 85% |
| 乱码率 | 非常用字符占比 < 1% |
| 段落长度分布 | 没有 > 3000 字的巨段（说明没切开），也没有大量 < 20 字的碎段 |
| 人工抽检 | 随机抽 30 段，对照原 PDF 逐字比对，错字/丢句为零 |

任何一份不达标就重切，不往下走。

### 4.4 物种标记怎么打

三层判定，逐层收紧：

1. **文件级先验**：纯猫 / 纯异宠文件整份标掉（15 份）
2. **段落级规则**：段落里猫词频 > 0 且犬词频 = 0 → 猫；两者都有 → 犬猫通用；都无 → 中性（保留）
3. **人工校准**：抽 100 段人工标注，校准规则准确率；准确率不到 90% 就改规则重来

> 为什么强调段落级：慢性肾病第 37 章里，犬的蛋白尿管理和猫的分期建议是并列写的。整章标成"混合"等于整章都不能用；切到段落才能只留犬的。

## 5. 阶段三 · 结构改造：让 AI 好用（4 天）

这是老板说的"**最核心的一点**"。分三件事。

### 5.1 条目：改成"AI 问什么就有什么"

现在一条知识 = 标题 + 结论 + 5 条要点 + 2 条注意 + 一句出处。**AI 拿到它，不知道"什么时候该用""能不能说给顾客听""依据在哪一段"。**

改造后每条带这些维度：

| 维度 | 作用 | 现状 |
|---|---|---|
| 领域（28 个） | 疾病 / 器官 | ✅ 已有 |
| 问题类型 | 解读 / 分诊 / 复查 / 营养 / 预防 / 免疫 / 定义 / 安全 | 仅 189 条有，**"营养"类型 0 条** |
| **物种** | 犬 / 犬猫通用 | ❌ 没有，新增 |
| 适用条件 | 什么阶段、什么体征下成立 | 部分（`applicableTo` 标签） |
| 风险等级 | 说错了会不会伤狗 | 仅 189 条有 |
| 紧急程度 | 立即就医 / 尽快 / 可观察 | 仅 51 条有 |
| 审核状态 | 能不能给顾客看 | 仅 189 条有 |
| **出处段落** | 指向具体段落 ID | ❌ 现在只有"第 40 章"这种文字 |

补齐顺序：先补最常用的 4 个领域（泌尿结石 12 / 肾 11 / 胰腺炎 12 / 肠胃 14 = 49 条），跑通再铺开。

### 5.2 检索：按"AI 会怎么问"设计，不按"数据库有什么"设计

现在 AI 只能拿一整串问题去撞标题。改造后给三种明确动作：

| AI 想干什么 | 对应动作 | 返回什么 |
|---|---|---|
| 这个库里有什么 | 列目录 | 领域 / 问题类型 / 物种 / 条数 |
| 我遇到这个问题，有依据吗 | 检索 | 最多 8 条摘要卡：一句话结论 + 紧急程度 + 风险 + 审核状态 + 出处段落预览 + 命中总数 |
| 把这条展开 | 取详情 | 完整条目 + 引用段落全文 + 出处 |

检索命中按这个优先级打分：关键词精确 > 别名 > 标题 > 标签（领域/物种/问题类型）> 摘要。
**不命中就不返回**，并明确告诉模型"这个知识库没有这条，别凭记忆编"。

### 5.3 别名表（决定能不能查得到）

同样的意思有太多说法：草酸钙结石 / 草酸钙 / 尿石 / 膀胱结石 / oxalate / calcium oxalate……

现在库里只有条目自带的关键词，覆盖不全。新加一张别名表，初始由关键词自动生成，再人工补 100–200 条常用说法（含中文口语、英文、缩写、检验指标名）。

**"草酸钙结石营养管理"能不能查到，八成取决于这张表。**

### 6.1 页面

│ ▸ 肾脏病 11    │ ▸ 不同结石对策相反…    │ 【要点】1. … 2. …               │
│ ▸ 胰腺炎 12    │ ▸ 水分管理…           │ 【注意】…                       │
│ …              │                       │ 【出处】小动物临床营养学 第40章  │
│                │                       │  ┌─────────────────────────┐   │
│                │                       │  │ 原文（第40章 第12页）      │   │
│                │                       │  │ ……草酸钙结石的饮食管理……  │   │

三个关键点：

1. **右边是文本，不是 PDF**。每条出处直接展开它引用的那一段原文，前后可各看几段上下文。
2. **搜索穿透到原文**。搜"草酸钙"，条目命中的同时，原文段落命中的也列出来。
3. **一致性看板**。一眼看出：哪些条目没有原文依据、哪些出处定位不到、哪些复核过期。

## 8. 猫内容的三层处理（汇总）

| 层 | 做法 | 规模 |
|---|---|---|

**第二步结束时是一个重要检查点**：这时原文已经是可搜索的文本了。你可以先在那儿搜几个词（比如"草酸钙"），看看数字化质量到底行不行，再决定要不要继续。
