# 生命阶段自动匹配 · 优化设计方案

> 日期：2026-11-02
> 上游：[生命阶段自动匹配：页面盘点与交互评审](../plans/2026-11-02-life-stage-auto-match-audit.md)
> 状态：**设计稿，待评审后拆任务实施**
> 范围：小程序顾客端（详情 / 订购 / DIY / 制作单 / 订单 / 首页 / 收藏 / 我的）+ 必要的后端接口

## 0. 摘要

让系统替顾客把"这只狗该吃哪一版"选对，并且只在**选错真的会有后果**的时候打扰他。

四句话概括这次改造：

1. **版本跟着狗走**：换狗自动换版，不再要顾客点"切换到 X"。
2. **一个版本条，八种状态**：详情 / 订购 / DIY 用同一个组件、同一套话；制作单只留一行版本记录。
3. **确认分级**：幼犬、繁殖期选错要确认并留痕；成犬↔老年只提示，不拦。
4. **版本可见**：订单确认、订单详情、制作单、复购页都能看到"是哪一版"。

### 0.1 已拍板的三个决定（2026-11-02）

| # | 决定 | 说明 |
|---|---|---|
| 1 | **提醒分级** | 高风险（幼犬/繁殖期 ↔ 其他）下单前确认一次并留痕；低风险（成犬 ↔ 老年/活动量档）只提示。**修改 2026-09-19 "每次都确认"的口径** |
| 2 | **换狗自动跟随版本** | 顾客手动选的版本只对当前这只狗、当前这次有效；换狗即重置为自动 |
| 3 | **首页不默认按狗过滤** | 只提供"按它筛选"一键 + 卡片"适合旺财"标记，避免减少曝光 |

### 0.2 我作为设计者做的判断（实施时可推翻，但要说一声）

| 判断 | 理由 |
|---|---|
| 首页筛选项从 10 个收敛为 **4 个**（幼犬/成犬/老年/繁殖期）+ 一个"按我家狗" | 顾客答不出"幼犬"和"小于14周幼犬"的区别；14 周是配方细节，不是购物维度 |
| 卡片上的"我已知晓"**全部删除** | 确认只发生在下单/生成制作单那一下，避免"点过又问一遍" |
| "无法确认"只给中性提示 + 重试，**不拦** | 网络抖动不该挡住成交；但要如实说"不知道" |
| 复购时若阶段已变，**自动切新版并说明** | 这是"幼犬→成犬"过渡的关键触点，不能靠顾客自己发现 |
| **版本中文名统一**为"幼犬版（14 周内）/ 幼犬版（14 周以上）/ 成犬版 / 低活动·老年版 / 繁殖期版" | 现在后端一套、前端兜底一套，同一个版本两个名字；统一后三页和订单、制作单才能说同一句话 |

## 1. 目标与非目标

### 目标

| # | 目标 | 判断标准 |
|---|---|---|
| G1 | 顾客不需要理解"生命阶段版本"这件事，也能买对 | 换狗后无需任何额外点击，版本即正确 |
| G2 | 不该提醒的场景不再提醒 | 未选狗、单版本菜、结论未知时，不出现"不匹配"字样 |
| G3 | 该提醒的场景说对话 | 文案区分"系统选的""你选的""没有这一版"三种原因 |
| G4 | 一次下单只确认一次 | 卡片不再有确认按钮；下单时才确认 |
| G5 | 版本可追溯 | 订单确认、订单详情、制作单、复购页都能看到版本 |
| G6 | 可度量 | 能看到"多少人换了版、多少人放弃了" |

### 非目标

- 不改生命阶段判定算法（仍用后端 `resolveDogProfileStage`）。
- 不改营养配方、不改价格、不改分装逻辑。
- 不改后台（admin-web）与员工端生产流程（只补一个版本展示）。
- 不做 A/B 实验，不做个性化推荐排序。
- 不在本轮做"换粮指导"内容（只做提醒入口，内容后续补）。

## 2. 状态模型

### 2.1 后端的匹配结论（在现有 `matchType` 上扩展）

| matchType | 含义 | 新增/现有 |
|---|---|---|
| `NO_DOG` | 没有传 dogId，无法判断是否适合 | **新增** |
| `MATCHED` | 展示的版本 = 该狗阶段对应的版本 | 现有 |
| `MANUAL_MISMATCH` | 顾客**主动**选了另一个版本，且该版本存在 | 现有（语义收紧） |
| `FALLBACK_ADULT` | 该狗阶段没有对应版本，回退到"成犬版" | 现有 |
| `FALLBACK_FIRST` | 该狗阶段没有对应版本，回退到第一个可用版本 | 现有 |
| `LEGACY` | 这道菜没有版本之分 | 现有 |

新增 `riskLevel` 字段，由**后端**算，前端不自己判断：

| 组合（狗的阶段 vs 展示的版本） | riskLevel | 依据 |
|---|---|---|
| 幼犬（任一档） ↔ 非幼犬 | `HIGH` | 钙磷比例、能量密度不同，长期喂可能影响发育（知识库 growth-004/005） |
| 繁殖期 ↔ 非繁殖期 | `HIGH` | 能量密度、脂肪、钙的需求显著更高（repro） |
| 成犬 ↔ 老年/低活动 | `LOW` | 同一生理阶段内的能量档差异，不是安全问题 |
| 相同阶段 / `LEGACY` / `NO_DOG` | `NONE` | — |

> 注意：`riskLevel` 看的是"狗的阶段 vs 展示版本"，**与怎么选出来的无关**。所以"幼犬 + 回退到成犬版"也是 `HIGH`。

### 2.2 前端的界面状态（八种）

由 `matchType + riskLevel + checkFailed` 推导，**只在这一处推导**（composable）：

| 界面状态 | 条件 | 视觉 | 是否拦 |
|---|---|---|---|
| `no_dog` | 没有 dogId | 中性 + "去添加爱犬" | 否 |
| `unknown` | 菜谱加载成功、但没带回可用的结论 | 灰色 + "重试"（重载菜谱） | 否 |
| `matched` | `MATCHED` | 中性（常规卡片色） | 否 |
| `manual_low` | `MANUAL_MISMATCH` + `LOW` | 琥珀 | 否 |
| `manual_high` | `MANUAL_MISMATCH` + `HIGH` | 红 | 下单时确认 |
| `fallback_low` | `FALLBACK_*` + `LOW` | 琥珀 | 否 |
| `fallback_high` | `FALLBACK_*` + `HIGH` | 红 | 下单时确认 |
| `legacy` | `LEGACY` | **整条不显示** | 否 |

视觉上一共 4 种色调：中性 / 琥珀 / 红 / 灰。

## 3. 交互设计

### 3.1 版本条（新组件 `LifeStageVersionBar`）

**位置：紧贴"当前爱犬"卡片下方。** 详情页放在狗头像行下面；订购页、DIY 页放在选狗区下面。（制作单不用这个组件，见 4.4。）

**布局（两行，右侧一个动作）：**

```
┌────────────────────────────────────────────────┐
│ 成犬版                                          │
│ 旺财 2 岁 · 按档案匹配                 换一版 › │
└────────────────────────────────────────────────┘
```

- 第一行是**当前版本**（顾客最需要知道的信息）。
- 第二行是**为什么**（按档案匹配 / 你选的 / 这道菜没有这一版）。
- 右侧动作：`换一版 ›` / `恢复为{匹配版本名}` / `看看幼犬能吃的菜` / `重试` / `去添加爱犬`。
- 只有 `versionCount > 1` 才出现"换一版"；单版本菜不显示切换入口。
- 匹配态**不用绿色大块**，也不写"已匹配"（"匹配"是系统词）。

**四种色调：**

| 色调 | 用在哪 | 底色 / 描边 |
|---|---|---|
| 中性 | matched | `#fff` / `#ede0d0`（沿用现有卡片） |
| 琥珀 | manual_low / fallback_low | `#fffcf7` / `#f0dfc4` |
| 红 | manual_high / fallback_high | `#fffbfa` / `#f0c8bc` |
| 灰 | unknown / no_dog | `#f7f7f5` / `#e6e4df` |

**切换版本时的加载**：只在版本条上显示"正在切换…"，**不要**全屏 loading、不要跳回顶部、不要清空已选的分装。

### 3.2 版本选择面板（新组件 `LifeStageVersionSheet`）

点"换一版"从底部弹出，复用现有详情页的版本列表结构：

```
选择生命阶段版本                          ×
────────────────────────────────────────
成犬版                 按旺财档案匹配 ✔ 当前
  成年、活动量正常或偏高
低活动 / 老年版
  活动量偏低，或已进入老年
幼犬版（14 周以上）
  14 周以上、尚未成年
────────────────────────────────────────
[ 用这个版本 ]
```

- 每行：版本名 + 一句"适合谁"（用 5.1 那张固定文案表，不写在页面里）。
- 当前版本标"当前"；档案匹配的版本标"按旺财档案匹配 ✔"。
- 高风险版本被选中时，底部出现一行红字："幼犬与成犬配方不同，选错可能影响发育。"
- 选中后**不立刻生效**，点"用这个版本"才切换（避免误触）。

### 3.3 换狗 / 换版规则（详情 / 订购 / DIY 共用）

| 动作 | 行为 |
|---|---|
| 进入页面（有狗） | 按狗自动选版 |
| 进入页面（无狗） | 展示默认版，版本条为 `no_dog`，不判断 |
| **换一只狗** | 清空手动选择 → 按新狗重选 → 版本条上方出现 2 秒轻提示："已按旺财切到成犬版"（不弹窗、不红卡） |
| 顾客手动选版 | 记为该狗的"手动选择"；版本条转琥珀/红；**只对这只狗有效** |
| 再换回匹配版 | 手动选择清除，回到 matched |
| 再次购买 | **以当前档案为准重新选版**（不继承上次的手动选择）；顶部显示"上次买的是幼犬版"，若已换版同时写"旺财现在 14 个月，已换成成犬版"，并提供"还用幼犬版"一键切回 |
| 下单 / 生成制作单 | 高风险且本次未确认 → 弹一次确认；确认后同一单不再问 |
| 已确认后又换狗 / 换版 | 之前的确认**作废**（判定依据变了），下次下单重新确认 |
| 切换版本失败（接口报错） | 回到切换前的版本 + 提示"切换失败，请重试"；不留半新半旧的状态 |

**手动选择的生命周期**：存在页面内存里（不写 storage），刷新/重进即回到自动。理由：顾客的临时浏览不该变成长期设置。

### 3.4 确认弹窗（只在高风险时出现）

- 触发：下单（成品）或"生成制作单"（DIY）时，`riskLevel === HIGH` 且本次未确认。
- 每次下单确认一次（保留 2026-09-19 的"每次都告知"），但**同一单不重复**。
- 确认后立即留痕（沿用 `life_stage_acknowledgement`，`source` 仍为 order/diy）。

文案（按钮受微信 4 字限制）：

```
标题：生命阶段提醒
正文：旺财 3 个月，属于幼犬期；这份是「成犬版」。
      幼犬与成犬的钙磷比例、能量密度不同，长期喂可能影响骨骼发育。
      继续表示您已知晓并自行决定；如正在遵医嘱，请先咨询执业兽医。

[ 看合适版 ]   [ 仍要继续 ]
```

- 高风险但**是系统回退**（没有幼犬版）时，取消键仍为"看合适版"，点了跳到"适合幼犬的菜"（首页筛选）。
- 低风险**不弹窗**，版本条已经说清楚了。

**确认状态机**

| 发生了什么 | 已确认是否作废 |
|---|---|
| 换狗 / 换版 | 作废（判定依据变了） |
| 改分装、份数、饭量、地址、备注 | **不作废**（狗和版本都没变） |
| 退出页面再进来 | 作废（新的一次下单） |
| 确认后放弃、改天再来 | 作废（新的一次下单） |

- 已确认状态只存在页面内存，键是 `{dogId, recipeId, recipeVersion}`；不写 storage，也不发服务端 token。
- 留痕在"确认"那一刻写入，与这单最终有没有下成无关——它证明的是"我们告知过、顾客知道了"。

### 3.5 订单 / 制作单 / 复购：让版本看得见

| 位置 | 展示 | 说明 |
|---|---|---|
| 订单确认页 | 菜品行右侧小字："成犬版" | 下单前最后一次核对 |
| 订单详情 | 菜品名下方："旺财 · 成犬版" | 从订单快照读，历史单也能显示 |
| 制作单（页面） | 头部信息加一行"版本：成犬版" | |
| 制作单（打印 / 分享图） | 同上，加在标题下方 | 车间和顾客都能核对 |
| 复购页 | 顶部提示条："上次买的是幼犬版"；若已自动换版，写"已换成成犬版" | 仅当版本变化时出现 |

### 3.6 未选狗 / 游客

- 版本条：`no_dog` 状态，文案"添加爱犬后，自动匹配适合的版本"，动作"去添加"。
- **绝不出现**"不匹配""没有完全匹配版本""请确认是否适合"。
- 详情页原有的"订购前需先创建狗狗档案"提示保留，二者不重复：版本条只管版本，建档提示只管下单条件。

### 3.7 首页筛选

**抽屉结构改为两块：**

```
生命阶段
┌─────────────────────────────────────┐
│ 旺财 · 2 岁 · 成犬   [按它筛选] │  ← 有狗时才有
└─────────────────────────────────────┘
幼犬    成犬    老年犬    繁殖期
（可多选；14 周的分档由系统在详情页精确判断）

[重置]                    [查看结果]
```

- 手动筛选 = **粗筛**，按卖点维度（4 类）。
- "按它筛选" = **精确筛**，用这只狗的食谱阶段（`recipeLifeStage`）。
- 粗筛的展开规则（后端做，前端不拼）：

| 粗筛 | 展开为 |
|---|---|
| 幼犬 | `PUPPY`、`PUPPY_UNDER_14_WEEKS`、`PUPPY_14_WEEKS_PLUS` |
| 成犬 | `ADULT`、`HIGH_ACTIVITY_ADULT` |
| 老年犬 | `SENIOR`、`LOW_ACTIVITY_ADULT_OR_SENIOR` |
| 繁殖期 | `PREGNANCY`、`LACTATION`、`REPRODUCTION` |

- 卡片角标："适合旺财"——仅当该菜的**系列里**有这只狗的精确阶段版本时显示（列表是按系列聚合的一行，不是按版本一行）。
- 角标与"按它筛选"用同一套等价规则：`PUPPY_*` 也认 `PUPPY`，`HIGH_ACTIVITY_ADULT` 也认 `ADULT`，`LOW_ACTIVITY_ADULT_OR_SENIOR` 也认 `SENIOR`，`REPRODUCTION` 也认 `PREGNANCY` / `LACTATION`。
- `filter-options` 的计数按新的 4 类重算（并集去重），否则会出现"选了幼犬却只有 3 道菜"这种对不上的数字。

### 3.8 收藏

- 卡片加"适合旺财"角标（同上规则）。
- 没有狗 / 未登录：不显示角标，不显示任何"不适合"。

### 3.9 阶段跨越提醒（P2）

- 触发点：14 周、成犬阈值（按品种/体型）、老年阈值（按品种/体型）。
- 展示：首页顶部一条轻提示（可关闭，7 天内不再出现）：

```
旺财快 10 个月了，幼犬版该换成成犬版了。   [看成犬版食谱]  [怎么换粮]
```

- 数据由后端算（前端不得自己算阶段），在 `/dogs` 返回 `upcomingStageTransition`。
- 一次只显示最近的一条。

## 4. 逐页规格

### 4.1 食谱详情 `pages/recipe-detail/index.vue`

| 项 | 规格 |
|---|---|
| 顺序 | 封面 → 标题/卖点 → 狗头像行 → **版本条** → 配方 |
| 自动选版 | 保持现状（换狗 → 带 dogId 重新请求 → 后端选版） |
| 换版 | 点"换一版" → 版本面板 → 选中后带 `manual=true` 重载 |
| 匹配态 | 显示版本条（现在也有，改成新组件与文案） |
| 未选狗 | `no_dog`，不显示"不匹配" |
| 跳订购 | 传 `dogId`；**仅当顾客手动选过版**时额外传 `lifeStage` + `manual=true` |
| 跳 DIY | 同上 |

### 4.2 成品订购 `pages/recipe-order/index.vue`

| 项 | 规格 |
|---|---|
| **删除** | 页面顶部的版本下拉（`.recipe-life-stage-picker`） |
| 新增 | 选狗区下方放版本条；点"换一版"打开版本面板 |
| 选狗 | `loadRecipeDetail` 增加 `dogId`（现在只传 lifeStage） |
| 换狗 | 清空手动选择 → 重载菜谱 → 重算饭量/价格 → 轻提示"已按旺财切到 X 版" |
| 手动换版 | 带 `manual=true` 重载；保留分装天数；只重置与菜谱相关的价格/饭量 |
| 下单 | `riskLevel=HIGH` 且未确认 → 确认弹窗一次；`LOW`/`NONE` 不弹 |
| 卡片 | 移除"我已知晓"（确认只在下单时发生） |
| 再次购买 | 接收 `previousLifeStage`（仅展示用，来源订单快照；老订单没有就不显示）；版本已变时显示对比提示 |

### 4.3 DIY 配置 `pages/recipe-diy/index.vue`

| 项 | 规格 |
|---|---|
| 新增 | 选狗区下方版本条 + 版本面板（**现在没有换版入口**） |
| 换狗 | 同订购页：自动跟随 + 轻提示 |
| 匹配态 | 显示版本条（现在完全不显示，顾客不知道做的是哪版） |
| 生成制作单 | `riskLevel=HIGH` 且未确认 → 确认一次；确认后留痕，`source='diy'` |
| 卡片确认 | 移除"我已知晓"（改由生成时确认），`dismissWarning` 与 `acknowledgedLifeStageDogIds` 一并删除 |

### 4.4 DIY 制作单 `pages/diy-sheet/index.vue`

制作单是**冻结的历史记录**，不应该再"实时判断"——现在的做法是拿狗当前的阶段去比，比出来的甚至可能不是这张单用的版本。

| 项 | 规格 |
|---|---|
| 实时匹配 | **移除**（不再调 `life-stage-match`） |
| 版本展示 | 固定一行"版本：成犬版"（来自制作单记录） |

| 打印 / 分享 | 标题下加"版本：X"，与页面一致 |
| 为什么 | 顾客已经确认过、也留了痕；在结果页再算一次只会前后矛盾 |

### 4.5 订单确认 `pages/checkout/index.vue` 与订单详情 `pages/order-detail/index.vue`

## 5. 文案表（逐字，开发照抄）

### 5.1 版本名先统一

同一个版本现在有**两套叫法**：后端返回"普通成年犬 / 低能量成年犬 / 老年犬"，前端兜底用的 `getLifeStageLabel` 说"普通或高运动量成犬 / 低运动量成犬或老年犬"。两处不一致时，同一个版本在卡片和筛选器里会显示不同的名字。

→ 统一为下表，**后端 `SERIES_LIFE_STAGE_LABELS` 与前端 `getLifeStageLabel` 逐字一致**，并各加一条测试锁死。

| 枚举 | 版本名（顾客看到） | 一句话说明（版本面板第二行） |
|---|---|---|
| `PUPPY_UNDER_14_WEEKS` | 幼犬版（14 周内） | 断奶后到 14 周 |
| `PUPPY_14_WEEKS_PLUS` | 幼犬版（14 周以上） | 14 周以上、尚未成年 |
| `HIGH_ACTIVITY_ADULT` | 成犬版 | 成年、活动量正常或偏高 |
| `LOW_ACTIVITY_ADULT_OR_SENIOR` | 低活动 / 老年版 | 活动量偏低，或已进入老年 |
| `REPRODUCTION` | 繁殖期版 | 妊娠或哺乳期 |
| `LEGACY` | 不显示 | 这道菜不分版本 |

说明里**不写具体月龄/岁数**——成犬与老年的阈值按品种和体型不同，写死会与系统判定打架。

### 5.2 状态文案

| 场景 | 标题（第一行） | 副文案（第二行） | 右侧动作 |
|---|---|---|---|
| matched | `{版本名}` | `{狗名} {年龄} · 按档案匹配` | `换一版 ›` |
| manual_low | `{版本名}` | `当前不是按{狗名}档案匹配的版本` | `恢复为{匹配版本名}` |
| manual_high | `{版本名}` | `{狗名}还在幼犬期，这一版不是给幼犬的` | `换合适版` |
| fallback_low | `{版本名}` | `这道菜没有适合{狗名}（{阶段}）的版本，现展示这一版` | `看看适合的菜` |
| fallback_high | `{版本名}` | `这道菜没有适合{狗名}（{阶段}）的版本，幼犬配方与成犬不同` | `看看幼犬的菜` |
| unknown | `暂时无法确认` | `这份食谱是否适合{狗名}，稍后再试` | `重试` |
| no_dog | `还没选择爱犬` | `添加后自动匹配适合的版本` | `去添加` |

**禁用词**（任何页面都不出现）：

- "不匹配"（对顾客说"不是给它的版本"）
- "没有完全匹配版本"（说"这道菜没有适合它的版本"）
- "手动展示"（顾客不关心系统怎么选的）
- "档案对应 XX 阶段"（太系统；说"它现在 3 个月，是幼犬"）

## 6. 接口与数据

### 6.1 请求参数语义（关键改动）

`GET /recipes/:id`

| 参数 | 现状 | 改为 |
|---|---|---|
| `dogId` | 参与选版 | 不变 |
| `lifeStage` | 同时承担"展示"和"手动选择" | 只表示"要展示的版本" |
| `manual` | 无 | **新增**：`true` 表示顾客主动选的；缺省按"兼容旧版"处理（见 6.6） |

选版逻辑：

```
if 没有 dogId:
    selected = 请求的 lifeStage ?? 默认版本
    matchType = NO_DOG
else:
    dogStage = 权威判定(dog)
    if manual && lifeStage: requested = lifeStage
    else:                   requested = dogStage
    selected = 精确匹配(requested) ?? 钉住的版本 ?? 回退版本
    matchType = manual && selected ≠ dogStage ? MANUAL_MISMATCH
              : selected = dogStage          ? MATCHED
              : FALLBACK_*
riskLevel = 风险(狗阶段, selected)   // 见 2.1
```

`GET /recipes/:id/life-stage-match` 同步支持 `manual`，返回同样的 `matchType` / `riskLevel`。

### 6.2 返回结构（增量字段）

```ts
lifeStageMatch: {
  matchType, riskLevel,          // riskLevel 新增
  selectedLifeStage, selectedLifeStageLabel,
  dogLifeStage?, dogLifeStageLabel?,
  dogId?, dogName?,
  manualLifeStage?,              // 新增：顾客手动选的（没有就不返回）
  message?,
}
```

前端**不再根据 `matchType` 自己拼风险**，只用 `riskLevel` 与 2.2 的状态映射。

**结论只从一个地方来：`/recipes/:id` 的 `lifeStageMatch`。**

- 订购页、DIY 页不再单独请求 `/life-stage-match`（现在两处各请求一次，容易先后不一致）。
- 换狗、换版都走"重新加载菜谱"这一条路，结论和菜谱版本天然同步。
- `/life-stage-match` 接口保留（兼容与后续列表用），但页面不再依赖它。
- `dogId` 传了但狗不存在 / 不属于当前顾客时，一律按 `NO_DOG` 处理，不要退化成"回退版本 + 警示"。
- 整页请求失败（断网、500）用**页面级错误态 + 重试**，不要用版本条的 `unknown`；`unknown` 只处理"菜谱回来了、但没有可用的结论字段"这种半残响应。

**首屏加载顺序要跟着改**：现在是"菜谱先加载、狗后加载"，结论只能靠第二次请求补。改为：

```
取狗列表 → 选定默认狗（上次选的 / 第一只）→ 带 dogId 取菜谱（一次拿齐版本 + 结论）→ 算饭量与价格
```

无狗时跳过第二步，直接取菜谱，结论为 `NO_DOG`。这样首屏不会出现"先显示成犬版、再跳成幼犬版"的闪动。

### 6.3 首页 / 收藏的适配结论

- `GET /recipes?dogId=` 时，每个卡片返回 `lifeStageSuitability: 'EXACT' | 'FALLBACK' | 'NONE'`（只用于角标，不参与排序）。
- `GET /favorites?dogId=` 同样返回。
- 没有 dogId 时不返回该字段。

### 6.4 订单快照

- `RecipeSnapshot` 增加 `series_life_stage?: string`、`series_life_stage_label?: string`。
- 由 `buildProductionRecipeSnapshot` 从菜谱对象写入；订单与试吃装共用，保持形状一致。
- 历史订单无该字段：详情页按 `recipeId` 回查菜谱；查不到就不显示。
- 制作单（DIY）：`diy_sheet` 增加三列（可空）`selected_life_stage`、`life_stage_match_type`、`life_stage_risk`，在**创建时**由页面写入。版本名从 `selected_life_stage` 映射，**不 join 菜谱**——菜谱的 `series_life_stage` 理论上可被改，join 会漂移。
  - 这样制作单上写的是"生成时发生了什么"，而不是"现在再算一遍"，两者不会打架。
  - 需要一条 Prisma migration；老单为空，不显示那行灰字。

### 6.5 下单时"确认的那一版"就是"买到的那一版"

- 下单用 `recipeId` 锁定具体版本，快照记录 `series_life_stage`；后端**不重新按狗推导版本**。
- 价格预览与 `recipeId` 绑定；换版会重置预览，因此"确认 → 提交"之间版本不会变。
- 确认弹窗在提交前同步弹出，确认后立即提交，中间没有可改版的入口。
- 结论：不需要新增"服务端确认凭证"；`life_stage_acknowledgement` 仍是告知凭证，订单快照是履约凭证。

### 6.6 阶段跨越

- `GET /dogs` 每只狗增加 `upcomingStageTransition?: { toStage, effectiveDate, daysUntil }`。
- 只在 `daysUntil <= 30` 时返回；由后端用权威阈值算（前端不重算）。

### 6.7 兼容旧版小程序

**必须做的兼容**：旧版仍会传 `lifeStage` 但不传 `manual`。若把缺省当 `false`，旧版订购页传的版本会被忽略，可能出现"页面显示的版本"和"后端算的版本"不一致。

→ **规则：`manual` 缺省 = `lifeStage` 是否存在**。旧版行为完全不变；新版显式传 `true/false`。

`NO_DOG` 对旧版是安全的：旧版的 `isLifeStageMismatch()` 对未知类型返回 `false`，卡片不显示。

### 6.8 埋点

| 事件 | 时机 | 关键字段 |
|---|---|---|
| `life_stage_bar_shown` | 版本条渲染 | page, state, matchType, riskLevel |
| `life_stage_sheet_opened` | 点"换一版" | page, versionCount |
| `life_stage_version_switched` | 切换成功 | page, from, to, direction(auto/manual) |
| `life_stage_confirm_shown` | 确认弹窗出现 | page, riskLevel, cause |
| `life_stage_confirm_result` | 确认/取消 | accepted, page |
| `life_stage_unknown_shown` | 结论失败 | page |
| `life_stage_no_dog_shown` | 未选狗展示 | page |

现有 `trackFunnelEvent` 通道即可，不新建表。

## 7. 测试计划

### 7.1 后端单测

- 无 dogId → `NO_DOG`；无 dogId + lifeStage → `NO_DOG` 且 selected 为该版本。
- `manual=true` + 版本存在 + 与狗阶段不同 → `MANUAL_MISMATCH`。
- `manual=false` + dogId → 忽略传入 lifeStage，按狗选版。
- 无匹配版本 → `FALLBACK_*`，且幼犬/繁殖期时 `riskLevel=HIGH`。
- `manual` 缺省 + 传 lifeStage → 视为 manual（兼容旧版）。
- 风险分级表逐组合覆盖。

### 7.2 前端回归（更新现有 spec）

现有这些断言会失效，需要同步改：

- `miniapp/src/pages/life-stage-warning.regression.spec.ts`（断言"我已知晓"、`confirmLifeStageMismatch` 在 DIY/订购页）
- `miniapp/src/pages/recipe-order.regression.spec.ts`（断言顶部下拉、`toggleLifeStageDropdown`）
- `miniapp/src/pages/recipe-diy`、`diy-sheet` 相关 spec（断言卡片 props）
- `miniapp/src/composables/useLifeStageVersion.spec.ts`（新增 `manual` / `state`）

新增断言：

- 未选狗时不渲染任何"不匹配"文案。
- 换狗后版本自动正确（不点击）。
- 同一单只出现一次确认。
- 订单详情、制作单能读到版本。

### 7.3 手工验收脚本

1. 游客打开分享链接（无狗）→ 不出现红字；版本条为"去添加"。
2. 登录 + 有幼犬 → 打开一道有幼犬版的菜 → 版本条显示幼犬版。
3. 换成犬狗 → 版本自动变成犬版，出现"已按 X 切到成犬版"。
4. 手动切到成犬版（幼犬狗）→ 琥珀/红条；下单 → 确认一次；留痕出现在后台。
5. 同一单改分装后再次下单 → 再确认一次（新的一单）。
6. 打开一道没有幼犬版的菜（幼犬狗）→ 红条"这道菜没有适合它的版本"；下单 → 确认；取消 → 跳到幼犬筛选。
7. 下单成功 → 订单详情显示版本；再次购买 → 若阶段已变，显示对比。
8. DIY 生成制作单 → 制作单与打印件都有版本。
9. 断网打开订购页 → "暂时无法确认" + 重试；不拦下单。
