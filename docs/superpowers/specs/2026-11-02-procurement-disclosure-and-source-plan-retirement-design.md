## 0. 一句话

订购页不再承诺**单品级**的渠道 / 品牌 / 规格，改为写清「优先顺序 + 断货怎么办」，并承诺采购完成后公开实际采购；订单详情新增「实际采购」，**只展示渠道 + 采购产品名称**，走库存的原料给最近一次真实采购并标注「来自库存」+ 采购日期。同时把「有机 / 商超 / 批发」三档来源方案与「来源等级」字段整体清理掉，算价改为**按该标准原料最近一次采购价**计算（以已确认完成的采购清单为准）。

## 1. 本次拍板的六件事

| # | 决定 | 落地口径 |
|---|---|---|
| 1 | 订购页文案 | 三条固定文案（食材优先商超 / 补剂优先 iHerb / 采购后公开），不说死单品渠道、品牌、规格 |
| 2 | 采购完成后在订单详情公开实际采购 | 采购清单「确认完成」即公开，不再加人工审核 |
| 3 | 订单详情展示什么 | **只展示渠道 + 采购产品名称**；不展示品牌、规格 |
| 4 | 走库存的原料 | `来自库存` + 最近一次真实采购（渠道 + 采购产品名称）+ `库存采购日期：YYYY年M月D日` |
| 5 | 来源方案整体下线 | 三档方案、来源等级字段、匹配逻辑、相关页面与导入字段全部删除 |
| 6 | 算价口径 | 该标准原料**最近一次采购价**（仅取**已确认完成**的采购清单）；无历史 → **创建时采购单价** |

> 边界说明：「不承诺」定在**单品级**——顾客不会被告知「这包鸡胸是泰森 2kg 装」，但会被告知「我们优先去哪些渠道买、买不到怎么办」，以及「这一单实际买的是山姆的泰森鲜鸡大胸」。

## 2. 顾客端看到什么

### 2.1 订购成品页

原料明细只保留**原料名 + 本单用量**。「采购标准」卡改写为「采购与公开」，文案逐字如下：

> 食材优先从山姆、盒马、沃尔玛、永辉等商超渠道采购，若遇无货或断货，再选择农贸市场、团购网站等渠道。
>
> 营养补充剂优先从iHerb采购，若遇无货或断货，再选择亚马逊国际、天猫/京东国际等渠道。
>
> **采购完成后，实际采购的原料将展示在订单详情中。**

排版：前两条常规字重，第三条用绿色强调（承诺句）。后台价格预览接口同步不再下发渠道 / 品牌 / 规格。

### 2.2 订单详情页

位置：商品信息 → 原料清单，每行名称 / 用量下方。

| 订单 / 采购状态 | 顾客看到 |
|---|---|
| 已付款、未生成采购清单 | 「采购完成后，这里会显示每种原料的实际采购渠道和采购产品。」 |
| 采购中（清单未完成） | 同上；已有部分清单完成时，已完成的原料照常显示 |
| 采购完成 | 「✓ 采购已完成 · 11 月 5 日」+ 每行实际采购信息 |
| 试吃装 / 现货单 | 不显示（本来就不采购） |
| 定制单 | 本期不做，后续复用同一接口 |

### 2.3 每行怎么判定

| 情况 | 判定条件 | 展示 |
|---|---|---|
| 本单采购 | 本单所属采购清单里，该原料有采购记录 | `[本单采购]` 渠道 + 采购产品名称 |
| 部分库存 | 有采购记录，且该采购明细的库存抵扣 > 0 | `[本单采购]` + 小字「部分来自库存」 |
| 来自库存 | 无本单采购记录，采购明细库存抵扣 > 0 | `[来自库存]` + 最近一次真实采购（渠道 + 采购产品名称）+ `库存采购日期：2026年10月28日` |
| 无需采购 | 标记「无需采购」且无库存抵扣 | 该行不显示采购信息 |
| 多次采购 | 同一原料在本单有多条记录 | 取最近一条；P2 可展开看全部 |
| 字段为空 | 渠道或产品名缺值 | 只显示有值的；两项都空则整行不显示 |

**「最近一次」的口径**：全库范围内、**已完成**采购清单里的该原料采购记录，按采购时间倒序取第一条。它不等于「本单买的那批」，所以必须用「来自库存」标签和日期说清楚。

### 2.4 不展示

品牌、规格、金额、单价、供应商、员工备注、采购清单编号。接口层也不返回。

## 3. 数据与接口

### 3.1 字段变更

| 表 | 字段 | 类型 | 说明 |
|---|---|---|---|
| `ingredient` | `initial_price_per_purchase_unit` | `Decimal(10,2)` | 创建时录入的采购单价；**只写一次，永不自动更新**；无采购历史时用它算价 |
| `order_item` | `ingredient_source_plan` | — | **删除** |
| `procurement_sku` | `source_tier` | — | **删除**（含枚举 `ProcurementSkuSourceTier` 与索引） |

> 不需要给采购记录加品牌字段——顾客不看了。

### 3.2 订单详情返回（`GET /orders/:id` 内嵌）

| 字段 | 说明 |
|---|---|
| `status` | `NOT_STARTED` / `IN_PROGRESS` / `COMPLETED` |
| `completedAt` | 最近一张相关采购清单的完成时间 |
| `items[]` | 每种原料一条 |
| `items[].source` | `ORDER_PURCHASE` / `FROM_INVENTORY` |
| `items[].channel` | 采购渠道 |
| `items[].productName` | 采购产品名称 |
| `items[].purchasedAt` | 采购日期（库存来源时展示为「库存采购日期」） |

`productName` 取值顺序（兼容老数据）：

1. `purchase_record.procurement_sku_name`（**采购时冻结的商品名** —— 顾客看到的就是当时买的那款）
2. 为空 → 按 `procurement_sku_id` 取当前商品名
3. 仍为空 → 用原料名兜底

> 商品名一律保留渠道商原始写法，不做美化、不删渠道词（老板 2026-11-02 定）。历史订单显示采购当时冻结的名字，不会被后来的商品改名影响。留存清单：`docs/audits/2026-11-02-procurement-product-names-90d.xlsx`。

判定与查询：

1. 查 `purchase_list`：`source_order_ids` 含本单 id，按状态分组。
2. 已完成清单 → `purchase_record`（按 `purchase_list_id`）→ 按 `ingredient_id` 取最近一条 → `ORDER_PURCHASE`。
3. 未命中的原料 → `purchase_item.stock_deducted_quantity > 0` → 全库最近一条该原料采购记录 → `FROM_INVENTORY`。
4. 都没有 → 不返回该原料。

> 现状约束：采购清单与订单是「多对多」（清单记 `source_order_ids`，一单也可能出现在多张清单），所以只能做到「订单级 + 原料级」，做不到「这一袋是哪个批次」。这正是库存来源要单独标注的原因。

## 4. 来源方案下线与算价改造

### 4.1 现状

- 食材 SKU 上有「来源等级」（有机 / 商超 / 批发）。没标的 SKU **不参与算价**。
- 算价时按固定的 `MARKET_PREMIUM`（商超优先）回退链挑一个 SKU，并在同档里**挑单价最高的**。
- 采购清单的建议 SKU、生产标签的选品、试吃装参考价都跟着这套逻辑走。
- 顾客在下单页看到的渠道 / 品牌 / 规格，就是这套算法挑出来的。

### 4.2 新算价口径

1. 取该**标准原料**最近一次采购记录，**只认已确认完成的采购清单**。
2. 单价 = `实付金额 ÷ 实际入库数量`，再折算到该原料的采购单位（复用现有 `buildPurchaseRecordPricingBasis` 的算法）。
3. **合理性校验**：若该价格与参考价（创建价 → 商品参考价 → 当前价）相差超过 5 倍，视为采购记录录错，跳过该条、记 warn，不用于算价。
4. 没有可用采购价 → 用 `initial_price_per_purchase_unit`（创建时单价）。
5. 创建价也为 0 / 缺失 → 用「商品参考价」（该原料所有启用商品基础单位成本的**中位数**）。
6. 仍为 0 → 当前价；再没有 → 0，并在后台列出「缺算价依据」的原料。

**精度**：算价单价保留 **6 位小数**。很多原料的采购单位就是 1g（`purchase_to_base_ratio = 1`），单价只有 0.0037 这种量级，按 2 位小数会被抹成 0（实测影响 48 个原料）。

**只影响成品鲜食 / 试吃装算价**；补剂商城仍用现有口径，`ingredient.current_price_per_purchase_unit`（加权均价）保留不动。

### 4.3 与旧口径的差别

|  | 旧 | 新 |
|---|---|---|
| 依据 | 商超档里**最贵**的 SKU 价 | 最近一次**真实采购**价 |
| 数据范围 | 商品档案 | 已完成的采购清单 |
| 更新时机 | 报销审批后写加权均价 | 采购清单完成后，**下一条新订单**生效 |
| 没有数据 | 直接拦住下单 | 用**创建时单价** |
| 运营干预 | 改 SKU 的来源等级 | 无需干预；想调价就改采购价或创建价 |

### 4.4 影响（必须提前知道）

- **售价会变**，大概率下降（旧口径取最贵的一档）。上线前必须出「20 道公开食谱 · 改前 / 改后」对比表。
- 老订单价格不变（下单时已冻结在快照里）。
- 员工改分装规格会按**当时**的算价口径重算（与今天行为一致）。

### 4.5 迁移

1. 加 `ingredient.initial_price_per_purchase_unit`（DECIMAL(14,6)），存量按**迁移前正在使用的口径**回填：来源等级优先 MARKET_PREMIUM → ORGANIC → WHOLESALE，同档取最高单价，折算到采购单位；没有可用商品用当前价。
   - 为什么不回填「最早一条价格变更的变更前价格」：历史上改过采购单位（g ↔ kg），老价格会差上千倍（实测出现 45 元/g 这种值）。
2. 切算价逻辑，跑对账。
3. 对账通过后删来源方案与来源等级字段（不可逆）。

### 4.6 上线前对账结果（2026-11-02，生产只读库）

| 指标 | 结果 |
|---|---|
| 参与对比的原料 | 116 个 |
| 价格不变 | 97 个（83.6%） |
| 上涨 / 下降 | 8 个 / 11 个 |
| 加权平均变化 | +4.8% |
| 0 元原料 | 0 个 |
| 判定为「采购记录录错」而跳过的原料 | 6 个（鹿腿肉、生蚝、巴旦木、姜黄粉、火鸡胸、鸭肝） |
| 变化 ≥30% 的原料 | 10 个（生菜 +336%、羊肚菌 +189%、胡萝卜 +139%、鸡心 +137%、红薯 +44%、白蘑菇 +33%、猪里脊 −30%、鸭蛋 −56%、牛脾 −65%、上海青 −80%） |

> 结论：口径切换后绝大多数原料价格不动；变化大的都是**最近一次采购价**与旧「最贵商超 SKU」确实不同，属于规则预期内。6 条录错的采购记录（实际入库数量换算异常）已跳过，建议运营核对后修正。
>
> 逐条明细：`docs/audits/2026-11-02-recipe-pricing-change-review.xlsx`（10 个变化超 30% 的原料 + 6 条录错记录 + 116 个全量对比）。

**2026-11-02 已执行的数据修复**（生产库，用户确认）：

- 6 条入库数量录错的采购记录已修正（巴旦木、鹿腿肉 ×2、生蚝、火鸡胸 ×2），采购金额与报销单未动，备注里留了修正前后与原因。
- 鸭肝「12kg/件 · ¥10.2」的商品档案已停用（同类鸭肝 1kg 装 ¥19.8 仍启用）。
- 姜黄粉的 1kg 装 ¥21 商品档案本身正常，坏记录继续被算价校验跳过，不做改动。
- 修复后这 4 个原料重新按真实采购价算价：巴旦木不变、鹿腿肉 +6%、火鸡胸 +14%、生蚝 −48%。

## 6. 建议顺序

> 仓库规则要求一个模块一次改完、可回滚。按「后端 → 后台 → 小程序」推进，共 3 个任务。

1. **后端（含数据迁移）**：先加字段、算价依据与披露查询；对账通过后再删列。
2. **后台**：算价依据只读卡、删来源等级。
3. **小程序**：订购页文案与去承诺、订单详情公开、员工端预览。
4. **验收**：内部订单跑一遍「下单 → 采购完成 → 顾客看到」。

## 7. 风险

| 风险 | 处理 |
|---|---|
| 算价改口径后售价波动 | 已做 116 个原料对比（97 个不变，平均 +4.8%）；上线前再跑 20 道食谱整单对比 |
| 创建价回填不准（历史改价 / 采购单位变更） | 存量按迁移前口径回填；不同量级的不采用，回落商品参考价 |
| 商品名较长或含渠道词（渠道原始名） | **已决定保留原名**，不美化、不删词；订单详情允许换行，不截断 |
| 库存原料展示的「最近一次」与实际不符 | 标签与日期写清是库存采购日期；不写「本单采购」 |
| 删列不可逆 | 先停用、对账通过后再删；备份受影响字段 |
| 跨模块改动 | 按模块拆成 3 次任务，每次跑该模块全量测试 |
