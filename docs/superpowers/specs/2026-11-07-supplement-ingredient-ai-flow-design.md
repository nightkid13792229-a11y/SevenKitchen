## 0. 一句话

补剂不再从"拍照认标签"开始，而是从**一个商品链接、或一句话、或直接手填**开始：AI 把商品挑出来、把标签读成"每粒"、把标准原料档案和营养档案填好，人只做**判断和核对**；写入后仍然要人点一次「确认可用」，才进配方。

## 1. 为什么做

### 1.1 现状（截至本稿）

| 位置 | 现在是什么 | 问题 |
|---|---|---|
| 「AI 添加原料」入口 | 第一屏是食材 / 补剂二选一，**补剂是硬闸门**（`lineEntry.ts` + `ai-agent/index.vue` 的 `SUPPLEMENT` 分支），点了直接挡回："补剂线还没开放" | 补剂加原料没有 Agent 入口 |
| 「新增补剂」弹窗（`SupplementOptionForm.vue`） | 第一步是**拍照/上传包装标签**，OCR 出文字，人要自己把名称、用量单位、营养基准、每份重量、一格一格的营养素填进去 | 半成品；识别出来的字没有落到字段上，等于还是手抄 |
| 「补剂识别」页签（`IngredientNutritionGovernancePanel.vue`） | 另一套上传标签 → 出草稿 → 确认写入营养档案 | 与上面重叠，两个入口做同一件事 |
| 真实工作方式 | 九成从 **iHerb** 商品链接开始，少量淘宝/京东 | 起点是**链接**，系统等的是**照片**，对不上 |

**一条必须记住的事实**：现在**唯一**能让补剂进配方的路，是那个半成品弹窗。直接走标准原料表单也能建出 `type=SUPPLEMENT` 的记录，但它不建 `nutrition_food` + mapping，而配方选原料只认 `nutritionFood.status = VERIFIED`（`recipe-designer.service.ts` 的 `listIngredientOptions`）。所以**新流程必须自己把营养档案建全**，否则删掉旧弹窗等于把补剂这条业务线断开。

### 1.2 补剂为什么不能照抄食材线

食材是"某种食材"，补剂是"**某个品牌的某个商品**"——一条标准原料就对应一瓶东西。由此有五条硬差异：

1. **单层产品模型**：品牌、规格、渠道、采购价、剂型都挂在同一条标准原料上，没有"原料 / 商品 / SKU"三层。
2. **计量口径是粒**：标签按"每份 N 粒"给数，档案要按"每粒"记，中间必须折一次，且折法要留在明面上。
3. **合规命名靠目录**：标签上印的名字必须取自《饲料原料目录》/《饲料添加剂品种目录》，且不带剂型。目录是**命名依据**，不是选品门禁。见 §1.3。
4. **选品本身是判断**：同一营养素有好几种化学形态，选哪瓶需要专业判断，不是查表。
5. **标签要能翻旧账**：商品可能下架、改规格、换包装，当时那瓶的标签必须留得下来。

### 1.3 调研结论（2026-11-07）

**（a）本地知识库可用，但它是"原料"，不是"规则"。**

`docs/knowledge-base/` 里有 159 份文献、20,658 条段落、500 张已校验表格。和补剂直接相关的：

| 文献 | 段落数 | 能支撑什么 |
|---|---|---|
| NRC 2006《犬猫营养需要》 | 3,337 | 营养素需要量、缺乏与过量 |
| FEDIAF 2025 营养指南 | 432 | 微量元素生物利用率受钙/植酸影响；氧化铜不能作为铜源 |
| SACN5《小动物临床营养》各章 | 3,000+ | 矿物质功能、缺乏症、补剂使用 |
| WSAVA / AAHA 各指南 | 1,000+ | 临床立场与建议 |

结论：**"为什么这个形态更好"这类知识有出处**，但"哪一档算过关"这个**判断阈值**没有现成的，必须写下来并由人签字。见 §4.2。

**（b）《饲料添加剂品种目录》能拿到、能解析，而且本身就是一道门。**

已实际下载并解析（全国畜牧总站 / 全国饲料评审委员会发布的汇总版，65KB docx，29 段 + 5 张表，截至 2025 年 6 月）：

- 源地址：`https://www.nahs.org.cn/xxcm/slpj/202109/P020250714562168149044.docx`
- 公告原文：农业农村部第 2045 号（2013-12-30 发布，2014-02-01 实施，后经多次修订）

- 表结构：`类别 / 通用名称 / 适用范围`，**适用范围里直接写"犬、猫"**，可机器读。
- 例：`矿物元素及其络（螯）合物` 下确有 **甘氨酸锌**（适用范围：猪、犬、猫）、**蛋氨酸锌络（螯）合物**、**葡萄糖酸锌**（表四，适用范围：犬、猫）。
- 反例：**吡啶甲酸锌在全文出现 0 次**——目录里只有"吡啶甲酸铬"，没有"锌"。

**目录不参与选品排序。** 选品从狗的健康出发：先看吸收和安全，再看人用还是犬用，最后比性价比。目录是**查名字**用的——选完之后，用它在档案上填「标签名称 / 名称依据 / 标签类型」。

但这条反例要记住：**选中的形态如果在目录里查不到名字，标签名称就是空的**，只能人工填、并且要有人负责。界面表现是留空标红，不是退回去改选。

> 注：《饲料原料目录》（2038 号及历次修订）尚未取全文；鱼油这类"原料"归它管，不归添加剂目录管。这一步留给实施前补。

## 2. 目标与非目标

**目标**

- 在**同一个页面**里把「挑一款」「建标准原料」「写营养档案」做完，不跨页。
- AI 负责检索、比对、抽取、折算、按目录查规范名；人负责**判断**和**核对**。
- 每份 → 每粒的折算写在明面上（`650 ÷ 2`），事后能回查。
- 写入前 3 道门禁；写入后人工确认可用。
- 写入后**留得下**当时那张商品标签（原图 + 原文 + 每份粒数）。

**非目标**

- 不做分装方案、等价组、预装上架——另立，不进这条流程。
- 不做采购执行、比价下单；只记采购价和换算倍数，够算成本即可。
- 不改食材线的流程、字段与文案。
- **不做商品主数据**（不维护"候选商品库"）；每次选品都当场检索。
- 补剂**不计入**食谱总重量（见 §7）。

## 3. 三条入口，两个状态

| 入口 | 什么时候用 | 落到哪 |
|---|---|---|
| **A · 贴链接**（九成） | 手里已经有商品链接（iHerb / 淘宝 / 京东） | 直接进对照屏；顺手比 2 个替代品，结论压成一条绿条，点开才看明细，**不打断建档** |
| **B · 说一句话**（"给狗狗加个锌"） | 还不知道买哪瓶 | 先进选品屏，比完点一个 → 进对照屏 |
| **C · 手动录入** | 链接读不出（反爬 / 下架 / 改版），或手上没有链接 | 直接进对照屏，**左栏空着、右栏全可手填** |

入口 C 是兜底，不是副路径：**读不出就换链接，换不到就手填**，两条都在同一个页面里完成，不需要回旧弹窗。

两个状态共用一个路由、一份草稿，靠草稿的 `step` 区分：

| step | 左栏（证据栏） | 右栏（档案栏） |
|---|---|---|
| `PICK` | 候选对比（四列） | 判断表 + 结论 + 动作按钮 |
| `PROFILE` | 选中那瓶的**标签原样**（手填时为空壳，可上传图片补齐） | 标准原料档案 + 营养档案 + 门禁 |

## 4. 选品屏

一张表：四列候选 × 五行判断。

| 行 | 看什么 | 规则 |
|---|---|---|
| ① 化学形态 | 这个形态对狗安不安全、好不好吸收 | 螯合/氨基酸络合优先于离子型；按形态本身判，不看品牌 |
| ② 人用还是犬用 | 一律先人用 | 除非**有明确研究**指出犬用更优（例如必须上缓释技术），否则不破例；破例要写明依据。饲料级/不可零售算这一层——它进不了我们的货 |
| ③ 性价比 | 每 1000mg 有效成分的单价 | 鱼油按 EPA+DHA 合计；矿物质按**元素量**，不按化合物总量。前两层打平才比 |
| ④ 结论 | 选它 / 留着 / 不划算 / 不能用 | 被上面任一行淘汰的，后面不再算，显示"—" |

> 《饲料添加剂品种目录》**不出现在这张表里**。它只用于选定之后的命名步骤（§6）。

### 4.1 四条不能含糊的规则

1. **顺序不能倒。** 先形态、再人用犬用、最后比价。从狗的健康出发；"便宜"不能反过来影响前两层。
2. **进不了货的不进性价比。** 饲料级、不能分装零售、没有零售包装——这是"进不了我们的货"，判"不能用"，不能算成"贵"。
3. **逐层淘汰。** ⓪不过的不进①；①不过的不进③。表上要看得出来是被哪一层淘汰的。
4. **口味/型号不做判断依据。** 只比这四层；其它差异放备注，不参与排序。

### 4.2 三层判断的规则文本由谁出

这部分是**专业内容，不是代码**。做法：

- 我按 §1.3 的知识库出处起草一份「补剂选品判断规则」（含：常见矿物质/维生素的形态优劣、哪些形态必须排除、犬用破例的判据），放在 `backend/skills/ingredient-agent/` 下，与现有三份食材 skill 同规格：markdown、可版本化、可评审。
- 老板逐条签字后才生效；每条结论要挂出处（NRC / FEDIAF / SACN5 的章节）。
- 目录白名单**不进 skill**，进数据表（见 §11），因为它随公告修订而变。

### 4.3 动作

`就选它，往下建档` / `我贴链接` / `换一批候选`。

> 原稿的「三个都先存着」已删：没有真实需求，还要多养一条"候选暂存 + 恢复"的链路。

## 5. 对照屏

左边**钉住不动**，右边滚：

| 栏 | 内容 | 为什么在这一栏 |
|---|---|---|
| 左 · 商品卡 | 品牌、规格、每份几粒、剂型、人用/犬用 | 一眼确认"是哪瓶" |
| 左 · 标签原文表 | Supplement Facts 原样（Serving Size 行必须在） | 唯一的**证据**，只读 |
| 左 · 算一下 | 每瓶份数、每份价、每 1000mg 有效成分价 | 性价比那层要用的数 |
| 左 · 标签原图 | 可点开放大 | 表格读错时能对原图 |
| 右 · 选品摘要条 | 已选 + 一句话结论 + "回头比了什么 ▾" | 贴链接进来的也要能回看比较 |
| 右 · 标准原料档案 | 折叠组 + **待你定** + 标签名称（AI 填、带依据） | 一次只展开要改的 |
| 右 · 营养档案（每 1 粒） | 有值的行 + 折算算式；没写的行收起 | 避免十几行空表 |
| 右 · 门禁条 | 3 道门的通过状态 + 存草稿 / 核验并写入 | 最后一道关 |

**联动**：点右栏任一格 → 左栏对应行高亮。**左右互不改写**——左栏是证据，只读；右栏是结论，可改。

**折叠规则**（右栏只展开两样东西）：

- **你要改的**：待你定的字段，永远展开、标黄。
- **有值的**：标签上写了数的营养素，展开并显示折算；标签上没写的不猜、留空、收起。

## 6. 字段归属

| 字段 | 谁填 | 来源 |
|---|---|---|
| 原料名称 | AI | 商品名 + 营养素，按目录收口 |
| 原料类型 | 固定 | 补剂 |
| 基准单位 / 单位展示名 | AI | 剂型决定（粒 / 片 / 胶囊 / 平勺） |
| 产品品牌 | AI | 商品页 |
| 产品规格 | AI | 商品页（含每份几粒） |
| 采购渠道 | AI | 链接域名（iHerb / 淘宝 / 京东） |
| 当前采购价 | AI | 商品页 |
| 采购单位 / 换算倍数 | AI | 规格（1 瓶 = N 粒） |
| 物理形态 | AI | 剂型（粉 / 片 / 胶囊 / 液体） |
| 生产损耗率 | AI 给默认 | 全局默认 1.05，人可改 |
| 用于 DIY 推荐 / 采购生产 | AI 给默认 | 人可改 |
| **标签名称** | **AI** | 选定后才查目录取规范名；查不到就留空标红，**不猜** |
| **标签类型**（饲料原料 / 饲料添加剂） | **AI** | 跟着"查的是哪本目录"走：添加剂目录命中 → 饲料添加剂；原料目录命中 → 饲料原料 |
| 名称依据 | AI | 查到的目录 + 版本 |
| **标签分类** | **人** | 原料身上挂的标签（多选，可快速新建）——**与"标签类型"不是一回事** |
| **添加时机** | **人** | 制作中 / 成品后添加 |
| 营养素值（每粒） | AI | 标签 ÷ 每份粒数 |

标签名称的口径（沿用现有表单提示）：用目录里的规范写法，**不带"片 / 胶囊 / 粉"这类剂型**；复合补剂**按营养素逐个填写**。

## 7. 计量口径

- 基准单位：`个/件（PCS）`；单位展示名 = 粒 / 片 / 胶囊 / 平勺（跟商品一致）。
- 营养基准：`每 1 粒`（现有词汇 `PER_SERVING` + 单位"粒"）。
- 标签写 `Serving Size 2 Softgels` → **每粒 = 每份 ÷ 2**，折算必须显示（`650 ÷ 2 = 325`）。
- 标签写 `Serving Size 1 Softgel` → 1:1，也照样显示，不隐藏。
- 每份粒数 N 必须是 ≥ 1 的整数；拿不到 N 就拦在门口，不许猜。
- **折算只有服务端一处**：接口收的是「标签每份值」，服务端除以 N 再写库；客户端送来的每粒值只用于核对，对不上就 400。页面上那一行 `÷ 2 = 325` 只是预览。

**补剂不计入食谱总重量。** 现有评估口径已经是这样：`resolveIncludedFoodTotalWeightG()` 只累加 `type = FOOD` 的配料，补剂的目标浓度按「每 kg 食材」算。因此：

- **不加「每粒重量(g)」这个字段**，档案里也不需要 `meta.servingWeightG`。
- 旧稿里"1 粒当 1 g 估"的说法作废——按现有代码，新建补剂在总重里记的是 **0 g**，与"补剂不计重"的口径一致，不需要修。

## 8. 门禁（写入前 3 道）

| # | 门 | 判什么 | 不过怎样 |
|---|---|---|---|
| 1 | 折算闭合 | 每粒值 × N 必须回得到标签每份值 | 拦死，标红那一行 |
| 2 | 单位闭合 | 基准单位（粒）与营养单位（mg/g）不串；每份粒数 > 0 | 拦死 |
| 3 | 成本可算 | 采购价 × 换算倍数 → 每粒成本有值、> 0 | 拦死 |

点门禁条上任一条 → 跳到对应字段。

不列入门禁但**会禁用写入按钮**的：标签分类、添加时机未填（这两项是人定的，不存在"判错"，只有"没填"）。

**查重不进这道门**：不做成第 4 道门禁，改成写入前的**提醒**——"库里可能已经有这条（同品牌 + 同规格，或同营养素已有档案），要不要并过去"。理由是 AI 每次起的名字可能不同（"Nordic Naturals Ultimate Omega" vs "挪威小鱼鱼油"），靠 `@@unique(name, brand, productModel)` 挡不住，但也不该因此拦住一次正确的建档。

## 9. 写入与确认可用

- 写入是一个事务，落**三样**：标准原料、营养档案（`NutritionFood` + mapping）、**标签证据**（见 §11）。
- 营养档案初始状态 `待验证`（与食材线一致）。
- 写入成功后页面出现「**确认可用**」；点了才会进配方、制作单、DIY 推荐。
- 没点之前，档案在库里存在，但配方里选不到。

## 10. 异常与降级

| 情况 | 处理 |
|---|---|
| 链接读不出（反爬 / 下架 / 改版） | **换链接**，或**直接手动录入**（入口 C）。不弹旧页面 |
| 成分表是图片 | 走视觉模型读图；读出后进左栏"标签原文表"，标注"来自图片识别" |
| 目录查不到规范名 | 标签名称留空标红，人填；不猜、不套近似名 |
| 商品页有多个规格 | 让用户选规格，再继续 |
| 标签没有"每份几粒" | 拦在门口，要求人补 |
| 淘宝/京东（非 iHerb） | 同一套流程，读不出的概率高，走同一兜底 |

## 11. 与现有代码的关系

**复用**

- 草稿 `IngredientCreationDraft`（`type = SUPPLEMENT`），`step` 增加 `PICK`（varchar，不需要 migration）；现有 `INTAKE / SOURCES / PROFILE / CHECK / INGREDIENT / COMMIT` 保留给食材线。

## 13. 验收口径

1. 贴一个 iHerb 链接，**不用手填任何字段**，能走到门禁条。
2. 链接读不出时，能在同一个页面里手填完并写入，不需要回旧弹窗。
3. 标签写"每份 2 粒"的，营养档案里写入的是**每粒值**，界面上看得见 `÷ 2`。
4. 三道门任一不过，**写不进去**；过了，写入后是"待验证"，要人点「确认可用」才进配方。
5. 标签名称不带剂型；目录里查不到时是**空的**，不是猜的。
6. 选品屏里**不出现目录这一行**；目录只在命名步骤用，查不到名字时留空标红，不退回改选。
7. 写入后，能翻出当时那张标签原图、原文和每份粒数。

## 14. 仍需拍板

1. **《饲料原料目录》要不要也在实施前取全文**：鱼油、酵母这类"原料"不归添加剂目录管；不取全，这类补剂的标签名称只能人工填。
2. **旧入口下线的时间点**：新流程验收到位之前，旧弹窗要不要先留着？建议——先留着，新流程跑通一批真实补剂后再删。
3. **候选从哪来（入口 B）**：现有网页检索是**域名白名单**制（只放营养库站点），iHerb / 淘宝 / 京东会被拒。要新开一条电商抓取通道。这条决定入口 B 能不能成立；入口 A（贴链接）无论如何都要这条通道。
