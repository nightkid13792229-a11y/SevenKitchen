# 库存台账与盘点方案

> 2026-11-09 · 决策来源：2026-11-08 ~ 11-09 与老板的对话（见附录 A）。
> 台账口径由老板拍板；技术实现留给实现者（第 12 节）。
> UI 与交互不在本文范围，方案定稿后单独做。

---

## 0. 一句话

把库存从「只进不出的估算账」，改成**每笔进出都有来源、有经手人、差异要复核**的台账。
代价：员工日常不多做任何动作；只多一件事——**每半个月盘一次库（全盘）**。

---

## 1. 背景：现在的账为什么不准

不是公式错，是记账方式没按公式走。三条结构性原因：

1. **日采原料完全不进账。**
   `inboundFromPurchaseRecords` 只处理 `STOCK_REPLENISHMENT / HYBRID` 两种策略，
   `usesInventoryForRequirement` 也只对这两种抵扣库存。
   所以日采原料「买不进、用不掉、永远 0」，而它恰恰是每天在动的那批货。

2. **出库有两套口径，同时在跑，且都不完整。**
   - 按锅扣（`KITCHEN_TASK`）：配方理论用量，但由
     `global_config.autoDeductInventoryOnProduction` 控制，**出厂默认关**。
   - 按预占扣（`PRODUCTION_ALLOCATION_CONSUMPTION`）：批次结算时**总是**执行，
     但只覆盖「事先用库存抵扣掉的那部分」。
   结果：库存原料在本批被买进来、又被用掉的那部分**从来没扣过**；账面永远领先实物一批。
   若把开关打开，两条通道叠加，同一批料会被扣两次。

3. **没有经手人、没有复核、流水可删。**
   `InventoryStocktake` / `InventoryAdjustment` / `InventoryLedgerEntry` 都没有
   操作人字段；盘点只有 `DRAFT / APPLIED` 两态，任何员工一点就入账；
   采购「撤回完成」会 `deleteMany` 删掉入库流水。

> 这三条合起来，就是「账面只涨不跌 / 差异说不清 / 查不到是谁」。
> 补货建议、库存页、盘点记录都建在这个账上，所以先修账，再谈界面。

## 2. 目标 / 非目标 / 反目标

### 目标

| # | 目标 | 怎么算达成 |
|---|---|---|
| G1 | 账目完整 | 每次实物进出都有对应流水，无「无来源」变动 |
| G2 | 差可得 | 账面与实物的差，能在下一次盘库被量化、被归因 |
| G3 | 可追责 | 每笔变动有操作人 + 时间；盘点有提交人/复核人 |
| G4 | 零额外日常人工 | 除盘库外，员工不新增称重、不新增填单 |

### 非目标（本期不做）

- N1 不追求逐克精确：员工不逐样称重，出库用配方理论量。
- N2 不动订单成本口径：成本仍按「当前价 × 配方用量」算。
- N3 不做多仓/库位：冻库与包材区视为一个逻辑仓。
- N4 不做批次/效期追踪。
- N5 不管成品库存：鲜食成品不留库；试吃装备货是另一条线。

### 反目标（这样算失败）

- **A1** 为了准，让员工每天多填一张单 → 一定没人填。
- **A2** 复核变成堵点：盘点单压一天，账就旧一天。
- **A3** 盘库变成「照着账面抄」（明盘）。

## 3. 核心模型：一本账、七个动作

**这本账只回答一件事：东西去哪了。** 任何不在下表里的动作，最后都会变成盘点差异。

| # | 动作 | 触发点 | 账上 | 数量依据 | 操作人 |
|---|---|---|---|---|---|
| 1 | 采购完成 | 员工点「完成采购」 | **＋入库** | 采购记录的实际数量（换算到基准单位） | 员工 |
| 2 | 一锅做完 | 员工点「完成」 | **−食材 / 补剂** | 配方理论用量（含损耗） | 员工 |
| 3 | 补剂分装 | 员工分装 | −补剂原料 | 每袋克数（已有实现） | 员工 |
| 4 | 装袋贴标 | 发货确认 | −真空袋 / 标签 | 袋数 × 该袋规格 | 员工 |
| 5 | 装箱发货 | 发货确认 | −泡沫箱 / 保温袋 / 冰袋 | **包裹数** × 箱型 | 员工 |
| 6 | 盘库 | 每半月任务 | **± 调整** | 实称 | 员工盘 → 管理员复核 |
| 7 | 报废 / 内部领用 | 员工记一笔 | **−** | 人工填 + 选分类 | 员工 |

### 四条硬原则

- **P1 一源一笔**：每笔流水都有 `sourceType + sourceId`，唯一约束防重复。
- **P2 只增不删**：撤销用**同源负数冲红**，不删历史行（采购撤回也改成冲红）。
- **P3 谁做谁留名**：入账、盘点、复核、报废都记操作人。
- **P4 一套出库口径**：食材/补剂只认「配方理论用量」；包材只认「包装数量」；
  预占只负责「占用」，**不再扣账**。

## 4. 进：采购入库

| 项 | 规则 |
|---|---|
| 时点 | 采购单「完成采购」时 |
| 范围 | **日采 + 补货，全部入库**（取消策略判断） |
| 数量 | 采购记录的 `actualBaseQuantity`（录入时已换算到基准单位） |
| 前提 | 自动排单有「采购未完成不能排单」的门禁；**手工建批次没有**（只校验订单状态）。一期补上排产门禁；紧急情况允许管理员强制排产并留痕 |
| 负库存 | 不拦（配方理论量可能大于进货量），但标红 + 进「待核实」清单；连续为负要提醒 |
| 报销 | 可以延后，不影响入库时点 |

### 在途与净额（二期）

- **在途**：已下单、未完成采购的数量，不写流水，但要从「可用量」里扣掉，否则会重复下单。
- **净额下单**：需求 −（现存 − 已预占 − 在途）。
- ⚠️ 顺序不能反：**先把入库/出库记准，再启用净额**。账没准就净额，会出现「系统说还有、实际没了」→ 断货。
- ⚠️ 日采启用净额时，必须同步启用**预占**，否则两天的订单会抢同一袋虾。

## 5. 出：生产扣料

### 5.1 食材 / 补剂

- 唯一入口：`backend/src/application/production/production-ingredient-usage.ts`（已在，口径统一）。
- 食材：`净产出 × 损耗率 × 克数占比`。
- 补剂：按营养素目标定量（回退到配比）。
- 时点：包装单元（一锅）状态变为 `COMPLETED` 时。
- 幂等：`(sourceType, sourceId, ingredientId)` 唯一约束。
- **批次结算不再扣账**：`consumeAllocationsForOrderIds` 改为只把预占标为 `CONSUMED`，
  不再写 `PRODUCTION_ALLOCATION_CONSUMPTION` 流水。
- 开关：`autoDeductInventoryOnProduction` 改为**开**；开启前必须先做一次期初盘点（见 7.5）。

### 5.2 包材（不走配方，按包装动作）

包材单位各不相同，但「用几个」系统已经算过，而且**已经存进每一单的价格快照**
（`Order.pricingBreakdownSnapshot.packagingDetails`）。扣库存直接读快照，不用重算，
也不会因为以后改规则而变化：

| 包材 | 单位 | 扣几个 | 来源 |
|---|---|---|---|
| 食品真空袋（4 规格） | 个 | 每袋 1 个，**规格按该袋克重选** | 快照 `vacuumBagsCount` + 袋型 |
| 产品标签 | 张 | 每袋 1 张 | 快照 `labelsCount` |
| 泡沫箱（多规格） | 个 | **1 个运单 = 1 个箱子**（老板确认）；箱型发货时选 | 发货单 |
| 铝箔保温袋 | 个 | 每箱 1 个 | 按箱号适配 |
| 冰袋 | 个 | 4 号箱 3 个、3 号箱 5 个 | 箱号映射 |
| 自封袋 / 干燥剂（补剂） | 个 | 按补剂分装规则 | `SupplementPackagingRule`（POUCH / DESICCANT / LABEL） |

- **时点**：发货确认时一次扣。袋数在发货单上也有快照（`OrderShipmentOrder.totalBags`）。
- **箱型**：老板确认「一张快递单 = 一个泡沫箱，规格自己选」。
  所以发货确认时加一个箱型选择：**默认按总重推荐**（复用现有贪心算法），可以改。
  这是包材里唯一新增的人工动作，大约一次点击。
- **保温袋、冰袋跟着箱号走**，选了箱型就自动带出，不用手填。
- **备货/试吃装**：成品是现货，袋子和标签在**分装完工时**就用掉了，不走发货确认，
  所以在 `PackagingUnit COMPLETED` 时扣；给试吃装订单再走发货扣袋会重复。
- **合并发货**：箱/保温袋/冰袋按**包裹**扣（一个运单＝一个箱子），袋和标签按各单袋数扣。
- ⚠️ **定价口径没动**：合并发货时，价格快照仍按「每单一个箱子」计费，实物只用 1 个。
  这是定价问题、不是库存问题，本方案不处理，仅记录（见 §13）。
- 现有 `supplement-packaging.service.ts` 明确写着「本轮不扣包材库存，只算需求量」——本期把它接上。

## 6. 调整：报废 / 内部领用

| 项 | 规则 |
|---|---|
| 分类 | 内部领用 / 过期报废 / 破损污染 / 其他（后台可增删） |
| 入口 | 库存页「记一笔」，选原料 + 数量 + 分类（约 30 秒） |
| 审批 | **内部领用免批**；**报废单笔 ≥ 50 元 → 待复核**；低于阈值直接入账 |
| 成本 | 单列科目，**不摊进订单成本** |
| 顾客退货 | 仅退款，不涉及实物，**不进库存** |

> 「内部领用」是老板定的名字：描述「东西去哪了」，不指向「谁吃了」。
> 记录里可以带用途备注，但分类名不再出现「员工餐」。

**金额怎么算**（评审补）：

- 按「**发生当时的单价**」快照到流水行（`costAmount`），不用现价——
  否则改一次价，上个月的报废总额就变了，报表对不上。
- 单价为 0 或换算比例没配的原料：报废**一律走复核**，不自动放行。

## 7. 盘：盘库与复核

### 7.1 频率与提醒

- 默认**每月 1 号、16 号**（半个月一次），后台可改。
- 提前 1 天在工作台弹提醒；过期未盘标黄。
- 排期必须是**具体日期**，不能是「大约每 15 天」。

### 7.2 范围

**期初盘点（上线前那一次）**：食材 + 补剂，**全部原料，包括账面为 0 的**。
因为现有账本来就不可信，账面 0 的原料冰箱里可能还有货——漏掉就等于把库存永久藏起来了。

**日常盘点（每半月）**：
- 默认**有账面余额、或本期有变动**的原料（老板说的「所有」，落到日常就是「所有真实存在的货」；
  账上为 0 且半年没动过的进清单只会让人乱填，正踩反目标 A1）。
- 期初盘过、之后一直没动、余额为 0 的，不进日常清单。
- 补剂按粒/片**点数**，不称重；食材按称重。

**包材**：不在前两期的盘点范围内。三期把包材扣减接上时，**单独做一次「包材期初」**，
之后才纳入常规盘点。否则包材只进不出，每半个月会算出一笔大额假盘亏。

后台可把范围改成「指定清单」，供临时抽盘。

### 7.3 盲盘

- 默认**不显示账面数**，员工只填实称；提交后才看差异。
- 理由：看到账面就会照着填，盘点就失去意义（反目标 A3）。
- （**这是我的判断**，老板未明确表态，可调。）

### 7.4 状态机与容差

```
DRAFT ──提交──> SUBMITTED ──复核通过──> APPLIED
   ↑                │
   └────驳回────────┘ (REJECTED，可改后重提)
```

- 员工只能编辑 `DRAFT` / `REJECTED` 的单；`SUBMITTED` 后锁定。
- **容差**：差异 ≤ max(2%, 50g) 自动通过、仍留记录；超容差进 `SUBMITTED` 等管理员复核。
  （小数量用绝对值兜底，避免 50g 的原料 2% 只有 1g，天天报警。）
- **差异在建单时算定**（相对当时的账面），复核只决定放行/驳回，**不改数字**。
  盘点之后每一笔进出都会同时改变账面和实物，差额不变，所以不存在「复核时要重算」。
  ⚠️ **不要**用复核时的账面重算 delta：那会把复核窗口里的真实消耗记成盘盈。
  （2026-11-09 评审纠正：初稿写的「按复核时账面重算」是错的。）
- 单笔盘点只允许入账一次（`APPLIED` 幂等）。

### 7.5 期初盘点（上线前置）

- 现在的账面不可信，上线前必须**全盘一次**，把实称当起点。
- **旧流水归档不删**：在账本里加一条「期初结转」的调整（`MANUAL_ADJUSTMENT` 或新增 `OPENING_BALANCE`），
  让余额等于实盘，而不是清空历史。

## 10. 分期

| 期 | 内容 | 为什么排这个顺序 |
|---|---|---|
| **一期** | 全量入库 → 统一出库口径（关掉预占扣账）→ 补排产门禁与车间鉴权 → 操作人 → 流水只增不删 → 期初盘点 → 开自动扣料 | 先把「账」修对，否则后面都是错的 |
| **二期** | 盘库任务 + 盲盘 + 复核状态机 + 容差 | 有了对账机制，账才不会飘 |
| **三期** | 报废/内部领用入口 → 包材扣减 → 在途 + 净额下单 + 预占 | 先把主料管住，再管包材和下单 |

> 包材（三期）会比主料晚，因为改动面在发货链路。
> 但比预想的轻：数量直接读订单价格快照，只需给包裹加一个「箱型」字段、在发货确认时挂一笔扣减。

## 11. 验收标准

1. **三段对得上**：一笔采购 → 一锅生产 → 一份出库，原料数量能对上（允许损耗，但要有差异记录）。
2. **无孤儿流水**：每条 `inventory_ledger_entry` 都能点回源单（采购记录 / 锅 / 盘点单 / 调整单）。
3. **差异可统计**：能按分类出「本期报废 / 内部领用 / 盘亏」三个数。
4. **可追责**：任意一笔变动能查到操作人和时间。
5. **不卡流程**：盘库单从提交到复核，目标 ≤ 24 小时；超时提醒。

## 13. 已确认的现场事实（2026-11-10）

| # | 事实 | 对方案的影响 |
|---|---|---|
| F1 | 一张快递单 = 一个泡沫箱；**箱子规格由发货人自己选** | 箱型在发货时选，默认按重量推荐；保温袋、冰袋跟箱号自动带出 |
| F2 | 团队只有两个人：老板（发货 + 采购）、另一名员工（生产 + 采购） | 一人一个账号，车间接口补鉴权就能记到「人」；盘点由员工提交、老板复核 |

### 本期不处理的观察

- **合并发货的定价口径**：价格快照按「每单一个箱子」计费，实物一个包裹只用 1 个箱子。
  这会让「包材成本」和「包材实物消耗」在合并发货时对不上。属于定价口径，本方案不动，留作后续。

| 5 | 必须先完成采购才能进生产 → 采购完成即入库，报销可延后 |
| 6 | 除日采，还有日常补货（长期冷冻食材、补剂、包材），进同一本账 |
| 7 | 包材很多类（标签、自封袋、真空袋、铝箔保温袋、泡沫箱），单位各不相同 |
| 8 | 盘库半个月一次，且频率应该可配 |
| 9 | 盘库盘「所有」 |
| 10 | 员工餐/报废需要统计和归类；分类名用「内部领用」 |
| 11 | 顾客退货仅退款，不涉及实物，不进库存 |

## 附 B：我的判断（老板未明确表态，可调）

| 判断 | 理由 |
|---|---|
| 盲盘（不显示账面） | 显示账面就会照着填，盘点失去意义 |
| 容差 max(2%, 50g) 自动通过 | 防复核变成堵点（反目标 A2） |
| 报废单笔 ≥ 50 元才复核 | 全批没人记，最后都变盘点差异 |
| 包材在发货时一次扣 | 袋数/包裹数到发货才确定，合并发货才不会多扣 |
| 包材数量读订单价格快照，不重算 | 快照里已经有确切数量，重算会随规则变化而不稳 |
| 箱型发货时选，默认按重量推荐 | 老板确认规格自己选；给个默认值就只多一次点击 |
| 期初盘全部、日常盘「有账或有变动」 | 期初不能漏；日常几百行空白会让人乱填 |
| 上线前必须期初盘点 | 现有账面不可信，不定起点后面全错 |
| 撤回用冲红、不删行 | 删行等于改写历史，审计断链 |
| 在途计入可用量 | 否则重复下单 |
| 盘点差异用建单时的 delta，复核不改数字 | 复核窗口的进出会同时改变账面和实物，差额不变（评审纠正初稿） |
| 一期补「采购未完成不能排产」门禁 + 管理员可强制 | 否则完工扣料可能早于入库，先扣成负数 |
| 负库存不拦，标红 + 进待核实 | 配方理论量可能大于进货量，拦了会卡住厨房 |
| 报废/领用按发生当时单价快照 | 用现价会让历史报表随改价变化 |
| 前两期盘点不含包材 | 包材还没接扣减，纳进去会造假盘亏 |
| 零余额且半年无变动的原料不进盘点清单 | 几百行空白会让人乱填 |
