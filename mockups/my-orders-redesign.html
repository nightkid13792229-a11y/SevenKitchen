「我的订单」优化原型

同一位家长、同一批订单：左边是现在打开看到的样子，右边是调整之后的样子。 目标很具体 —— 打开这一页，三秒内知道哪一单要我先动手、 这一单做到哪一步、什么时候能到。

375 × 812 · iPhone 尺寸 沿用深墨绿 + 金 以改前端为主 2026-10-30
一、同屏对照 左：现状（按现有页面还原，含真实按钮与文案）　右：优化方案
1
两层筛选压成一行 类型收进「筛选」，状态做成带数字的胶囊。顶部少占约 40px，卡片本身也更矮，一屏自然能多放一张单。
2
待付款在卡上就能处理 倒计时说清"这单会自己关掉"，两个按钮就地付钱或取消，不用再点进详情页。
3
状态文字 → 四步进度 已付款 · 制作中 · 已发货 · 已签收，再加一行预计发出日。不点进详情也知道"做到哪了、什么时候到"。
4
一单最多两个按钮 主按钮只留一个，其余动作进详情。已发货单从 4 个按钮降到 2 个，不用再在一排里挑。

二、四个关键状态 把"最着急的四种时刻"各画出来，逐个确认
三、三类订单，同一套骨架 成品鲜食 / 食谱定制 / 预分装补剂，卡片结构统一，靠颜色和状态词区分
01

一眼分清是哪一类

一个彩色小圆点 + 两个字：绿=鲜食、橙=定制、紫=补剂。现在是大色块标签再配一条竖色条，同一件事说了两遍。

02

状态词跟着类型换

鲜食"制作中"、补剂"分装中"、定制"定制中"，但进度条永远四步。顾客换类型时不用重新学一遍。

03

补剂明细折成一行

卡片只留"软骨素 60g×2 · 鱼油 30ml×1"，单价和金额收进详情。现在三行明细会把一张卡撑到 200px 高。

04

类型筛选退到二线

绝大多数订单是鲜食，类型筛选放进「筛选」面板；少数要找定制单的家长，多点一次也就找到了。

订单类型进度四步卡片副信息
成品鲜食 已付款 → 制作中 → 已发货 → 已签收 狗狗 · 餐数 · 每餐克数
食谱定制 已付款 → 定制中 → 已交付 → 已完成 为谁定制 · 可修改次数
预分装补剂 已付款 → 分装中 → 已发货 → 已签收 明细一行 · 件数
第一步 · 一周内 只改卡片 进度条 + 预计日期 + 一单两个按钮。不动筛选结构，风险最小，家长感知最强。
第二步 合并筛选，补上待办 一行状态胶囊 + 筛选面板；待付款卡加倒计时和"取消订单"。这一步省下的首屏空间最多。
第三步 收拾边角 空状态分两种、客服入口、单号复制、下拉刷新与骨架屏、把"待管理员排期"这类内部说法换掉。
这次刻意不做：订单搜索框（一年几十单，胶囊筛选够用）、按月份分组折叠（会让"找那一单"多一步）、改动品牌配色（深墨绿 + 金是这家店的识别度）。
四、改了什么、为什么 每一条都能单独上线，也可以整包一起改
01

两层筛选 → 一行

状态做成带真实数量的胶囊，类型和"近三个月"一起收进右侧筛选。

为什么：订单类型每天只在少数几单上用得到，却天天占着首屏最贵的位置。省下的 40px 加上卡片本身变矮，一屏从两张变成三张。

02

状态文字 → 四步进度 + 预计日期

用①已付款 ②制作中 ③已发货 ④已签收四步表示，下面固定一行"预计 X 月 X 日发出"。

为什么：家长真正的问题是"我的狗什么时候能吃上"，不是"现在是哪个状态码"。现在的"进行中"标签下还混着已付款 / 采购中 / 生产中 / 急冻中，标签和卡片对不上。

03

待付款在卡上就能处理

倒计时 + 去支付 + 取消订单，都在卡片上。

为什么：未付款的单现在只有"立即付款"，想取消只能点进详情；已付款的单虽然有个"取消订单"，点进去却是售后申请页——两件事混在一个词里。

04

一单最多两个按钮

主按钮只留一个，其余（取消、投诉、复制单号）进详情或长按菜单。

为什么：已发货的单现在会同时出现 查看物流 / 申请售后 / 确认收货 / 再次购买 四个按钮，手指要在一排里挑。而且"再次购买"不看状态，连没付款的单都有。

05

客服从固定底栏挪进导航栏

导航栏右侧一个客服小圆钮（微信右上角的胶囊按钮让不出位置，这里就放个图标）；每张卡里也留"联系客服"。

为什么：固定底栏常年吃掉 68px，还盖住最后一张卡；客服又不是每一屏都要按。

06

详情入口和单号都变得可用

卡片可以点；右下角给"查看进度 ›"提示；单号改成可读短号 + 复制。

为什么：现在整卡可点但没有任何提示；成品单上根本没有单号，找客服时说不清是哪一单。

07

加载不打断人

首屏用骨架屏；从详情返回时静默刷新，不再每次弹"加载中"遮罩。

为什么：现在每次从详情回到列表都会闪一次全屏 loading，还会挡住点击；这一页也没有下拉刷新。

08

文案说人话

"待管理员排期" → "等待安排发货"；"分装中"保留但配一句解释；英文状态码一律不出现。

为什么：顾客不需要知道"管理员"是谁，也不该看到内部叫法。

09

保留不变

深墨绿 + 金的品牌色、三单合一的合并列表、按时间倒序、售后与退款的判定规则。

为什么：这页的骨架是对的，问题都在"占地方"和"说不清"上，不需要重做信息架构。

说明：原型里的订单、金额、单号、物流轨迹都是示例数据；配色、字号、间距取自小程序现有的设计变量 （#f0f3e9 背景 / #fbfcf7 卡片 / #1e3a2f 主色 / #b08d4f 金 / #b4553f 金额）。 这套方案以改前端为主：进度四步、预计发货日、两个按钮、筛选合并、倒计时都能用现在的订单数据算出来； 只有"可读的单号"需要订单列表接口多带一个短号字段。
