01

首屏合并成一张主卡

进度 + 商品 + 袋数克数 + 实付 + 预计发货，都在第一张卡。

为什么：现在商品被"订单中心卡 / 基本信息 / 购买人与配送"三张表压在下面。

02

六类信息去重

单号、状态、下单时间、账号电话、收货地址、预计制作，每样只留一处。

为什么：现在每样都出现两次，顾客要对照着看才知道哪个是真的。

03

进度改四步、换回品牌色

已付款 · 制作中 · 已发货 · 已签收，和列表页一致；去掉采购中/急冻中。

为什么：现在这条是旧的蓝色六步，和全站墨绿金不搭，词也是内部工序。待付款时第一步显示"待付款"而不是"已付款"（列表页同样要改）。

04

订单号统一成可读短号

顶部那张卡不再显示 36 位长 ID，统一用 SK20261029-004 并可复制。

为什么：顾客要报单号给客服，长 ID 念不出来也抄不下来。

05

没有动作就不出现底部栏

制作中、售后中不再有一条空白操作栏。

为什么：现在这四个状态底部是一条有阴影的空栏，看着像页面坏了。

06

售后入口合成一处

中部三段（取消 / 锁定提示 / 售后）和底部按钮栏合并成一张卡 + 一条底栏。

为什么：同一个动作现在有两套按钮，规则也分在两个地方写。

07

生产结算改成说人话

有调整才出现，写"少了 20g，退了 ¥12"；没有调整整块不显示。

为什么：现在"计划成品 / 实际成品 / 成品缺口 / 待结算"是商家账目，顾客看不出跟自己有什么关系。数据和规则不变。

08

商品卡只留顾客要的

食谱名、袋数、总重、分装明细；版本号 v3、营养标准、原料来源收进"查看食谱"。

为什么：这些是内部规格，顾客核对的是"是不是我买的那份、多少袋"。

09

说明折叠、物流跳转

"商家说明"五条收成一行，点开看；物流从字段列表改成"查看轨迹"，跳到已有页面。

为什么：说明占了整整一屏；轨迹要单独接快递接口，这轮先复用现成页面。

说明：原型里的订单、金额、单号、物流轨迹为示例数据；配色与字号取自小程序现有变量。 这套改动以改前端为主，只有"物流轨迹"需要另接接口，本轮不做，改为跳转现有「物流与食用提醒」页。 页面有 26 个用例、106 条源码断言，重排时只新增不改名，与「我的订单」那次同一套做法。
