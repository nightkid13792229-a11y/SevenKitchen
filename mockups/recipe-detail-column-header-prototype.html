配方明细 · 加一行列头

配方编辑器中间的「配方明细」，现在只有每行自己的一点小字（比如「部位 / 状态 / 预处理」）， 右边的重量、百分比、开关、删除都没有名字。加一行列头以后，每个数字和开关都对得上名字， 还能顺手把每行重复的那串小字收起来，给原料名多让出约 110px；标题行的计数也拆成食材、补剂。

二、列宽与对齐

列宽固定，只有「原料 / 营养档案」吃剩余空间
列宽度对齐说明
排序18px居中拖拽手柄；列头不写字，只留手柄
类型38px居中食材 / 补剂，颜色区分
原料 / 营养档案自适应（≥ 220px）左第一行原料名，第二行营养档案
预处理方式240px左行内那串「部位 / 状态 / 预处理」小字收到列头里
用量84px右单位跟在数字后（g / 勺 / 粒），随原料变
占比50px右占总重（食材 + 按克或毫升计的补剂）的百分比
计入评估56px居中关掉后整行置灰，不参与营养评估
操作30px居中删除这一行；列头不写字，只留图标

除列头外，一起改的四件事

  • 去掉每行的「部位 / 状态 / 预处理」小字：列头已经说明；把鼠标放到列头上能看到填写格式。原料名因此多出约 110px。
  • 数字列右对齐：用量和占比从个位数到三位数都对齐，竖着扫一眼就能比大小。
  • 开关列写明「计入评估」：现在很多人不知道这个开关是干嘛的；关掉后整行变灰，不参与营养评估。
  • 标题行的数字拆开：原来只有「原料 7 种 · 总重」；现在食材、补剂各多少种分开写。总重和占比的算法不变，还是食材 + 按克或毫升计的补剂（粒 / 片 / 勺不计），改用量时当场就变。

三、几种情况

什么时候显示、什么时候不显示
A列表往下滚时

列头固定在列表上方不动，只有原料行滚动。加到十几二十种原料时，往下翻也始终知道哪一列是什么。

B配方是空的时候

不显示列头，只留「从左侧原料库点击食材加入配方」这句提示。没有内容的空表格看着像坏了。

C窗口比较窄时

这一页五栏本来就允许横向滚动。列头和原料行同宽一起移动，不会出现「列头对不上数字」；优先压缩的是原料名列。
